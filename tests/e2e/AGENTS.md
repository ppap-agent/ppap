# 浏览器测试

沿用根目录开发与验证要求。Preview 只证明受控 UI 行为，不能替代真实 API、持久化、计费或模型验收。

- 按用户可见的业务身份定位目标，如任务编号、文件名与对应区域；区域中的任意 `button`、按钮数量或 `.first` 不能证明选中了任务。点击后核对目标页面、地址或状态转换。
- 区分未读取、debounce、读取中、成功空/非空及失败。只有当前查询范围的成功结果能证明空列表；旧查询的结果或错误不能覆盖新查询。刷新失败保留已知数据，不能伪装为零结果。
- 用现有 adapter 与受控 Promise 决定回包顺序，用 Playwright Clock 驱动 debounce/轮询。先证明请求挂起或时钟冻结，再断言等待期间的 UI；覆盖失败恢复、乱序、重复操作及关键终态不回退。
- 排障先核对失败步骤、页面/地址、请求及资源证据，分别判断产品错误和测试定位/装配错误。不得靠增加 timeout、固定 sleep、全局 networkidle、强制点击或削弱业务断言掩盖原因。
- 复用现有 node:test、preview 和真实产品旅程的分层；新增框架须有独立收益依据。仅合成数据场景可留有界失败证据，不录制真实凭据或敏感业务数据。报告区分已通过、失败和因环境未运行。

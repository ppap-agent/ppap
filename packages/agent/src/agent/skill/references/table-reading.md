# 通用表格读取

## 合并与空白

保留原始单元格、有效值和锚点地址。只有单元格属于真实合并区域时，才继承该区域左上角的值。普通空白不自动向下填充；即使上下两行相似，也可能是真实漏填。

纵向合并可能表示多条控制记录共属一道工序。继承工序名称不会把这些控制记录合并为一条。横向合并覆盖多个字段时，检查它是否为标题或备注，而不是将同一值误当成多个独立答案。

数字 0、布尔 False 保留其类型。空白、缺少字段、公式无缓存、解析失败分开表示。公式缓存不代表已重新计算；数值检查涉及公式时确认是否需要重算。图片、签章、控件勾选不能仅凭单元格文本排除。

## 多层表头

先找互相支持的一组表头及其正文，再解释单个关键词。跨行表头是一段区域，不是一行。沿物理列向上收集父子标签，按合并锚点去重，得到例如 `特性 → 产品`、`抽样 → 频率`、`现行控制 → 探测`。

父标签不能取代子标签。相同“日期”可能位于编制、修订或批准下面；相同“产品”可能是产品名称元数据或特性子列。结合表头关系和正文值解释，而不是全页第一个关键词命中。

识别完整表头区域后再选择正文范围；头部纵向合并结束前仍可能是表头。常规表向下展开，修订卡等也可先列数据、再在下方列标签，需确认其方向。表名来自表内容和角色，工作表名称只是线索。

## 行选择

先界定候选网格，再判断各行是否为业务记录。候选范围不等于正文范围；编号、边框或已知空白都不能单独确定行角色。结合业务身份、列分布、填写说明或示例、汇总公式引用范围和相邻内容，区分正文、未用模板、重复表头、分节标题、修订履历和脚注。一个空行或一个“备注”词不是通用终止条件。

汇总公式可能未随新增记录更新；明确的业务身份不能被公式终点裁掉。确认是未用模板或其他非正文时，才写入对应 use.scope 的 `excluded_rows` 并保留依据；角色证据不足或互相冲突时，写入同一用途的 `unresolved_rows`。`unknown_formula_cache` 是值未知，不能当作已知空白来确认未用模板。

重复表头需要与已识别的表头结构一致，正文中的相同词不能单独触发删除。分页后重新观察表头和列位置，重复表头的行数不固定。保留每个排除行及理由，让后续可检查是否误删违规行。

已确认的业务记录仍按规则审核必填空白，不能因缺值而改成模板。记录身份已确认时，字段值未知只影响相关判断，不改变记录角色。正文行可有空工序编号，但仍有测量项目、控制方法或频次；结合上下文识别同一工序的后续记录，不能仅凭编号为空就排除。

## 关联与标准化

跨文件比对前记录提交组、零件号、版本和工序身份。仅表格长得相似不足以关联。连接键的取值范围和重复性先统计，再选一对一、一对多或集合包含检查。

空白规范化、单位换算、编号标准化与语义等价分别说明。保留原值及转换理由。精确比对不能暗中删掉材料牌号、版本后缀或单位。

## 读取一次的完成条件

缓存带源哈希的原始快照；保存映射和正文范围。多个规则共用同一绑定，计算只读取缓存。如果新证据要求改变边界或字段含义，更新绑定并重算受影响规则；不要在不同规则中临时采用矛盾映射。

# 跨文件比较

本轮授权来源由 documents.json 和 document-index.json 固定。按零件、版本和原文要求确认文件关联。文件名只供导航；身份未确认时 input 保留 unresolved。

## 缓存程序拥有比较含义

例如“PFD 每项工序均在 CP 中体现”：records.source 为 pfd_processes，require 为 Related(target=cp_processes)。PFD→CP 有方向，CP 多余一项不自动违规。源和目标的逻辑键、显式拼接或格式模板、归一化、匹配基数及值比较均来自原文，不由本次绑定临时决定。

- any：至少一条对应记录满足全部要求。
- all：存在对应记录，且所有对应记录满足。
- one_to_one：源对象唯一，目标恰好一条，并且没有两个源对象共用该目标。需要反向覆盖时，另由原文声明反方向。

完整源集合、重复行和原始身份全部保留。不要先去重，也不要只用 JOIN 的匹配结果作为审核范围。

## 绑定及用途

同一物理 Binding 可供不同 input 使用。工序组标题可参与流程覆盖，并在特性明细用途中明确排除。不能把某条规则的筛选写进共享绑定。

Late binding 只映射原始列、表和范围。保留父子表头路径、原生数值及真实合并锚点，不能把计算后的字符串冒充原始列。需要“产品”和“过程”两种投影时，程序分别声明 Related，再按原文组合。

默认 typed key 区分布尔、文本和编号；原生数值 10/10.0 同值。原文允许时才用 separator、template 或 whitespace/casefold_whitespace。separator 只放字面分隔符；字段占位符必须使用 template，如 `【{type}】【{kind}】{desc}：{value}`。不要默认删除小数点、标点、前导零，或纠正 O/0。

## 全量计算和局部问题

正式关系由固定 checker 执行。any 先检查全部精确键候选；目标资格不依赖模型答案且已有原生值充分匹配时，不再询问其余语义配对，并明确候选搜索未完整。其余情况保留候选图；all/one_to_one 仍检查完整候选、重复和共享目标。目标资格未知仍是可能候选；已知不等的键分量可在精确比较中排除无关候选。局部 any 命中不能消除未完成的范围或未知记录成员资格。

不同的已知值只有在 mode=semantic 时才提出局部问题。问题包含双方原始记录、字段和值来源。原始值不可读时，不能用语义答案伪造已知值。语义键还需处理别名和唯一性；没有充分回答时保留未知。

完整观察留在原件读取结果里。SQL/Python 可辅助探索，但不提交另一份最终判定或逐行证明。

旧 checkers 可提供字段别名、实际布局、方向及反例。其 normalize_key 删除标点、value_matches 接受子串、提取器只选最佳单表等策略，必须核对原文后才能使用，不能成为通用相等或范围定义。

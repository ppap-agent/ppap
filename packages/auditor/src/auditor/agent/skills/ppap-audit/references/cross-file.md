# 跨文件比较

条款要求目标文件与同批其他文件一致时，直接去读那份文件，证据写那份文件自己的名字和位置。

## 确认是同一件事

- 同批全部文件在 `files.json`，勘查记下的零件号、版本在 `dossier.json`。
- 按零件号、版本和条款的要求确认两份文件说的是同一个零件。文件名、目录名和相似的标题只帮你找，不是证据。
- 条款要求的对端文件不在本批时，依赖它的要点是 `unknown`，写明缺哪份文件。不能因此通过，也不能因此判不通过，除非条款明文规定缺件即不通过。

## 比较的含义来自条款

- **方向**：「A 的每一项都在 B 中体现」是 A 到 B 的覆盖，B 多出来的不自动违规。
- **数量**：分清「至少有一条对应」「所有对应的都满足」「一一对应」。
- **怎么算相等**：按条款写的办。条款没说可以去空白、忽略大小写、换前缀或截尾缀，就按原值逐字比较。不删小数点、前导零和标点，不把 O 改成 0。数值 10 和 10.0 相等；文本数字不强转。
- 先数清楚两边各有多少条、连接键有没有重复，再比较。保留全部源记录，不要先去重，也不要只拿匹配上的那几条当范围。

## 未知与反例

- 一边读不到、公式无缓存值、或记录身份不确定时，这项比较是未知。
- 同一身份的记录两边取值不同，或要求覆盖的项目在对端确认不存在（对端的相关范围你读完了），是不符合，两边的出处都要写。
- 没搜完不能写成「对端没有」。

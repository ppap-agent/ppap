# auditor

实验：不用检查程序，让模型像审核员一样，凭一组读取工具直接对照条款审原件。它不在客户路径上，产品的审核仍由检查程序和深度复核完成；这里用来对照两种做法的差异和潜力（见 [bench/pure-audit](../../bench/pure-audit/README.md)）。

本包不依赖 `audit`、`agent`、`product`、`documents`，只用读取库、LibreOffice 和 Pi。

## 组成

| 文件 | 作用 |
|---|---|
| `originals.py` | 按位置读原件：单元格、合并区域、PDF 页（表格按行列还原，页上的图片连同所在的格）、Word 段落和表、内嵌图片、绘制的图形、页面渲染、视觉模型转写（同一处只转写一次）。只观察，不判断。 |
| `tools.py` | `look` 命令，审核员的眼睛和手。每次读取都说明显示了什么、还有什么没显示，记下看过的范围，并告诉审核员还剩多少时间。 |
| `verdicts.py` | 结论能不能记下：引文回到原件核对，声明查过的范围确实看过，结论由要点推出。案卷里的事实同样带出处并重新核对。 |
| `run.py` | 一个批次的调度：准备、阅卷，再让每条条款各走审核、专审、质证、裁决。 |
| `agent/` | 审核员的固定要求（`AUDITOR.md`）、各步骤的任务说明和技能 `ppap-audit`。固定要求和技能的参考在启动时合成一份系统说明。 |

## 结论的形状

一条结论由若干要点组成，每个要点是条款通过所必须成立的一件事，结果是 `met`、`unmet`、`na`、`unknown` 之一。结论由要点决定，由程序核对：

- `PASS`：全部 `met` 或 `na`，至少一个 `met`。有 `unknown` 就不可能是 `PASS`。
- `NG`：至少一个 `unmet`。
- `UNABLE`：没有 `unmet`，至少一个 `unknown`。
- `NA`：全部 `na`。

要点的依据有两种：

- **引文**（`evidence`）：文件、位置、原文。单元格、文字层、段落的引文去掉空白后必须是该位置原文的一部分。图章、签名、扫描页上的内容没有文字可比，标为所见（`seen`），事后由视觉模型独立转写同一处，记下两者是否一致。
- **查过的范围**（`searched`）：要点说「每一处都…」或「哪里都没有…」时列出。程序按 `look` 的记录核对这些范围确实完整看过；每名审核员只对自己看过的负责。

这些核对不判断结论对不对，只保证依据能回到原件、没看全的不能写成看全了。

## 流程

调度在宿主这边，每名审核员只做一件小事，各有时限：

```text
准备 prepare     不用审核模型：转换格式、找出 PDF 的表格和图片，扫描页和图片各由视觉模型转写一次，全批共用
阅卷 read        每份文件一名审核员翻一遍，把身份、表结构、签署和图片记成带出处的案卷，全批共用
审核 audit       每条条款一名审核员，只审这一条
收尾 close       审核或专审到时限还没有结论：同一名审核员接着原来的会话再给 240 秒，不能再读，只把已读到的写成结论
专审 focus       收尾后仍没有结论的条款，交给另一名审核员，推理强度更高，并告诉他前一名看过哪里
质证 challenge   （默认关，--challenge 打开）第二名审核员看这条结论站不站得住：维持，或提交改判
裁决 arbitrate   改判的条款交第三名审核员，回到条款和原件定夺，推理强度更高
```

后一步只在前一步留下了要做的事时才运行。一条条款一个会话，难的条款拖不住别的条款，也没有哪个会话要背着整份文件的阅读记录。审核员读到别人也用得上的事实就记进案卷（`look note`）。阅卷的审核员还可以用 `look remember` 记下同类文件的读法经验，下次审同类文件时读入；只记怎么读，不记结论。

审核模型能直接看图：`look render`、`look picture` 给出的图片用读取工具打开。表格文件可以只画一张工作表或一块单元格区域（`look render 文件 --sheet 表名 --range A1:S10`）：复制一份工作簿，只改打印设置（隐藏其余工作表、把区域设为打印区域并缩到一页），单元格、图片和图形都是原件的，所以盖在那几格上的章和签名照原样出现。启动时在 Pi 配置的副本里声明模型接受图片；设 `AUDITOR_BLIND=1` 可以关掉，只靠转写。

## 运行

在镜像里运行（[deploy/auditor](../../deploy/auditor/README.md)）。批次目录含 `files/` 和 `batch.json`：

```json
{
  "files": [{"name": "01.xls", "path": "files/01.xls"}],
  "targets": [{"name": "01.xls", "document_type": "PFD", "rules": {"title": "过程流程图（PFD）", "rules": [{"id": "PFD:1", "rule_to_check": "…"}]}}]
}
```

```bash
python -m auditor.run /work/batch --thinking medium --hard-thinking high --seconds 600 --concurrency 12
```

结果写在批次目录的 `results.json`。批次目录里还有：`cache/`（全批共用的渲染、转换和转写）、`dossier.jsonl`（案卷）、`read/NN/`（阅卷）、`audits/NN/<条款>/`（每条条款的工作目录：`logs/` 是各步骤 Pi 的事件，`.audit/` 是看过的范围、记下和被退回的结论）。

### 实施、验收与设计判断

通用改动由 `05b1a4be`、`036c7203`、`f6d5155b`、`42af7d18` 提交：规则和目标驱动布局导航，展示前八列外、合并与无命中区域；紧凑 JSONL 按字节展开，保留类型、公式、合并和出处；固定机械检查交给宿主，保留原规则语义核对；图形可能覆盖的空值保持未知，原生非空、0、false不丢失；模型补充值单独保存。没有新增 Agent 阶段、DSL、第二求值器或生产渲染服务。

固定源代码回归：Deep／原型／Core相关 **1032 passed、1 existing xfailed**；独立 wheel **836 passed、1同一xfail**；本机PG产品Deep／反馈／MCP owner **94 passed**；浏览器反馈 owner **1 passed**；Web适配器 **3 passed**。集合有重叠，不相加为准确率。既有 xfail 是 PDF 背景网格边界。精确源码的 Spec／Standards 审查无未解决发现。补充核验及统计器的精确代码也经过独立正、负控；它们没有重跑 provider。生产镜像和部署没有在本轮验收。

设计上的下一步应落在现有 ontology 与逻辑文档：先以布局、合并和上下层关系证明对象角色，避免用被检属性是否为空反过来筛掉对象；再对视觉来源做局部、可复用且有出处的观察，减少整表未知向逐格事实请求扩散。存在性真需要有效见证，否定需要完整范围；证明非空不一定要求完整转写；列存在与每个值已读出不同。保留全部对象和独立义务的覆盖，不能找到一个 NG 就结束整份审核。

规则附录用于已确认的含义、别名和政策。含义固定后仍须读取事实；视觉事实不可读不能自动回答否。用户界面也应区分规则解释、证据不足和身份关系不明。本轮观察支持这些方向，没有证明相关能力已完成；不为某个水印、工序名或样本添加特判。

原评分曾将概念记为 4/9、绑定记为 8/9。只读复核发现三类 oracle 过严，已修评分并保留旧报告：

- 文件候选可以包含本次其他授权文件；规则只要求目标附件存在，不能强制候选集合恰好为一个文件。
- 字面拼接规则未规定源记录的完整身份集合。`code` 与 `code+name` 都可保留合法记录；仍严格核对拼接字段、顺序、标点、来源和完整对象范围。
- 预期的语义澄清可将目标身份保留为 `field_holes.unresolved`，而不是提前认定原列含义。只有同身份字段、实际确认问题、正确表头证据和明确未知结果相符时才接受；错列、无问题和源侧漏绑仍拒绝。

最后复审还发现评分器曾只找到 Related 节点，没有检查它是否是必选义务：OR 分支可能绕过关系，额外前置门控或条件也可能在当前样本中碰巧不改变最终状态。现在本组 oracle 要求唯一 Related 位于正向 All 路径，只允许原规则蕴含的 `not_empty` 合取，并拒绝未声明的 precondition。成对 Not 会先消除，保留双重否定的逻辑等价；没有扩展成通用逻辑求解器。字面拼接不自动要求各分量非空。

受控 metadata 提案此前也曾只比较名称相等，漏掉原文明确要求的名称非空；两个名称都空时会错误通过。控制器现从原始规则文字补上这项义务，不读取 gold 开关。新增反例同时检查删除义务、OR 绕过、额外条件及翻转 oracle 不会改变控制器提案。旧 controlled 输出没有覆写；[最终 controlled-04](output/ontology-v8-controlled-04/report.json) 的 11 项三层各 11/11。这是受控接口验收，不能称为模型能力提升。全套回归在最后双重否定等价简化前为 797 通过、1 项既有预期失败；简化后相关 51 项再次通过，未推算未运行的全套数量。

当前重放评分为：严格概念合同 7/9、绑定 9/9、最终预期 9/9。其余两项是关系 kind 的解释差异：模型将同编号记录的对应表示为 `association`，gold 采用 `same_instance`；实际匹配键、一一对应与重复检查仍正确。它们保留为未裁定的建模差异，不据标签直接宣称业务错误，也不放宽所有 association 的身份校验。

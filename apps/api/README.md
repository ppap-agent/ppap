# Product API

PPAP 唯一公开 HTTP API（含同进程的 `/mcp`）。isolated-dev 的构建与启动见 [deploy/isolated-dev](../../deploy/isolated-dev/README.md)。

- 路由与 JSON 形状：FastAPI OpenAPI（`app.openapi()`，Web 生成物 `apps/web/src/generated/openapi.ts`），不在此列举。
- 职责：身份/会话、租户与对象授权、文件版本、任务受理与幂等、上传准备草稿、结果与历史读取、人工复核、用量与飞书适配。见 [AGENTS.md](../../AGENTS.md#架构)。
- 不负责：OCR、LibreOffice 转换、长模型/审核执行和 Worker 租约，这些在 Worker。
- 生产 JSON 日志带 `request_id` / `tenant_id` / `round_id`，响应带 `X-Request-ID`；不记录 token 或客户内容。
- MCP 服务合同见下文「MCP」；测试见 [tests/README](../../tests/README.md)。

## MCP

用户给出一个飞书文件夹，PPAP 在服务端把它准备成一次可确认的审核；只有人能决定的事才问人，决定后自己接着做。工具与参数形状以服务端注册为准。

- **任务是中心**：持久状态机，记着资料来源、每份文件的导入和用户的决定。`product.workflow` 的 `apply`（事件→状态）、`effects`（状态+事实→要做的事）、`project`（状态+事实→阶段、问题、下一步）不做读写；`api.mcp_runtime` 经 Product API 执行副作用，请求编号由任务编号推导，中断重做不重复；状态存在 `product.audit_workflows`，按修订号比较写入。文件之间互不依赖、结果累积；阶段之间有依赖，一个问题只挡住依赖它的部分；中断是常态，任何时候读它都得到同样的问题和下一步。
- **工具**：`find_submissions`、`prepare_audit`（必须带用户选的客户 `key`）、`get_task`、`get_issue`、`resolve_issue`、`confirm_audit`、`get_results`、`get_finding`、`record_review`、`publish_report`、`sign_round`、`find_audits`、`get_operation`、`get_account`（含各客户的规则库版本）、`get_rulebook`（只读：某客户规则库某修订按文件类型分组的条款原文、摘要、改动说明与是否有检查程序，不给修订号取最新，可分页）、`prepare_rule_clarification`、`get_rule_questions`（只读：某客户规则库某修订已发出的问题卡片逐张原文、选项与每人的答复，不给修订号取最新发过卡片的修订，可按等答复／已答复筛选、分页）、`answer_rule_question`（按本人说的选项或原话作答一张卡片，需授权 `rulebooks:answer`，同一 `request_id` 只记一次）。只有工具，没有 Resources 与 Prompts；MCP 不传字节，没有检查程序工具，不改审核用的规则。每个面向用户的路由要么由工具到达，要么在 `apps/api/tests/test_mcp_coverage.py` 写明为何留给网页。网页或插件发起的审核同样能用 `get_task`、`get_results`、`record_review`、`publish_report`。
- **每次返回** `result`（已确定的事；`phase` 取 `preparing`、`awaiting_decision`、`ready_to_confirm`、`auditing`、`completed`、`closed`，各阶段状态分开表达）、`issues`（带 `allowed_actions`）和 `next`：`wait`（`check_after_ms` 后再读）、`user_action`（交给用户；带 `url` 的是签字类提议，用户在 PPAP 网页里核对当前内容后完成或拒绝，之后用同一 `request_id` 再调读回结果：已完成、没完成及原因、已拒绝及原因）、`user_action` 带 `ask` 时问用户要 `ask` 列出的内容，再按 `then` 调用（`new_request_id` 表示换新编号）、`call_tool`、`recover`（用同一 `request_id` 重复或读回执，`new_request_id` 策略表示换新编号）、`done`、`blocked`（只用于权限、角色、政策拒绝，`message` 原样转述；合同测试 `apps/api/tests/test_mcp_next.py`）。`next` 是建议不是授权：`confirm_audit`、`record_review`、`publish_report`、`sign_round` 只在用户明确要求时调用。
- **问题与决定**：问题由状态推导，起因消失即消失；任务可读多个来源：`add_source`（准备与待确认阶段，也挂在缺资料的预检问题上）补一个用户给的飞书文件或文件夹，`replace_source` 替换读不到的来源，补或换之后重读全部来源、报价随之改变，旧报价不能再开始审核；`resolve_issue` 只接受列出的动作并带 `task_revision`，过期、已关闭或不在列表的一律拒绝。类别有 `access`、`import`、`source_changed`、`rule_conflict`、`missing_evidence`、`quote_changed`、`fact_confirmation`、`review`、`delivery`。文件夹连同子文件夹读取（最多 5 层、100 个子文件夹、200 份文件），内容相同的文件只审一次。
- **报价与确认**：`quote_id` 随文件、规则版本、模式或计费依据变化而变；与当前报价不符、文件夹已变或不在待确认时不开始。网页完成时按当前内容和业务前提执行，内容变了返回 409 并刷新为最新内容。
- **写操作**：每个写操作带新的随机 UUID `request_id` 并一直沿用；任务编号由用户和 `request_id` 共同决定。同编号同参数读回原结果，换参数拒绝；结果未知不换编号。复审用 `follows_task_id`。
- **服务与授权**：`PPAP_MCP_ENABLED=true` 时 API 提供 `/mcp`（Streamable HTTP）；生产地址 `https://ppap.icoastline.com/ppap/mcp`。授权服务器在 API 下的 `/oauth`，`resource` 必须精确等于服务器地址；客户端申请的权限默认全选，用户可取消。发现地址 `https://ppap.icoastline.com/.well-known/oauth-authorization-server/ppap/oauth` 与 `.../oauth-protected-resource/ppap/mcp` 必须由代理交给 API（`deploy/tke/edition-proxy.conf`）。其他网页直接调用时把完整 HTTPS Origin 加入 `PPAP_MCP_ALLOWED_ORIGINS`。用户在 `/mcp/connections` 撤销连接，已受理的审核照常执行。
- **客户端身份**（#356）：除动态注册外支持客户端元数据文档（`client_id` 是 HTTPS 地址，元数据声明 `client_id_metadata_document_supported`）。外部客户端只是人的工具，授权来自人本身的行为：授权页、连接页、网页提议横幅和回执只写人做了或要做什么（授权、连接、请求，回执的经由只写本人完成的地方），从不显示是哪个工具发起的。
- **接入**：任何支持 Streamable HTTP 与 OAuth 的客户端都可连接，如 `codex mcp add ppap --url https://ppap.icoastline.com/ppap/mcp` 后 `codex mcp login ppap --oauth-client-registration dcr`。豆包工作建 MCP OAuth 2.1 连接器，并上传 [`deploy/doubao/ppap-audit`](../../deploy/doubao/ppap-audit/SKILL.md) 技能。停止使用时先撤销委托，再清客户端凭据。

## 飞书外部事实

以开放平台为准，变更后重新核对。发消息最小权限 `im:message:send_as_bot`，附件上传用 `im:resource`；租户授权须 `grant_status=1`；用户信息接口与字段权限分开；通知卡片用 JSON 2.0（`schema: "2.0"`、`body.elements`、`behaviors`，客户端 7.20+），动态文本须转义；卡片按钮经 `card.action.trigger`（需 `FEISHU_VERIFICATION_TOKEN` 与开发者后台「卡片回传交互」回调地址 `/integrations/feishu/events`）回到 PPAP：按钮值是网页的签字调用（方法、路径白名单 `feishu.CARD_CALLS`、请求体与前提），`api.card_actions` 把点击人绑定为企业成员并核对这张卡片确是 PPAP 发给他的，再在同一进程以本人身份调用该接口，2.5 秒内回 toast 并把结果写回卡片，超时只说已受理（同一请求号，再点不会重复）；按钮出现的条件见 [AGENTS.md](../../AGENTS.md#架构)「通知」；旧卡片上的开始按钮只回提示（#355）；`app_ticket` 由同一回调接收，过渡期见 [deploy/tke/README](../../deploy/tke/README.md)。飞书报告文档（#359，用户身份）：报告授权登录（`/login/feishu?purpose=report`）请求 `docx:document:create`、`docx:document:write_only`、`docx:document:readonly`、`docs:permission.setting:write_only`、`docs:permission.setting:read`、`docs:document.media:upload`，普通登录不请求；建 `POST /docx/v1/documents`；设为企业内只读用「更新云文档权限设置」`PATCH /drive/v2/permissions/{document_id}/public?type=docx`，只传 `external_access_entity=closed`、`link_share_entity=tenant_readable`（增量更新，`docs:permission.setting:write_only`），结果未知时用同地址 `GET` 读回（`docs:permission.setting:read`）；附 PDF 三步：在文末建空文件块（`block_type` 23，返回的是包着它的视图块 33）→ `POST /drive/v1/medias/upload_all`（`parent_type=docx_file`、`parent_node`=文件块、`extra={"drive_route_token": 文档}`、Adler-32 `checksum`，≤20 MB，`docs:document.media:upload`）→ `PATCH /docx/v1/documents/{document_id}/blocks/{block_id}` 的 `replace_file` 绑定；只有建块会重复，建块结果未知时用 `GET /docx/v1/documents/{document_id}/blocks`（`docx:document:readonly`）读回没有记录的空文件块；同一文档每秒最多 3 次编辑；文本链接 URL 要整体 URL 编码；用户未授权时返回 99991679（重新登录报告授权）。通知总开关 `PPAP_FEISHU_NOTIFICATIONS_ENABLED`；单任务联调用 `dispatch_task_notification(..., task_id=...)`，历史补发须另行授权。

# PPAP 飞书项目插件

飞书项目（Meego）工作项详情里的“PPAP 审核”标签页。需求与验收见 #324。

打开标签页看到的是这个工作项的一包 PPAP 资料，而不是一次次审核任务：

- **资料**：列出工作项的全部附件，以及最近一轮审核对每份资料的结论。审核客户（例如联电）在 PPAP 客户登记里的资料类型集中还没有提交的，单独列出。
- **使用说明**：页签右上角“更多 → 使用说明”和连接页都能打开，写给使用者的操作步骤只放在插件里（`src/features/ppap_tab/Guide.tsx`），这里不再重复。
- **上传资料**：在页签里选择文件或整个文件夹，用本人的飞书项目身份放进工作项的“PPAP 资料”附件字段（空间没有这个字段时，用唯一的非报告附件字段）。同名文件不重复上传，隐藏文件跳过；上传结果不确定时先读回字段。
- **审核整包**：每次审核都覆盖当前选中的整包资料。已有一轮结果时走 PPAP 的重审入口：上一轮冻结过的文件保持原版本，新附件作为新文件加入，这样跨文件的要求总是对着完整的一组文件检查。上一轮用的规则若已有新版本，确认时提示“审核规则已更新”，默认使用新版本，可改为沿用上次版本。送审份数以 PPAP 保存的确认范围为准；只有送审文件上的文件级预检阻断会挡住开始审核。重审按整包计费，确认前显示预计用量。
- **结论**：页面顶部的结论就是这个工作项最近一轮的结论（不论是谁发起的），不跨轮次拼凑。附件在审核后有增减时明确提示“当前结论针对变化前的资料”。
- **问题**：最近一轮里需要人处理的检查项，对照原件核对、记录人工复核；与上一轮相比标出“新出现”“仍存在”“已解决”（按识别出的文档类型对应同一份资料）。可一键复制整改清单。
- **写回**：由最近一轮的发起人把这一轮的结论写入工作项评论区，供没有连接 PPAP 的同事查看；较早的轮次不能再写回。
- **AI 节点**：流程里配置了 [PPAP AI 节点](../meego-ai-node/README.md) 时，节点等待期间、且这个工作项上还没有任何人的审核时，打开标签页会自动准备第一次审核，停在确认；结论为“符合”并写回后节点自动完成。

审核事实（冻结的文件版本、规则、结果、复核）都在 PPAP，标签页每次从 PPAP 读取，不依赖浏览器本地存储。附件与审核文件的对应关系来自文件版本记录的来源附件。

## 工作方式

- 插件页面由飞书项目托管，运行在 `https://projectplg.feishupkg.com` 的 iframe 中，只调用 PPAP 后端，不复用 PPAP 网页前端。
- 界面用飞书项目的组件库 Semi，并跟随宿主的主题和深浅色；提示、剪贴板、跳转用宿主 SDK。布局按标签页自身宽度响应：窄时一次只看一件事，宽时问题列表、检查项和原件并排。
- 原件按审核冻结的文件版本显示：Office 文件用 PPAP 的 OnlyOffice 只读预览，PDF 和审核报告用与 PPAP 网页端相同的 pdf.js，图片直接显示。
- 首次使用时，插件用 `JSSDK.utils.getAuthCode()` 获取授权码，交给 `POST /integrations/meego/session`；PPAP 返回一个连接链接。用户在浏览器里用飞书账号登录 PPAP，并在确认页确认后，飞书项目身份才会绑定到这份飞书授权上。
- 之后每次打开标签页，插件都换取一个 2 小时有效的宿主会话令牌，并通过 `Authorization: Bearer` 调用 PPAP 接口。令牌只保存在内存里，网页的 Cookie 会话不能当作令牌使用。
- 附件由 PPAP 后端直接从飞书项目下载，不经过插件页面上传。写回时先查评论里是否已有本轮的标记；结果不确定时只读回，不会重复写入。

## 后端配置

API 进程需要以下配置（见 `.env.example`）：

- `PPAP_MEEGO_PLUGIN_ID`、`PPAP_MEEGO_PLUGIN_SECRET`：插件凭证。Secret 只注入 API。
- `PPAP_MEEGO_TENANT_MAP`：飞书项目 `saas_tenant_key` 到同一企业飞书 `tenant_key` 的显式映射。没有映射的空间一律拒绝。
- 该飞书租户还必须在 `PPAP_CURRENT_TENANT_ALLOWLIST` 中。

插件需要在开放平台“权限管理”中申请读取工作项、读取附件、读写评论和读取用户的权限，并在空间中安装。

## 开发与发布

```sh
cp plugin.config.example.json plugin.config.json   # 填入插件 ID、Secret 和详情页 resourceId；该文件不入库
npx -p @lark-project/cli@2.8.6 lpm start          # 本地调试，需要信任 CLI 生成的本地根证书，并允许浏览器访问本地网络
npx -p @lark-project/cli@2.8.6 lpm release --source-type remote   # 构建并上传产物，输出产物版本
```

产物上传后，在开放平台“插件发布”中创建版本：使用范围选“指定空间”，不发布到插件商店。PPAP 后端地址在 `src/features/ppap_tab/config.ts`。

# Northstar：一个可追溯的 PPAP 审核产品

状态：2026-09-18 接受的产品方向。本文件拥有目标产品语义，不证明能力已上线。

两家公司合并后，旧公司、语言和服务名不再决定产品边界。保留业务知识和可验证能力，收敛重复身份、文件、轮次、结果与用量记录。

## 产品承诺

用户可以准备一组资料，明确目标与参考文件，选择规则，提交一次审核，离开后回到同一轮；能够看懂检查覆盖范围、逐项结果和原始依据，记录自己的复核与下一步。

优先实现普通浏览器/PWA；同一产品后续承接现有飞书应用入口。渠道不新增第二套业务事实。PWA 不默认承诺离线运行审核或缓存敏感原件。

## 产品语言

本词汇从 [hax 已核对版本](https://github.com/ppap-agent/hax/blob/0923f5acea380ddd09813621703777153a8c7971/products/ppap/CONTEXT.md) 迁入。本文件是新产品语义入口；hax 继续拥有遗留现场事实，不再作为新仓日常开发的必读依赖。

| 词 | 含义与边界 |
|---|---|
| 资料集 | 为同一审核目的选定的待审文件与参考文件 |
| 待审文件 | 本轮需要得出检查结果的资料 |
| 参考文件 | 判断的上下文；被引用不等于它已被完整审核 |
| 文件版本 | 确定内容的版本；同名、同路径、上传时间或审核次数都不能代替内容身份 |
| 审核草稿 | 尚未受理的范围、文件和规则选择 |
| 审核轮次 | 固定输入版本、资料角色与规则版本的一轮检查；用户重审创建另一轮 |
| 检查项 | 规则要求，不一定是问题 |
| 检查结果 | 机器结论 PASS、NG 或 ERR，执行状态另存；空结果和未知值不能变成 PASS |
| 待核对问题 | 需要人核对的疑点或不符合项，不等于已确认质量问题 |
| 证据 | 可追溯的原始资料及位置；模型解释和建议不是原文证据 |
| 检查覆盖范围 | 实际检查了什么、用了哪些资料、未检查什么；不能外推为完整 PPAP 批准 |
| 人工复核 | 有对象权限的人记录判断、理由和后续要求；不修改原机器结果 |
| 问题处置、整改事项 | 人工判断及具有可核对完成条件的后续工作；不是审批工作流的默认授权 |
| 正式批准 | 组织授权人对明确版本和范围作出的接受决定；本轮目标不实现正式签批制度 |

## 完整产品的验收面

1. 真实身份、租户和对象权限；同一企业内的协作能力不得无声退化为仅创建者可见。
2. 本地/飞书来源成为可核验的历史版本；下载、预览与证据定位对应同一份内容。
3. 草稿明确目标、参考资料和版本化规则；未提交不会自动消耗一次审核。
4. 一次产品受理，持久执行、断线回访、技术重试；显式重审才创建新轮次。
5. 如实呈现 PASS/NG/ERR、未覆盖内容和定位缺口；授权复核、并发冲突可见。
6. 真实用量、外部权益/计费确认、历史链接与数据迁移。
7. 可重复部署、恢复和回退；只退出已无调用方的 PPAP 遗留路径。

首批格式、规则和证据定位按真实样本建立支持矩阵。没有矩阵证据不写“支持所有 PPAP”。质量门槛来自已审阅 oracle 和业务要求，不临时制造准确率数字。

## 不属于自动扩展的范围

不重建链企云通用组织树，不迁入完整 FMEA/PQM/8D 产品，不另建群聊审核产品，不要求所有飞书原生组件，不把开发自动修复工具当成审核运行时。对既有客户或 Docs 入口的承诺，先识别消费者，再迁移或由产品负责人明确改变范围。

“完整”不是全部 Issues 关闭这个动作。它要求核心 Stories 的真实结果、格式/规则支持矩阵、迁移与恢复证据以及剩余限制共同成立。

# Northstar：一个可追溯的 PPAP 审核产品

本文件只定义产品语义，不描述实施顺序或测试治理。

## 产品承诺

质量工程师上传 PPAP 资料，确认系统为每份文件匹配的客户规则，离开后仍能回到同一任务，查看逐文件、可对照原件的审核结果与报告。

普通浏览器/PWA 是主入口；飞书进入同一个产品事实和轮次体系，不建立第二套业务台账。

## 近期客户旅程

近期交付以 [#162](https://github.com/ppap-agent/ppap/issues/162) 的 V3.1 合同为准：上传与检查 → 确认规则 → AI 审核 → 报告/历史。

- 客户可不选客户直接上传；不要求先建批准事项、填写供应商/工厂/修订，或配置 Agent。
- 每份选中的文件分别匹配实际生效规则，确认后冻结文件版本与每文件规则快照。多文件类型不能因页面只有一套审核依据而被悄悄改为参考文件。
- 客户导航承载 PPAP Audit、审核文件、模板库、用量记录与联系支持。客户模板与系统判定规则分开，不把规则编辑/发布作为客户必经步骤。
- 任务进度、文件执行、业务判断、检查覆盖、报告生成和费用结算分别表达；未知、未覆盖和技术失败不能冒充通过，也不能一律当成不符合。
- 界面就绪只证明交互；示例数据仅用于明确的预览/测试通道，不能产生真实审核结果、收费、通知或报告。

人工复核记录及其历史继续保留；补件、变更影响和正式批准不成为本期客户主流程。费用、权限及其他未决政策按 [#163](https://github.com/ppap-agent/ppap/issues/163) 的明确决定处理，不由界面默认值或示例推导。

Alpha 入口边界：ppap-web 保持全局默认；`/enter-current` 在登录与租户校验通过后默认进入新版 `/audit`。显式的合法同源任务、报告与历史轮次深链保留，选择新版不授予对象访问权。此入口决定不代表已获准合并、部署或切换生产流量。

### 结果与报告边界

按 #163 已确认的 D1～D3：全部适用项执行完成且依据有效才可判文件 PASS。有效 NG 如实显示，同时列明未知、未覆盖和执行错误；未完整验证的文件只保留审核记录，不生成正式 PASS/NG 报告。

零匹配使用独立的“结束任务”，说明“未匹配到可用规则，未开始审核”，零收费、零报告，不制造通过结论或报告生成通知。

审核结果与报告生成状态分开。文件审核均终态，且应生成的报告均到就绪或失败后，任务可完成。失败报告保留可达的重新生成入口，只恢复相同冻结结果的产物，不重跑审核；没有就绪报告时不能声称报告已生成。重生成的费用和余额政策不由此推导。

## 迁移下限与最终目标

现有 PPAP 系统的客户可见能力是**迁移下限**：整合不能因为换仓库、框架或架构而丢掉当前客户能够完成的任务。

Northstar 是**最终产品目标**：旧系统没有的、但已经在本文件接受的能力（例如统一审核轮次、可追溯复核）仍应完成。不能因为 legacy baseline 没有它就取消目标。

因此迁移验收同时满足：
- engine 与固定 `ppap-agent` baseline 不新增 regression；
- 飞书与固定现有产品 baseline 相比客户功能不减少；
- 新系统完成本 Northstar 定义的产品闭环。

`ppap-agent` 长期保留：其它用户仍需要它；对本仓它是新审核算法的验证基地和参考实现。本仓客户入口可以切到 current `ppap`，但不 archive、不 sunset、不拆除 `ppap-agent`。算法优化先在 `ppap-agent` 验证，再进入本仓；不把拆除它当作交付条件。

## 产品语言

| 词 | 含义 |
|---|---|
| 资料集 | 为同一审核目的选定的待审文件与参考文件 |
| 待审文件 | 本轮需要产生检查结果的文件 |
| 参考文件 | 判断上下文；被引用不等于已完整审核 |
| 文件版本 | 一次明确上传/导入产生的产品版本；历史轮次引用该版本 ID，新上传创建另一版本 |
| 审核草稿 | 尚未受理的文件角色和规则选择 |
| 审核任务 | 从识别、确认到查看结果的用户流程；不等于内部执行工作或某次技术尝试 |
| 审核轮次 | 固定文件版本、资料角色和规则版本的一轮检查 |
| 检查项 | 规则要求，不一定是问题 |
| 检查结果 | 机器业务结论与未知、未覆盖、技术错误分开；现有结果记录不被改写 |
| 依据 | 原始资料及可定位位置；模型解释或建议不能冒充原文 |
| 检查覆盖范围 | 实际检查了什么、未检查什么 |
| 人工复核 | 有权限的人对具体结果记录判断、理由和下一步；不改写机器结果 |
| 正式批准 | 组织授权人对明确版本/范围作出的正式决定；当前产品不自动实现审批制度 |

## 必须成立的产品边界

1. 真实身份、租户与对象权限。
2. 历史轮次稳定引用当时的文件版本；后续上传不能改变旧轮次。
3. 受理时明确待审/参考角色和每文件规则版本；自动匹配只发生在确认前，未受理不会产生审核轮次。
4. 一次受理对应一个产品轮次；断线和技术重试不制造第二轮。
5. 如实呈现 PASS/NG/ERR、覆盖范围和定位缺口；人工复核不改机器事实。
6. 外部使用/计费不制造虚假状态或重复业务事件。
7. 只退出已确认无其它消费者的遗留 PPAP 路径。`ppap-agent` 有其它用户，不属于可退出路径。

首批格式和规则支持范围以固定 legacy baseline 和本仓迁入后的 canonical regression 为准；算法优化不属于迁移整合验收。

## 不自动扩展的范围

不重建通用组织平台，不迁入完整 FMEA/PQM/8D 产品，不另建群聊审核产品，不为了未来可能性增加多 Agent/workflow 平台、第二套 ledger 或证据治理系统。

当前试用阶段不要求迁移旧审核历史；客户若未来明确需要，再针对实际客户数据处理。

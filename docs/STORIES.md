# 用户结果与 Live 证明

权威：[Northstar](NORTHSTAR.md)、[数据语义](DATA_MODEL.md) 和各 owning Issue。以下拆分不增加新业务政策，验收覆盖与实现状态分离。每次审阅绑定确切文件版本；修改结果断言后旧审阅失效。执行记录进 owning Issue 或一次性报告，不在此累积。

## 共用证明边界

在获授权的隔离实例，通过真实产品支持路径操作。固定构建、测试租户/权限、输入摘要与审阅过的 oracle。正常 LLM/OCR/对象存储/渠道调用成本已获许可，不因费用退化为 mock。身份、样本或环境未知则报告缺口，不猜测。

每个 proof run 只执行下文计划的顶层业务动作。内部传输重试不等于新业务提交；验证器不能再提交一次来掩盖超时。新的明确修复后验证是一份新证据，保留旧失败。超时不是产品 SLA，也不能单独定位责任。

报告只能对所测边界给出 PROVEN 或 NOT_PROVEN；后者另记 repository、external_environment 或 inconclusive。依赖探针、测试代码自测和用户 Story 分开。任何必需子证明缺失都不能聚合通过。业务结果 NG 可以是正确的测试通过；页面空白或没有检查项不是 PASS。

## S01：提交后离开，回来仍知道审了什么、依据和下一步

用户：有资料权限的审核者。拥有者：[#9](https://github.com/ppap-agent/ppap/issues/9)，前置 #3/#6/#7/#8。

Given 一个已审阅的资料集、目标/参考角色和规则版本，When 在真实 Web 提交一次并离开页面，Then 从新页面回访同一轮次，看到实际检查覆盖、逐项 PASS/NG/ERR、正确版本的原件、证据定位或明确缺口，以及下一步。等待状态或 DB completed 不足以完成。

证明：浏览器真实提交和新页面回访；下载当时原件核对 SHA-256；检查项与独立 oracle 比较；能定位的项目实际打开其原件位置。无 locator 的项目必须明确表示缺失。与同一构建的真实检查器/corpus 证明联合使用，演示页或返回预制结果不能替代真实执行。

预算：一轮审核提交，必要只读轮询和下载。不得因断线再提交。不证明全部格式、PWA 安装、OAuth 初次登录或正式批准。

## S02：真实登录后只进入自己有权访问的租户和资料

用户：两个测试租户内的授权成员与无权成员。拥有者：[#4](https://github.com/ppap-agent/ppap/issues/4)。

Given 已确认权限的真实 IdP 测试身份，When 完成一次浏览器 OAuth 并打开允许/不允许的对象，Then 授权用户回到原目标；跨租户或无原件权限的浏览器及 API 访问被拒绝，退出或失效不能继续越权。

证明必须包含真实登录和对象授权两个子结果；预存 session 只可用于后者，合成 IdP 不能证明前者。验证 state/回跳和授权到期，不从邮箱推断租户。预算：每个必要角色一次登录，随后按权限矩阵只读访问。权限矩阵不明确则 NOT_PROVEN；不承诺通用组织管理。

## S03：新版本不会改变历史审核的原件和规则

用户：更新资料的审核者。拥有者：[#5](https://github.com/ppap-agent/ppap/issues/5)，关联 #7/#9。

Given 文件 A 和内容不同但同名的 B，且 A 已有固定轮次，When 上传并固化 B，Then B 成为新版本，A 的历史页面仍显示原规则与原结果，下载仍是 A 的精确字节。暂存对象、同名匹配或抓取当前云盘不能替代历史证据。

证明：真实上传 A/B、读取两个版本、从历史页面下载 A 并校验摘要；规则变更后的旧引用不变。预算：建立 A 时一次审核，之后一次 B 上传，不隐式重审。并发 finalize/暂存覆盖的确定性集成测试是前置。不能据此证明所有历史数据已迁移。

## S04：故障和技术重试不制造第二个产品轮次

用户：提交后遇到网络/Worker 故障的审核者。拥有者：[#8](https://github.com/ppap-agent/ppap/issues/8)。

Given 固定输入及幂等键，When 同一业务请求被重复递送并在执行中中断/恢复 Worker，Then 只有一个产品轮次，最终结果完整可回访，过期实例的晚到提交被拒绝；输入不同却复用键明确冲突。

证明：真实 PG/Worker 故障注入、幂等返回与用户最终页面共同成立；只证明其中一个不足以关闭。预算：一个业务提交的两次相同递送、一项同键不同输入的拒绝验证、一次 Worker 中断/恢复；不得在失败后偷偷创建新业务命令。不声称外部模型调用严格一次。

## S05：人工复核可回访，且不会重写机器事实

用户：具备对象复核权限的成员。拥有者：[#10](https://github.com/ppap-agent/ppap/issues/10)。

Given 一份已完成的固定结果，When 保存一次有理由和下一步的复核，Then 重开页面仍可见本人记录，原机审结论和证据不变；另一个并发更新得到明确冲突。用户主动重审得到新轮，旧轮与复核仍独立可读。

证明包含保存/回访、并发/授权、显式重审三个子结果，不能只测表单成功提示。预算：一条复核、必要并发冲突请求和一轮显式重审。复核不是正式签批，新轮不自动获得旧轮批准。

## S06：飞书资料进入同一产品，不另生一套账

用户：原飞书应用的授权用户。拥有者：[#11](https://github.com/ppap-agent/ppap/issues/11)。

Given 实际应用具有目标资料的读取权限，When 选择真实 Drive/Docs 来源并提交一次审核，Then Web 与飞书入口回访的是同一产品版本和轮次；变更云盘当前内容不改旧结果。已有 Docs/深链消费者的兼容证明单独列出。

证明：真实来源读取到固定字节、同一轮回访、来源权限反例。确需写评论/通知的场景必须显式操作和读回一次；仅查询结果不得产生写回。预算：一次导入与一次审核；写回只执行被审阅的场景。SDK 支持格式不等于该应用已获导出权限。

## S07：用量来自真实使用与外部确认，不凭空制造余额

用户：查看本租户使用历史的成员。拥有者：[#12](https://github.com/ppap-agent/ppap/issues/12)。

Given 已确认计费政策和测试租户，When 一轮实际审核产生用量并完成上报/对账，Then 产品显示实际、试用、待确认和平台确认的区别；外部暂不可用显示待对账，不虚构固定额度，同一事实重查不再扣费。

证明：真实使用事件、provider 回执/查询与用户页面关联同一轮；超时后先对账。预算：一轮审核，一次稳定业务标识的上报及只读确认；重放验证须使用已证明的 provider 幂等契约。费率/权益未知则 NOT_PROVEN，不能用历史 500/10000 默认值。

## S08：旧链接能回到迁移后的正确历史

用户：通过既有链接回访的客户。拥有者：[#13](https://github.com/ppap-agent/ppap/issues/13)。

Given 授权导出、对象清单和旧标识，When 在隔离副本迁移并用同一批输入再执行一次，Then 旧链接指向正确的新对象，归属、规则、原件、结果和用量可核对，不多造轮次。无历史快照的记录明确不可核验。

证明：迁移差分/摘要/归属检查与新 UI 回访联合；当前文件不得冒充历史。预算：同一迁移批次两次执行及只读回访；含一项缺快照和一项错误租户反例。增量写入与回切另按拥有者 Issue 验收，不代表整机可下线。

## S09：恢复的不只是数据库，而是可用产品

用户：执行恢复的维护者及回访审核者。拥有者：[#14](https://github.com/ppap-agent/ppap/issues/14)。

Given 关联的数据库与对象备份，When 在一个新的隔离实例恢复并继续未完成工作，Then 用户仍可读取原轮次、原件摘要、结果、复核和用量；未完成工作不产生第二轮，旧实例不能覆盖恢复后的结果。

证明：一次真实恢复、原件下载校验、用户路径回访、待执行工作恢复；pg_restore 成功本身不够。预算：一次备份/恢复演练和一个已有未完成轮次，不新增替代审核。记录实测耗时，不自行承诺诺未确定的 RPO/RTO。

## S10：另一位开发者能够从发布物重建和验证产品

用户：无原团队帮助的新维护者。拥有者：[#15](https://github.com/ppap-agent/ppap/issues/15)。

Given 有明确版本、依赖和许可/样本边界的候选发布物，When 在干净环境依照本仓安装、升级并验证，Then 可运行同一产品和相应核心 Stories；不依赖开发者本机文件或未提交状态。

证明：可重复安装构建、迁移、核心真实验收与升级/恢复入口；所需子证明不能由 skip 计为通过。预算：一次候选安装和一次支持版本升级；其余只复用同一候选的兼容证据。开源工程质量不授权公开客户样本，也不替公司选择许可证。

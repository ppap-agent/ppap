# 迁移与退出

只有当前迁移任务需要读本文件。来源清单见 [INVENTORY](INVENTORY.md)；正常产品开发不需要理解全部遗留系统。

## 迁移原则

- 来源仓只作为一次性迁移输入。固定 Git revision 后，迁入仍有当前产品价值的代码、tests、fixture、oracle 和必要 helper；迁完以后本仓成为唯一当前 authority。
- 不建立“新仓长期 checkout 旧仓”的 CI、测试或运行路径。跨仓依赖必须随着对应资产迁入而消失。
- 旧实现输出不是天然 oracle；已有人工 expected 保持独立。
- 不逐行翻译旧服务，也不因为服务名存在就保留同形微服务。
- 新旧 ID 映射带来源系统、租户和对象类型；不按同名文件、邮箱或本地 ID 猜同一对象。
- 历史原件缺失时明确缺失，不抓当前文件冒充过去版本。
- 某个业务测试文件是否进入本仓按其**具体真实访问/分发限制**判断；不因为它来自业务 corpus 就默认未授权。
- 切换期间只保留一个明确写入 authority，避免默认双写两套 ledger。

## ppap-agent

`ppap-agent` 的目标是 sunset。#3 迁测试资产，#6 按本仓失败测试迁最小实现。迁移完成后，开发、CI、测试、构建、部署和 runtime 都不再依赖旧仓；历史来源链接可以保留在 Git/Issue 中，但不是正常开发前置。

## 退出其它旧路径

每次只退出一个已确认无消费者的入口。退出前确认：

- 当前调用方和其它产品影响；
- 数据/文件仍可访问或已迁移；
- 新路径满足该入口实际使用的行为；
- 旧链接有明确去向；
- 新写入和外部副作用有回切处理；
- 已实际演练一次切换与回退。

不知道谁在用，就不退出。`ppap-agent` sunset 是当前明确目标；其它共享仓库、主机或客户引擎仍按各自消费者判断。

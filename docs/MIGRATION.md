# 迁移与退出

只有当前迁移任务需要读本文件。来源清单见 [INVENTORY](INVENTORY.md)；正常产品开发不需要理解全部遗留系统。

## 迁移原则

- 固定来源仓和 Git revision，优先运行来源仓已有测试，再根据真实失败迁入最少实现。
- 旧实现输出不是天然 oracle；已有人工 expected 保持独立。
- 不逐行翻译旧服务，也不因为服务名存在就保留同形微服务。
- 新旧 ID 映射带来源系统、租户和对象类型；不按同名文件、邮箱或本地 ID 猜同一对象。
- 历史原件缺失时明确缺失，不抓当前文件冒充过去版本。
- 切换期间只保留一个明确写入 authority，避免默认双写两套 ledger。

## 退出旧路径

每次只退出一个已确认无消费者的入口。退出前确认：

- 当前调用方和其它产品影响；
- 数据/文件仍可访问或已迁移；
- 新路径满足该入口实际使用的行为；
- 旧链接有明确去向；
- 新写入和外部副作用有回切处理；
- 已实际演练一次切换与回退。

不知道谁在用，就不退出。终态不依赖旧服务，不代表可以关闭整个共享仓库、主机或客户引擎。

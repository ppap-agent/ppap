# 条款改写

目的是得到一版**干净、可单独读懂、意思不走样**的条款。只改依据要求改的地方；其余每一句都在新文里有对应。原文没说清的地方不在改写时补上，单独列出，交给 [clause-check](../clause-check/SKILL.md) 审查后进问卷。

整条改写由 agent 逐条读原文后亲手写出。不能用脚本生成、套用、分发或沿用条文和审查记录。脚本只用于写完之后的格式核对、提交和导入导出。

## 输入

只用三样：

- 该条的原文；
- 答复人对该条卡片的原话（选项与附言）；
- 产品负责人在对话里明确给出的裁定。

不读检查程序及其测试、人工真值、旧修订的正文、以前的审查记录、样本和评测结果。它们是别人对条款的理解，会替客户做掉本该问的选择。

## 不加

- 原文没有的不补：结论句（如「全部满足才通过」「否则通过」）、例子、定义、比较方式、先后步骤都不补。
- 原文列举末尾写「等」或用「如」引出的，保持开放，不写成封闭清单。只有原文逐项列全的，才能整理成固定清单。
- 只在原文明确写了先后时才写顺序（如「核对前先按日期重排」），不从句子先后推出步骤。
- 答复只回答它问的那一处。答复的意思要推到别处时（例如答复给了旧版表的分档，条文别处要用新版表的分档），先问产品负责人，不自行推断。

## 不减

- 有判定意义的句子一律不删，包括理由句和执行说明：依据怎么写、提示项、未审、不适用、缺陷落在哪、只记一次、严重度。
- 只删说来历的字眼：编译侧、客户原文、卡片编号、第 N 轮、经裁决、源侧、补充判据，以及指向条文以外文件的引用。
- 来历和「对外怎么说」写进该条的修订说明，不进条文。
- 一句话里既有来历又有规则时，只删来历那几个字，规则照留。

## 照抄

- 引号里的字、数字、比较词（不低于、晚于、≥、＜）、单位，原样照抄。
- 「须」「可」「不得」「才」「即」「之一」「全部」这类词的强弱和范围不变：不把「可」写成「须」，不把「才通过」写成「即通过」，不把只管某一项的例外写成管全条。
- 条款编号与交叉引用（「规则 2」「本条与规则 3」）原样照抄。
- 原文用的词不换成同义词。被引用的口径写进条文时，照被引用处的原话写。

## 不解决

原文的模糊和冲突照原样留着，不靠换说法或重新排版让它看起来确定。在产出里单独列出：哪一句、哪里没说清、会让哪类文件的结论不同。

## 写法

- 用中文和业务词，不用英文记号和技术词。条款要给客户读。
- 整理分节时，小标题只用原文已有的部分：适用、要求、不通过、不适用、例外、记录与提示、定义。原文没有的部分不加。
- 固定清单（占位词、等价写法、列名对应等）在用到它的每一条里各写一份。同名清单在各条之间逐字一致。
- 每条自足：不把别条的规则搬进来，也不引用条文以外的文件。
- 不以省字为目标。省字不能成为删句子的理由。

## 产出

每条改动写一节：

- 依据：卡片编号与所选选项、答复原话，或裁定原话及日期；
- 意思：变了／不变；
- 改动：逐处说明改了什么；
- 修订说明：来历和「对外怎么说」，没有就不写；
- 正文：完整条文。

最后单独列出原文没说清、本版没有消除的地方。

## 核对

1. 写完后，用脚本把每条新文和原文按句并排列出。脚本只负责列出差异，不判断对不对。
2. 由 agent 逐处确认：
   - 每个删除都是来历，或在新文里有对应；
   - 每个新增都有依据；
   - 同名清单逐字一致。
3. 设想几份具体文件，按原文和新文各判一次。要包括边界情况：恰好等于阈值、缺件、空白、占位、例外刚好适用。
   - 「意思不变」的条，结论必须处处相同。
   - 「意思变了」的条，只能在依据所指的那类文件上不同。
4. 改写后，该条原文的摘要会变，要用 clause-check 重新审查，审查记录逐条手写。
5. 按 [docs/rules.md](../../../docs/rules.md) 的澄清循环提交：改写写明依据的卡片或裁定，再提交新写法的审查记录。

# CEA:1 条款语义检查报告

- **规则文件**：顾客工程批准：认可结论-判定（CEA:1）
- **规则原文**：顾客工程批准文件按认可路径分两支判定，前置条件与分支条件如下。 前置：封面“否决/Reject”列中，尺寸、材料、性能、试装四项均不得标有否决，任一项标记否决即直接不通过。 分路：备注栏文字须能归入“完全认可”或“偏差认可／条件认可”之一；无法归入任一路径的，按“认可结论无法辨识”处理，判不通过并提示人工复核。分流结果决定下列两支是否执行。 “两处表述相互冲突”按无法归入处理。 完全认可路径：组长（Team Leader）、审核（Checked by）、批准（Approved by）的签名及日期须齐全，且日期满足组长 ≤ 审核 ≤ 批准。此时偏差认可汇总清单、整改期限、临时偏差有效期、两处期限一致性四项无判定对象，记“不适用”并写明依据，仅作提醒，不判不通过，也不计入通过率分母；不得记作“通过”。 偏差／条件认可路径（备注虽含“完全认可”但同时载有偏差、超差或整改承诺的，按本路径处理）：文件内或同批次应有同零件编号、同零件名称的偏差认可汇总清单，且清单含“零件号”“偏差项”“UAES 评估确认”“是否需要偏差”字段；封面整改承诺的最晚期限须晚于当前日期（不取“预计整改时间”）；清单备注列中“临时偏差至<日期>”的各条有效期须晚于当前日期；封面期限须与清单中的相应期限一致（同一天为一致）。封面只给合并整改的最晚期限、清单各条有效期不同的，封面的合并期限与清单各条有效期中最晚的一日相同，即为一致。 相应认可路径的全部条件满足才通过。 “否决”列的勾选使用图形勾选、特殊符号或单元格填充标识时，须先完成视觉层取证；取证后仍无法读出的，按不通过处理并提示人工复核。
- **结论**：1 处候选问题；结构与原文引用已校验，语义仍须人工审阅。

## 逐条发现

### 1. 偏差认可但封面没有整改期限

原文：「封面整改承诺的最晚期限须晚于当前日期（不取“预计整改时间”）」「相应认可路径的全部条件满足才通过」

例子：封面否决列四项都未标否决；备注栏写“偏差认可，该偏差长期接受，无需整改”，封面没有整改承诺期限，只有一栏“预计整改时间”留空；同批有零件编号、名称相同的偏差认可汇总清单，四个栏目齐全，清单备注没有“临时偏差至”字样。

- 理解一（缺期限即不满足）：这一支要求封面有整改期限且晚于今天，没有期限就是条件不满足。（该例判不通过）
- 理解二（无整改承诺则无对象）：没有整改承诺就没有要比较的期限，这一项不构成不通过。（该例判通过）

反例复核：原文只在完全认可这一支写明期限类四项记不适用，偏差这一支没有同样的说明；但原文同时允许“只载有偏差”而无整改承诺的备注走这一支，此时“整改承诺的最晚期限”本身不存在。其余条件在两种理解下都满足，差别只在缺期限算不满足还是无对象。

**请确认**：备注写偏差认可、但封面没有任何整改承诺期限时（例如长期接受的偏差），这一项算不满足，还是没有可查的对象？

## 已排除的疑似问题（不进入问卷）

- **当前日期指哪一天**：按字面就是审核进行的当天，同一次审核不会因此得出不同结论。
- **“两处”指哪两处**：分路只看备注栏文字，两处就是备注栏里两段说法；备注同时含完全认可与偏差内容的情形，原文已另写明走偏差这一支，不会落到冲突。
- **偏差这一支是否也要检查三人签名**：原文只把签名日期写在完全认可这一支，偏差这一支列出的条件里没有签名；不能替原文补上。

# MSA:4 条款语义检查报告

- **规则文件**：测量系统分析评价：CP人工检测-kappa（MSA:4）
- **规则原文**：同批次必须提交《控制计划》。 若控制计划（CP）存在出货检验／GP12 类工序，且该工序的评价测量技术使用人工、目测等人为检测方法，则同批次必须有相同零件号、相同量具名称（或量具名称为“综合检具”）的 Kappa 独立文件；缺少时不通过。 量具名称按工序级语义匹配认定，不死抠字面：控制计划写“目视”“目测”“Visual”“感官检验”时，同批存在以该对应工序检验人员为分析对象的合格计数型 Kappa 报告即视为已覆盖；报告标题与分析对象名未与工序名逐字一致但能对应到该工序的，判通过并留痕提示，不判不通过。无法确认对应到哪个工序的，才按缺少处理。 若不存在出货检验／GP12 工序，或此类工序不存在人为检测方法，则该项要求判通过，同时输出一条提示项通知用户：本批次未发现出货检验／GP12 工序（或该类工序无人工检测方法）。该情形按客观无检测对象处理，不作缺项，提示项不改变结论、不进任何分母。 本条为本册保留的显式口径：与“不适用不能记作通过”的一般规定并存，仅本条这样处理——无该工序时不存在可评价的检测方法，属客观无对象而非漏检，故判通过并留痕提示，不按不适用处理。执行时不得反向把“已判通过”写成“不适用”，也不得因输出提示项就把结论改成不通过。 工序名称列缺失属文件结构问题，不等同于“没有出货检验工序”，两者不得混判。
- **结论**：3 处候选问题；结构与原文引用已校验，语义仍须人工审阅。

## 逐条发现

### 1. Kappa 文件是否必须结论合格

原文：「则同批次必须有相同零件号、相同量具名称（或量具名称为“综合检具”）的 Kappa 独立文件；缺少时不通过」「同批存在以该对应工序检验人员为分析对象的合格计数型 Kappa 报告即视为已覆盖」

例子：控制计划的出货检验工序写“目视”检测外观；同批有一份零件号相同、量具名称写“目视”的 Kappa 独立文件，但 Kappa 值 0.62，结论写“不可接受”。

- 理解一（有文件即可）：零件号、量具名称都对得上的 Kappa 文件存在，本条要求满足。（该例判通过）
- 理解二（须结论合格）：只有合格的 Kappa 报告才算覆盖，结论不合格等于缺少。（该例判不通过）

反例复核：第二段只要求有零件号、量具名称相同的 Kappa 文件，没有提结论；第三段讲名称按意思对应时，写的是“合格”的 Kappa 报告才算覆盖。此例名称逐字相同，两段都可适用，原文没有说第二段的文件是否也须合格。

**请确认**：零件号、量具名称都对得上的 Kappa 文件，结论不合格时，本条算有还是算缺？

### 2.1. 哪些工序算出货检验或 GP12 类

原文：「若控制计划（CP）存在出货检验／GP12 类工序」

例子：控制计划最后一道工序叫“终检”，用目视对外观 100% 检查；没有名为出货检验或 GP12 的工序；同批没有 Kappa 文件。

反例复核：原文用了“类”字，说明不只认这两个名字，但没有说明哪些工序算同类。若终检算，此例缺 Kappa 不通过；若不算，此例按没有该类工序判通过并提醒。其余要求在此例中不影响结论。

**请确认**：“终检”“最终检验”这类没写出货检验或 GP12 字样的工序，算不算“出货检验／GP12 类工序”？

### G1. 控制计划没有工序名称列时怎么判

原文：「工序名称列缺失属文件结构问题，不等同于“没有出货检验工序”，两者不得混判」

例子：控制计划已提交，但表里没有工序名称列；测量技术栏有若干行写“目视”；同批没有 Kappa 文件。

原文没有明确规定这个例子的判定结论。

反例复核：原文只排除了按“没有出货检验工序”判通过，但没有给出此时应判的结论；也没有说按缺 Kappa 判不通过。此例无法从原文得出结论。

**请确认**：控制计划没有工序名称列、看不出哪道是出货检验工序时，本条判通过还是不通过？

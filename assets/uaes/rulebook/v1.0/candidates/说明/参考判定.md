# 对着 UAES v1.0 修订 3 做参考判定

你像审核员一样，逐份读分到的样本文件，按修订 3 的条文判每条适用条款，写成参考判定。它不是人工真值，只用来和检查程序的结果比差异。

## 条文

- `assets/uaes/rulebook/v1.0/m3/条文/<类型缩写>.json` 的 `rules[].rule_to_check`，条款编号如 `CP:6`。这是唯一依据。
- 只依据条文原文判。不读检查程序（`packages/audit/`、`assets/uaes/rulebook/v1.0/candidates/m3/uaes/`、`candidates/runs/`）、真值与评测集（`assets/corpus/`）、审查记录（`assets/uaes/clause-check-semantic-v2/`、`assets/uaes/rulebook/v1.0/m3/reviews/`）、旧的参考判定（`candidates/reference-judgments.claude.jsonl`）。

## 样本

- `assets/uaes/samples/<零件>/测试文件/<序号 类型>/` 下的文件；缺陷样本在 `<零件>/缺陷样本(-test-)/`；比对文件（图纸、采购件质量计划）在 `<零件>/比对文件/`。
- 跨文件条款去同一零件目录里找关联文件；同一零件目录以外的文件不算同批。
- 样本批次怎么组成：
  - 正常批次 = 该零件的 `测试文件/` 各类目正常件，加上 `比对文件/`。
  - 缺陷样本批次 = 同一零件的正常批次，把同一类目的正常件换成缺陷样本（`<零件>/缺陷样本(-test-)/<类目>/` 下的文件）；其余类目的正常件、比对文件照常同批。被换掉的正常件不在缺陷批次里。
  - `通用文件/` 下的文件不属于任何零件，是单独提交的，同批没有其他文件。
- 表格可以用 Python（openpyxl、xlrd）读；PDF 有文字层就读文字，扫描页、印章、勾选框、签名等要看图时，把页渲染成图片自己看。读不到的记 `unable: "unreadable"`。

## 判定

- 每份文件 × 它所属类型的每条条款，写一行。条款写明本文件不含判定对象的，记 NA 并写明依据。
- PASS／NG 至少给一条证据：`file`（仓库相对路径）、`where`（工作表与单元格，或页码与位置）、`quote`（逐字取值）。
- 原文没说清、这份文件因此判不了的，记 `UNABLE`，`unable: "unclear"`，`unclear` 逐字引用卡住的那句原文。不替客户选读法。
- 规则可以模糊；判不了就如实记，不推测。
- 严格按条文判，不加条文没有的假设：零件号等身份逐字比对文件上实际写的内容，不以「批内文件互相一致」之类理由放过；条文没写的处理方式不套用；条文没定义的情形记 UNABLE（unclear）。（产品负责人 2026-11-23）

## 产出

- 格式按 `tests/corpus/contracts/src/corpus_contracts/reference_judgment.schema.json`（JSON Lines，一行一个对象）。
- `batch`：零件目录名；缺陷样本写 `<零件目录>/<缺陷文件名去扩展名>`。
- `digest`：该条条文的摘要，`python3 -c "import hashlib,json,sys; print(hashlib.sha256(<条文>.encode()).hexdigest())"`，条文取 rules 文件里的原字符串。
- `model`：`claude-opus-5-5`。
- 写到 `assets/uaes/rulebook/v1.0/candidates/reference-judgments.parts/<你的分组名>.jsonl`，写完用 schema 校验每一行（`python3 -m jsonschema` 不可用时自己写个校验），并核对每个 `file` 路径存在。

## 汇报

用中文、不用黑话：判了哪些文件、多少行、结论分布，哪些地方读不到、哪些因原文没说清判不了。

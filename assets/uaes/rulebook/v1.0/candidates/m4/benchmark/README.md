这是一份可复跑的候选检查评测资料，不是人工真值，也不是已发布的检查程序或线上准确率。参考判定先按[签署条文](../../../m4/条文/)与原件独立完成，没有使用候选检查程序的输出、历史判定或已有人工真值。结论适用于条文摘要和原件字节均一致的批次。

| 文件 | 用途 |
|---|---|
| `batches.jsonl` | 19 个批次；缺陷批记录正常基线及替换前后的文件。 |

## 分组与覆盖

- 主集：10 个正常零件批及 4 个 A40 独立缺陷批，117 次待审文件提交、5 次只作比对的文件提交，634 条参考判定。每个 A40 缺陷批从完整正常批开始，PCE、CP、PSW 各替换一份；MSA 按整套 9 份换成缺陷套件 7 份，不补回缺失件。
- 补充集：5 份真实独立原件各成一批，没有同批对端，30 条参考判定。6 份空白模板排除。
- 合计：210 通过、320 不通过、84 不适用、50 待确认（含条文未裁定及本件号无法确定）。没有以原件不可读为由判不了的条目。覆盖 58 项签署条款；未出现适用真实样本的 `LAB:1`、`MCMP:1`、`PHOTO:1`、`PKG:1`、`TA:1` 不计入。
- 输入快照：原件和签署条文取自提交 `2f3a592599e2f6bc7edaed7119302847c7572b44`，此 PR 基线中所涉原件和条文逐项核验相同。

## 搭建 benchmark

1. 只用原件和 `submission_role` 重现实际提交；文件哈希用来校验输入未变。C50 的偏差汇总清单随正常件提交，是否识别为 E11A 比对件是评测结果。比对件可作证据，不生成对它本身的条款判定。
2. **编号、字段角色和文档覆盖范围由 checker 从原件读取，本身就是被测能力。** 不把预期文件类型、`expected_role`、人工摘录的件号及编号角色、适用页、参考结论等喂给识别和检查。目录名、文件名和样本标签不是件号证据。人工确认的原件位置、字段名与原值只放在参考证据里。
3. 只比较签署条文指定的字段。保持完整原值，不换前缀、不截尾缀、不用供应商号或图号替代客户件号；只做条文明示的归一化。条款明定要匹配而已证实不一致的，照条文报不匹配；缺唯一件号时，仅依赖该范围的条款待确认，不能掩盖其他已证实的缺项和错配。
4. 按 `(batch, file, clause)` 对齐，另校验文件与条文哈希。漏识别、漏判和技术错误保留，不能因为没有输出就从固定范围中消失。与模型参考判定的分歧只作差异分析；正式准确率另以独立人工真值验证。
5. 做留出集时，同一零件的正常批与缺陷批不要分开。按文件哈希检查串集，已有 776–777、776–A40 各共享一份原件的情况。

# UAES v1.0 修订 4：原件分组与独立模型参考判定

这是一份可复跑的候选检查评测资料，不是人工真值，也不是已发布的检查程序或线上准确率。参考判定先按[签署条文](../../../m4/条文/)与原件独立完成，没有使用候选检查程序的输出、历史判定或已有人工真值。结论适用于条文摘要和原件字节均一致的批次。

| 文件 | 用途 |
|---|---|
| `batches.jsonl` | 19 个批次；缺陷批记录正常基线及替换前后的文件。 |
| `file-inventory.jsonl` | 每个批次原样提交的文件、仓库相对路径、SHA-256、提交角色和期望角色。 |
| `expected-rows.jsonl` | 固定比对范围：每批受审文件、条款编号及签署条文 SHA-256。 |
| `reference-judgments.jsonl` | 664 条独立参考判定，使用仓库现有 `reference-judgment-v1` JSONL 合同。包含理由、证据所在文件及原件位置。公开版省略了 33 处个人或商业标识的逐字取值，保留位置、判定和有无该字段的依据。 |

## 分组与覆盖

- 主集：10 个正常零件批及 4 个 A40 独立缺陷批，117 次待审文件提交、5 次只作比对的文件提交，634 条参考判定。每个 A40 缺陷批从完整正常批开始，PCE、CP、PSW 各替换一份；MSA 按整套 9 份换成缺陷套件 7 份，不补回缺失件。
- 补充集：5 份真实独立原件各成一批，没有同批对端，30 条参考判定。6 份空白模板排除。
- 合计：237 通过、322 不通过、83 不适用、22 因条文有歧义判不了。没有以原件不可读为由判不了的条目。覆盖 58 项签署条款；未出现适用真实样本的 `LAB:1`、`MCMP:1`、`PHOTO:1`、`PKG:1`、`TA:1` 不计入。
- 输入快照：原件和签署条文取自提交 `2f3a592599e2f6bc7edaed7119302847c7572b44`，此 PR 基线中所涉原件和条文逐项核验相同。

## 搭建 benchmark

1. 只用文件清单与 `submission_role` 组装输入，不把预期类型、`expected_role` 或参考判定送入识别程序。C50 的偏差汇总清单随正常件提交，期望识别为 E11A 比对件。比对件可作证据，不能生成对它自身的判定。
2. 按 `(batch, file, clause)` 对齐，另校验文件与条文哈希。漏识别、漏判和技术错误保留，不能因为没有输出就从固定范围中消失。与模型参考判定的分歧只作差异分析；正式准确率另以独立人工真值验证。
3. 做留出集时，同一零件的正常批与缺陷批不要分开。按文件哈希检查串集，已有 776–777、776–A40 各共享一份原件的情况。

## A40 参考判定复核

下表是对冻结参考的复核建议，不回写旧评测结果。应先按签署原文及原件完成独立复判，发布新参考后才用它比较检查程序；不得用候选程序输出反推参考。

| 条款 | 冻结参考 | 建议与依据 |
|---|---|---|
| PSW:3 | 通过 | 改待确认。签字栏有独立嵌入的手写笔迹图片，不证明供方代表是为本件签的；修订 4 审查记录已明确列出这个未裁定口径。若取证另有明确缺项，再独立判不通过。 |
| PFD:2 | 通过 | 改待确认。工序 110 的名称可解释为同类测试，但 PFMEA 同号行的工序栏空白，完整名称出现在失效模式栏。没有足够的独立证据确认三表的测试对象与名称均对应；不把“不据此判不通过”写成通过。 |
| PFD:4 | 不通过 | 暂不改。先独立复核全图支路、图片和提交说明；只有查全且没有异常处置或明确豁免，才能确认不通过。 |
| PFMEA:5 | 通过 | 重审未证实的工序，不用同号补齐证据。例如第 70 道喷砂和喷丸可能是不同工艺；需核实工艺对象、目的及对应失效分析。 |
| MSA:2（卡尺） | 通过 | 不能仅以区间数字相同认定配对。报告分析表 C7 的 mm 是量具量程的单位，需另证适用于同一被测尺寸，才可确认报告写法与计划的区间等效。 |
| SCL:2 | 通过 | 第 13 行仅在本轮的确审 A40 时有资格作为证据。当前资料中存在完整件号冲突，不能从通过行反推审查对象。缺权威件号应记待确认。 |
| CEA:1、PFMEA:3 | 通过、待确认 | 暂不改。CEA 封面原件支持完全认可，查运行中为什么转为待确认；PFMEA F20 未登记的含字符图符应待确认，除非另有已证实的独立缺项。 |

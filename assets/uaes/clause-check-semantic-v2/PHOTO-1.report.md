# PHOTO:1 条款语义检查报告

- **规则文件**：生产件样品照片（UAES 审核规则库 规范性条款 v1.0）：UAES-PHOTO-图片格式-校验（PHOTO:1）
- **规则原文**：提交的生产件样品照片文件必须为图片格式（jpg／jpeg／png／bmp／tif／tiff）；文件属于图片格式时通过，否则不通过。 判定以文件头魔数为准，扩展名不作为唯一依据：魔数属图片类型即符合。文件为 0 字节、或文件头不足 4 字节无法判型的，属文件对象不可获取，按不通过处理并提示补交原始图片文件，不记未审——“未提交可读文件”与“证据无法辨识”是两件事，前者按缺件处理。 非图片容器一律不通过，不以内含实物图像作为替代载体：.pdf／.xlsx／.xls／.docx 等文档容器，即使内含可提取的实物照片或其缩略预览图，也不构成本条通过条件；带表头与签章的《样品照片报告》PDF 同样判不通过。执行时不得以“容器内确有图像对象”为其放行，也不得把“可提取图像”当作图片格式的等效载体。 此处为本册经裁决保留的口径，与源侧“允许内嵌清晰实物照片的 pdf／xlsx／docx 样品照片报告”不同；对外说明时须按本册口径表述，不得混用两种载体标准。容器内确有图像对象的，仍按“载体不符”判不通过，并在依据中写明该容器内含 N 个图像对象、建议供应商改交原始图片文件；此类情形的整改指向是改交载体，不是重拍照片。 同批多张照片分多个文件提交时，逐份判定，每份都须满足图片格式；不得只判第一份而把其余记作不适用。
- **结论**：1 处候选问题；结构与原文引用已校验，语义仍须人工审阅。

## 逐条发现

### 1. 未列举的原生图片格式能否提交

原文：「图片格式（jpg／jpeg／png／bmp／tif／tiff）」「魔数属图片类型即符合」

例子：本批只交一份零件实物照片，文件不为空，可正常打开；扩展名与文件头均确认是 WebP。它本身就是图片，不是内嵌照片的 PDF、表格或其他文档。

- 理解一（只收括号内格式）：文件头应属于所列图片格式之一。WebP 未列入，不能通过。（该例判不通过）
- 理解二（接受可识别的原生图片）：括号列举常见格式，本例已证实文件本身是图片，符合格式要求。（该例判通过）

反例复核：已排除空文件、类型无法识别和文档容器替代。开头括号列出一组具体格式，未注明“例如”或“仅限”；后文用“魔数属图片类型即符合”作判准，未说明“图片类型”是泛指图片还是回指该组。明确拒绝 PDF 等文档不能区分这两种读法。

**请确认**：文件头能确认是 WebP 的原始照片，可以通过，还是只接受括号列出的格式？

## 已排除的疑似问题（不进入问卷）

- **带章 PDF 内确有清晰照片，是两种现行标准在打架吗**：不是。正文已选定本册口径；PDF 仍按载体不符处理，写明图像对象数并建议改交原图，不要求重拍。
- **空文件名叫 JPG，应该记“未审”吗**：不能。此处已给出缺件性质及不通过结论，不能用扩展名或通用不可辨流程改判。

# UAES 规则库版本

改动 UAES 规则、条款检查结果、规则确认问卷或 UAES 检查程序的条款正文前，先读本文件和 [docs/rules.md](../../docs/rules.md)「规则处理 SOP」。

版本与修订的规则、一轮澄清怎么走、用户看到什么，见 [docs/rules.md](../../docs/rules.md)；本文件只记 UAES 自己的目录、标识和状态。

## 目录

- 仓库里已有的修订放在 `assets/uaes/rulebook/<版本>/<修订>/`：规则库原件或修订文本、逐类抽取的 `rules/*.json`。入库后不改；企业第一次读取时原样写入数据库。之后的每个修订，上传（提交到澄清任务）时把上传的那份原样存进 `<版本>/m<修订>/`：逐类条款 `条文/*.json`、每条的审查记录与报告 `reviews/`、每条的改动说明与依据 `上传依据.json`、修改说明；上传后不改，审核运行时以数据库为准。条款目录不能叫 `rules/`：带 `rules/` 的修订目录会被当成随产品发布的修订，在企业登录时自动写入数据库，绕过澄清与确认。例外：v0.0 的 m0 是客户原稿 `assets/uaes/rules/*.docx`。
- 条款检查的审查记录与报告、问卷导入文件、检查程序使用的条款正文，都从对应修订的这些材料生成，不各自维护另一份。条款检查材料在 `clause-check-semantic-v2/`；检查程序有没有实现某段写法，由规则页按检查程序叶子的条款原文比对得出（见 docs/rules.md 第 7 步），候选检查程序按修订分别放在版本目录的 `candidates/m<修订>/`，不覆盖旧修订的叶子。
- 每次升修订或升版本，在目标版本目录里附一份对照：每条新条款对应哪条旧条款，按判定结果是否会变分为「意思不变」「意思变了」「新增」，删除或合并的写明去向，并列出每条相关的问卷卡片。
- 版本和修订靠「客户 + 版本 + 修订号」识别：仓库里的靠目录与 Git 历史，之后的靠数据库里的修订记录，不另建台账或清单。

## 条款标识

- 一条条款的标识是「客户 + 版本 + 文件类型缩写:编号」，如 UAES v1.0 `CP:5`。修订号不属于标识，只说明内容是哪一版。问卷卡片、人工判定、检查程序都用这个标识，不另建映射。
- 文件类型缩写和编号照抄客户规则库原件，平台不自己重排。`rules/<缩写>.json` 里只放 `<缩写>:<编号>`，编号在一份修订内唯一。
- 同一版本的所有修订，条款编号集合完全相同；编号有增、删或改名（包括文件类型缩写改名）就是新版本。`packages/product/tests/test_rulebooks.py` 按这条检查仓库里的每份规则库。
- 跨版本不按编号相同对应：客户新版重新编号就照新版，新旧条款只按对照表对应。
- v0.0 沿用检查程序目录号（如 `U19:1`），旧语料的人工判定和回放都绑定它，不迁移；对照表里写作「v0.0 修订 1 U19:1」。
- 问卷导入文件写明它针对的修订（`rulebook_version`、`rulebook_revision`，如 `v1.0`、`0`），规则页按这两个字段把问卷挂到修订上，不从标题推断。

## 规则、检查程序与人工真值

- **版本和修订**固定审核依据。已确认的修订都可供评审；这不代表当前审核默认，不能借展示入口让未切换的修订进入受理。
- **Checker 的 Suite Revision**固定实际绑定和代码。受理时锁定规则修订、Suite Revision、Checker 摘要、共享运行库及执行器摘要；程序修正不要求重写规则，规则改动后不能默认沿用旧程序的结论。
- **人工真值（Oracle）**绑定样本、原件证据、判定时的规则修订、条款和人工依据。规则含义未变时可以复用真值；含义变了，原件仍可复用，但要重新判定，不能改写旧真值。模型回放只用于复现调用，不是真值。
- **对齐验收**按规则修订和程序证据核对。只有新修订下验证过的绑定才标「已对齐」；错判通过或不通过都不算对齐。缺绑定记为「未登记检查程序，暂未检查」，不算通过，也不算执行失败。检查程序按文件类型成组，变动类型及读取其结果的关联类型一起复核。
- **旧版回归不等于新版验收。** 现有 UAES 语料明确用 v0.0 m1 的归档入口、条款、预置规则和原人工真值。归档入口仍调用当前检出的共享库；没有原运行库/执行环境的确切版本时，不宣称是原程序的逐字节复现。新版的代表性样本和预期结果在切换发布后，由看到真实结果的人对着当前修订给出。
- **当前审核用 v1.0 修订 4**：已安装叶子 `packages/audit/src/audit/checkers/uaes/` 来自修订 4 的候选，候选叶子在 `rulebook/v1.0/candidates/m4/uaes/` 原样保留，修订 3 的在 `candidates/m3/uaes/` 留作历史；预置规则的条款标识与分类取自 `rulebook/v1.0/m4/条文/`。修订 4 的检查程序另用了产品负责人 2026-11-24 确认、尚未写进条文的同义写法与口径（见 `candidates/m4/benchmark/README.md`），下一修订写进条文。
- **切换是单独的发布决定。** 先核实实际官方默认和适用的租户绑定、未检查项的客户表现、冲突裁决和切换影响。运行库或执行器摘要改变时，要在切换前停止旧版本受理并排空已受理任务，或保证它们仍路由到原来匹配的执行环境；不绕过摘要校验，不改写历史轮次。

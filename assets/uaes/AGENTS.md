# UAES 规则库版本

改动 UAES 规则、条款检查结果、规则确认问卷或 UAES 检查程序的条款正文前，先读本文件。

## 版本只由客户发布

- 一个版本是一整份规则库，版本号用客户的写法（如「规范性条款 v1.0」）。
- 只有 UAES 发布新的规则库原件，才产生新版本。我们不自行出修订版，也不在已有版本里改条款原文。
- 规则确认问卷里的分歧与答复只作记录，交 UAES 改进规则；UAES 据此发布新版本后，才按新版本执行。
- 经他人转达、没有客户原始答复记录的口径，不当作客户已确认，不写进条款，也不自动套用到判定。

## 原件不可变

- 每个版本的材料放在 `assets/uaes/rulebook/<版本>/`：客户原件、逐类抽取的 `rules/*.json`、通用判定说明。入库后不改；发现抽取错误时对照原件订正，并在提交说明里写明。
- 条款检查的审查记录与报告、问卷导入文件、检查程序使用的条款正文，都从对应版本的这些材料生成，不各自维护另一份。
- 版本靠目录与 Git 历史识别，不另建版本台账或清单。

## 版本之间条款变化

- 新版本入库时附一份新旧条款对照：保留、改写、拆分或合并、新增、删除，并写明理由。条数变化（如线上 52 条与 v1.0 的 63 条）只通过这份对照说明。
- 旧编号不复用；新版本的条款用新版本自己的编号。
- 条款检查按新版本重新审查。上一版本的问卷不搬到新版本：仍未解决的问题由新版本的审查重新提出，已由客户在新版本里写清的不再提问。

## 检查程序与产品

- 检查程序按文件类型成组。新版本里条款文字有变化的文件类型，以及读取这些类型的关联类型，重新验证；条款没变的类型沿用原程序。
- 新版本作为系统规则的新版本发布。已受理的审核轮次仍用当时冻结的规则版本和程序，不改写历史。
- 重审时，有新版本就默认用新版本，提醒「审核规则已更新」，用户可以沿用上次的版本。

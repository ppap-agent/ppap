# 材料、产品及分供方清单 — 数据标准化预检规则

> 版本：v3.8
> 定位：正式业务规则审核前的输入质量门禁。
> 核心原则：**预检只判定「这批提交能否被可靠审核」，不判定「这份清单是否合规」。无阻断项即通过；警告不拦截，仅记录并随报告移交正式审核。** 每次调用独立判定，仅检查、判定和报告，不执行修复。
> 上位框架：《PPAP-00_数据标准化预检总纲_v0.14.md》，配套《PPAP-00-A 覆盖矩阵 · 路由表 v1.7》。本文件为其分则，二者冲突时以总纲为准。
> **路由前提**：先按总纲 4.5 定（客户 × 文件类型），再加载本分则。本分则承载 **UAES × `T04`** 与 **理想 × `T04`** 两条条目；两者材料列组合与签字要求**结构不同**（见 8.4），不得互相套用。
> 编制依据：原 PRD《〈材料、产品及分供方清单〉AI 预审与深审全量规则说明书 V1.0》（模板代际、预审/深审边界）；UAES / 理想 客户审核规则（结构基线，见 8.4）；总纲 v0.6（级别体系、结论档位、责任归属、识别与路由）。

## 1. 目的与定位

### 1.1 核心目的

在正式规则审核之前，判断本次提交的文件集是否具备被可靠审核的条件。核心目的、非目标与三维度口径见总纲第 1、2、7 节；本类目的失真形态有三类：**必然全 NG**（代际不可判、结构不可还原）、**结论相反**（提交范围错配）、**无法判定**（关键字段缺失、关联证据不足）。

本预检**只做检查、判定和报告**，不做修复、补全、转换，不包含整改后复检流程。整改为线下人工操作。

**边界**：预检通过不等于清单合规，预检不通过不等于清单不合格。所有业务规则的符合性结论、防造假结论均由正式审核（预审 + 深审 + 人工）出具。

**判定维度只有三维**：正确性、完整性、一致性。原「规则可执行性」（`PC-F` 组）按总纲 2.3 不属本分则判定范围，本文件不接收规则集实体、不判断规则能否套上、不输出任何关于规则集的结论。

### 1.2 交互背景与推论

实际流程分三段：**规则先行**（上游入口完成规则提交、解析、录入与口径裁定）→ **文件后到**（审核发起时只提交某项目中的全部或部分 PPAP 文件）→ **审核时配对**（规则与文件首次配对）。

| 推论 | 对预检的要求 |
| --- | --- |
| 规则侧问题已在上游闭环 | 本阶段**只判文件**：提交范围与归属（PC-A）、结构可读性（PC-B）、三维度数据质量（PC-C/D/E），不判规则能不能套上 |
| 部分提交是合法业务动作 | 不得因「项目文件不全」判不通过（§4.3） |
| 提交范围与归属须单独判定 | 审的是谁的文件、哪个项目、哪一份有效，即 PC-A 组 |

预检对象是**「本次提交文件子集」的数据标准化状态**，不是项目全集完整性，也不是规则集质量。

### 1.3 与正式审核的边界

| 判断对象 | 预检问什么 | 正式审核问什么 |
| --- | --- | --- |
| 单件重量 | 列是否可得？值是否可数值化？ | 是否保留 4 位小数？父子重量是否守恒？ |
| 部件状态 | 四列是否齐备可识别？每行勾选数量是否可判？ | 勾选是否与供应商角色相符？ |
| 材料字段 | 本代际应有几列、实际几列、是否整列空白？ | 牌号与工艺是否互斥？标准是否填了试验方法？ |
| 供应商 | 名称是否完整、是否仅填地名？ | 与证书主体是否一致？ |
| 签字 | 本代际应有几处栏位？栏位是否存在？ | 是否已签署？签署人是否授权？ |
| 图纸 | 随包是否提交可追溯图纸件？ | 图纸材质、牌号、企标版本是否一致？ |

## 2. 范围与非目标

### 2.1 范围内

- 接收本次提交文件子集、文件清单与项目上下文。
- 判定提交范围与归属：是否属于本项目、是否为有效版本、能否唯一对应模板代际。
- 判定内容可判读性（扫描件、图像件、乱码件）与结构可还原性。
- 以整个提交子集为对象，执行数据正确性、完整性、一致性检查。
- 自主推断跨文件、跨表切片、字段间的可能关联项并做初步一致性判断。
- 输出 Markdown 报告，含文件级、预检项级、提交子集级、状态登记四类结论。
- 区分「数据不规范」与「文件无法解析」。

### 2.2 非目标

- 不负责文件读取、表格抽取、版面还原、图像识别等底层实现；不规定工具、技术路线、算法。
- 不修复、不补全、不转换原始文件；不执行整改后复检。
- 不做重量守恒核算、几何密度反推、工艺耦合推理、跨文档三角比对（属正式审核）。
- 同源一致性属本预检（PC-E 组）：同一清单的表格件与版式件之间、同一文件多切片之间。清单与 PSW / 图纸 / 证书 / 控制计划之间的交叉验证不属本预检。
- 不做供应商评级、责任定性、造假定性、签字有效性鉴定。
- 不评价「项目文件是否齐全」。
- **不评价规则集**：不判断规则是否录入、是否启用、字段是否可得、代际标注是否一致、阈值是否冲突、口径是否裁定（总纲 2.3）。
- 不输出程序可直接消费的 Schema。

### 2.3 移交正式审核的项

| 移交项 | 归属 | 预检对应 | 状态码 |
| --- | --- | --- | --- |
| 单件重量是否 4 位小数 | 预审 | 仅判可数值化（PC-C3） | — |
| 父子重量守恒、漏乘件数、偏差分级 | 预审 | 仅判重量覆盖率与量级一致（PC-C4 / PC-D4） | — |
| 自制 / 外协勾选与供应商角色是否相符 | 预审 | 仅判四列互斥（PC-C10） | — |
| 全表误勾领用件的定性 | 预审 | 同上 | — |
| 材料牌号与成型工艺是否物理互斥 | 深审 | 仅判两列未同词（PC-C7） | — |
| 材料执行标准是否为试验方法标准 | 深审 | 仅判非标准内容（PC-C6） | — |
| 几何包络 × 密度反推、管材精算、毛坯与净重混淆 | 深审 | 仅判尺寸列无寄生语义（PC-C5） | — |
| 表面处理产线与焊接次序悖论、CQI 特殊过程派生 | 深审 | 不涉及 | — |
| 与 PSW / 图纸 / 证书 / 控制计划的三角比对 | 深审 | 仅判关联证据是否到位（PC-A8 / PC-D7，记 `W01`） | — |
| 体系认证过渡态 / 代理商 / 仅 ISO9001 是否可申诉 | 预审 | 只判表述有效性（PC-C9 警告），可申诉情形移交 | `S03` |
| 签字是否已签署、是否本人、是否授权 | 人工 | 仅判栏位存在性（PC-D6） | — |

## 3. 术语

| 术语 | 说明 |
| --- | --- |
| 本次提交子集 | 发起审核时实际提交的文件集合，可为项目内全部或部分 PPAP 文件 |
| 文件清单 | 提交方声明本次提交范围的清单，用于核对归属、版本与件数 |
| 项目上下文 | 本次审核所属项目、车型、供应商、零件范围 |
| 模板代际 | 按列数与结构特征划分的模板版本群：V1.0 / V1.5 / V2.0 / V3.0 / UAES / 非标准 |
| 表切片 | 一个文件内可独立成篇的一段总成清单；单文件可含多个切片 |
| 根节点 | 清单中层级最高的一行，对应清单所描述的总成 |
| 一物多材拆分行 | 同一零件由多种材料构成时，为每种材料单列的附加行 |
| 叶子节点 | 无下级的末端零件行 |
| 占位符 | 表达「不适用 / 无」的非空标记，见附录 C |
| 勾选符 | 表达「已选中」的标记，见附录 C |
| 可判读性 | 内容是否可被稳定识读；扫描模糊、图像化、乱码均属不可判读 |
| 成对件 | 同一份清单以表格件与版式件（PDF / 扫描件）同时提交 |
| 原因码 | 结论为「不通过」时对每个阻断项的归因标签，见 5.2 |

### 3.1 状态词：四个必须区分的概念

**「不适用」一词禁用**，必须按下表拆分为四种之一。四者为**状态**，不是级别，不参与通过判定。

| 状态 | 代码 | 定义 | 是否产生级别 |
| --- | --- | --- | --- |
| 范围外 | `S01` | 该对象**本就不属**本次提交范围（如 R1 档下项目内其他 PPAP 项本不在范围）。**判据与「交没交」无关** | 否 |
| 对端未到 | `S04` | 属本次范围、**在可及证据集内不存在**（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源，总纲 3.2.1）。**分两子型**：`src=SUB`（PSW / 控制计划 / 证书等提交方文件）→ `W01` + **`S04-S`**；`src=CUS`（**图纸**、客户规范、客户台账）→ 仅 **`S04-C`**、**不配 `W01`**、不进缺件数，措辞为「向甲方索取」 | 否 |
| 规则不适配 | `S02` | 规则侧成因导致某项在本类目 / 本代际上无判定依据（预检不评） | 否 |
| 移交 | `S03` | 该判断属正式审核（合规、有效性、可申诉性、造假），预检只登记不判 | 否 |

**关键区分：**

- 「范围外」≠「文件不含该对象」。前者是该对象本就不属本次范围，后者是交了但清单里没有这个栏位。
- **「本批没交」不再等于「范围外」**：属本次范围而应收未到记 `S04`（对端未到，配套 `W01`），`S01` 只留给「本就不属本次范围」（总纲 3.1）。
- **`S04` 分两子型，判前必先核「可及证据集」（总纲 3.2，v0.7 新增）**：对端在 `SRC-1`（提交件）或 `SRC-2`（受控提供源：客户图纸、技术规范、客户表单模板、客户侧台账）内**已存在**的 → **正常比对，绝不记 `S04`**。集内确实没有时按 `src` 落码：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取）→ 仅 **`S04-C`**、**禁配 `W01`**、不进缺件数、进报告七章 7.2b。`src` 一律查《PPAP-00-A》**§4.3 对端来源登记表**，查不到记 `S02` 并报缺口，**不得现场推定**。**本分则全文凡记 `S04` 之处，一律按本子型标注。**
- **`S05`（受控模板缺结构）继承总纲**：本分则凡判 `B05` 之处，须先按总纲 **3.1 三分界**与 **5.2 两问**确认成因——查《PPAP-00-A》**§4.4 客户受控模板登记表**：该（客户 × 类型）登记**有**受控模板、且**模板本体也没有该列** → 记 **`S05`**（状态，**不阻断**、不配 `B`/`W` 码、不进缺件数、进报告七章 **7.2c**）；登记**无**（不限定表单格式）或**模板有而文件没有** → 仍记 `B05`。**本分则的 3.1 状态词表不列 `S05`**——它的定义、边界与取证要求只在总纲 3.1 / 3.3 / 5.2 维护，避免同一概念在多处分别表述。**`B`/`W` 原因码取值与判定严格程度逐字未改。**　**枚举优先级**：本分则凡用列举方式写状态码的地方——**判定结果取值、状态登记清单、六章装填白名单、「必须按 3.1 拆为…」之类的执行要求**——`S05` **都在其列**（分「已核对」/「待核」两种形态）。**若某处枚举文本仍只列到 `S04-C`，以本条为准**，不得因该处漏列而拒绝登记 `S05`。理由：v0.9 把 `S05` 加进总纲 3.1 之后，各分则的枚举没有同步扩，若按枚举字面执行，`S05` 会**有判据、无落点**——判出来了却装不进状态登记清单，等于这一档不存在。
- 「文件不含该对象」（如本代际模板本身无成型工艺列）**是材料侧问题，按缺项处理记 `W01` 警告**，不得记 `S01` 或 `S02`。
- 「规则不适配」只用于规则侧成因，且本版**不再由本分则判定**（规则侧不属本分则判定范围），仅在必要时登记已确认的、由上游明确告知的适配限制。

| 所属项目 / 车型 | 归属判定 | 阻断 `B02` |
| 供应商名称 | 归属判定、表头一致性比对 | 阻断 `B02` |
| 零件号 / 零件名称 | 范围与主键核对 | 阻断 `B02` |

| 提交方 | 一致性比对 | 警告 `W03` |

| 成对关系 | 标记表格件与版式件对应 | 警告 `W01` |

### 4.3 「部分提交」的处理原则

| 情形 | 判定 | 依据 |
| --- | --- | --- |
| 项目内应有 10 份 PPAP 文件，本次只提交本清单 1 份 | 不记问题 | 部分提交合法 |
| 本清单自身只有部分章节 / 部分总成 | 阻断 `B04` | 提交件自身不完整 |
| 本清单有多份，本次只提交其中一份 | 不记问题 | 须能指明有效件（PC-A4） |
| 清单与项目内其余文件（PSW / 图纸）未同时提交 | PSW 缺 → 警告 `W01`；**图纸缺 → `S04-C`（不配 `W01`）**，写明「向甲方索取图纸」 | 影响深审，不拦截（PC-A8 / PC-D7） |
| 提交了其他项目的清单 | 阻断 `B02` | 归属错配（PC-A2 / A3） |

判据：**「本批不全」不算问题，「本件不全」才算问题。**

「不记问题」不产生任何问题条目；「警告」在报告中逐条列明并随报告移交正式审核。

### 4.4 解析责任边界与能力前提

- 文件读取、表格抽取、版面还原、图像识别由外部系统或模型层负责，本规则不规定实现方式。
- 本规则基于可访问的文件内容、解析结果或模型多模态理解能力判断。
- 无法获得可判定证据时，记“文件无法解析”类问题（`PC-B7` 阻断 `B01`），不得跳过检查。
- **执行方不具备视觉能力时**：扫描件、印章、签字类检查标注为「未执行」，在报告「未进行的检查」栏逐项声明。此类情形不产生任何级别、不判提交方——它不是文件缺陷，而是本次预检未覆盖的部分。

### 4.5 证据封闭性

判定证据须落在**可及证据集**内（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源，总纲 3.2.1 / 4.4）——**本分则的图纸就是 `src=CUS` 的受控件，其常规位置在比对源而非提交目录，必须纳入比对**；提交范围声明、项目上下文、应有件清单只能用于**排除**，不能用于**推定应有**。**不得因「应该有但没交」判缺件阻断**；缺项按两条通道分流——跨文件对端缺按 `src` 记 `W01`+`S04-S` 或仅 `S04-C`（图纸属后者），本文件区块缺按 7.2 分流（承载关键字段 → `B05`，不承载 → `W01`）。

## 6. 执行流程

### 6.1 接收与范围确认

1. 接收本次提交子集、文件清单与项目上下文。
2. 双向核对文件清单与实际提交（清单有实无 → 阻断 `B02`；实有清单无 → 警告 `W01`）。
3. 确认文件归属：项目、车型、供应商、零件范围。
4. 确认有效版本：同一零件多份清单并存时，能否指明唯一有效件。
5. 确认件内完整性（区别于项目完整性，见 §4.3）。

### 6.2 类目与代际归属确认

| 确认项 | 不成立时 |
| --- | --- |
| 文件是否属本类目（材料/产品/分供方清单） | 不属 → `S01` 剔除，不计数 |
| 能否唯一判定「主机厂 + 模板代际」 | 无法唯一判定 → 阻断 `B03`（`PC-A5`），**终止** |
| 模板代际是否为「非标准」 | 是 → 阻断 `B03`（`PC-A5`），**终止** |

### 6.3 分组执行

按 §7 五个分组依次执行，组内并列，任一不满足即按其级别记录。

| 分组 | 内容 | 主要目的 | 属性 |
| --- | --- | --- | --- |
| PC-A | 提交范围与归属 | 确认审的是「谁的那一份」 | 前置条件 |
| PC-B | 结构与可审核性 | 确认清单能按结构被读懂 | 前置条件 |
| PC-C | 数据正确性 | 确认字段内容本身合理 | 维度 |
| PC-D | 数据完整性 | 确认规则所需数据存在 | 维度 |
| PC-E | 数据一致性 | 确认关联数据互不矛盾 | 维度 |

**终止条件**：仅 `PC-A5`（代际不可判）、`PC-B7`（内容不可判读）两项不通过时整体终止，不再产出数据层判定。其余不通过项不终止流程，但须标注「结论不予采信」的适用范围。

### 6.4 汇总判定

1. 汇总所有问题，同类合并（同一文件同一字段同类问题合并为一条，注明影响行数）。
2. 标注编号、类型、位置、证据链、影响、级别、原因码、责任侧、置信度。
3. 按 §5.4 四种颗粒度给出结论。
4. 按 §5.1 给出总体结论并附原因码。
5. 单列「状态登记」。

### 6.5 输出报告

按 §10 模板输出，须明确总体结论、原因码、问题清单、责任侧、整改方向、状态登记，以及「本预检不执行修复与复检」。

### 7.2 PC-B 结构与可审核性（8 项）

| --- | --- | --- | --- | --- | --- |
| PC-B1 | 表头主键齐备 | **零件号、零件名称**须在表头信息区非空（这两个是对象键，缺则无法归属）；**供应商名称**只要求「表头信息区**或**明细区的供应商列**任一位置**非空」——不得因表头区没有供应商栏判不通过（v3.8 改，见下注） | 零件号 / 名称任一为空 → 阻断 `B03`；**仅表头无供应商栏但明细区有供应商列 → 满足**；两处均无 → 阻断 `B03` | 材料侧 | 全部规则 |

| PC-D7 | 审核依赖证据到位 | 该清单审核所依赖的图纸件是否随包提交 | 未到位 → **`S04-C`（对端未到·甲方受控件）**，**不记 `W01`**、不进缺件统计，措辞为「向甲方索取」 | **甲方**（属状态项，不进三维度责任侧统计；见 7.2b） | R07 |

### 7.5 PC-E 数据一致性（7 项）

| 编号 | 预检项 | 判定条件 | 级别 | 责任侧 | 关联正式审核 |
| --- | --- | --- | --- | --- | --- |
| PC-E1 | 切片间同零件一致 | 同文件不同切片中同一零件的材料牌号、供应商、实现方式应一致 | 冲突 → 警告 `W04` | 材料侧 | 跨切片比对 |
| PC-E2 | 表头与根节点一致 | 表头供应商名称应与根节点行的部件供应商一致或可解释 | 冲突 → 警告 `W04` | 材料侧 | R-MB-02 |
| PC-E3 | 成对件一致 | 表格件与版式件为同一份时，零件号、零件名称、主要数值应一致 | 冲突 → 警告 `W04` | 材料侧 | 全部规则 |
| PC-E4 | 文件名与内容一致 | 文件名所含车型 / 总成 / 版本应与表头信息一致 | 不一致 → 警告 `W04` | 提交方 | 归属判定 |
| PC-E5 | 跨行同名件一致 | 同一零件号多次出现时，名称、材料、实现方式应一致 | 冲突 → 警告 `W04` | 材料侧 | 全部规则 |
| PC-E6 | 单位一致 | 重量、尺寸、密度的单位口径应统一（kg/g、mm/cm） | 混用 → 警告 `W03` | 材料侧 | 深审物理核算 |
| PC-E7 | 占位符使用一致 | 同列内占位符不得与空白、勾选符混用而无规律 | 混用 → 警告 `W03` | 材料侧 | R01 / R02 / R03 |

### 7.6 PC-F 规则可执行性：本分则不设

按总纲 2.3，规则侧问题不在预检判定范围内，原 `PC-F1`~`PC-F5` 五项，均不设。

| 原编号 | 原预检项 | 处置 |
| --- | --- | --- |
| PC-F1 | 规则已录入并启用 | 删除（纯规则侧） |
| PC-F2 | 规则所需字段在本代际可得 | **现象重分类为 `PC-B8`**（本代际模板自身应有列是否齐备）；「规则要不要这一列」的判断删除 |
| PC-F3 | 规则代际标注与实际一致 | 删除（纯规则侧） |
| PC-F4 | 规则阈值无冲突或空档 | 删除（纯规则侧） |
| PC-F5 | 关键判定口径已裁定 | 删除（纯规则侧）；下表六项待裁定口径随之关闭 |

**原 PC-F5 六项待裁定口径的关闭方式**

| 口径 | 本版处置 |
| --- | --- |
| 单件重量精度（数值精度 / 呈现精度） | 规则侧口径，退出预检；预检只判可数值化（`PC-C3`），精度是否合规由预审判 |
| 占位符语义（`/`、`—`、`N/A`、`无` 是否判不适用） | 由附录 C 白名单直接定义，不再是缺口；白名单外写法记 `W03` |
| 不适用字段范围 | 规则侧口径，退出预检 |
| 材料体系认证取列（材料侧 / 部件侧同名两列） | 转为运行假设（14 节第 5 条）：两列分别检查，不取单列，避免取错导致整列漏检 |
| 部件状态列构成（四列 / 父列 + 五个叶子列） | 转为运行假设（14 节第 6 条）：按「父列 + 五个叶子列」理解，`PC-C10` 按此判互斥 |
| 黑盒件豁免范围 | 转为可配置项（13 节）：默认「标准电子黑盒件、标准紧固件」 |

> **关闭的实质**：这六项都不再是「必须先裁定才能出结论」的阻塞条件。预检不再因口径未定而整体挂起——这正是取消「不可审」态的技术后果。凡影响判定基数的（认证取列、部件状态列、黑盒件豁免），一律在 14 节以运行假设固定并在报告中显式声明，供正式审核复核。

## 8. 判定口径

### 8.1 三维度并列

| 维度 | 关注 | 判定依据优先级 |
| --- | --- | --- |
| 正确性（PC-C） | 单份文件内某信息本身是否科学、合理、符合基本逻辑 | ① 字段类型 / 格式 / 值域 → ② 基本常识与科学逻辑 → ③ 业务常识 → ④ 领域规则或知识 → ⑤ 数据标准字典 |
| 完整性（PC-D） | 对照本代际模板与实际审核需要，数据是否存在、是否可追溯 | 直接呈现或隐含关联均可；允许推断须说明依据、来源与置信度 |
| 一致性（PC-E） | 不同数据之间的关联关系是否满足要求 | 不预设关联键，自主推断；覆盖跨文件、跨切片、跨行、字段间 |

C / D / E 三维度并列，任一存在阻断即不通过。原第四维度「规则可执行性（PC-F）」不属本分则判定范围（7.6）。

### 8.2 前置分组

PC-A / PC-B 属**前置条件**，不归入三维度：A、B 组不通过时，C / D / E 组结论须标注「不予采信」。例外：`PC-A5` / `PC-B7` 不通过时按 §6.3 终止。

### 8.3 严格标准及其边界

- 认为可能存在问题时即可按严格标准记录；不得以「可能有问题」代替证据。
- 所有推断性判断须标注推断依据与置信度。
- **严格仅作用于「是否记警告」，不作用于「是否判阻断」**。严禁把「看起来很差」判成阻断（总纲 7.5 / 8.2）。
- **禁止降级原则**：某类问题在全批次普遍存在，不得因其普遍性而降低级别；须注明「该问题在本批次普遍存在，属系统性缺口，非个别疏漏」。

### 8.4 客户差异层（按客户 × 类型路由）

本分则的两条 L1 条目（UAES / 理想 × `T04`）共用 40 项判定（`PC-A`~`PC-E`），但**材料列组合与签字要求完全不同**。本节只写差异，不改任何判定口径。

| 项 | UAES × `T04` | 理想 × `T04` |
| --- | --- | --- |
| 载体代际 | UAES 分支（含项目编号、IMDS 表单号） | V1.0 / V1.5 / V2.0 / **V3.0**（现行） |
| 材料列组合 | 3 列：材料分类 / 材料标准 / **材料名称和牌号** | **6 列**：材料执行标准 / 材料类型 / 材料牌号 / 材料规格·尺寸 / 材料供应商名称（含生产地点）/ 通过何种质量管理体系认证 |
| 材料列缺失判定 | 按 UAES 3 列组合判；**不得**因缺「材料规格·尺寸」「材料供应商名称」等理想 6 列而判 `B05` | 6 列缺任一 → `B05`（客户原文「只要有一列没有，该项结果判定为 NG」） |
| 单件重量格式 | 无小数位强制要求 | **必须保留小数点后四位**（不符 → `W03`） |
| 签字要求 | **三处**：供应商负责工程师、UAES NE 工程师、UAES SQD/SQE 工程师 | **无签字区要求** |
| 部件状态四列 | 无；使用「指定件 / 替代 / 领用件」口径 | **四列互斥**：自制 / 外协-国产 / 外协-进口 / 领用件，有且仅有一列有内容（多选或全空 → `W06`） |
| 「完成 PPAP」列 | 无 | 必须有；外协件（国产或进口）对应行须为 `Y`（否则 → `W06`） |
| 跨文件依赖 | **图纸**（同项目 + 同物料编号）→ 校验零件名称 / 零件号一致；缺 → **仅 `S04-C`**（图纸 `src=CUS`，提交方无权出图，**不配 `W01`**，措辞为「向甲方索取」） | 无 |
| 空值口径 | 「除备注外其余字段不为空」（客户原文整体判 NG） | 按列判：结构列缺失 → `B05`；个别单元格空 → `W02` |

**关键校准**：客户原文对「除备注外其余字段不为空」判**整体不通过**，预检按总纲 7.2 拆为——**整列全空 → `B05`（结构不可用）；个别单元格空 → `W02`（缺值）**。不得因为一行备注列以外有个空格就把整份清单判阻断，那会让预检退化成「逐格挑错」。

**四条执行纪律**：

1. **先定条目，再定代际**。条目决定材料列组合与签字要求，代际决定同一列在不同版本下的位置差异（附录 A）。顺序反了会把 UAES 文件按理想 6 列量、稳定产出 `B05` 假阻断。
2. **UAES 3 列与理想 6 列不可互换为「必备列」**。这是本类目最高频的跨客户误判点。
3. **本节不新增级别与原因码**，落点全在 `PC-A`~`PC-E` 既有项内。
4. **客户非 UAES / 理想** → 落 L3 记 `S02`，不得按通用结构硬判。

## 9. 严重级别与通过规则

### 9.1 严重级别

| 级别 | 定义 | 对结论的作用 |
| --- | --- | --- |
| 阻断 | 至少一条正式审核规则**无法得出唯一结论**（取不到数或结论方向不唯一） | **不通过** |
| 警告 | 判定仍可完成，但结果不完整或存在被误判风险 | **不影响结论**，仅记录并移交 |

**四种状态（不是级别，不参与通过判定）：**

| 状态 | 代码 | 本分则典型形态 |
| --- | --- | --- |
| 范围外 | `S01` | 不属本类目的文件剔除；R1 档下项目内其他 PPAP 项本不在范围 |
| 对端未到 | `S04` | **图纸等受控件**应收未随包 → `S04-C`（不配 `W01`）；**项目内其他 PPAP 项**声明同批而未同批 → `W01` + `S04-S` |
| 规则不适配 | `S02` | 规则侧成因导致某项在本代际无判定依据（上游已声明的适配限制） |
| 移交 | `S03` | 体系认证过渡态 / 代理商 / 仅 ISO9001 的可申诉性、签字有效性、造假定性 |

一条问题的级别只由「能否得出唯一结论」决定，「是否规范、是否合规、是否严重」一律留给正式审核。

> **警告不拦截的补偿**：警告项 100% 列入报告第五章并随报告移交正式审核；正式审核**不得因「预检已通过」而跳过警告指向的字段**（总纲 8.3）。

### 9.2 通过规则

无阻断即通过，存在任一阻断即不通过并给出原因码；警告不影响结论但须 100% 列报并移交；状态项不参与判定但不得略去不记（总纲 8.2 / 8.3）。

### 9.3 不得作为不通过理由的情形

| 情形 | 处理 |
| --- | --- |
| 项目内其他 PPAP 文件未同时提交 | `S01` 范围外，不记问题 |
| 同一零件只有一份清单且未提交其他版本 | 不记问题 |
| 体系认证过渡态、代理商、仅 ISO9001 | 记 `S03` 移交，走正式审核豁免流程 |
| 本代际模板本身不含某列（如 V1.0 无成型工艺列） | 记 `W01` 警告（本代际模板不含该对象），不得判提交方漏填 |
| 图纸等**受控**关联证据未随包 | 记 **`S04-C`**（**不配 `W01`**），措辞为「**向甲方索取**」，**不得写「提示补交」**——提交方无权出图，让他补交等于把整改单派错人；不表述为「清单错误」 |
| 单件重量小数位、父子重量守恒、勾选与角色相符 | `S03` 移交，预检不判 |

## 12. 执行要求与约束

1. 按本文件流程执行，不跳过范围确认与代际判定。
2. 以整个提交子集为对象，不局限于单文件；不得以「项目不全」判不通过。
3. 先判模板代际，再执行数据层检查；禁止用同一套字段要求套所有代际。
4. 正确性优先依据字段类型、基本常识、业务常识与领域知识。
5. 完整性允许合理推断，但必须说明推断依据与置信度。
6. 一致性不要求预先指定关联键，应自主推断可能关联项。
7. C / D / E 三维度并列；任一存在阻断即不通过。
8. **不得执行任何 `PC-F` 类检查，不得输出任何关于规则集、口径、规则代际标注的结论或建议**（总纲 2.3）。
9. 采用相对严格标准（仅作用于是否记警告，不作用于是否判阻断）。
10. 不通过打回材料侧整改；提交方补正与解析侧核查单列，不混入供应商整改项。
11. 每次调用无状态，不继承历史整改记录。
12. 必须区分「数据不规范」与「文件无法解析」。
13. 证据定位到最小颗粒度：单元格 / 行 / 切片。
14. 输出 Markdown 报告，不要求程序化 Schema。
15. **禁止用「无问题」代替「未覆盖」**；`S01`~`S04` 状态项必须单列并说明。
16. 不描述、不建议、不评价任何技术实现方式；不给出「应填什么值」的建议。
17. 不得因「项目内其他文件未同批提交」判不通过。
18. 不得把「本代际模板不含该列」记为提交方缺陷，须先判是否属代际固有差异（`PC-B8`）。
19. 不得对不可判读的扫描件产出具体 NG 条目，只能给「不可判读 + 人工复核」。
20. 无图纸时只能输出「**向甲方索取（`S04-C`）**」，**不得写「提示补交」**（提交方无权出图），不得编造图纸比对结论。
21. 不得把警告项计入阻断清单或据以判不通过。
22. 不得把单文件的「字段命中」等同于「逐行填写合规」。
23. PC-A / PC-B 组不通过时，不得仍以精确到单元格的结论呈现 C / D / E 组结果。
24. 不得跨层级比较总成行与叶子行的单件重量来判定量级异常。
25. 不得用 UAES 的三处签字要求判理想模板（理想为两处）。
26. 不得从表格件单元格判断「是否已签字」；不得把 `/`、`—`、`N/A` 一律当成缺失。
27. 不得给出「4 位小数合规率」类结论（精度判定属预审）。
28. 不得因执行方无视觉能力而把该项判成提交方问题（应标注「未执行」，见 4.4）。

## 14. 运行假设

以下为**运行假设**，不作判定依据、不产生任何级别，但须在报告中显式声明，供正式审核复核。原 v2.2 的「待确认口径」六项按 7.6 处置后，其中四项转入本节。

1. 本预检不接收规则集实体，不重复判定规则文本的可执行性（总纲 2.3）。
2. 「部分提交」为合法状态；只判提交件自身完整性。
3. 模板代际以「主机厂 × 代际」二维区分，UAES 视为独立分支而非理想代际的变体。
4. 占位符判为不适用但须有依据；白名单外写法按原文字面处理，记 `W03` 警告。
5. **材料体系认证取列**：材料侧与部件侧同名两列**分别检查**，不取单列——取错会导致整族漏检，双列同查的代价只是多记一条警告。
6. **部件状态列构成**：按「父列 + 五个叶子列」理解（自制 / 外协-国产 / 外协-进口 / 领用件 / 完成PPAP）；「领用件」在 UAES 模板中名为「指定件」。`PC-C10` 按此判互斥。
7. 系统认证过渡态、代理商、仅 ISO9001 属可申诉范围，以 `S03` 移交正式审核，不记警告。
8. 图纸长期缺失，输出措辞为「**向甲方索取（`S04-C`）**」，**不得写「提示补交」**，不表述为「清单错误」。
9. 签字是否本人签署、是否授权，不在预检范围。
10. 跨文件关联由模型基于整体内容自主推断，不预先指定关联键。
11. 整改为线下人工操作，整改后重新无状态调用本预检。
12. **已裁定**：级别只有两级（阻断 / 警告），结论只有两级（通过 / 不通过）+ 原因码；`S01`/`S02`/`S03`/`S04` 为状态不是级别。

## 15. 补充口径
> 本节条款与正文冲突时以本节为准。

### A. 层级序号行的判定顺序（新增，替代原 PC-B3 与 PC-B4 各自解释）

**先判「行是否为空」，再判「层级是否合法」**，两步不得颠倒：

| 步 | 条件 | 判定 |
| --- | --- | --- |
| 第 1 步 | 该行**仅填了层级序号**（如 `2.6.1`），其余各列全空 | 视为**空行**，记 `W02`（空值占位）。空行**不参与**层级关系判定，不得据其判 `B04` |
| 第 2 步 | 该行**有实质内容**且层级序号跳级（如 `1` 之后直接 `2.6`）或倒序（`9.3` 后接 `9.2`） | 记 `B04` |
| 合并 | 同一批空行 | 合并为**一条** `W02`，列出全部行号，不得逐行计阻断 |

### B. 共用母版列报（引用总纲 8.7）

同一清单在批次内出现多份副本时，缺陷逐件列报、只计一次阻断，其余件标注「继承自共用件」。

## 1. 目的与定位

### 1.1 目的

本分则 用于在 PFMEA 正式规则审核之前，对待检查的 PFMEA 文件族进行数据标准化预检，判断当前输入是否具备被后续 23 条规则完整审核的条件。

核心目的：

- 拦截「不可审」：关键列不存在、关键字段无值、规则所需信息无法获得。
- 拦截「难审」：语义歧义、模板混杂、符号体系冲突、跨文件无法配对。
- 拦截「证据不足」：控制措施不带分值导致派生字段无法计算、履历日期为占位符导致时间关系无法比较。
### 1.2 预检与正式审核的规则切分（关键边界）

23 条整合规则按「判定是否需要语义理解」切分。**切分依据**：凡可通过确定性计算、值域比对、集合包含、跨文件主键匹配得出结论的，属预检；凡需要理解文本语义、判断业务合理性才能得出结论的，属正式审核。

| 规则 | 规则名称 | 归属 | 切分理由 |
| --- | --- | --- | --- |
| R01 | PFMEA 表与变更履历表存在性 | **预检** | 结构存在性，纯确定性 |
| R02 | 表头 8 要素完整性 | **预检** | 字段存在性，纯确定性 |
| R03 | 表头日期与变更履历一致性 | **预检** | 日期值比对，纯确定性 |
| R04 | 过程项功能三维度 | 预检（存在性）+ **审核**（内容合理性） | 三维度是否出现可确定；描述是否恰当需语义 |
| R05 | 失效影响三维度 + 每维独立严重度分值 | 预检（存在性 + 分值是否标注）+ **审核**（描述合理性） | 同上 |
| R06 | 严重度 = 失效影响三维度分值最大值 | **预检** | 派生字段自洽性，可计算 |
| R07 | 现行探测控制列存在且为有效探测措施 | 预检（列存在 + 非空）+ **审核**（是否「有效」） | 存在性可确定；有效性需语义 |
| R08 | 探测度 = 现行探测控制分值最小值 | **不启用**（v1.1 起） | 客户已确认探测度取「预防+探测合并最小值」，本条「仅探测控制」口径不再使用，由 R09 统一 |
| R09 | 预防/探测控制末位分值 + 探测度取最小 | **预检**（唯一探测度口径） | 分值是否内嵌可确定（读取控制措施文本末尾数值）；v1.1 起为探测度唯一计算口径 |
| R10 | AP 措施优先级与 S/O/D 查表一致 | **预检** | 查表比对，纯确定性 |
| R11 | 特殊特性列取值合规 | **预检** | 白名单值域，纯确定性 |
| R12 | S/O/D 为 1~10 的整数且非空 | **预检** | 值域 + 类型，纯确定性 |
| R13 | S 与失效后果匹配 | **审核** | 需理解后果严重性的业务含义 |
| R14 | O 与失效起因 + 预防控制匹配 | **审核** | 需评估控制措施的有效性 |
| R15 | D 与探测控制匹配；无探测措施不得 D<10 | 预检（D=10 硬规则）+ **审核**（匹配合理性） | 「无探测措施却 D<10」是确定性矛盾；分值高低合理性需语义 |
| R16 | 相同失效模式/相同控制条件下 S/O/D 一致 | 预检（失效模式文本完全相同的键）+ **审核**（语义归并后的键） | 文本完全相同可确定；「不同措辞是否同一失效模式」需语义 |
| R17 | 流程一致性：PFD 工序 ↔ PFMEA 过程步骤 | **预检** | 集合包含关系，纯确定性 |
| R18 | 特性一致性：PFD 特性类别 ↔ PFMEA 特殊特性 | **预检** | 集合包含 + 符号映射，纯确定性 |
| R19 | 关键特性标识 + 特殊特性清单覆盖 | **预检** | 集合覆盖关系，纯确定性 |
| R20 | PGQP1 采购件质量计划特性覆盖 | **预检** | 集合覆盖关系，纯确定性 |
| R21 | 三大文件一一对应（零件号/零件名称/工序号） | **预检** | 主键匹配，纯确定性 |
| R22 | 三大文件履历时间顺序 | **预检**（**三份履历须均存在且可取行方启用**，否则记 `S02`） | 日期序关系，纯确定性 |
| R23 | 是否结合过往经验教训追加失效模式 | 预检（关键词存在性）+ **审核**（是否恰当采纳） | 是否提及可关键词判定；采纳是否有效需语义 |

切分结果：

- **纯预检 14 条**：R01、R02、R03、R06、R09、R10、R11、R12、R17、R18、R19、R20、R21、R22。
- **预检与审核共担 6 条**：R04、R05、R07、R15、R16、R23。预检只判其中可确定性的部分（存在性、分值是否标注、值域、文本完全相同键），语义部分移交审核。
- **正式审核独占 2 条**：R13、R14。
- **停用 1 条**：R08。客户已确认探测度取「预防+探测合并最小值」，R08 的「仅探测控制」口径不再使用，由 R09 统一承担。
- 合计：14 + 6 + 2 + 1 = 23 条，无遗漏、无重复。

> **重要**：预检判「不满足」不等于正式审核判「NG」。预检只回答「输入是否具备被审核的条件」；正式审核回答「内容是否合规」。两者可以给出相反结论——例如 R10 的文件自带 AP 表与标准表取值冲突，预检判「两处取值冲突（`B06`）」，而正式审核直接按标准表重算后判 NG。报告中必须注明这一区别，避免下游把预检结论直接当作审核结论。

### 1.3 预检不做什么

- 不判断 S/O/D 分值的业务合理性（如「这个严重度给 8 是否偏高」）。
- 不判断控制措施是否真正有效。
- 不判断经验教训是否被恰当采纳。
- 不判断失效模式措辞是否专业。
- 不给整改方案，只给整改方向。
- 不生成、不修改、不覆盖任何源文件。

## 2. 范围与非目标

### 2.1 范围内

- 接收待检查文件族及文件清单。**不接收规则文件实体**——规则在「规则入口」定型，预检不评判规则本身（总纲 2.3、4.1）。
- 识别每份 PFMEA 的模板版本体系（五版/简化五版/四版(RPN)/四版(RPN+AP)/混合/未判定），并按版本路由条款适用性。
- 以整个文件族为标准化对象，进行数据正确性、完整性、一致性检查。
- 自主推断跨文件、跨表格、字段间关联项；优先使用 6.5 给定的配对键候选。
- 判定文件族是否齐备（本体 + PFD + CP + 特殊特性清单 + PGQP1）：**缺件记 `W01`、受阻判定项记 `S04`，不阻断**（4.4）。
- 输出 Markdown 检查报告。
- 区分「数据不规范」和「文件无法解析」。
- 给出文件级、文件族级、规则项级、文件集级结论。

### 2.2 非目标

- 不负责 OCR、表格抽取、文档解析等底层实现。
- 不规定必须使用何种解析工具或技术路线。
- 不修复、不补全、不转换原始文件。
- 不执行整改后的复检流程。
- 不进入正式业务规则合规审核（R13、R14 及 R04/R05/R07/R15/R16/R23 的语义部分）。
- **不评判规则本身的表述质量、完整性、可执行性**（总纲 2.3）。执行中若发现规则口径存在歧义，按 `S02`/`S03` 登记后继续判定其余项，不得因此中止或改变本分则的判定口径。
- 当前不输出程序可直接消费的 JSON Schema。
- 不依赖特定模型、特定平台或特定 Agent 框架。
- 不评估供应商质量管理体系（VDA 6.3、IATF 审核）层面的问题。

## 3. 术语

### 3.1 继承总纲的通用术语

待检查文件集、文件清单、数据标准字典、数据标准化预检、阻断、警告、证据链——含义与总纲第 3 节一致。

#### 3.1.1 状态词（强制，不得互换）

判定项级结论除「满足 / 不满足」外，另有四个**非结论**状态词。四者的区别在于「为什么没判」，混用会导致责任归属错位。

| 状态词 | 含义 | 判定条件 | 是否计入问题数 | 后续动作 |
| --- | --- | --- | --- | --- |
| `S01` | **范围外** | 该判定项的对象**本就不属**本次提交范围（本批无该类目文件；或委托方已出具书面范围声明，如「本项目无 PGQP1」） | 不 | 记录范围声明，不产生整改要求 |
| `S04` | **对端未到** | 该判定项须与本批另一份文件比对，而**对端在可及证据集内不存在**（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源，总纲 3.2.1）；本文件已提交、结构可判。**分两子型**：`S04-S`（`src=SUB`，如 PFD / CP / 特殊特性清单 / PGQP1 填报件）/ `S04-C`（`src=CUS`，如客户图纸、规范、模板本体） | 不 | `S04-S` 随 `W01` 移交并写明缺哪一件；`S04-C` **不配 `W01`**、进七章 7.2b 向甲方索取；受影响判定项在此登记；补件后重新预检 |
| `S02` | **规则不适配** | 该判定项在本文档的模板体系下无承载位置（如四版模板无 AP 列、无结构分析列） | 不 | 记录模板体系与条款对应关系 |
| `S03` | **移交** | 该判定项需要语义判断或需后续人工/正式审核确认，预检不判 | 不 | 写入报告「移交清单」，随报告移交正式审核 |

**「不适用」一词全体系禁用。** 历史文档与本文件早期版本中的「不适用」已按上表拆分，见到「不适用」须按以下规则还原：因模板体系无此列 → `S02`；因**本就不属提交范围** → `S01`；因**对端未提交** → 先查《00-A》§4.3 得 `src`，`SUB` → **`S04-S`**（配 `W01`）、`CUS` → **`S04-C`**（不配 `W01`）；因需人工/语义判断 → `S03`。

**`S01` 与 `S04` 不得互换**：`S01` 是「本就不该有这比对」，无整改要求；`S04` 是「该有但这批没到」，必须进整改单（`W01`）并在补交后重新预检。把 `S04` 记成 `S01`，缺件就从此消失于整改单。
- **`S04` 分两子型，判前必先核「可及证据集」（总纲 3.2，v0.7 新增）**：对端在 `SRC-1`（提交件）或 `SRC-2`（受控提供源：客户图纸、技术规范、客户表单模板、客户侧台账）内**已存在**的 → **正常比对，绝不记 `S04`**。集内确实没有时按 `src` 落码：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取）→ 仅 **`S04-C`**、**禁配 `W01`**、不进缺件数、进报告七章 7.2b。`src` 一律查《PPAP-00-A》**§4.3 对端来源登记表**，查不到记 `S02` 并报缺口，**不得现场推定**。**本分则全文凡记 `S04` 之处，一律按本子型标注。**
- **`S05`（受控模板缺结构）继承总纲**：本分则凡判 `B05` 之处，须先按总纲 **3.1 三分界**与 **5.2 两问**确认成因——查《PPAP-00-A》**§4.4 客户受控模板登记表**：该（客户 × 类型）登记**有**受控模板、且**模板本体也没有该列** → 记 **`S05`**（状态，**不阻断**、不配 `B`/`W` 码、不进缺件数、进报告七章 **7.2c**）；登记**无**（不限定表单格式）或**模板有而文件没有** → 仍记 `B05`。**本分则的 3.1 状态词表不列 `S05`**——它的定义、边界与取证要求只在总纲 3.1 / 3.3 / 5.2 维护，避免同一概念在多处分别表述。**`B`/`W` 原因码取值与判定严格程度逐字未改。**　**枚举优先级**：本分则凡用列举方式写状态码的地方——**判定结果取值、状态登记清单、六章装填白名单、「必须按 3.1 拆为…」之类的执行要求**——`S05` **都在其列**（分「已核对」/「待核」两种形态）。**若某处枚举文本仍只列到 `S04-C`，以本条为准**，不得因该处漏列而拒绝登记 `S05`。理由：v0.9 把 `S05` 加进总纲 3.1 之后，各分则的枚举没有同步扩，若按枚举字面执行，`S05` 会**有判据、无落点**——判出来了却装不进状态登记清单，等于这一档不存在。

状态词与原因码的区别：`S0x` 表示「不判」，`B0x`/`W0x` 表示「判了且判为问题」。同一判定项不得同时以状态词和原因码出现。

### 3.2 PFMEA 专有术语

| 术语 | 说明 |
| --- | --- |
| PFMEA | 潜在过程失效模式及后果分析（Process FMEA），PPAP 第 9 类交付物 |

## 5. 输出契约

### 5.1 总体结论

输出必须包含总体结论，且仅有以下三种结果（与总纲 5.1 一致）：

| 总体结论 | 判定条件 | 后续处理 |
| --- | --- | --- |
| 通过 | 未发现任何级别为「阻断」的问题。**警告项的存在不影响结论** | 文件族可进入后续正式审核，警告项随报告一并移交 |
| 不通过 | 存在至少一项级别为「阻断」的问题 | 必须打回整改，不得进入后续流程 |
| 未执行 | 该类别无可判定的输入（本批无该类目文件），或执行方能力不足导致全部判定项均无法执行 | 不计入结论统计，在报告中单列 |

**禁止的中间结论**：「基本通过」「有条件通过」「部分通过」。若实际状态介于通过与不通过之间，一律判「不通过」。

**警告不拦截的含义**：警告项不改变结论，但**不因此免责**——报告必须 100% 列报，且正式审核不得因「预检已通过」跳过警告指向的字段（8.3）。

### 5.2 报告形式

- 输出 Markdown 报告，结构见第 9 节。
- 当前不要求程序可直接消费的 Schema。
- 报告应清晰、可读、可追溯，便于人工整改。
- 所有结论必须可回溯到「文件 + 工作表/页 + 行 + 列」的最小定位。

### 5.3 问题记录字段

每个问题记录至少包含：

| 字段 | 说明 |
| --- | --- |
| 编号 | P-nn，全局唯一，按报告顺序 |
| 类型 | 「数据不规范」或「文件无法解析」 |
| 细分类型 | 正确性 / 完整性 / 一致性（**不再设「规则可执行性」**，该维度已随规则侧退出） |
| 关联判定项 | R01~R23，可多条；不同判定项因同一根因失败时并列 |
| 文件位置 | 文件名 + 工作表名/页码 + 行号区间 + 列字母 |
| 证据链 | 原文摘录（≤50 字）+ 位置说明 + 推断依据 + 关联项说明 + 已检索范围 |
| 影响 | 对后续正式审核的具体影响（哪项无法完成、结论精度下降多少） |
| 严重级别 | 阻断 / 警告 |
| **原因码** | `B01`~`B06` 或 `W01`~`W06`，取值见总纲 5.2；一个原因码只能对一个级别 |
| **责任侧** | 材料侧 / 提交方 / 解析侧，取值见 6.6 |
| 置信度 | 高 / 中 / 低，须说明依据（如「列定位经数值分布自校验」= 高；「无客户确认的符号映射」= 中） |
| 整改方向提示 | 一句话方向，不含具体改法 |

> **原因码不是装饰**：它与级别、责任侧三者必须自洽——`B` 类只能配「阻断」，`W` 类只能配「警告」；不得出现「阻断 + `W01`」或「警告 + `B05`」。

### 5.4 结论颗粒度

| 颗粒度 | 输出要求 |
| --- | --- |
| 文件级 | 每个文件是否存在问题、问题数量、阻断/警告数、最高严重级别、识别出的模板版本 |
| **文件族级** | 每个文件族（按配对键聚合）本体与配对件齐备性、受阻判定项清单 |
| 判定项级 | 每项结果（满足 / 不满足 / `S01` / `S02` / `S03` / `S04` / 未执行）、原因码、问题明细 |
| 文件集级 | 总体结论、阻断项清单、警告项清单、状态登记、版本分布统计 |

> **状态词不得计入「满足」，也不得计入问题数**，但必须在判定项级结论中列出并说明理由。报告中「无法判定」一词已废止，按成因改用：拿不到内容 → `B01`；判定依据不成立 → `B05`；需语义判断 → `S03`。

## 6. 执行流程

### 6.1 接收与文件集确认

1. 接收待检查文件族、文件清单；**不接收规则文件实体**（总纲 4.1）。
2. 核对文件清单与实际文件是否一致；不一致时记 `W01` 并列出差异。
3. 确认文件是否可访问、内容是否可获得（是否有文本层、表格是否可抽取、图像是否可识别）。
4. 若文件缺失、无法访问或无法获得可判定内容，记录问题，按 8.2 定级。
5. **区分两类失败**：
   - 「文件无法解析」= 技术上拿不到内容 → `B01`，该文件全部判定项不可判。
   - 「数据不规范」= 拿到了内容但内容不合标准 → 按 8.2 定级。
   二者不得混为一谈。把解析失败写成「内容为空」是**最严重的误判**（附录 C C7）。

### 6.2 判定口径（内置固化）

本节内容为**已确定并固化的判定口径**，随本分则一起下发，执行时直接采用，不再讨论、不再登记为问题。原先「规则描述文件预检」一节已不属本分则判定范围：预检不接收规则文件、不评判规则本身（总纲 2.3）。

| 编号 | 口径点 | 固化结论 | 责任侧 | 落地方式 |
| --- | --- | --- | --- | --- |
| K1 | 失效影响三维度命名不统一（内部/工厂内/公司内；客户工厂/OEM/主机厂/顾客；最终用户/终端客户/用户；另有 `S:/O:/C:`） | 采用同义词集合判定；`S:/O:/C:` 视为「内部 / 客户 / 最终用户」的等效简写，**判满足，不记录问题**，仅在报告「已确认口径」节登记为写法变体 | — | 附录 B R04/R05 判定式 |
| K2 | 探测度取最小值的比较范围 | **统一按 R09**（预防+探测合并取最小），R08 停用 | — | 上文 R08 行、附录 B R08/R09 卡 |
| K3 | 特殊特性符号体系 | R11 用白名单集合；R18 按 4.2.3 双体系映射判定，**G ≡ CC、Z ≡ SC、NA ≡ 空**，置信度「高」 | — | 4.2.3、附录 B R11/R18 卡 |
| K4 | 「无法辨识」的处置 | 内容拿不到 → `B01`（解析侧）；拿到了但读不成可判定值 → `B05`（材料侧）；能读出但需语义判断 → `S03`（移交）。**不再使用「无法辨识 → 一律不通过 + 人工复核」这一笼统表述** | 按成因分 | 8.2 原因码表 |
| K5 | 跨文件依赖的强制程度 | **配对件缺失一律 `W01` + 受阻判定项 `S04-S`，不阻断**（总纲 7.2 / 10.5 / 3.1 / 3.2 / 5.1）；配对件 `src` 全为 `SUB`，`CUS` 件另按 `S04-C`、不配 `W01`。`B05` 只用于**本文件**结构上无此字段——对端未交不是本文件的结构缺陷 | 提交方 | 4.4、8.2、J17 |
| K6 | AP 判定基准 | 以内置标准表（7.5.1）为唯一基准；文件自带表仅作被核对对象。两者冲突 → `B06`，责任侧材料侧 | 材料侧 | 4.2.4、7.5.1 |
| K7 | 控制措施分值缺失的定级 | 五版/简化五版下控制措施无末位分值 → `B05`（探测度取不到可判定值）；四版下 → `S02`。**分值内嵌在控制措施列文本中，形如 `目视检查（6）`——见 7.2.1 与 A14（v2.9 已澄清，本行判据未改）** | 材料侧 | 8.2 Z8 行 |

> **本节的口径冲突已全部关闭**，无残留开放项、无待确认项。执行中发现新的口径疑问时，按 `S02`（规则不适配）或 `S03`（移交）登记后**继续判定其余项**，不得中止、不得自行改变本分则口径、不得把疑问转记为供应商问题。

### 6.3 模板版本识别与条款路由

**这是 PFMEA 预检的强制前置步骤，不可跳过。**

1. 对每份 PFMEA 按 4.2.2 特征表识别版本体系：五版 / 简化五版 / 四版(RPN) / 四版(RPN+AP) / 混合 / 未判定。
2. 按版本路由条款适用性：

| 判定项 | 五版 | 简化五版 | 四版(RPN) | 四版(RPN+AP) |
| --- | --- | --- | --- | --- |
| R04 过程项功能三维度 | 适用 | `S02`（无结构分析列） | `S02` | `S02` |
| R05 失效影响三维度 | 适用 | 适用 | 适用（仅三维度，不要求分值） | 适用 |
| R06 严重度=三维度最大值 | 适用 | `S02`（无分值设计） | `S02` | `S02` |
| R08 探测度=探测控制最小值 | **`S02`（停用）** | **`S02`（停用）** | **`S02`（停用）** | **`S02`（停用）** |
| R09 控制措施末位分值 | 适用 | 适用 | `S02` | `S02` |
| R10 AP 查表 | 适用 | 适用 | `S02`（无 AP 列） | 适用 |
| RPN = S×O×D（派生字段） | `S02` | `S02` | **适用** | **适用** |
| 其余：R01~R03、R07、R11、R12、R15~R23 | 适用 | 适用 | 适用 | 适用 |
| R13、R14（正式审核独占，不在本分则范围） | — | — | — | — |

> **R08 全版本判 `S02`**，不产生阻断也不产生警告。探测度一律按 R09 口径计算。
>
> **条款为 `S02` 时，挂在该条款下的问题项同样不触发。** 例如四版文件的 R05 只要求三维度齐备、R09 判 `S02`，因此 Z8、Z9 对四版文件一律不产生问题，不得因「未见分值」判阻断——那会把「体系差异」误判成「数据缺陷」。
>
> **「版本不同」不是缺陷，「版本与声明不符」才是。** 四版模板本身合法，只要求版本识别准确、条款路由正确。

3. **版本混杂判定**：

| 情形 | 处置 | 原因码 | 责任侧 |
| --- | --- | --- | --- |
| 同一文件族内出现两种及以上版本体系 | 记录，不阻断 | `W04`（非主键不一致） | 提交方 |
| 委托方已书面要求五版，实际提交四版 | 阻断 | `B02`（提交范围不可判） | 提交方 |
| 版本无法识别（「未判定」） | 阻断——版本不可判则 R04~R10 的路由全部失去依据，后续结论均不可信 | `B03`（对象身份不可归属） | 提交方 |
| 同一文件内版本特征互相矛盾（判为「混合」） | 记录，不阻断；按 `S02` 排除矛盾的条款 | `W04` | 提交方 |

> **版本无法识别定为阻断的理由**：版本不可判时 R04/R05/R06/R09/R10 五项的适用性全部悬空，报告的规则项级结论会出现「一半有结论、一半没结论」的残缺状态，与总纲 5.1「不通过 = 存在阻断项」的门禁语义不兼容。记为 `B03` 后，整改方向明确（补版本声明或提供可识别特征），也不会把责任错挂到供应商的数据质量上。

> **为什么必须做版本路由**：不做路由时，四版文件会在 R04~R10 上产生大量「填错」型假阳性——这正是把「换版问题」误判为「质量问题」。

### 6.4 检查需求映射

对每条纳入预检的规则，识别：

| 映射项 | 说明 |
| --- | --- |
| 需要的原始信息 | 规则判定必须观察到的最小数据集 |
| 承载位置 | 在哪个文件、哪个工作表/页、哪个字段 |
| 允许隐含 | 允许通过关联或合理推断获得（须说明依据与置信度） |
| 禁止推断 | 明确不得推断的项（见 7.2.3） |
| 关联关系 | 与哪些字段/表格/文件存在一致性约束 |

示例（R09）：需要「现行预防控制」「现行探测控制」两列每行内容的**末位分值**；承载位置为 PFMEA 主表的这两列；**禁止**从控制措施文字长度、语气或行业惯例推断分值；若无末位数字，判完整性问题（阻断），而非降置信度后继续。

> **分值的物理位置**：控制措施分值**填写在控制措施列内**，是控制措施文本末位的括号数字，基础格式示例 **`目视检查（6）`**。
>
> **无独立分值列 ≠ 无分值**：表头 `PC` / `O` / `DC` / `D` / `AP` 并列时，分值内嵌在 `PC` / `DC` 列的文本末位，**只能按文件实际取值得分**——取不到末位分值 → 材料侧 `B05`；四版模板 → `S02`。不得因「无独立分值列」判 `S02`。

### 6.5 跨文件配对

1. 按 4.2.5 的配对键优先级，为每个 PFMEA 寻找 PFD / CP / 特殊特性清单 / PGQP1。
2. 每个配对结果必须记录：配对键类型、键值、候选文件列表、置信度。
3. 多候选时按置信度排序，取最高者为主配对，其余列为「备选」并说明未采用理由。
4. 无候选时判「配对失败」，按 4.4 定级。
5. **禁止**仅凭文件名相似直接认定配对成功。文件名只能作为第 3 优先级线索。

### 6.6 三维度标准化检查

对整个文件族并列执行：数据正确性、数据完整性、数据一致性。**三维度并列，任一维度不满足均视为数据标准化不通过。** 具体判定式见第 7 节与附录 B。

### 6.7 汇总判定

1. 汇总所有问题，去重（同一根因导致的多条规则失败应合并为一条问题并列出关联规则）。
2. 标注类型、位置、证据链、影响、严重级别、置信度。
3. 分别给出文件级、文件族级、规则项级、文件集级结论。
4. 按 8.3 通过规则给出总体结论。
5. 不通过时明确列出阻断项和警告项，供线下整改。

### 6.8 输出报告

按第 9 节模板输出 Markdown 报告。报告应明确：是否通过、不通过原因、问题清单、整改方向提示、本分则 不执行修复和复检。

## 7. 判定口径（PFMEA 具体化）

**数据正确性（7.1）、数据完整性（7.2）、数据一致性（7.3）三个维度并列，不设优先级**，任一维度出现阻断项即判不通过。

**本分则只有这三个维度。** 「规则可执行性」维度**不属本分则判定范围**——预检不评判规则本身，规则侧问题在规则入口处理，不进入预检结论（总纲 2.3）。原先由该维度承载的登记事项，去向如下：

| 原 7.4 内容 | v2.0 去向 |
| --- | --- |
| 三项已确认口径（`S:/O:/C:` 语义、符号映射、探测度口径） | 保留为 6.2 的 K1~K3，属**判定口径**而非问题 |
| 「残留开放项」登记 | 随维度退出；规则侧疑问按 `S02` / `S03` 登记（6.2 末注） |
| 「新增开放项 → 记 Z15」 | **Z15 整项删除**，编号不复用 |
| 「规则不可执行则数据也不通过」 | 删除。预检结论只反映文件数据质量 |

### 7.1 数据正确性

关注某一份文件内某个信息本身是否科学、合理、符合基本逻辑。

判定依据优先级（按序执行）：

1. 字段类型、格式、值域等基本要求。
2. 基本常识和科学逻辑。
3. 业务常识（FMEA 方法论常识）。
4. 领域规则或领域知识参考（AIAG / AIAG-VDA 手册、IATF 16949）。
5. 可选数据标准字典（本文件 4.2）。

**PFMEA 正确性检查项**：

| # | 检查项 | 判定式 | 关联规则 | 不满足级别 |
| --- | --- | --- | --- | --- |
| A1 | S/O/D 类型与值域 | 每行 S、O、D 均为 1~10 的整数（允许 `5` 或 `5.0`，不允许 `5分`、`高`、`N/A`、空） | R12 | 阻断 |
| A2 | AP 值域 | AP 列每行 ∈ {H, M, L}（允许小写，需归一化） | R10 | 阻断 |
| A3 | RPN 派生自洽（含 RPN 列的文件） | RPN = S × O × D。按是否实际存在 RPN 列判定，不看版本标签；无 RPN 列 → `S02` | R12 扩展 | 阻断 |
| A4 | 严重度取三维度最大 | 严重度 = max(对内部影响分值, 对客户影响分值, 对最终用户影响分值)。三维度中任一缺分值 → 转 7.2 完整性问题 | R06 | 阻断 |
| A5 | 探测度取所有控制措施分值最小 | **探测度 = 该行全部预防措施分值与该行全部探测措施分值中的最小值**（R09 口径，v1.1 起唯一）。任一措施无分值 → 转 7.2 完整性问题 | R09 | 阻断 |
| A6 | AP 与 (S,O,D) 查表一致 | 该行 AP = APTable[S][O][D] | R10 | 见 8.2 |
| A7 | 特殊特性取值在白名单内 | 该列每行归一化后 ∈ 白名单（4.2.3） | R11 | 警告 |
| A8 | 日期可解析 | 表头日期、履历日期可解析为 YYYY-MM-DD 或 YYYY/M/D；不得为 `XXXX年XX月XX日`、`/`、`-`、空、`待填` 等占位符 | R03 | 阻断 |
| A9 | 日期不晚于提交日 | 表头修订日期、履历日期不得晚于当前日期 | R03 扩展 | 警告 |
| A10 | 无探测措施不得 D<10 | 若该行现行探测控制为空/为「无」，则 D 必须 = 10 | R15 | 阻断 |
| A11 | 三维度分值独立标注 | 失效影响的三个维度各自带有 1~10 分值（形式不限：`S:…5`、`（5）`、`5分`） | R05 | 阻断 |
| A12 | 过程项功能三维度齐全 | 过程项功能描述中同时出现「内部/工厂内」「客户/OEM/主机厂」「最终用户/终端客户」三类语义（允许同义词） | R04 | 警告 |
| A13 | 行内容非空 | 失效模式、失效起因、现行预防控制、现行探测控制四列无空单元格（允许「无/NA」，须记录为待确认） | R07 / R09 / R16（前置） | 阻断 |
| A14 | 控制措施末位分值可抽取 | 现行预防控制、现行探测控制单元格文本末位为 1~10 数字（允许 `（5）`、`5`、`[5]`）。**基础格式：`目视检查（6）`——分值写在控制措施列的值里，不是独立列**；整列都无末位数字 → 阻断；个别行缺 → `W02` | R09 | 阻断 |

**判定注意**：

- A1 与 A13 检查的是不同列，不会对同一单元格重复判定：A1 管严重度/发生度/探测度三列的值域，A13 管失效模式、失效起因、预防控制、探测控制四列的非空。若因整行空白使两者同时触发，按 6.7 去重合并为一条问题，关联规则并列。
- A4/A5 是**派生字段自洽性**判断，不是业务合理性判断。不要讨论「这个严重度是否合理」，只判断「严重度是否等于三维度最大值」。
- A6 的 AP 判定基准为**内置标准表**（见 4.2.4、7.5.1）；文件自带的 AP 表只作被核对对象。二者不得倒置——用文件自带的表去校验 AP 列，等于让被考者自评，被改动的表下 AP 会「全部正确」（附录 C C14）。

### 7.4 严格标准与「宽严边界」

采用相对严格的标准，但严格只作用于**是否记警告**，不作用于**是否判阻断**。

| 情形 | 严格标准的适用 | 不得逾越的边界 |
| --- | --- | --- |
| 某个写法可能有歧义、也可能合规 | 按严格标准记为警告 | 不得据此判阻断 |
| 某个字段可读、但读出的值不足以支撑派生计算 | 记阻断（`B05`） | 这是判据不成立，不是「可疑」 |
| 行业普遍存在的缺口 | 按 8.4 维持原级别 | 不得因整改成本高而降级，也不得因「别人都没有」而升级 |
| 模型拿不到内容（无文本层、无视觉能力） | 标「未执行」，不记级别 | 不得按严格标准「从严推定」为阻断 |

具体规则：

- 宁可严格误判，也不放过潜在不规范——但仅限于记警告。
- 若模型认为数据标准化可能存在问题，即使实际可能没有问题，也允许按严格标准**记警告**。
- 所有推断性判断必须标注推断依据和置信度。
- **不得因为「行业普遍如此」而降低要求**（见 8.4）。
- **不得把「从严」当作判阻断的理由**：阻断只能由「某条判据在结构上取不到可判定值」触发（`B01`~`B06`），不能由「感觉不放心」触发。

## 8. 严重级别与通过规则

### 8.1 严重级别

仅设置两种级别（与总纲 8.1 一致）：

| 级别 | PFMEA 场景下的具体含义 | 对结论的作用 |
| --- | --- | --- |
| **阻断** | 该问题导致至少一项判定在**结构上取不到可判定值**（对应原因码 `B01`~`B06`），使该规则**无法得出唯一结论**。**「配对件未交」不属此列**——它使比对项无对象，按总纲 3.1 / 5.1 记 `S04` | 总体结论判「不通过」 |
| **警告** | 该问题不影响「能不能判」，只影响「判得准不准」：写法不规范、非主键不一致、局部不可解析、内部不自洽 | **不影响结论**，但必须 100% 列报并移交正式审核（8.3 补偿条款） |

**定级的唯一判据**：某项判定是否仍能得出确定结论。能得出 → 最多记警告；不能得出 → 阻断。**不以「问题看起来严重不严重」定级，也不以「整改成本高不高」定级。**

### 8.2 判定项 → 原因码 → 责任侧映射

按问题类型给出默认映射。**执行时直接采用，不得自行调整**（调整需走 8.5）。原因码语义见总纲 5.2，责任侧定义见 8.6。

#### 8.2.1 阻断类（`B` 码）

| --- | --- | --- | --- | --- |

| Z2 | PFMEA 主表无法定位（无表头区，或表头区无任何可识别关键列） | `B04` 结构不可判 | 材料侧 | R01 |
| Z3 | 关键列缺失：严重度 / 发生度 / 探测度 / 失效模式 / 失效起因 / 现行预防控制 / 现行探测控制 任一缺失 | `B05` 关键字段结构上不存在 | 材料侧 | R12/R07 |

### 8.3 通过规则

无阻断即通过，存在任一阻断即不通过并给出原因码；警告不影响结论但须 100% 列报并移交；状态项不参与判定但不得略去不记（总纲 8.2 / 8.3）。

本分则补充：状态词 `S01`/`S02`/`S03`/`S04` 与「未执行」均不作为通过与不通过的判定依据，但必须在报告中列出并说明理由。

#### 8.3.1 警告补偿三条款

全量列报、移交留痕、不得免检三条按总纲 8.3 执行，本节不重述。报告第五章章首与第八章须逐字保留 11.8 固定话术。

### 8.4 禁止降级原则

**当某类问题在全批次普遍存在时，不得因其普遍性而降低级别。**

若因普遍性将上述问题降为警告，则本分则将失去门禁作用。**这些是行业性缺口，恰恰是预检最应该拦住的问题。** 因此：

- Z8、Z11 在**其适用范围内**一律维持阻断（Z8 仅对五版/简化五版；四版见 6.3 表）。
- 报告须在相应问题中说明「该问题在本批次普遍存在，属系统性缺口，非个别疏漏」，便于委托方判断整改成本。
- 若委托方确认某类文件在本项目范围内不适配（如总成级 PFMEA 无 PGQP1），须走「书面范围声明」流程（4.4 注），记 `S01`，而**不是**降低级别。

### 8.5 级别调整规则

允许的调整仅限以下情形，且必须在报告中说明调整理由：

| 调整方向 | 触发条件 | 说明 |
| --- | --- | --- |
| 警告 → 阻断 | ① 该警告项直接导致下游判定完全无法计算（**不含「缺对照件」**——7.2 与 4.4 已定为 `W01` 且明令不阻断；该项无对象时按 5.1 记 `S04`）；② 同一根因在文件族内 ≥80% 文件出现，且导致该族全部结论不可信 | ① 如 J13（配对置信度低）叠加 B8 判定时，跨文件结论不可信；② 系统性问题按族级阻断处理 |
| 阻断 → `S01` / `S03` | 有明确的书面范围声明（`S01`）或明确的人工复核/语义判断依据（`S03`） | 须记录声明来源或移交理由，**不得由模型自行推定** |

> 「同根因合并」不属于级别调整，属 6.7 的去重机制：多条判定项因同一缺失而失败时合并为一条问题、并列关联判定项，不重复计数，但级别不变。

**禁止的调整**：

- **阻断 → 警告**（无任何例外情形）。
- 因置信度低而降低级别（低置信度应保持级别并标注置信度）。
- 因整改成本高而降低级别。
- 因「本批全部如此」而降低级别（见 8.4）。
- 因执行方能力不足而降低级别（应标「未执行」，见 4.3）。

### 8.6 责任侧与处理去向

每个问题除级别与原因码外，必须明确「归谁」。责任侧错挂会导致整改要求发给错误的一方，比不判更糟。

| 责任侧 | 含义 | 典型问题 | 处理去向 |
| --- | --- | --- | --- |
| **材料侧** | 文件内容本身不合标准：缺列、空值、取值不合规、派生字段不自洽、跨文件取值冲突 | Z2~Z8、Z10、Z12~Z14、Z17~Z22、J1~J8、J11 | 打回供应商补正材料 |
| **提交方** | 文件的组织方式或选择有误：提交范围、版本体系、配对失败、清单不符 | Z11、Z16、Z23、J10、J12、J13、J17 | 提交方补正提交范围或文件组织，**不要求供应商重做数据** |
| **解析侧** | 执行方在内容获取或结构识别上存在不确定性，与文件质量无关 | Z1（文件无文本层等）、J14 | 换解析通道/换工具重试，或标「未执行」，**不得发整改给供应商** |

> **责任侧不是级别**：材料侧的问题不一定阻断（如 J1），提交方的问题也可能阻断（如 Z11）。两者独立判定。
>
> **解析侧的三种情形要分清**：① 文件本身无文本层、加密、损坏 → `B01`，虽归解析侧但确实是文件缺陷，仍需提交方换文件；② 执行方无相应读取能力 → 标「未执行」，责任侧不成立（4.3）；③ 有内容但结构识别存在多种可能且经自校验已选定 → `W05`，归解析侧，仅作记录。

### 8.7 跨文件判定项的缺陷归属与去重

> **本节是总纲 10.3「跨文件比对项的缺陷归属」在本分则的落地细则。** A/B/C/D 四情形与四条硬约束的权威定义在总纲，本节只补充 PFMEA 侧的具体适用说明；二者如有解释差异，**以总纲 10.3 为准**。

R21、R22 这类比对项把本文件与配对件放在一起看。**判据只回答「是否一致」，不回答「谁的错」**。若两份文件的报告都就同一处冲突各开一张整改单，供应商会收到两份方向相反的要求——改本文件还是改配对件？因此比对失败后必须先做**缺陷归属定位**，再定级别。

| 情形 | 识别依据 | 本文件该判定项 | 缺陷计入 |
| --- | --- | --- | --- |
| **A 单向定位到本文件错** | 配对件有内部他证（编号栏内嵌号段、图纸号、其他引用位）指向与本文件不同的值，且本文件无相反他证 | 记**阻断** | 本分则 |
| **B 单向定位到配对件错** | 配对件内部自相矛盾，且矛盾的一侧与本文件取值一致——即配对件的自身他证**支持**本文件的取值 | 记 `S03` 移交 | 配对件所属分则 |
| **C 缺陷确定在配对件、本文件是否有错不可判** | 配对件内部自相矛盾（缺陷确定存在），本文件该字段为单点取值、内部无矛盾可对照 | 记 `S03` 移交 | 配对件所属分则 |
| **D 无法定位** | 两方均无他证；或两方各自内部均有矛盾且方向相反 | 记**阻断** | 本分则（配对件分则同判，但整改单合并为一张） |

**四条硬约束**：

1. **同一缺陷只在一个分则计阻断。** B、C 两种情形下，本报告该判定项记 `S03`，但冲突事实、位置、原文取值、影响、证据链**仍须完整列报**，并在责任侧栏写明「缺陷归属：见 PPAP-10 控制计划报告对应条目」。
2. **`S03` 不得用作免责出口。** 只有配对件缺陷**已被证实**（内部自相矛盾或存在反向他证）才能用 B、C。本文件自身有疑点但未证实、或双方各自均有矛盾，属 A、D，仍记阻断。
3. **结论可逆性必须声明。** B、C 情形下本文件结论按 8.3「无阻断即通过」计算，但报告总体结论须写明：「本结论受 N 项移交事项制约；若正式审核确认缺陷实际在本文件，则本文件结论应改判不通过。」
4. **归属不等于责任侧。** B、C 情形下本文件责任的判定被挂起（移交），不得写成「材料侧 1 项」——那会把整改指向本文件。判定项级责任侧栏写「待定（移交）」。

**C 情形的判定要点**：本文件字段「无内部矛盾可对照」是 C 与 A 的分界。若本文件也存在同一字段的其他引用位（如本文件编号栏也内嵌零件号）且与本文件取值冲突，则本文件自身已不自洽，属 A（或 D），不得记 `S03`。

5. 一致性不要求预先指定关联键，应自主推断可能关联项；但 4.2.5 提供的配对键候选优先使用。
6. 三维度并列，任一维度出现阻断项即判不通过。
7. **不评判规则本身的表述质量、完整性、可执行性**（总纲 2.3）。规则侧疑问按 `S02`/`S03` 登记后继续判定其余项。

### 11.1 表结构可判性的四项前置条件

本节不是「建议」，而是**判定前必须成立的前提**。任一前提不成立，行级判定项（R04~R12）的结论都不可信，须按成因处置：结构上无法确定哪一块是主表 → `B04`（`B03` 适用于文件身份不可归属）；已能确定但某一前提仅部分成立 → `W05`（局部不可解析）并说明是哪一项前提未满足。

> 本节只规定**判定要求**，不规定解析怎么实现——解析责任见 4.3 与 2.2 非目标。

| # | 前置条件 | 不成立时的后果 | 判定方法 |
| --- | --- | --- | --- |
| H1 | **主表与参考表须能分开** | 评分准则表、AP 判定/查询表、修订履历、填表说明页同样含「严重度/发生度/探测度」列名，且行数可能多于主表；选错即整表结论无意义 | 主表候选须同时满足：① 表名或表头不含「准则/準則/数据库/資料庫/判定表/履历/履歷/说明」等参考表标识；② 可识别的语义字段 ≥8 个；③ 满足前两条的候选中取数据行最多者。多个候选均满足时，按列定位歧义登记（J14） |
| H2 | **表头须能拼合完整** | 表头跨行时（中文行 + 英文行或单字母行），只取任一行都会导致关键列漏识别；若让单字母行覆盖中文行，则会绑到「措施结果」区块的第二套评分列 | 先按中文行识别；再逐字段检查缺失项，单字母列（S/O/D/AP）**只允许补足**尚未识别的字段，不得覆盖已识别字段。拼合后仍缺关键列 → Z3 |
| H3 | **纵向合并须继承** | 一个工序下挂多条失效起因时，「过程步骤 / 失效影响 / 严重度」常纵向合并，仅左上角有值；不继承会把下方行判成「未评分」，产生大面积假阻断 | 纵向合并区间内，子行须继承合并块首行的值。**横向合并不得作为继承来源**——跨列填充会把相邻列的值误当本列值 |
| H4 | **数据行须是失效分析行** | 章节标题行（仅有「要求：原材料进料检验」「过程步骤：来料进厂」）不是数据行，计入分母会虚增「未填」比例 | 一行计为数据行，须至少满足：失效模式 / 失效影响 / 失效起因三者之一非空。不得仅凭「过程步骤」或「要求」有值即判为数据行 |

**列定位须满足的唯一性要求**：

1. 每个语义字段只允许绑定一列；同一列只允许承载一个语义字段。
2. 多个候选列时，按「精确别名 > 包含式别名 > 位置靠左」择优；但不以此作为最终依据，**必须**再过值分布校验（见 4.2.1 第 3 条）。
3. 值分布校验不通过时，说明绑定有误，须重新定位；重新定位后仍不通过，登记「列定位歧义」（J14）。
4. 三元组交叉校验：文件含 RPN 列时，用 `RPN = S×O×D` 复核绑定正确性；命中率低于 60% 说明发生度绑错，须在严重度与探测度之间重新定位。无 RPN 列时，用列序 `严重度 < 发生度 < 探测度` 复核。
5. 定位结果须写入证据链：工作表名 + 列字母 + 列标题原文 + 值分布校验通过率。

> **停用判定项的状态一致性**：R08 对**所有文件、所有解析状态**一律记 `S02`，不因「该文件无法解析」而改为 `B01`——否则同一判定项会在结论里出现两种状态，读者会误以为停用有例外。

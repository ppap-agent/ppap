## 1. 目的与边界

**目的**：判定这份《特殊特性清单》**是否具备可被对应客户审核的特性台账结构**——字段 / 列是否齐、行内是否填全、标题是否带产品编号（蔚来）。

**为什么三家共用一份分则**：同一文件类型、同一判定对象（特殊特性台账），差异集中在**列的粒度**上——UAES 是 7 列简版，理想是 10 列 + 8 个监控子列 + 2 个风险列，蔚来是 11 列。按字典号归并、差异放进 §7，与 `PPAP-T09` 的处理一致。

**三家差异是实质性的，不可互换判据**：

| 客户 | 列结构 | 核心差异 | 判据数 |
| --- | --- | --- | --- |
| **UAES** | 7 列简版 | 编号 / 特性名称 / 特性及公差 / 特性类型 + 物料名称、物料编号两个字段；另含材料类特性登记（`S8`）与母表完备性（`S9`，跨文件） | **9** |
| **理想** | 10 列 + **8 个监控子列** + 2 个风险列 | 要求「T1-特性监控方法」的 8 个子列（测量设备 / 测量方式 / 防错控制 / 检查控制 / 抽样频率 / SPC 监控 / SPC 线上管理计划时间 / 说明），并要求风险评估与预防措施；含母表完备性（`S9`，跨文件） | **8** |
| **蔚来** | 11 列 | 要求「控制方法（制造过程）」「防错方案描述」「频次」「样本数」；并要求**标题前有产品编号**；含母表完备性（`S9`，跨文件） | **5** |

**最容易被误用的一点**：把理想的 8 个监控子列套到 UAES 或蔚来（两家规则均未要求）；或把 UAES 的「物料名称 / 物料编号」字段套到理想（理想用的是「零件名称 / 零件号」）。**跨客户套用会整片误判。**

**边界三条**：

1. 本类目**不判实测值**，故不产生 `B06`；判行内完整性，落 `W02`。
2. 本类目**基本无跨文件依赖**——**唯一例外是 `S9`（母表完备性，v1.5 起三客户通用）**，它需要 CP / PFMEA 作为对端来反证「母表漏标」；对端不在**可及证据集**内时按 `W01` + `S04-S` 处置，**不阻断**（总纲 7.2 / 10.5）。蔚来 PFD（`T09-N05-S11`）依赖本类目，**方向相反**——本分则不得因缺 PFD 记任何问题。
3. 客户差异层互不生效——报告须写明命中的是哪一条路由。

### 4.2 理想 × 过程特殊特性清单（路由 `L12`，8 项）

**5.2 斜杠写法 = 同义可选（UAES 的 S3~S6 专用）**

UAES 规则原文使用「编号 / 序号」这类斜杠表述，含义是「**两者任一存在即满足**」。判定时：

1. 用同义词表全量匹配，命中**任一**即通过。
2. **不得**要求同时存在两个列。
3. 若两列都存在，取**实际使用的那一列**作行键（有内容者优先）。

**5.3 理想 8 个监控子列的还原（`L12-S4`）**

1. 先定位「T1-特性监控方法」一级列。
2. 在其下识别 8 个二级列，逐项匹配（§5.1）。
3. 若合并单元格结构丢失、8 个子列被拆成独立一级列，**按列名语义归属**，不判缺失；记 `W05` 并在 10.2 说明「表头层级丢失，已按列名语义归属」。
4. **不得**因「子列顺序与判据列举顺序不同」判缺失——列序无关。

**5.3.1 空值与占位符口径**

同一个占位写法在不同判定项上不能得出两个结论。本类目统一按下列口径：

| 写法 | 认定 | 落码 | 依据 |
| --- | --- | --- | --- |
| 空单元格 | 空值 | `W02` | 总纲 5.2 `W02` |
| `NA` / `N/A` / `NULL` / `null` / `-` / `/` / `待填` | **占位符**（不是值，也不是「不适用」声明） | `W02` | 总纲 5.2 `W02` 含「占位符」 |
| `#N/A` / `#VALUE!` / `#REF!` 等 Excel 错误值 | 取不到可判定值（个别单元格） | `W02` | 5.2 边界表「有列个别为空」 |
| **客户差异层已把 `NA` 列入该列合法取值域**（如理想控制计划「特殊特性分类」列） | **合法取值** | 不记问题 | 7.1 差异对照 |

**三条硬规则**：

1. **`NA` 不等于「不适用」。** 本分则里「不适用」是**状态**（`S01`/`S02`），有严格判据；单元格里手写 `NA` 只是**占位符**，两者不是一个概念，不得互替。
2. **同一列内 `NA` 与 `NULL` 并存时，两者结论必须一致**——v1.2 之前 `NA` 被判「非空 → 通过」、`NULL` 被判「空 → `W02`」，同一模板同一列得出两个结论（实测 `DQ040091` 填 `NA`、`DQ040093` 填 `NULL`，一处通过一处 9 条 `W02`）。按本节**两者同为 `W02`**，差异消失。
3. **占位符不得用来规避「该填什么」**：若某行 `NA` 出现在承载特殊特性判定的列（特性值 / 规格 / 分类），除 `W02` 外还须在报告注明「该行是否应列为特殊特性需正式审核判断」（`S03`），**不得由预检替客户认定不适用**。

| 判据 | 行键 | 判定范围 | 计数规则 |

**行键为空的行一律跳过**，不判——空行不是缺陷。
**剔除标题行、小计行、合计行**：整行仅 1~2 个单元格有值且首列含「合计」「小计」「说明」等字样。

**计数单位**：上表「一行只记一次」是**问题计数的颗粒度**，不等于**特性条数的计数口径**——后者按 §5.9（处数 / 行数 / 编号数三数并列，判定以编号数为准，v1.4）。

**5.6 三家差异不得混用的三个具体点**

1. **理想的 8 个监控子列只对理想生效**。判 UAES 时要求「测量设备 / 测量方式 / …」是加严；判蔚来时同理。

3. **蔚来的产品编号前缀要求只对蔚来生效**。不得因蔚来要求而给理想 / UAES 记 `W03`。

**5.8 符号字典（v1.4 新增 · `RW-36`）**

> **落位说明**：第一轮建议写作「新增 `§5.3 符号字典`」，但本分则 §5.3 已被「理想 8 个监控子列的还原」占用、§5.3.1 为「空值与占位符口径」，故**按续编落为 §5.8**（编号续编、不复用已占用节号）。

本表只收录**客户书面定义或本批已确认**的符号。**未收录符号不得自行解释**——按总纲 7.5 记 `S02`（确实定不了），并按总纲 §10.6 登记冲突 `C-xx`。**不得记 `S05`**（`S05` 专指受控模板缺结构）。

> **这不等于「必须有」**。白名单是「**出现时如何解释**」的字典，不是「**应当出现**」的要求清单——把白名单当成必备项，会反向变成加严（供应商本来不用这些符号，却被判缺项）。执行时只对**文件中实际出现的符号**查表。

**六条判定纪律**：

1. **GD&T 公差框是公差表达，不是特性分类符号**，不计入特殊特性标记；其所在位置**不影响「符号列为空」的判定结论**，但须按总纲 §7.2.2① 记录「信息在邻列」。
2. `K` 为**材料类特性标识**，计入特性清单完整性（`S8`），**不计入工序特殊特性**。
3. **同一符号在不同文件中形态可不同**（印刷体 / 手写 / 图形），须按**语义**而非形态判定，并在报告中记录形态差异。
4. **符号列宽与坐标**：须记录列边界（页间存在漂移——实测三页列边界可为 `1253/1368`、`1259/1370`、`1266/1377`），统计前做一致性校验（总纲 §7.2.3 第 3 项）。
5. **未收录符号不得自行解释**——记 `S02`（总纲 7.5），并按总纲 §10.6 登记 `C-xx`，**不得**按「看起来像特殊特性」计入或不计入；**不得记 `S05`**（`S05` 是「受控模板缺结构」，不是「读不懂」）。
6. **不得以符号形态差异判「混用两套体系」**——体系判定看语义归属，不看字体或大小。

**5.9 计数口径（v1.4 新增 · `RW-34`）**

本类目凡涉及「项数 / 条数 / 覆盖率」的判定，按总纲 §7.2.1 同时给出**处数 / 行数 / 编号数**三数，**判定与跨文件比对一律以编号数为准**。要点：

1. 一格内含 `18/36` 计 **2 个编号**（不是 1 个，也不是 2 行）；
2. **禁止**以两份清单的「标记处数」相减求差集——处数受行粒度与符号形态影响（一格多编号、一格一编号混排时必然得错数）；
3. **禁止**用「页数 × 行数」估算条目数；
4. 报告写「N 处 / M 行 / K 个编号」，只给单数视为不合格。

### 7.2 四条硬约束（v1.4 由三条扩为四条）

1. **监控子列只对理想生效**（§5.6 第 1 条）。
2. **身份字段不可互换**：UAES 用「物料名称 / 物料编号」，理想用「零件名称 / 零件号」，蔚来用「零件编号 / 零件名称」（§5.6 第 2 条）。
3. **产品编号前缀只对蔚来生效**（§5.6 第 3 条）。
4. **`S8` / `S9` 的生效范围不同（v1.5 按裁决 Q4 拆分，原「两项都只对 UAES」已废止）**：
   - **`S8` 只对 UAES 生效**——依据是**结构承载位有无**，且**两类证据强度不同**（v1.7）：`U12` 的「有」来自**本批实到件**（`U12` 无受控模板，00-A §4.4.1 登记「无」），**每批重判、不可迁移**；`L12` / `N04` 的「无」来自**模板本体**（模板均在库），跨批稳定。详见 §4.1 后「适用范围」表。**不得把 `S8` 的依据写成「UAES 客户要求标 `K`」——客户并未发布表单要求。**对理想 / 蔚来执行属**加严越界**；它们出现材料类特性（`K`）时记 **`S02`**，不产生级别、不进整改单，并在报告注明「该客户清单结构未设符号位，材料类特性按字段完整性判」。
   - **`S9` 三客户通用**——依据是 **IATF 16949 §8.3.3.3 + §8.5.1.1**（CP / PFD / PFMEA 须标同一批特性），属体系要求，不因客户规则原文有没有写「母表」二字而改变。三家均有 PFMEA + CP 对端，不存在「无对端所以不做」的障碍。**但必须保留「限 `W` 级、不判 `B05`」**——这是「体系要求但非准入条件」的正确表达。执行条件为**能力条件**（两侧均以编号列承载特性），任一侧无编号列 → `S02`。

### 7.3 预留位

新增客户时在本表加行，并同步在 00-A §1 / §2 登记。客户差异**只允许增删判定项、调整必填范围**，不得改本分则 §5 的通用细则。

## 10. 不要做

1. **不要跨客户套用判据**（§7.2）。
2. 不要要求 UAES / 蔚来提供理想的 8 个监控子列（§5.6 第 1 条）。
3. 不要因缺「物料名称」判理想 `B05`——理想的字段是「零件名称 / 零件号」（§5.6 第 2 条）。
4. 不要给理想 / UAES 记「无产品编号」的 `W03`（§5.6 第 3 条）。
5. 不要把 UAES 的「编号 / 序号」斜杠写法当成「两者都必须有」（§5.2）。
6. 不要判特性选得对不对、分类标得准不准、监控方法是否有效——那是 `S03`。
7. 不要判蔚来标题里的编号是否与本批次零件一致（§5.5 末段）。
8. 不要在理想多级表头未还原时判子列缺失（§5.3 第 3 项）。
9. 不要因 8 个子列「顺序与判据列举不同」判缺失——列序无关（§5.3 第 4 项）。
10. 不要把一行的多个空列记成多条 `W02`——一行只记一次（§5.4）。
11. **不要因缺 PFD（`T09`）记任何问题**——蔚来 PFD 依赖本类目，方向相反（§1 边界第 2 条）。**但 `S9` 所需的 CP / PFMEA 对端缺失不在此列**：对端不在可及证据集内时按 `W01` + `S04-S` 处置，**不阻断**（总纲 7.2 / 10.5）。
12. 不要在未锁定路由时开始判据（§6 第 2 步）。
13. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。
14. 不要在报告里出现「疑似」「可能」类未定级表述。
15. 不要新增章、调整章序或自定义报告字段。
16. 不要修改 `00-A §2.1 / §2.2 / §2.3` 的判据文本；判据有误应先改 00-A，再同步本分则。
17. **不要把 GD&T 公差框（`⌖`/`⌓`/`⊥`/`∥`）当特性分类符号**（§5.8 第 1 条，v1.4）。
18. **不要自行解释未收录符号**——`S02` + 冲突登记，**不得记 `S05`**，也不得按「看起来像」计入或不计入（§5.8 第 5 条）。
19. **不要用「标记处数相减」求差集，也不要用「页数 × 行数」估算条目数**——按 §5.9 用编号数（v1.4）。
20. **不要因 `S8` / `S9` 判 `B05`**——二者为总纲基础层判据落地，级别上限 `W`（§4.1 表后注，v1.4）。
21. **不要把 `K`（材料类）计入工序特殊特性**；也不要因 PFMEA 未建 `K` 的失效模式行而判问题（`PPAP-09` `R24`，v1.4）。
22. **不要对理想 / 蔚来执行 `S8`**——它们的**模板**清单结构里**没有符号列**（`L12` 10 列 + `T1` 八子列、`N04` 11 列，均无符号位；这是**模板事实**、可打开核对），没有承载位却要求标 `K` 等于要求增列，属**加严越界**（v1.5 · 裁决 Q4）。这两家出现材料类特性时记 `S02`，并在报告中注明「该客户清单结构未设符号位，材料类特性按字段完整性判」。
23. **不要因名称或限值含有害物质关键词（镉 / 铅 / 汞 / 六价铬 / PBB / PBDE / ROHS / REACH / ELV）就要求供应商新增 `K` 标识**——客户规则原文**没有**这项要求，供应商以文字写「有害物质：镉 ≤100PPM」完全合规。这一条在 v1.4 曾被我方写成要求，v1.5 已废止（裁决 Q4）。
24. **不要把 `S9` 的「过程特性」也判成母表漏标**——须先按 `PPAP-10` 分则 `M-15` 差集分级表第 5 档的**三支过滤**处理：可编号且规范值来自图纸 / 设计记录 → `W02`；**过程特性 → 不判**；来源不可判 → `S03`（v1.5 · 裁决 Q5）。
25. **不要对 `S9` 用名称强行配对**——执行条件是**能力条件**：两侧均以编号列承载特性时才执行；任一侧无编号列 → 记 `S02` 并说明缺哪个编号列（v1.5 · 裁决 Q4）。
26. **不要把 `S8` / `S9` 的项数算进 155**——155 是客户规则原文 `required_structure` 的抽取条数；`S8` / `S9` 属基础层判据，**独立计数、不计入 155**（总纲附录 A.2，v1.5 · 裁决 Q1）。

## 1. 目的与定位

### 1.1 目的

本 Skill 用于在正式规则审核之前，对本次提交的 07 过程能力研究待审文件集进行数据标准化预检，判断当前输入是否具备被后续规则审核的条件。

核心目的（通用目标见总纲第 1 节）：拦截因结构缺失、字段缺失、数据类型混乱、规格限逻辑错误、卷面数值自相矛盾、计算过程不可追溯而导致的后续审核结论错误或执行中断。

- 预检判为拦截时，必须打回整改，不得进入后续正式审核流程；仅有警告项时可通过，但警告须在报告中逐条列清。

本 Skill **只做检查、判定和报告**，不做修复、补全、格式转换，不做统计重算，不判断过程能力是否达标，不包含整改后复检流程。整改为线下人工操作，整改完成后重新无状态调用本 Skill。

### 1.2 运行前提：规则前置、文件后置

实际产品运行链路是两段式，**不是**在一次调用中同时提交规则与文件：

- **第一段（前置规则入口）**：过程能力研究相关规则在专门的规则入口定型，形成带版本号的规则项集合。
- **第二段（本 Skill 所在入口）**：某项目进入 PPAP 审核阶段时，只提交该项目下 07 过程能力研究的**全部或部分**待审文件。

**本 Skill 的触发时点固定在"提交动作完成之后"。** 调用发生时待审文件已提交完毕，"本次提交的文件集合"是既成事实的输入，不存在"尚未提交""提交中""清单待补"这类中间态。这一时点直接决定了下面第 3、4 条推论，也决定了本文件不存在"没有输入""输入为空"的判定分支。

由此产生七条必须遵守的推论：

1. **本 Skill 不评判规则描述文件本身的可执行性。** 该职责已在前置入口完成。本 Skill 只校验"本次提交的文件集能否被当前生效的规则版本判定"。
2. **提交范围可能是不完整的。** 可能只有部分特性、部分工序、部分供应商、部分阶段的研究报告。因此"该交未交"不能凭直觉判断，不能默认"没提交 = 不存在"。
3. **本 Skill 在"提交之后"运行，能看到的是"已交了哪些"，看不到"应该交哪些"。** 调用发生时文件已提交完毕，系统侧能提供的只有本次提交的文件枚举，无法声明"本批次应覆盖哪些特性/工序/供应商/阶段"。这是运行前提的直接推论，也是已确认的系统约束。因此本 Skill **无法区分"真缺项"与"本批次未提交"**。
4. **不存在"空提交"，也不存在"文件清单缺失"。** 调用前提是至少一份文件已完成提交，文件枚举由提交动作自动产生，恒等于本 Skill 的判定对象。因此"未收到文件清单""清单与实际文件不一致"这两类判定在本 Skill 中不成立——不是判警告，而是情形本身不存在。只有当提交物内部另带自述清单（清单文件、目录表、报告目录页）时，才存在可对账的对象，见 PRE-03a。
5. **由此产生的直接后果：所有"缺项"类判断一律降级为警告，不得判阻断。** 包括 PGQP1 缺失、其他关联文件缺失、自述清单对账差异、特性清单不闭合等（唯一例外是报告自身缺目录页，见 PRE-04a——它属文件内部结构缺陷，不依赖批次范围）。理由是：把范围裁剪误判为阻断，会让合规的部分提交被打回，代价高于放过一个可能存在的缺项。报告中必须显式声明这一局限。
6. **同一项目可能多次、分批提交。** 本 Skill 只对本次提交的文件集独立判定，不与历史批次比对，不做批次间进度累积。
7. **结论作用域仅限本次提交的文件集。** 不得表述为"该项目过程能力研究整体合格/不合格"，也不得表述为"该供应商能力不足"（后者属正式审核）。

### 1.3 与正式审核的分界（最重要的一条）

| 维度 | 本 Skill（预检） | 正式审核 |
| --- | --- | --- |
| 回答的问题 | 这份文件集**能不能被审** | 过程能力**是否合格** |
| 对能力值 Cpk/Ppk | 只看：是否填了、是否为合法数值、是否与结论栏自洽、是否来自可追溯的计算 | 看：是否 > 1.33 / > 1.67，是否按特性等级分档 |
| 对原始测量数据 | 只看：类型、格式、样本量是否达最低门槛、时间序列是否可信 | 从原始数据**独立重算**全套统计量，与卷面值对撞 |
| 对控制图 | 只看：图型与子组容量是否匹配、常数是否被篡改、是否配有短期能力区块 | 基于原始数据重算控制限，跑八大判异准则 |
| 对分布 | 不判 | 做正态性检验、偏度峰度、Box-Cox 判断 |
| 典型输出 | 拦截判定、阻断项、警告项、处置方向 | 合格/不合格、逐特性明细、造假嫌疑证据 |

**一句话口径：预检判"输入是否可用"，审核判"数值是否合格"。任何"是否达到 1.33 / 1.67"的判断都不在本文档范围内。**

## 2. 范围与非目标

### 2.1 范围内

- 接收本次提交的待审文件集（文件枚举由提交动作自动产生，无需用户另行提供清单）。
- 确认文件集的可解析性、载体归属、版本与有效性。
- 以整个文件集为标准化对象，进行结构完整性、数据正确性、数据一致性、数据可追溯性检查。
- 自主推断跨文件、跨表格、字段间可能关联项（零件号、特性清单、公差）。
- 输出 Markdown 预检报告。
- 区分"数据不规范"和"文件无法解析"。
- 给出文件级、规则项级结论及总体结论。

### 2.2 非目标

- 不负责 OCR、表格抽取、文档解析等底层实现。
- 不规定必须使用何种解析工具或技术路线。
- 不重算 Cp / Cpk / Pp / Ppk 等统计量。
- 不运行控制图判异准则，不做正态性检验。
- 不判断过程能力是否达标，不比较 1.33 / 1.67 等能力阈值。
- 不判断本次提交阶段与 PPAP 流程阶段是否匹配（属业务审核）。

> 唯一需要说明的例外：PRE-13c 的样本量门槛（≥100 读数 / ≥30 单值点）不是能力阈值，判的是"输入是否充分"，不构成能力达标判定。
- 不修复、不补全、不转换原始文件，不提供一键修正。
- 不执行整改后的复检流程。
- 不进入正式业务规则合规审核。
- 不输出程序可直接消费的 JSON Schema。
- 不依赖特定模型、特定平台或特定 Agent 框架。

### 2.3 判定手段不作规定

本文档中的规则只描述**判定什么**，不描述**用什么手段判定**。使用何种解析能力、是否启用 OCR、是否读取文件内部结构，由执行环境决定。唯一硬性要求是：若无法获得可判定证据，必须记录为"文件无法解析"类问题，不得跳过检查、不得推断放行。

### 3.1 状态词：四个必须区分的概念

**「不适用」一词禁用**，必须按总纲 3.1 拆分为四种之一。四者是**状态**，不是级别，不参与通过判定。

| 状态 | 代码 | 本域形态 |
| --- | --- | --- |
| 范围外 | `S01` | 该规则**对本载体无判定对象**（如纯表格载体无目录页、无自述清单时无需对账）；提交物中含不属本类的文件（已剔除）。**判据与「交没交」无关** |
| 对端未到 | `S04` | 该对象属本次范围、**在可及证据集内不存在**（`SRC-1` ∪ `SRC-2`，总纲 3.2.1；如 `PGQP1` 表、同批 SPC 原始数据）。**分两子型**：`src=SUB`（SPC 原始数据、PGQP1 填报件）→ `W01` + **`S04-S`**；`src=CUS`（客户图纸、规范、客户台账）→ 仅 **`S04-C`**、**不配 `W01`** |
| 规则不适配 | `S02` | 规则侧成因导致某项在本域无判定依据（如子组容量超出常数表覆盖范围 n=1–25、当前规则版本无对应判定项） |
| 移交 | `S03` | 能力值是否达标、过程是否受控、抽样方案是否满足统计有效性、造假嫌疑——均属正式审核或全量深审 |

**关键区分：**

- 「范围外」≠「文件不含该对象」。前者是该对象本就不属本次范围、或本载体本不承载该对象，后者是交了但表单里没有这个栏位（→ 按结构缺失记阻断）。
- **「本批没交」不再等于「范围外」**：属本次范围而应收未到记 `S04`（对端未到，配套 `W01`），`S01` 只留给「本就不属本次范围」（总纲 3.1）。
- **`S04` 分两子型，判前必先核「可及证据集」（总纲 3.2，v0.7 新增）**：对端在 `SRC-1`（提交件）或 `SRC-2`（受控提供源：客户图纸、技术规范、客户表单模板、客户侧台账）内**已存在**的 → **正常比对，绝不记 `S04`**。集内确实没有时按 `src` 落码：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取）→ 仅 **`S04-C`**、**禁配 `W01`**、不进缺件数、进报告七章 7.2b。`src` 一律查《PPAP-00-A》**§4.3 对端来源登记表**，查不到记 `S02` 并报缺口，**不得现场推定**。**本分则全文凡记 `S04` 之处，一律按本子型标注。**
- **`S05`（受控模板缺结构）继承总纲**：本分则凡判 `B05` 之处，须先按总纲 **3.1 三分界**与 **5.2 两问**确认成因——查《PPAP-00-A》**§4.4 客户受控模板登记表**：该（客户 × 类型）登记**有**受控模板、且**模板本体也没有该列** → 记 **`S05`**（状态，**不阻断**、不配 `B`/`W` 码、不进缺件数、进报告七章 **7.2c**）；登记**无**（不限定表单格式）或**模板有而文件没有** → 仍记 `B05`。**本分则的 3.1 状态词表不列 `S05`**——它的定义、边界与取证要求只在总纲 3.1 / 3.3 / 5.2 维护，避免同一概念在多处分别表述。**`B`/`W` 原因码取值与判定严格程度逐字未改。**　**枚举优先级**：本分则凡用列举方式写状态码的地方——**判定结果取值、状态登记清单、六章装填白名单、「必须按 3.1 拆为…」之类的执行要求**——`S05` **都在其列**（分「已核对」/「待核」两种形态）。**若某处枚举文本仍只列到 `S04-C`，以本条为准**，不得因该处漏列而拒绝登记 `S05`。理由：v0.9 把 `S05` 加进总纲 3.1 之后，各分则的枚举没有同步扩，若按枚举字面执行，`S05` 会**有判据、无落点**——判出来了却装不进状态登记清单，等于这一档不存在。
- 「证据不足」不是状态，是**定级结果**：读不到按 `B01`，可另行确认按 `W05`，规则侧无判定依据按 `S02`。不得用「证据不足」代替定级。

## 4. 输入契约

### 4.1 必选输入

#### 4.1.1 待审文件集

- 本次提交的 07 过程能力研究相关文件。
- **提交走统一入口，不区分提交角色**（供应商、采购侧或其他方提交的文件在同一入口进入本 Skill），因此本 Skill 不按角色区分定级，也不因某类文件"通常不由某方提供"而调整判定。
- 文件类型不固定，随顾客与供应商变化，可含表格、PDF 报告、图文混排件、扫描件。
- 可含多个载体族并存，也可只含单族。
- **允许不完整**：可以是某项目下 07 类文件的全部，也可只是一部分（部分特性、部分工序、部分供应商）。

#### 4.1.2 文件枚举（由提交动作产生）

- 本次提交的文件名称列表由提交动作自动产生，本 Skill 直接采信，**不需要用户另行提供"文件清单"**。
- 因此下列两种情形在逻辑上不成立，不得作为判定依据、也不得作为降级理由：
  - **"文件清单缺失"**：调用发生在提交之后，文件枚举必然存在。
  - **"清单与实际文件不一致"**：二者恒为同一集合，不存在对账空间。
- 提交物内部可能另带一份自述清单（清单文件、目录表、报告目录页）。它才是 PRE-03a 的对账对象——对的是"它自己声明的文件"与"实际提交的文件"，而不是"应交文件"与"实交文件"。
- **不索取、也不假设覆盖范围声明。** 提交动作只确定"交了哪些"，不承载"应有哪些"；本 Skill 不得要求、也不得假设系统侧能提供后者。
- 清单格式当前不限定。

### 4.2 可选输入

- 项目上下文：零件号、零件名称、项目号、顾客名、PPAP 提交等级与阶段。
- 同批次关联文件：控制计划、特殊特性清单、采购件质量计划（含 PGQP1 表）。
- 数据标准字典或字段值域说明。
- 领域知识参考材料。

**目录页不作为可选输入**——它是报告自身应具备的结构要素（PRE-04a），其缺失由报告本身判定，不因外部未提供而免责。

**同批次关联文件缺席时，不得记「证据不足」**——必须按 PRE-04b / PRE-04d 判"本批次未识别到"并记 `W01` 警告。它虽然列在可选输入中（因为它可能确实不在本批次范围内），但"未收到"不等于"无法判断"，二者结论不同：前者是确定的观察，后者是能力不足。把关联文件缺席写成"证据不足"，会让本 Skill 在最有提醒价值的位置上失声。

可选输入为空时，仅**依赖该输入才能判定**的规则记 `W05`（可另行确认）或 `B01`（无替代）并注明依据不足，不默认放行。不依赖可选输入、可由文件本身判定的规则照常执行，不得因输入缺失而跳过。

### 4.3 不作为输入的内容

- **规则描述文件**：规则已在前置入口定型，本预检不接收、不评判规则本身，**也不校核规则集可用性与版本匹配**（总纲 2.3）。
- **规则版本协商**：不属本预检范围。预检只按本文件已固化的规则执行，不作版本比对。

### 4.4 解析责任边界

- OCR、表格抽取、图文理解、文档解析由外部业务系统或模型层负责。
- 本 Skill 不规定是否使用 OCR、如何抽取表格、如何解析图文。
- 本 Skill 基于可访问的文件内容、解析结果或模型多模态理解能力进行判断。
- 若无法获得可判定证据，记录为"文件无法解析"类问题（`B01`），不得跳过。
- **能力前提**：执行方不具备读取压缩包 / 图像 / 公式单元格的能力时，相关规则在报告"未进行的检查"栏声明，标「未执行」，**不记级别、不判提交方责任**——能力不足不是文件缺陷。

### 5.3 逐条判定细则

#### PRE-01 输入物形态门禁

**适用载体**：全族 · **级别**：阻断（d 为警告）

判定内容，命中 a/b/c 任一即阻断，不进入内容预检：

- a）提交物为压缩包格式（.zip / .rar / .7z / .tar / 分卷包），无论其内部文件是否合规。压缩包一律要求用户解压后以原始文件重新提交。
- b）提交物为加密文件，无法在无口令条件下读取。
- c）提交物损坏、无法打开、无有效内容页。
- d）**警告**：提交物中含不属于 07 过程能力研究范畴的文件（如误提交的其他类 PPAP 文件）。该类文件在报告第二章标注"不参与判定"并排除出后续规则，同时提示核对提交入口。**排除单份非本类文件不阻断整批**——其余 07 文件仍可判定，因一份误提交文件把整批打回，会让可审内容被无关文件拖累。
- e）**阻断**：本批次全部文件均不属 07 过程能力研究范畴，无任何可判定对象。

**说明**：压缩包拦截不因"内部看起来有正确文件"而豁免。一次调用只处理一种形态，避免范围不可控。

**与 PRE-02 的分工**：本项判"文件能不能被打开/是不是本类文件"（容器与形态层面）；文件能打开但内部关键数值读不出，归 PRE-02。同一份文件不因两处都涉及"读不到"而重复计数——能打开则走 PRE-02，打不开则走本项。

**整改方向**：解压后提交原始文件；取消加密；重新导出或重新获取文件；剔除误提交的非本类文件并核对提交入口。

#### PRE-02 判定证据可获得性

**适用载体**：全族 · **级别**：阻断

判定内容，逐文件确认承载判定依据的内容是否可读取：

- a）文档是否存在可读文本层。纯图片扫描件、拍照件、无文本层的导出件，若关键数值不可读，判不可解析。
- b）表格数据区是否可读取。以图片截图粘贴进单元格、以图表图片替代数值的，判证据不可获得。
- c）关键结论单元格是否存在可读的最终计算结果（仅存计算式而预览显示为空、为 0、为占位符号的，判不可获得）。
- d）数值是否仅以图形呈现。只提供控制图曲线、直方图、趋势图而不提供对应数值的，视为该项证据缺失。
- e）文件是否部分可读。可读部分照常判定，不可读部分逐项记录，不得因"大部分可读"而放过关键数值不可读。

**说明**：任何因不可读导致的「证据不足」，按本项阻断级计入（`B01`），构成不通过，并标注需人工复核。不得以"内容可能正确"推断通过。

**整改方向**：提交可解析版本（原始表格文件、带文本层的 PDF、可读的扫描件）；对仅以图形呈现的结论补充数值。

#### PRE-03 自述清单对账与载体归属

**适用载体**：全族 · **级别**：阻断 / 警告

判定内容：

- a）**警告**（**仅当提交物内部含自述清单时判定**）：自述清单对账。对账对象是"提交物自己声明的文件"与"实际提交的文件"，**不是**"应交文件"与"实交文件"。三类差异逐项记录：
  - 自述清单列了、实际未提交 → 表述为"本批次未提交该文件"，不得表述为"缺项"。
  - 实际有、自述清单未列 → 清单未更新。
  - 文件名与清单名称不一致（含版本后缀差异）。
  - 三类均判警告：无法排除"分批提交"或"范围裁剪"，且自述清单本身可能是跨批次沿用的模板。
  - **定级固定为警告，业务已确认（见 §14.1 第 16 条）。** "自述清单列了、实际未提交"同样只判警告，不升为阻断。理由有二：其一，预检对**已提交**的全部文件仍能完成完整判定，缺的那一份不改变"能不能审"；其二，自述清单常为跨批次沿用的模板，其列示不等于本批次的提交承诺，据此阻断会把模板滞后当成提交缺陷。本子项级别不可配置，不随载体族、清单措辞（如"应提交""必须提交"）或缺陷条数上调。
  - **无自述清单时本子项记 `S01`**：本批无对账对象。不得记「证据不足」（并非证据不足），不得记警告，更不得判"缺少文件清单"——文件枚举由提交动作产生，本就存在（见 §1.2 推论 4）。
- b）**阻断**：载体归属。每份文件能否归入四族之一（族1–族4）或明确的关联文件（目录页、PGQP1、特殊特性清单）。无法归属则后续规则无法确定适用子集，判阻断并说明归属失败原因。
- c）**阻断**：文件有效性。文件是否为有效填报件。空白模板、仅有表头无数据、整表为示例值（如全部数值相同、循环重复的演示数据）、标注"草稿/待填/DEMO/示例"字样的，判无效填报件。
- d）**警告**：重复提交。存在同一内容的多个副本（字节相同，或内容高度雷同仅文件名/版本号不同）。记录为"疑似重复提交"，要求用户确认以哪一份为审核对象；未确认前不得自行择一。**两副本均参与判定**，但由副本导致的同一缺陷仍只计一次，报告中并列记录并标注"需确认唯一审核对象"。

**说明**：b、c 与提交范围无关，可独立判定，故仍为阻断；a、d 与提交范围相关，按 §1.2 推论 5 降级为警告。**本项不承担"范围核对"职责**——提交动作不承载"应有哪些文件"，任何"该交未交"都不属预检能判的范围（见 §1.2 推论 3）。

**整改方向**：更新自述清单使其与实际提交一致，或补齐清单所列文件并统一命名；明确载体族；提交实测填报件替代表板；剔除重复副本并确认唯一对象。

#### PRE-04 同批次关联文件齐备

**适用载体**：全族（其中目录页仅适用具备报告外壳的载体） · **级别**：阻断 / 警告

判定内容。因提交动作不承载"应含清单"，本项**对关联文件缺失一律判警告**，不判阻断；**唯一例外是 a）目录页**：

- a）**阻断**：报告类载体的目录页存在性（适用于族3、族4，以及嵌有报告外壳的族1/族2）。是否存在可定位的目录页，接受三种形态——独立"目录"工作表、报告首页信息表、PDF 页码或区块索引页。
  - 判阻断而非警告的理由：目录页是**报告文件自身的结构组成部分**，不是跨文件的外部依赖，可独立判定，不受批次范围影响。一份报告没有目录页，就是这份报告结构不完整。
  - **本项无警告例外，不因"单特性独立页""页数少""内容简单"降级。** 报告形态一旦成立，目录页即为结构必需项。
  - **单区块报告的等效形态**：载体只有一个可导航区块（单页单表）时，以"首页信息表"（表头承载文件名、零件号、版本、日期、页码或区块索引）作为目录页的等效形态。等效形态仍不存在的，判阻断，不得记 `S01`。
  - **无报告外壳的载体记 `S01`**：单独提交的计划表、CCSC 清单、控制图工作表等纯表格，不承载目录页这一结构要素，本子项记 `S01` 范围外，不记问题、不记不满足。区分依据见 §3"报告外壳"定义——具备封面、报告编号、签署栏等报告特征，且由多个可导航区块组成。
- b）**警告**：采购件质量计划（PGQP1）存在性。PGQP1 是"采购件质量计划"文档中的一张表，属本批次同批提交的文件类型，**可要求提交方提供**。若在本次提交文件中未识别到 PGQP1 表，判警告，并明确列出**三种情形之一**（此处「情形」不是状态码，勿与 `S0x` 混用）：未找到采购件质量计划文档 / 找到文档但未含 PGQP1 表 / 找到 PGQP1 表但零件号不符。
  - **全族无条件适用，不得记 `S01`**：PGQP1 属本批次可提交的文件类型，与本批次涉及的是自制件还是采购件无关。不得以"本批次无采购件""纯自制件批次无对应对象"为由跳过本项——跳过即等于放弃一次提醒提交方补充的机会。
  - 判警告而非阻断的理由：本 Skill 无法排除"该文档属本批次未提交的范围裁剪"（提交动作不承载应含清单）；且该文件可通过向提交方要求补充而闭环，属**可补齐型提醒**，不需要阻断整批审核。
  - **报告中必须同时给出补充提醒**，不得只在警告清单里留一行了事：须明确写出"本批次未识别到采购件质量计划文档（含 PGQP1 表），请提交方确认并补充；若确不属本批次范围，请审核方确认豁免"。提醒位置见报告 10.5（专属缺失清单）与 7.2（提交方补正）。
  - 提交方补充后该警告消除；审核方确认不属本批次范围的，标注"可豁免"并不计入整改。
  - **对结论的影响须如实体现**：本项是警告，**不构成拦截**，本批次可正常通过并进入后续流程。该警告的作用是提醒提交方补充该文件、并让审核方知悉覆盖比对将缺基准，而非指责文件质量。因此报告中该条目的处置措辞统一为"待补充提交"。
- c）**零件号一致性不重复设条**：关联文件与本批次能力报告的零件号不一致，统一由 PRE-16a 判定为阻断，本项不另计，避免同一缺陷重复计两个阻断项。
- d）**报告要求（非判定项）**：报告中须显式列出"本批次未识别到的关联文件"清单，提示审核方确认是否漏交。**不得表述为"缺项"**，应表述为"本批次未识别到"。

**说明**：本项是"部分提交 + 提交动作不承载应含清单"背景下最容易误判的一条。判定用语必须严格区分"未识别到"（本 Skill 的观察）与"缺项"（需要范围声明才能下的结论）。目录页之所以例外，是因为它不回答"该交的文件交了没有"，只回答"这份报告自身是否完整"。

**整改方向**：补齐目录页或首页信息表；补充采购件质量计划文档及其中 PGQP1 表；统一零件号；若确实不在本批次范围，无需整改，但建议在提交说明中注明。

#### PRE-05 能力判定主表存在

**适用载体**：全族 · **级别**：阻断

判定内容，按载体族确认主表存在且可定位：

- a）族1：存在表名含"过程能力研究计划"（含"初始过程能力研究计划"）的表格，且含"过程阶段"列。
- b）族2：存在表名含"产品过程CCSC特性管理清单"（或同义命名）的表格，且含"P阶段Cpk结果"列。
- c）族3：存在能力值汇总清单，即逐特性具备"目标值 / 结果值 / 判断"三要素的清单表。**任务台账式的"过程能力分析总表"不算**——它只有任务项与责任人，没有逐特性目标值与结果值。
- d）族4：存在单特性能力报告页，含规格限、样本信息、能力指数三个区块。
- e）主表存在但表名被改写、跨多页拆分、被图片化，导致无法稳定定位的，判"载体不可定位"，按阻断处理并说明定位失败点。

**整改方向**：按标准模板提供主表；恢复表名与列名；避免整表图片化。

#### PRE-06 判定所需字段齐备

**适用载体**：全族 · **级别**：阻断（`a)`~`f)`） / 警告（`g)`，v2.9 新增）

判定内容，逐载体核对必需字段是否存在。缺失任一必需字段即阻断，并附缺失字段清单：

- a）族1 计划表：PPK目标值、PPK实际值、CPK目标值、CPK实际值 四列同时存在。另需过程阶段列、特性名称列、规格列。
- b）族2 CCSC 清单：P阶段Cpk结果、P阶段结果判定 两列同时存在。另需特性名称列。
- c）族2 控制图：每张图须有短期过程能力区块，区块内至少含 Cpk。**同区块内若印出了 Cp / Pp / Ppk 中的任一字段，则该组字段须齐备**，不得只印其一；区块内完全未印 Ppk 的，不因"缺 Ppk"判缺失（Ppk 是否为必需由正式审核按规则版本判定）。
- d）族3 汇总清单：逐行须有 目标(CPK)、结果(CPK)、判断、反应计划或备注 四类列。
- e）族3 / 族4 报告页：规格上限与下限（单边公差为唯一界限）、子组容量、子组数（或总读数）、Cpk、Ppk。
- f）跨表关联字段：零件号、特性名称（或特性编号）必须存在于主表，否则无法做一致性判定（见 PRE-16）。**本项按缺陷形态分两个码**：
  - **字段在文件中根本不存在**（无零件号列、无特性名称列）→ 记 **`B05`**（结构不承载该判定），整改方向「补齐缺失字段」。
  - **字段存在、但取不到唯一值**（同名同规格多页多读数、同一特性编号对应多行主体、只能靠页序区分）→ 按总纲 **10.4 `K1`** 记 **`B03`**（对象身份不可归属），整改方向「**提供唯一标识或明确页序映射**」。
    - **「只能靠页序区分」的准确定义**：仅指**簿内无任何页序登记**（总纲 10.4.1 `R-0`）——即除了打印顺序、肉眼翻页之外，没有任何可复核的页序凭据。若簿内有合法页序登记表（`R-1`）、或页签名承载语义标识（`R-2`）、或数据区有可唯一区分列（`R-3`），**本情形不成立，不得记 `B03`**；此时若 `R-2` / `R-3` 不成立，跨文件比对项按总纲 10.4 硬约束 3 记 `S02`（详见 5.6）。**`R-1` 即达要求，`R-2` / `R-3` 不要求达到、不设判定项、不核「页 ↔ 腔」对应**（总纲 10.4.1 边界 5、本文件 5.6.3）。
- **g）警告**：工具信息区**有栏无值**——模板自带栏位（如 `Tool number` 模具号、`# Cavities` 型腔数）**栏存在但值为空**，记 **`W02`**。
  - **与 `a)`~`f)` 的分界**：`a)`~`f)` 判「栏在不在」（栏不在 → `B05`）；`g)` 判「栏里有没有值」。**有栏无值不得记 `B05`**——结构是承载的，缺的是填写。
  - **与 `PRE-07` 的分界**：`PRE-07` 判**逐条目行**必填列留空（记 `B04`）；`g)` 只管**工具信息区**（表头 / 工艺信息 / 模具信息这类非条目区块）。两处不同区域，同一处空值只记一次。
  - **计数粒度：按（栏位 × 文件）计，不按页计。** `Tool number` 在 29 页上全空，记 **1 条**，记录里写「空值页：全部 29 页」；不得写成 29 条。理由：这是**全簿统一缺失**，逐页重复记录不产生新信息，只会让警告数虚高、把真问题埋掉。只有「部分页有值、部分页空」时才按页列出差异页。
  - **为什么单列而不并入 `PRE-07`**：`# Cavities` 空着，正是「多模腔文件无法把页归到腔」的物理原因——腔数不填，`255#卡口厚度` 的 6 页到底是 6 个腔还是 6 个测点，文件自己没说。**该项只到警告级**：它不使文件不可判定（页序映射仍可用），但必须随报告移交，否则正式审核看不到这一层。
  > **为什么必须拆**：v2.6 把整条映射为 `B05`，但 `B05` 的整改话术是「请补这一列」——而键不唯一的文件**这一列本来就是有的**，补不了。照原文发整改单，供应商收到的是「补齐缺失字段」，实际要做的是「给每一页一个可唯一识别的键」，两件事。**级别不变（两者都是阻断），结论不变，变的只是码与整改方向。**

**说明（同义字段识别取宽口径）**：字段按**语义**识别，可视为同义的情形包括：

- 同义命名：`Cpk` / `CPK` / `Cpk值` / `Cpk 实测值` / `结果(CPK)` / `工程能力指数`；
- 全角与半角、大小写差异：`ＣＰＫ` / `cpk` / `Cpk`；
- 中英文混用：`Number of readings` / `读数次数`；
- 前后缀差异：`目标值(PPK)` / `PPK目标值` / `PPK 目标`；
- 跨两行合并表头：`目标` + `(CPK)` 两行拼接后视为 `目标(CPK)`；
- 标点与空格差异：`P阶段Cpk结果` / `P 阶段 Cpk 结果` / `P阶段CPK结果`。

**唯一例外**：同一列名在同一张表内出现多次且指向不同语义区块（如多个阶段区块复用相似列名，见正式规则集 §3.4 记录的模板缺陷）时，记录为"字段定位歧义"，要求提交方明确区块边界。这属于表格设计缺陷，不是同义字段问题。

**整改方向**：补齐缺失字段；消除同名列的区块歧义。

#### PRE-07 逐条目行完整性

**适用载体**：全族（族4 仅适用 d 项） · **级别**：阻断

判定内容：

- a）计划表："过程阶段"列有值的行，除"备注"外各必填列不得为空。必填列白名单见 §13 可配置项；白名单外的列不判。
  - **"实际值"类列（PPK实际值、CPK实际值）不得为空，无论文件处于计划阶段还是执行阶段。** 空即判不符合，不因"文件还是纯计划表""研究尚未执行"降级。理由是：07 过程能力研究进入 PPAP 审核入口时，研究应已完成，实际值为空即说明该特性的能力研究尚未形成结论，不具备被审核的条件。
- b）CCSC 清单：P 阶段区块中已填写特性名称的行，其 Cpk 结果与结果判定不得为空。
- c）汇总清单：逐特性行必须有目标值、结果值、判断三项，不得跳行留空。
- d）报告页：区块内已开始填写但中途留空（如填了子组容量与子组数，Cpk 栏空着；填了规格限，样本栏空着）。**三区块整体缺失归 PRE-05d（区块不存在）与 PRE-06e（字段不存在），本项只管"部分填了、部分空着"。**
- e）仅"备注"列非空的行不计为有效行，不参与完整性判定（防止以备注行占位）。

**说明**：本项只判"该填的空了"，不判"填的值对不对"。空值与"NA"的区别见 PRE-09。**规格限单元格本身的缺失或错误归 PRE-11，不在本项重复计数**；本项只管"规格要求这一列/这一栏有没有填"。

**报告页三层分工（避免一错三计）**：PRE-05d 判"三个区块是否存在"→ PRE-06e 判"区块内必需字段是否齐备"→ 本项 d 判"已填区块内是否留空"。三者按"区块 → 字段 → 单元格"逐层细化，同一处缺陷只在最贴切的一层记录一次。

**整改方向**：补齐对应行的空缺内容；若该行本不适用，请在备注中说明并统一标注为 NA。

#### PRE-08 控制图组套齐备

**适用载体**：族2；族3 / 族4 中若含控制图，同样适用 · **级别**：阻断

判定内容：

- a）本应提供的控制图类型是否齐备。按过程中实际使用的子组容量判断应提供哪几类（n=1 对应 I-MR；2≤n≤8 对应 Xbar-R；n≥9 对应 Xbar-S），本应提供的类型缺失即判不齐备。
- b）每张控制图是否同时具备"控制图本体（中心线、控制限、数据点序列）"与"短期过程能力区块"两部分。只有图无能力区块、或只有能力数值无图，均判不齐备。
- c）控制图标题、纵轴标签、图例是否可辨识所属图型。标题缺失导致无法确认图型的，判不齐备。

**说明**：本项只判"齐不齐"，不判"图上点有没有出界"（后者属正式审核）。子组容量与控制图类型的匹配判定见 PRE-13。

**整改方向**：补齐缺失图型；为每张图补充短期过程能力区块。

#### PRE-09 占位符与错误值残留

**适用载体**：全族 · **级别**：阻断 / 警告

判定内容：

- a）**阻断**：能力指数、均值、极差、标准差、控制限等关键结论位置出现错误值符号：`#DIV/0!`、`#VALUE!`、`#NUM!`、`#REF!`、`#NAME?`、`#N/A`。
- b）**警告**：存在显示溢出占位符（`#####`）。该现象可能仅因列宽不足导致真实数据被截断显示，不足以证明数据错误，但必须消除后才能确认数值。
- c）**阻断**：保留模板占位符（`XX`、`--`、`待填`、`TBD`、`?`、`＊`）。**空白单元格不属本项**，归 PRE-07 行完整性判定，避免同一缺陷被两条规则重复计。
- d）**阻断**：存在未完成的痕迹标记，如"待补""待确认"批注、明显的待办高亮底纹，说明文件尚未定稿。
- e）**警告**：不适用标注不规范。规则明确允许"不适用"的位置应统一写作 `NA`；写成 `N/A`、`n/a`、`－`、`/`、`无` 的判格式不规范，要求统一。
- f）**阻断**：以无穷大符号 `∞`、或明显非能力值语义的符号（如 `√`、`≈`）出现在应填能力值或判定结论的位置。

**说明**：须区分两类易混符号——`#N/A` 是电子表格的错误值（计算结果失效），属 a）判阻断；`NA` 是文本标注（规则允许的不适用），属合法值，不受本项约束。`NA` 白名单之外的任何写法（含 `∞`、`/`）都不得代替"不适用"。`NA` 白名单范围见 §13 可配置项。

**整改方向**：修复导致错误值的计算或数据源；调整列宽确认数值；将占位符替换为实际值（空白单元格归 PRE-07 整改）；对确属不适用的位置统一写 NA。

#### PRE-10 数据类型与符号规范

**适用载体**：全族 · **级别**：阻断

判定内容：

- a）计量型数据区混入非数值字符：中文标点（如 `12。34`）、中文数字、不可见字符、零宽字符、全角数字与全角符号。
- b）存在文本型数字：视觉上是数字但不可参与计算（含以文本格式存储的数值、前置单引号、前后空格）。
- c）计量型数据区混入判定词或描述性文字：`OK`、`NG`、`合格`、`不合格`、`Pass`、`Fail`、单位混写（`10.02mm` 写在数值格内）。
- d）数值表达与字段语义不符：如"读数次数"填 `≥1.67`、"Cpk"填 `1.33组数据`、日期列填纯数字、规格列填计算式。
- e）数值与单位分离不当：数值与单位同格导致无法取值，或同一列内单位不一致（既有 mm 又有 cm 未标注）。

**说明**：本项只判"能不能被当作数值使用"，不判数值大小是否合理（合理性见 PRE-11、PRE-12）。

**整改方向**：统一为半角数值；拆分数值与单位；将判定词移至独立的判定列。

#### PRE-11 规格限与公差逻辑

**适用载体**：全族 · **级别**：阻断

判定内容：

- a）**代数倒挂**：LSL ≥ USL；名义值 > USL；名义值 < LSL；公差带宽度 ≤ 0。
- b）**算术错**：表头标注的公差与填写的规格限不符。如标注 `10.0 ± 0.2`，USL/LSL 却填 `10.02 / 9.98`（小数点错位）；或 USL − LSL 与标注公差带宽度不一致。
- c）**单边公差误填为双边**：特性名称属形位公差或单侧限定的（平面度、同轴度、位置度、垂直度、平行度、跳动、圆度、圆柱度、轮廓度、拉拔力≥、硬度≥ 等），却同时填了 LSL=0 且输出了下限能力指数（Cpl / Ppl）。
- d）**规格与特性语义矛盾**：规格限与特性名称所指的物理量明显不匹配，如"孔径"规格写成 `0 ~ 0.05`、"平面度"写成 `±0.5`。
- e）**规格缺失**：有实测数据与能力值，但规格限为空或全部为占位符。

**说明**：本项是预检中影响面最大的规则——规格限错误会使全部能力值失真，后续审核即使重算也建立在错误基准上，因此不待审核阶段处理。单边公差误填 LSL=0 的判定只依据"特性语义 + 是否同时输出下限能力指数"，不重算能力值。

**整改方向**：按图纸更正规格限；单边公差按单边模型处理，删除无效的下限能力值；补齐缺失规格。

#### PRE-12 卷面指标自洽性

**适用载体**：全族 · **级别**：阻断

判定内容。**只审卷面已印出的数值之间是否自相矛盾，不重算原始测量数据，不引用任何外部阈值作比较**：

- a）**数学悖论**：Cpk > Cp；Ppk > Pp。按定义能力指数不可能大于潜在能力指数。
- b）**极值与结论矛盾**：卷面极值已越界（卷面最大值 > USL 或最小值 < LSL，说明样本中已出现超差件），判定栏却填"合格""达标""能力足够"。
- c）**数值与卷面自带标准矛盾**：报告自身印出了判定标准（如表头、图例、判定说明中写着"≥1.33 合格"），而对应数值低于该自印标准，判定栏却勾选"合格"；或判定列填"达标"，而对应结果值为空、为 NA、为错误值符号。**判定基准只能取文件自身印出的标准，不得引用本文档之外的阈值。**
- d）**同源指标矛盾**：Cp 与 Cpk 在卷面均值与规格中心重合时仍不相等；同一单元格组内 Cp 与 Cpk 的计算基准（规格限、标准差）与卷面其他区块标注不一致。
- e）**区间指标矛盾**：控制限区间与中心线不自洽（如 UCL 与 LCL 相对中心线不对称，而该图型本应严格对称）。

**边界声明**：本项**不判断**"卷面值 1.33 是否满足 > 1.33 的准入"、"Ppk 1.21 是否合格"——凡是判定基准来自规则而非文件自身印出的，一律不属本项。本项只判断"卷面内部逻辑是否成立"。

**与其他规则的分工**：明细页与汇总清单之间的数值不一致归 PRE-16f；控制图常数取值归 PRE-13b。本项不重复判定。

**整改方向**：重新计算并统一卷面数值与结论栏；若结论栏为人工勾选，需与实际数值核对后重填。

#### PRE-13 控制图元数据合规

**适用载体**：全族（a、b、e 仅族2/族3/族4；c、d 全族） · **级别**：阻断 / 警告

判定内容：

- a）**警告**：控制图类型与子组容量不匹配。n=1 应用 I-MR；2≤n≤8 应用 Xbar-R；n≥9 应用 Xbar-S。错配时记录，要求确认是否图型选错。**若同一处错配已按 PRE-08a 判"应提供的图型缺失"，本项不再重复计**——PRE-08a 判"缺了哪类图"（阻断），本项判"选错了哪类图"（警告），二者只取其一，取"缺图"。
- b）**阻断**：控制图常数与标准值不符。按子组容量与控制图类型核对对应常数：
  - I-MR（n=1）：`E2=2.66`、`d2=1.128`、`D4=3.267`、`D3=0`；
  - Xbar-R（2≤n≤8）：`A2`、`D3`、`D4`、`d2`，如 n=5 时 `A2=0.577`、`D3=0`、`D4=2.114`、`d2=2.326`；
  - Xbar-S（n≥9，含 n≥11）：`A3`、`B3`、`B4`、`c4`，须核对到实际子组容量所在行，不得沿用相邻行或 Xbar-R 的常数。
  - **比对范围覆盖 n=1 至 n=25（含 n=11 以上）**，常数表按 AIAG SPC 手册；子组容量超过表中范围时不判本项，记 `S02` 规则不适配并注明超出常数表覆盖范围。
  - 卷面常数被改写（如 d2 写成 3.326、3.15）会直接压低或抬高组内标准差估计，属预检必须拦截的输入缺陷。
- c）**警告**：样本量未达最低门槛。计量型有效读数总数应 ≥ 100（常规 25 组 × 5 件 = 125）；单值-移动极差法应 ≥ 30 个单值点。低于门槛一律判警告，不设阻断档——样本量偏低不影响"能不能审"，只影响审核结论的支撑强度，量化后果由正式审核判定。表头注明小批量特批或经批准的替代方案的，按声明放行并记录豁免依据。
  - **族1 计划表按声明值判定**：计划表通常不含原始数据区，"有效读数"取"子组容量 × 子组数"的声明值，声明值 ≥100 即视为满足，不得因"无实际读数"判本项。声明值本身缺失归 PRE-07（必填列缺失），本项不重复计。
- d）**警告**：子组数、子组容量在各处表述不一致（表头、控制图标题、汇总清单、报告正文），导致样本量无法唯一确定。
- e）**阻断**：子组容量或子组数完全无法确定，且无法由其他信息推断。

**说明**：有效读数只统计实际可读的数值单元格，空白、占位、非数值不计入。若存在被剔除的异常组，需有剔除说明，无说明的剔除不计入有效读数。

**子项依赖**：e）成立时，样本量无从计算，c）不再单独记录（同一缺陷只计一次），c）在报告中标注"因 e）无法计算"；b）成立但子组容量可确定时，按该容量核对，不受影响。

**整改方向**：改用与子组容量匹配的图型；恢复标准控制图常数；补足样本量或提供特批依据；统一各处样本表述。

#### PRE-14 计算过程可追溯性

**适用载体**：全族 · **级别**：阻断 / 警告

判定内容：

- a）**阻断**：应由计算得出的关键统计量（均值、极差、标准差、Cp / Cpk / Pp / Ppk、UCL / LCL）为手填常量，**且**不具备任何追溯依据（无计算式、无计算过程说明、无原始测量记录、无系统导出凭证）。计算链条完全断裂意味着数值来源不可追溯，无法在审核阶段复现，也无法区分"算错"与"编造"。
- b）**阻断**：数据区或统计量区存在随机数生成类计算式（用于生成测量值或能力值）。
- c）**警告**：存在"结果与数据不匹配"的直接迹象但无法确证——如原始数据区为空而能力值已有结果、数据明显被替换后结果未变、控制限与数据分布明显不符。
- d）**阻断**：**取值单元格**（数据区 / 统计量区 / 结果区）存在指向外部文件或已断开链接的**引用**，且**三要件同时成立**——① 该单元格以 `=` 开头（真公式），**或**工作簿内存在 `xl/externalLinks/` 部件；② 该引用位于**参与判定的取值单元格**，不在表头 / 页眉页脚 / 备注区；③ 其目标在当前工作簿与随批文件中均不存在，**且**导致该单元格数值无法通过任何本地手段复现（既无缓存值、又无同源替代载体）。**三要件缺一，不得判阻断。**
- d2）**警告**：**非取值单元格**（表头区、页眉页脚、备注区）存在悬空引用的**文本残留**——形如 `'01 PSW'!A21`，但**不以 `=` 开头**、工作簿也**无** `xl/externalLinks/` 部件。此时该单元格的标签被污染、可读性受损，但**不承载任何判定取值**，记 `W05`（局部不可解析，另有替代来源），**不进 7.3 解析侧核查**——解析通道正常，属文件自身的编辑残留。
- e）**警告**：文件为"数值粘贴版"（整表无任何计算式，全部为常量），但能提供计算依据或系统导出说明。此时不判阻断，只记录"计算过程未随文件留存"，要求补充说明。

**说明**：本项不要求文件必须使用计算式。判定重点是"数值来源是否可追溯"——计算式、计算过程说明、原始测量记录、系统导出凭证，**四者具备其一即视为可追溯**，不判阻断；四者全无才按 a）判阻断。这一口径同时约束 e）：粘贴版文件只要附有追溯依据，就只属警告。

**判 d）前的取证三问（不可跳过）**：

| # | 问 | 答"否"时 |
| --- | --- | --- |
| ① | 该单元格**以 `=` 开头**，或工作簿含 `xl/externalLinks/` 部件？ | 是文本残留 → 走 **d2）** `W05`，不得判阻断 |
| ② | 该单元格**属于取值区**（数据区 / 统计量区 / 结果区）？ | 在表头 / 页眉 / 备注区 → 走 **d2）**，不得判阻断 |
| ③ | 该引用目标确不存在，**且**数值无法本地复现？ | 有缓存值或同源替代 → 按 8.5「阻断 → 警告」处理，须注明替代载体位置 |

> **本项最易误判之处**：看到单元格里有 `!` 就判外链。**形状**（有没有 `!`）与**性质**（是不是引用、在不在取值区）是两件事——文本残留不以 `=` 开头、也不在取值区，按 **d2）记 `W05`**，不得判阻断。必须按上面三问逐格验证，不得凭单元格字面推断。

**整改方向**：恢复标准计算式；删除随机数生成；补充计算过程说明或原始记录；重建外部引用为本地值。

#### PRE-15 时间与序列可信性

**适用载体**：全族 · **级别**：阻断 / 警告

判定内容：

- a）**阻断**：子组抽样时间逆序，后一子组的时间早于前一子组。
- b）**警告**：全部子组的时间戳（含时间部分）完全相同，或存在明显的批量复制未改日期痕迹——如多组记录的时间精确到秒一致、或日期与班次组合出现不可能的重复。**仅日期相同不构成本项**：25 组在一天内完成可能正常，只有当文件同时提供了时间信息且全部一致，或另有复制迹象时，才判定。
- c）**阻断 / 警告**：抽样日期早于该零件的试产/生产起始日期，或晚于报告签署日期。前两项可仅凭文件内日期互证，成立即阻断 `B06`；若需比对试产起始日期而项目上下文未提供，本子项记 `W05` 警告（证据不足，需人工复核），不得推定合格。晚于本次 PPAP 提交日期一项仅在提交日期可得时判定，否则记 `S01`。
- d）**警告**：抽样未覆盖正常生产过程——全部集中在同一天同一班次、或抽样间隔完全等距（如严格每 5 分钟一组）、且无抽样方案说明。
- e）**警告**：报告签署日期、批准日期为空白或早于数据采集完成日期。

**说明**：初始过程能力研究要求覆盖正常生产过程，本项只判断"时间序列是否存在逻辑矛盾或明显的人为痕迹"，不判断抽样方案是否充分（后者属正式审核的统计有效性范畴）。

**整改方向**：核对并更正抽样时间记录；补充抽样方案说明；补齐签署日期。

#### PRE-16 跨文件与跨表一致性

**适用载体**：全族 · **级别**：阻断 / 警告

判定内容：

- a）**阻断**：标识不一致。零件号、零件名称、项目号、顾客名、版本号、日期在目录页 / 自述清单、各报告页、汇总清单之间不一致。
- b）**警告**：特性清单不闭合。特殊特性清单 / CCSC 清单 / 控制计划中列明的特性，与本批次能力报告、汇总清单、控制图中出现的特性无法一一对应（名称、规格、编号均对不上）。因提交动作不承载"应含清单"，两个方向一律判警告：
  - 清单有、本批次报告无 → 判警告，标注"本批次未识别到该特性的能力报告，可能为本批次未提交"。
  - 报告有、清单无 → 判警告，提示该特性可能未纳入特殊特性管理。此方向不依赖批次范围，但性质属"可能遗漏管理"，仍按警告处理。
- c）**阻断**：同一特性的规格限在不同表/不同文件中不一致（如控制计划写 `15.0 ± 0.05`，能力报告写 `15.0 ± 0.15`）。公差放宽会直接掩盖能力不足，属预检必须拦截项。
- d）**疑似重复提交不重复设条**：多个文件或工作表内容高度雷同的，由 PRE-03d 判定，本项不另计。
- e）**警告**：阶段标注内部矛盾。同一特性在不同表/不同页的阶段标注不一致（如汇总清单标 P 阶段、明细页标 PP 阶段）；或某阶段区块整体空白而未作说明；或汇总清单标注的阶段与其实质填写内容不符（标 P 阶段却只填了 SOP 阶段列）。**业务意义上的"本次提交阶段与该阶段结论是否匹配"属正式审核，不在本项。**
- f）**阻断**：明细页与汇总清单不对应。包含两种情形，同属一份文件内部，与提交范围无关：
  - **数值不一致**：同一特性的能力值、判定结论在明细页与汇总清单中不同；
  - **特性集合不一致**：明细页出现的特性在汇总清单中找不到，或汇总清单列出的特性在明细页找不到。汇总清单与明细页特性集合必须等价。

**说明**：本项是"部分提交 + 提交动作不承载应含清单"背景下判定最需谨慎的一条。所有"缺失"类观察只能表述为"本批次未识别到"，不得表述为"缺项"；不得把范围裁剪误判为一致性问题。

**b）与 f）的边界**：b）比的是"特殊特性清单 / 控制计划"与"本批次报告"——属跨文件，受批次范围影响，故判警告；f）比的是"同一份文件内的明细页与汇总清单"——不跨文件、不受批次范围影响，故判阻断。同一特性的缺失不得同时按 b）和 f）记录。

**整改方向**：统一全文件集的标识信息；补齐或声明特性范围；统一规格限；剔除重复件；对齐阶段与结论。

### 5.5 客户差异层（按客户 × 类型路由）

**载体族定「结构长什么样」，客户定「门槛判据是什么」。** 两者是两个维度：同一客户可能用多个族（UAES 既用族3 也用族1），同一族也可能服务多个客户。本节只写客户侧的判据差异，**不改 PRE-01~PRE-16 的判据文本**——但**它是覆盖层**（v2.8 定，与总纲 7.6 同一条通则），见下方效力声明。

> **覆盖效力（全库统一）**：客户差异层不是"补充说明"，是对通用判定项在该客户上的**启用/关闭开关**。
>
> | 差异层写法 | 效力 | 落码 |
> | --- | --- | --- |
> | "**必备**" / 给出具体门槛 | 该判定项在**该客户上生效**，按差异层口径执行 | 按原项级别 |
> | "**无此要求**" / "不要求" | 该判定项在**该客户上关闭** | 记 `S02`（规则不适配），**不得判 `B05`／`W01`** |
> | 差异层未提及 | 沿用通用项 | 按原项级别 |
>
> **冲突时一律以差异层为准**。理由是**结构能力**：受控模板本体决定文件里能不能有那一栏，通用项若强于差异层，等于要求供应商往甲方模板里加列——那是把模板侧缺陷记成材料侧缺陷（3.1 三分界已在状态层修过一次，这里是它在判定层的同一处理）。差异层每次关闭/生效都须在报告 10.6「客户差异层清单」逐条列明项号。

**（1）常用载体族映射**

| 客户原文情形 | 预检口径 | 理由 |
| --- | --- | --- |

| 缺 PGQP1 / 缺对端文件 | `W01`，写明「缺比对文件《…》」 | 总纲 7.2：跨文件缺项按 `src` 分流（`SUB` → `W01`+`S04-S`；`CUS` → 仅 `S04-C`），均不阻断 |

> **这条校准是本分则最容易做错的地方**：客户规则里「Cpk ≤ 1.33 则不通过」是**业务判定**，如果照抄进预检，预检就会去评能力值——那已经越界到正式审核了。预检要判的是「这份报告的能力值算得出来吗、写在应有位置上吗、同表其它值自洽吗」，不是「这个 1.21 够不够」。

**（4）本节不新增级别与原因码**，落点全在 PRE-01~PRE-16 与 5.4 启用矩阵内。**但可关闭/启用**——关闭即记 `S02`、启用即按原项级别执行，见本节开头的覆盖效力表。

### 5.6 多页同名特性：映射成立后的判定与下游口径

本节是 `PRE-06 f)` 情形②的**配套解释**，不新增判据、不新增原因码。它回答一个问题：**同一个特性名占多页时，判定要走到哪一步。**

#### 5.6.1 认定顺序

| 步 | 动作 | 结果 |
| --- | --- | --- |
| 1 | 按总纲 10.4.2 归一化名称，找出「归一后同名」的页组 | 得到多页特性清单 |
| 2 | 按总纲 10.4.1 定映射档位（`R-0`~`R-3`），按序取**第一个成立档** | `R-0` → `PRE-06 f)` 记 `B03`；**`R-1` 即达要求**，`R-2` / `R-3` 不要求 |
| 3 | 逐一核该组各页的**规格限**（名义 / 上偏差 / 下偏差） | 组内不一致 → `PRE-16 c)` 记 `B06`（真冲突）；一致 → 不记 |
| 4 | 核工具信息区（模具号 / 型腔数）**是否填写** | 有栏无值 → `PRE-06 g)` 记 `W02`；**填写后不核与页的对应**（见 5.6.3） |

**第 3 步是撤回 `B03` 之后必须做的**——映射成立只说明「页能被指认」，不说明「页里的数值自洽」。**先撤阻断、再查冲突，顺序不得颠倒**：先撤后查，若查出冲突就换成 `B06`；若不查就撤，等于用映射掩盖了数值问题。

#### 5.6.2 `R-1` 成立时的跨文件口径

`R-1` 只到定位级。此时同一特性的 N 页对应控制计划 / PFMEA 的 1 行，属**一对多**：

- **不得**因「N 页对 1 行」记 `PRE-16 f)`（特性集合不一致）——集合语义下去重后相等，`f)` 不成立。
- **不得**因「对不上是哪个测点」记 `PRE-16 c)`（规格限不一致）——那是映射不足，不是数值冲突；按总纲 10.4 硬约束 3 记 `S02`。
- **可以**逐页与控制计划那一行比规格限；**全组一致即通过**，只要有一页不同才记 `B06`。
- **不因此要求提交方补建页↔测点映射。** 记 `S02` 的语义是「这项交给正式审核」，不是「打回整改」——预检不得在整改单里要求供应商把页签改成 `14#位置度-测点1` 或补腔号列（总纲 10.4.1 边界 5）。

#### 5.6.3 本节明确不做的四项检查

多页同名特性最容易引出「顺手多判一步」。以下四项**全部关掉**——不判、不记码、不进整改单：

| # | 不做什么 | 为什么不做 |
| --- | --- | --- |
| 1 | **不核「哪一页对应哪个测点 / 哪个腔」** | 腔号与页的绑定属**工艺台账**，不是 PPAP 文件的自证内容；模板无强制承载位，页内数据也反推不出 |
| 2 | **不核「腔数是否等于同名页数」** | `# Cavities` = 6 而某特性只有 2 页，完全正常——不是每个腔都测每个特性。**数量相等不是合规条件** |
| 3 | **不设「语义标识缺失」判定项** | `R-2` / `R-3` 只在供应商**主动提供**时用于识别，不是必达项；设成判定项会把「合规但简写」判成「不合规」 |
| 4 | **不核 `Tool number` 与页的对应** | 一份簿通常只有一个模具号，逐页对应无信息量；仅在**多页取值不一致**时按 `PRE-16` 的取值冲突口径处理 |

**唯一保留的核查**是「有栏无值」（`g)` → `W02`）：它只问「这一栏有没有人填过」，不问「填得对不对」。

> **这一条与 `R-1` 的关系**：`R-1` 已足够支撑**簿内**判定与不重计。语义级（`R-2`/`R-3`）只在供应商主动给了的时候顺手认一下，**不给也不算缺**。

## 6. 输出契约

### 6.1 总体结论

输出必须包含总体结论，且仅有以下三种结果：

| 总体结论 | 判定条件 | 后续处理 |
| --- | --- | --- |
| 通过 | 未发现阻断项（无论是否发现警告项） | 文件集可进入后续正式审核；警告项须在报告中逐条列清并随报告移交 |
| 不通过 | 存在任一阻断项 | 按责任侧分派整改，不得进入后续流程；须给出原因码 |
| 未执行 | 本批未提交任何本类目文件（无可判定对象），或执行方能力不足无法读取文件 | 不产出通过 / 不通过，说明原因。**第六章须分两行**：本类目标「未执行」；`S01` 只留给属其他类目的文件。**不得用 `S01` 代替本类目的「未执行」**（总纲 5.1 禁令） |

> **术语对齐**：本分则行文中的「拦截」即总纲的「不通过」结论，二者同义；报告结论字段统一写「通过 / 不通过 / 未执行」，处置栏写"打回整改"。全文出现的"拦截项"均指阻断项。

**只有阻断项具有否决效力。** 警告项在任何情形下均不得作为不通过的理由，即使数量很多、即使其中包含可能影响判定精准度的问题。警告项的作用是在报告中充分暴露风险，供提交方与审核方自行判断，而不是阻断流程。

**警告项在"通过"结论下必须完整保留。** 判为通过不意味着可以省略警告：报告仍须逐条列出全部警告项，含位置、证据链、影响、建议动作，不得只给数量、不得以"其他若干项"概括、不得因结论为通过而降级记录颗粒度。

**总体结论的作用域必须显式声明为"本次提交的文件集"**，不得扩大为项目整体结论。

### 6.2 原因码

结论为「不通过」时必须给出原因码。**一个阻断项一个码**，不得合并。本域取值：

**阻断原因码**

码的含义见总纲 5.2，下表只列本类目典型情形。

| 码 | 本分则典型来源 |
| --- | --- |
| `B01` | PRE-01a/b/c、PRE-02 |
| `B02` | PRE-03c、PRE-03d |
| `B03` | PRE-03b、PRE-16a、**PRE-06f（字段存在但取不到唯一值）** |
| `B04` | PRE-05e、PRE-07 |
| `B05` | PRE-06、PRE-07a/b/c、PRE-09a/c/d/f、PRE-10 |
| `B06` | PRE-11、PRE-12、PRE-15a/c、PRE-16c/f |

> **`B05` 的边界**：判据是该字段在本批**取不到可用于判定的值**，含「结构上无此栏」与「有栏但整栏不可归一」两种形态；**单纯空值不算**——空值按 PRE-07 行完整性判阻断（因实际值列为空即说明研究未形成结论），与本条的"取不到可判定值"不同源，同一处缺陷只记一次。**** 本条所指「空值按 PRE-07 判」限于**条目行的必填列**；**工具信息区**的有栏无值按 `PRE-06 g)` 记 `W02`，不入本条、也不记 `B05`。

**警告原因码**

码的含义见总纲 5.2，下表只列本类目典型情形。

| 码 | 本分则典型来源 |
| --- | --- |
| `W01` | PRE-04b、PRE-04d、PRE-16b |
| `W02` | PRE-09b/c、PRE-07 个别空值、**PRE-06g**（工具信息区有栏无值） |
| `W03` | PRE-09e、PRE-10e |
| `W04` | PRE-03a 自述清单对账、PRE-03d 重复提交、PRE-16b/e |
| `W05` | PRE-02e、PRE-15c、PRE-15d/e、**PRE-14d2**（表头区悬空引用文本） |
| `W06` | PRE-12 部分子项、PRE-13d、PRE-14c/e |

### 6.3 报告形式

- 输出 Markdown 报告。
- 当前不要求程序可直接消费的 Schema。
- 报告应清晰、可读、可追溯，便于人工整改。

### 6.4 问题记录字段

每个问题记录至少包含：

| 字段 | 说明 |
| --- | --- |
| 问题编号 | `B` + 两位序号（阻断）/ `W` + 两位序号（警告），全报告唯一；状态项不编号 |
| 类型 | 区分"数据不规范"和"文件无法解析"；数据不规范细分为结构完整性、正确性、一致性、可追溯性等 |
| 规则编号 | 触发的预检规则编号（PRE-xx） |
| 原因码 | `B01`~`B06` / `W01`~`W06` |
| 文件位置 | 文件名称及最小可定位位置，如工作表名、行号、列名、单元格、页码、段落 |
| 证据链 | 原文摘录、位置说明、推断依据、关联项说明 |
| 影响 | 对后续正式审核的具体影响（如"导致汇总清单无法逐行比对，R15 无法执行"） |
| 严重级别 | 阻断 / 警告 |
| 责任侧 | 材料侧 / 提交方 / 解析侧 |
| 置信度 | 高 / 中 / 低，需说明依据 |
| 整改方向提示 | 指向具体需补、需改、需确认的内容 |

### 6.5 结论颗粒度

| 颗粒度 | 输出要求 |
| --- | --- |
| 文件级 | 每个文件是否存在问题、问题数量、最高严重级别、所属载体族 |
| 规则项级 | PRE-01 至 PRE-16 每条的检查结果（满足 / 不满足 / `S01` / `S02` / `S03` / `S04`）及问题明细 |
| 文件集级 | 总体结论、原因码、阻断项清单、警告项清单、状态登记、判定局限声明（提交动作只表明"交了哪些"，不表明"应有哪些"） |

### 6.6 责任侧与处理去向

| 责任侧 | 涉及规则 | 处理去向 | 是否打回供应商 |
| --- | --- | --- | --- |
| 材料侧 | PRE-05～PRE-16 的全部内容类缺陷（主表缺失、字段缺失、行空缺、规格限错误、卷面矛盾、可追溯性、时间序列、跨表不一致） | 打回整改 | 是 |
| 提交方 | PRE-03a 自述清单对账、PRE-03d 重复提交、PRE-04b/d 关联文件未识别到 | 更新清单 / 确认唯一对象 / 补充文件 | 否 |
| 解析侧 | PRE-01a/b/c、PRE-02 的不可读部分 | 转技术支持核查文件（压缩包、加密、损坏、无文本层且渲染失败） | 否 |

**归口规则：**

1. 每条规则**只能有一个主责任侧**，以 §5.2 与本节为准。
2. PRE-01a（压缩包）虽由提交方形成，但处置是"退回要求重新提交"，责任侧记为**解析侧**并在报告中注明成因，不打回供应商整改。
3. 报告中"打回供应商整改"与"提交方补正 / 解析侧核查"必须分表列示。

## 7. 执行流程

### 7.1 接收与文件集确认

1. 接收本次提交的待审文件集。文件枚举由提交动作自动产生，直接采信，**不索取、也不等待"文件清单"**。
2. 若提交物内部含自述清单（清单文件 / 目录表 / 报告目录页），按 PRE-03a 与实际提交文件对账；不含则该项记 `S01`，不记问题。
3. 确认文件可访问、内容可获得（PRE-02）。
4. 记录本次提交的文件组成与载体族分布；**不记录、也不索取覆盖范围声明**（提交动作不承载）。
5. 若文件无法访问或无法获得可判定内容，记录问题并按级别判定（`B01` 或 `W05`）。

### 7.2 载体归属

1. 逐文件判定归属载体族（族1–族4）或关联文件（目录页、PGQP1、特殊特性清单）。
2. 无法归属的文件单独记录，不参与后续规则判定（PRE-03b，阻断 `B03`）。
3. 输出本次文件集的载体族分布，作为后续规则启用依据。

### 7.3 规则启用

1. 按 §5.4 启用矩阵确定本次适用的规则子集。
2. 规则对本载体无判定对象的，记 `S01` 并说明原因，不得省略、不得默认为满足。
3. 因缺少可选输入或证据不可获得的，按 3.1 定级并给原因码（`B01` / `W05` / `S02`），标注"证据不足，需人工复核"。

### 7.4 四维度标准化检查

对启用范围内的规则逐条执行：

- 可审性检查（PRE-01、PRE-02、PRE-03b、PRE-03c），已在 §7.1–7.3 完成，此处复核结论。PRE-03a（自述清单对账）不属可审性，归结构完整性一侧，判警告。
- 结构完整性检查（PRE-04 至 PRE-08）。
- 数据正确性检查（PRE-09 至 PRE-13）。
- 数据可追溯性检查（PRE-14、PRE-15）。
- 数据一致性检查（PRE-16）。

**四维度并列检查，任一维度出现阻断项即判不通过；警告项不构成否决，但须全部记入报告。** 每条规则须给出"满足 / 不满足 / `S01` / `S02` / `S03` / `S04`"之一，不得留空。

### 7.5 汇总判定

1. 汇总所有问题，按规则编号归并。
2. 标注类型、位置、证据链、影响、严重级别、置信度。
3. 分别给出文件级和规则项级结论。
4. 按 §9 通过规则给出总体结论。
5. 判拦截时列出全部阻断项；无论结论如何，警告项一律逐条列入警告清单。
6. 显式声明结论作用域为本次提交的文件集。

### 7.6 输出报告

按 §10 模板输出 Markdown 报告，明确结论（通过 / 不通过 / 未执行）、原因码（阻断依据）、完整警告清单、状态登记、整改分派、处置方向，并声明本预检不执行修复与复检。

## 8. 判定口径

本章共五个维度。其中**可审性**为前置维度（在 §7.1–7.2 完成），**结构完整性、数据正确性、数据可追溯性、数据一致性**为并列的四个数据维度（§7.4）。原第六维「规则适用性」按总纲 2.3 不属本分则判定范围，见 §8.6。

### 8.1 可审性

关注输入本身是否具备被审条件。

判断依据：

1. 文件是否可解析、关键数值是否可读。
2. 载体是否可归属、主表是否可定位。
3. 提交的是实测填报件还是空白模板/草稿件。

三项均为可审性成立的必要条件，任一不满足即判阻断——后续任何维度的判定都建立在可审性成立的基础上，故本维度**不设警告档**。

**"自述清单对账"不在可审性范围内**：它不回答"能不能审"，只回答"提交物自述与实际是否自洽"，故归 PRE-03a 判警告 `W04`，且无自述清单时记 `S01`。同理，"文件清单是否存在"不构成可审性条件——文件枚举由提交动作产生，必然存在。

### 8.2 结构完整性

对照规则要求，判断判定所需的结构与字段是否存在。

要求：

- 规则要求检查某项信息时，文件中应存在承载该信息的表格、列、区块。
- 结构性缺失不得通过"内容看起来齐全"来弥补。
- 结构性缺失必须明确指出缺失的表、列、区块名称。

### 8.3 数据正确性

关注某一份文件内某个信息本身是否科学、合理、符合基本逻辑。

判定依据优先级：

1. 字段类型、格式、值域等基本要求。
2. 基本常识与科学逻辑（如 Cpk 不可能大于 Cp）。
3. 业务常识（如规格限不得倒挂）。
4. 领域规则与领域知识（如控制图常数、子组容量与图型对应关系）。
5. 可选数据标准字典。

示例：温度字段不应填写时间信息；能力值位置不应出现错误值符号；规格限不应倒挂。

### 8.4 数据一致性

关注不同数据之间的关联关系是否满足要求。

要求：

- 不要求预先指定特殊关联键。
- 应基于整体文件内容自主推断所有可能关联项（零件号、特性、规格、版本、日期、特性等级）。
- 对可能关联项进行初步关联与一致性判断，包括跨文件、跨表格、字段间关联。
- 关联推断和判断依据写入证据链。
- **所有"缺失"类判断一律判警告，且只能表述为"本批次未识别到"。** 提交动作只表明"交了哪些文件"，不表明"应有哪些文件"，本 Skill 无法区分"真缺项"与"本批次未提交"；而把范围裁剪判为阻断会让合规的部分提交被误打回，代价高于放过一个可能的缺项。
- **能力值、判定结论、规格限之间的"不一致"仍为阻断。** 这类缺陷与提交范围无关，无论批次如何裁剪，同一特性两处数值不同都是确定的输入缺陷。

### 8.5 数据可追溯性

关注数值是否具备可复现来源。

要求：

- 统计量应能追溯到原始数据、计算式、系统导出记录或计算说明中的至少一项。
- 既无计算式又无任何追溯依据时判阻断。
- 随机数生成类痕迹判阻断。
- 时间序列应能支撑"数据来自实际生产过程"的基本判断。

### 8.6 已退出：规则适用性

原「规则适用性」维度按总纲 2.3 **不属本分则判定范围**——规则本身的可执行性、版本覆盖、覆盖缺口均属规则侧，预检不评、不输出、不登记。

| 旧机制 | 去向 |
| --- | --- |
| 「本次载体族是否落在当前生效规则版本的覆盖范围内」 | 删除。规则已在前置入口定型，预检按本文件固化的 PRE-01～PRE-16 执行 |
| 「提交了某载体但当前规则版本无对应判定项，在报告中列出并提示规则覆盖缺口」 | 删除。不输出任何关于规则覆盖的观察 |
| 「规则适用性不满足时判警告（因规则侧问题不应由提交方承担）」 | 删除。原属此类的唯一残留情形（子组容量超出常数表覆盖范围 n=1–25）并非规则缺陷，而是常数表边界，改记 `S02` 并在影响栏注明"该子组容量超出本文件常数表覆盖范围，需正式审核另行确认" |
| 术语「规则不适配」`S02` | 保留代码，仅用于上述常数表边界等本域实测边界，不再用于规则版本覆盖 |

### 8.7 严格标准

采用相对严格的标准：

- 宁可严格误判，也不放过潜在不规范。
- 若认为数据标准化可能存在问题，即使实际可能没有问题，也允许按严格标准记录。
- 所有推断性判断必须标注推断依据和置信度。
- **严格标准只影响"是否记警告"，不影响"是否判阻断"**：阻断的唯一判据是 §9.1（是否让某条审核规则无法得出唯一结论）。严禁把"看起来很差"判成阻断。
- **严格标准的边界**：严格只作用于"文件内部"——数值是否合理、结构是否齐备、是否自相矛盾、是否可追溯。对"跨文件是否齐备"不适用严格标准，因为清单无覆盖声明，无法确认应然范围；此类一律判警告。
- 同理，"同义字段"取宽口径（见 PRE-06 说明），不因命名差异判缺失。严格不能用在与判定结论无关的表述形式上。

## 9. 严重级别与通过规则

### 9.1 严重级别

仅设置两种级别：

| 级别 | 定义 | 典型情形 |
| --- | --- | --- |
| 阻断 | 该问题导致至少一条正式审核规则**无法得出唯一结论**（取不到数或结论方向不唯一）。**唯一具有否决效力** | 压缩包、无法解析、载体不可归属、无效填报件、主表缺失、必需字段缺失、目录页缺失、规格限错误、卷面数学悖论、计算完全不可追溯 |
| 警告 | 判定仍可完成，但结果不完整或存在被误判风险。**不否决，须在报告中逐条列清** | PGQP1 未识别到、自述清单对账差异、特性清单不闭合、样本量偏低、图型疑似错配、时间戳异常、疑似重复提交、不适用标注不规范 |

**四种状态（不是级别，不参与通过判定）：**

| 状态 | 代码 | 本域典型形态 |
| --- | --- | --- |
| 范围外 | `S01` | 纯表格载体无目录页（PRE-04a）；无自述清单故无对账对象（PRE-03a）；不属本类目的文件（已剔除）；抽样日期外推项缺提交日期（PRE-15c 末句） |
| 规则不适配 | `S02` | 子组容量超出常数表覆盖范围 n=1–25（PRE-13b） |
| 移交 | `S03` | 能力值是否达标、过程是否受控、抽样方案统计有效性、造假嫌疑 |

**两级效力不同，这是本文件的判定核心**：

- **阻断项 → 不通过。** 严格不可检查，或缺陷会导致后续审核结论错误，必须先整改。
- **警告项 → 不影响结论。** 影响判定精准度但不影响"能不能审"，因此在报告中充分列明即可，交提交方与审核方自行处置。

**不得把警告当阻断用，也不得把阻断降为警告**：前者会让本可推进的提交被打回，后者会让缺陷被"通过"结论掩盖。级别只能由本文件规定，不因"这批文件很重要/很紧急"而调整。

**警告不拦截的补偿条款（强制，总纲 8.3）**：

1. 警告项 100% 进入报告第五章，逐条含位置、证据、影响、建议动作。
2. 警告清单作为附件随报告移交正式审核，不得删减。
3. 正式审核**不得因「预检已通过」而跳过警告指向的字段**。警告是移交清单，不是免检证明。

### 9.2 通过规则

无阻断即通过，存在任一阻断即不通过并给出原因码；警告不影响结论但须 100% 列报并移交；状态项不参与判定但不得略去不记（总纲 8.2 / 8.3）。

本分则补充：不设「警告达到 N 条即不通过」的阈值——任何此类阈值都会让警告变相成为阻断手段。**「通过」不等于「无问题」**：报告须在总体结论处同时给出警告项数量，并声明「警告项未构成否决，但已列于第五章，请提交方自行判断是否处理」。

### 9.3 问题分级与处置

报告须为每个问题标注处置等级，便于用户排序：P0 / P1 必须处理，P2 为提示。

| 等级 | 含义 | 是否否决 | 典型情形 |
| --- | --- | --- | --- |
| P0 | 阻断项，且导致其他规则完全无法执行 | 否决 | 形态门禁、无法解析、载体不可归属、无效填报件 |
| P1 | 阻断项，影响判定基准正确性 | 否决 | 规格限错误、必需字段缺失、卷面矛盾、规格限跨表不一致、目录页缺失 |
| P2 | 警告项，影响判定精准度 | **不否决** | PGQP1 未识别到、自述清单对账差异、特性清单不闭合、样本量、时间序列、重复提交、标注不规范 |

**P2 的处置说明**：P2 不否决，报告中仅作提示并标注建议动作。其中两类可标记"可豁免"——①"本批次未识别到"的关联文件（PRE-04b、PRE-04d）；②自述清单对账中"清单列了但实际未提交"的方向（PRE-03a）。二者属提交范围问题，经审核方确认属范围外后无需处理。其余 P2（如特性不闭合、重复提交、时间戳异常、标注不规范）由提交方自行判断是否在本轮处理，**预检不因其存在而判不通过**。

**PGQP1 的"待补充提交"性质**：PRE-04b 的警告是最典型的 P2 情形——提交方补充提供该文件即可消除，不补充也不影响本次通过结论。报告中该条目统一表述为"**待补充提交**"，不得表述为文件质量不合格，也不得表述为"导致不通过"。

## 12. 执行要求与约束

模型或 Agent 执行本 Skill 时应遵守：

1. 按本文件流程执行，不跳过载体归属与四维度检查。
2. 以整个文件集为标准化对象，不局限于单文件。
3. 不评判规则描述文件的可执行性——该职责在前置入口。
4. 不重算任何统计量，不比较 1.33 / 1.67 阈值，不判断过程能力是否达标。
5. 正确性优先依据字段类型、基本常识、业务常识和领域知识。
6. 允许合理推断，但必须说明推断依据和置信度。**推断只用于识别关联项与定位结构，不得用于补足缺失内容**——不能因"另一份文件里有"就认定本文件该项已具备。
7. 一致性不要求预先指定关联键，应自主推断可能关联项。
8. 四维度并列检查，**任一维度出现阻断项即判拦截**；警告项不构成拦截。
9. 采用相对严格标准，宁可严格记录潜在问题；但严格只作用于文件内部判定，不用于"跨文件是否齐备"。
10. **所有"缺项"类判断一律判警告，不得判阻断。** 唯一例外是 PRE-04a 目录页缺失（属报告自身结构缺陷，不依赖批次范围）。
11. **缺失类问题只能表述为"本批次未识别到"**，不得表述为"缺项""漏交""未提交"。**唯一例外**：提交物内部自带的自述清单已明确列示该文件、而实际未提交时，可表述为"本批次未提交该文件"（PRE-03a）——此时有清单作为事实依据，与"无从判断应否提交"不同；但即便表述为"未提交"，仍只判警告。
12. **同义字段按宽口径识别**，不因命名、全角半角、大小写、前后缀差异判缺失。
13. 判为拦截时必须打回整改，不得进入后续正式审核；仅有警告项时判通过，可进入后续流程。
14. 每次调用无状态，不继承历史整改记录，不累积项目进度。
15. 必须区分"数据不规范"和"文件无法解析"。
16. 证据尽量定位到最小颗粒度，如工作表、行、列、单元格、页、段落。
17. 总体结论必须声明作用域为本次提交的文件集，并声明"无法区分真缺项与本批次未提交"这一判定局限。
18. 输出 Markdown 报告，当前不要求程序化 Schema。
19. **每条规则必须给出"满足 / 不满足 / `S01` / `S02` / `S03` / `S04`"之一**，不得留空。证据不足时按 3.1 定级并给原因码（`B01` 无替代 / `W05` 可另行确认 / `S02` 规则侧），记入阻断或警告清单；状态项不计入任何问题项，但必须显式说明原因。二者不得互换。
20. **判定基准只能取自文件自身或本次提交物内部**，不得引用本文档之外的规则阈值、行业阈值或历史批次数据。
21. 同一缺陷只计一次，不得在多条规则下重复计为多个问题（重复点已在 PRE-04c、PRE-09c、PRE-12、PRE-16d 标注）。
22. **只有阻断项可作拦截理由。** 不得因警告项数量多、或认为某项警告"很严重"，就判拦截、打回或要求必须先改完。
23. **警告项必须逐条列清。** 结论为通过时同样不得省略、不得只给数量、不得以"其他若干项"概括、不得降低记录颗粒度。
24. **不得以"没有文件清单""无法取得清单""清单与实际文件不一致"为由判任何问题。** 预检在提交之后运行，文件枚举由提交动作自动产生、恒等于判定对象；可对账的只有提交物内部的自述清单，且该类载体本身无自述清单结构时记 `S02`。

## 14. 运行假设

### 14.2 运行假设

以下事项属本分则的运行前提，**不作判定依据、不产生级别、不在报告中讨论**（总纲 12.1）：

## 15. 补充口径
> 本节条款与正文冲突时以本节为准。

### A. 跨文件匹配键

**匹配键 = 工序段 + 图纸气泡号**，不得以数字前缀单独匹配。

| 前置校验 | 要求 | 不通过时 |
| --- | --- | --- |
| K1 唯一性 | 同一键在任一侧只对应一个对象 | 记 `B03`，不得判冲突 |
| K2 口径对齐 | 两侧「编号」须为同一体系 | 记 `S02`，写明两种口径 |
| K3 反证 | 键命中后用名称或规格反向确认 | 属不同对象即判「键碰撞」，不计冲突 |

**名称同义写法差异**（如「电机舱直径 / 电机舱尺寸」「轴孔直径 / 气道孔直径」「喉口 / 候口」）**只记 `W04`**，不得记 `B06`。

### B. 控制图存在性的检查方法

**以包内绘图对象计数为准**：统计 `xl/charts/chartN.xml` 文件数，或 `xl/drawings/drawingN.xml` 中图表引用节点数。

| 情形 | 判定 |
| --- | --- |
| 包内 chart 计数 ≥ 1，且分布符合规则要求 | 满足 |
| 包内 chart 计数 = 0，且无 drawing 关系 | 不满足（按族定级） |
| 取不到图表对象，但文件包内确有图表关系 | **解析侧待核**（总纲 5.2 证据形态表），不得直接判缺图 |

### C. 族3 与族4 的判定优先级

**以页面模板形态为准**：逐特性出具 PROCESS CAPABILITY CERTIFICATION REPORT 页者归族3；仅在单页表格内列多特性数值者归族4。

**有无「目录」汇总清单不改变载体族**——族3 带汇总清单仍是族3，不得因「有汇总表」而按族4 规避主表检查，也不得因「有汇总表」而按族1 判缺计划表。

### 附录 B：预检禁止越界清单

**不要做：**

1. 不要重算 Cp / Cpk / Pp / Ppk，不要用原始数据独立复算后与卷面值对比——这是正式审核的核心动作。
2. 不要运行控制图八大判异准则，不要判断过程是否受控。
3. 不要做正态性检验、偏度峰度计算、Box-Cox 或 Johnson 转换判断。
4. 不要做末位数字卡方检验、矩阵克隆侦测、跨特性相关性分析等造假鉴定。
5. 不要判断能力值是否达到 1.33 / 1.67，不要判"过程能力合格/不合格"。
6. 不要与 PFMEA 发生度、MSA 的 GRR 做跨表物理定律对撞——这属正式深审。
7. 不要因为能力值不达标就判定预检拦截。预检判拦截的理由只能是阻断级的"不可审"或"不规范"，不能是"不合格"。
8. 不要对压缩包先解压再判，必须拦截并要求重新提交。
9. 不要因"无法辨识"而给出通过或"暂不判定"的放行结论。
10. 不要自动去重同名/近似文件，只输出疑似重复并要求确认。
11. 不要凭"其他文件里看起来有这项信息"来弥补当前文件的缺失，除非该关联有明确依据并写入证据链。
12. 不要把任务台账式的"过程能力分析总表"当成能力值汇总清单。
13. 不要修复、补全、转换、清洗任何原始文件，不提供"一键修正"。
14. 不要输出程序可直接消费的 JSON Schema（当前阶段不要求）。
15. 不要评判规则描述文件本身是否可执行，也不要输出任何关于规则集、版本覆盖、口径的问题——该职责在前置入口（总纲 2.3）。
16. 不要把"本批次未识别到"判定为"缺项"或"未提交"。提交动作只表明"交了哪些"，不表明"应有哪些"，本 Skill 无法下此结论，只能判警告并要求审核方确认。
17. 不要因为 PGQP1 缺失就判阻断——它是警告，且标注可豁免。
18. 不要以"本批次无采购件""纯自制件批次"为由把 PGQP1 记 `S01`——它是全族无条件适用项，缺失即警告；也不得只在警告清单留一行了事，必须在报告 10.5 给出补充提醒。
19. 不要因同义字段命名差异（如 `Cpk` 与 `结果(CPK)`）判字段缺失，也不要因此判定"字段定位歧义"；歧义只用于同一表内同名列指向不同语义区块的情形。
20. 不要把目录页缺失降级为警告。它是"缺项降级"的唯一例外，判阻断；也不要以"页数少""单特性独立页""内容简单"为由豁免。
21. 不要在载体为纯表格（无报告外壳）时，因"没有目录页"判不满足——应记 `S01` 范围外，二者结论不同。

27. 不要因为结论是"通过"就省略、合并、概括警告项，也不要只写"另有若干项警告"。警告清单必须逐条完整。
28. 不要为了让某条警告"起作用"而临时上调其严重级别——级别由本文档固定，不随批次紧急程度或审核偏好调整。
29. 不要判"文件清单缺失""清单无法取得""清单与实际文件不一致"——预检在提交之后运行，文件枚举必然存在且恒等于判定对象；只有提交物内部的自述清单才构成可对账的对象。
30. 不要因为"本批次只提交了一份文件"就降低判定强度或推定内容齐备——单文件同样按启用矩阵全套判定。
31. 不要把"自述清单列了但实际未提交"升为阻断，也不要因载体族、清单措辞（如"应提交""必须提交"）或差异条数上调 PRE-03a 的级别——该项定级固定为警告，已业务确认（§14.1 第 16 条）。

**不要画（不要在报告中生成）：**

1. 不要绘制任何控制图、能力曲线、直方图、正态分布示意或趋势图。
2. 不要生成"能力达标趋势图""供应商能力雷达图"——无跨批次数据源支撑。
3. 不要用红绿灯色块图替代逐条判定明细；每条规则必须带证据链文本。
4. 不要生成虚构的模板截图或示意图来替代真实位置描述。
5. 不要用"看起来正常/整体良好"之类的整体印象表述替代逐项证据。

> **解析口径注（v0.16 新增 · 裁决 Q6 · 全库统一；与总纲 §5.2 证据形态表一致）**：本类目对「读不出」一律按**三分口径**定级，**「无文本层」本身不构成阻断理由**——
> ① **整份无法识读**（无文字层**且**无图像层 / 加密 / 损坏）→ `B01`；
> ② **图像清晰、判定字段可读** → **判定照常执行，结论可为「通过」**，须标判定可信度 `目视识读` 并留痕（≥300dpi、逐页识读、**把关键字段取值写入报告**），**缺留痕记 `S06`**；
> ③ **模糊 / 缺页致判定字段读不出** → `W05`，该判定项记「未审」。
> **落码前必答一问：「是整份读不出，还是这一处读不出？」** 整份 → ①；这一处 → ②（可读则照常判）或 ③（读不出则 `W05`）。**只有「整份」才配 `B01`。** 本条不新增任何判据，只定「读不出」的落码路径；**判据文本、项数、级别取值一律不变**。

## 1. 目的与边界

**目的**：判定**本批提交件里有没有图片**——即预检能否确认「供应商确实交了图」，并**强制在报告中留下人工复核提示**。

**这是 41 个条目中结构判据最弱的一条**，必须说清：预检对照片**只能确认「有一张图」**，不能确认内容。UAES 规则原文对这一类目也只要求「提交生产件样品照片」，没有规定张数、角度、分辨率、命名——因此预检的正确产出是「**存在性合格 + 明确移交人工**」，而不是模拟图像审核。

**v1.5 改判据的理由（用户 2026-11-09 裁定）**：照片没有表单结构、也没有固定命名，供应商可能叫 `IMG_0231.jpg`、`样品照片.zip`、`外观.png`，也可能混在别的提交包里。按原路径「先识别为『生产件样品照片』类型、再判该文件是否图片」，**识别这一步本身就会失败**——文件名里没有任何语义线索，于是判 `B03` 或「未执行」。**那是把「命名不规范」判成「没交照片」，方向错了。**

改为批次检索后，判据变成「**本批有没有图片文件**」：有 → 推定已提供；没有 → 才是真的没交。依据从「语义识别」降到「文件类型识别」——**这是能力边界内的判断，不是降低标准**。

**边界三条**：

1. 本类目**不判实测值**、不判图像内容，故不产生 `B06`。
2. 本类目**无跨文件依赖**，不得因本批次缺其它文件记任何问题。
3. 本类目**没有分则专属的客户差异**（本期仅 UAES 一家），客户差异层为预留位。

## 4. 判定项（2 项）

> 判据文本以 `00-A §2.1` 为准，本节只把它落成可执行判定。

| # | 判定内容 | 判定方式 | 不满足时 | 来源条款 |
| --- | --- | --- | --- | --- |
| S1 | **本批提交件中存在独立图片类型文件**（`jpg` / `jpeg` / `png` / `bmp` / `tif` / `tiff` / `webp` / `heic`，或封装为单页纯图的 PDF）→ **命中即推定**本类目已提供 | 批次级扩展名 + 文件头识别 + 解码验证 + 像素尺寸读取 | 命中且可解码 → **通过**（报告须标「按文件类型推定」）；未命中但有含图文档 → `W01` + 提示提取（**不阻断**）；未命中且无任何文档 → **「未执行」+ `W01`**；全部命中件损坏 → `B01`；用户明确指定某件为本类目而该件非图片 → **`B03`** | 1 |
| S2 | 报告须附**双提示**：①「本类目按文件类型推定，未核验图像内容」；②「需人工确认样品照片是否符合要求」 | 检查报告 10.2 是否含**两句**提示 | 未附（缺任一句）→ **报告不合格**（不记原因码） | 1 |

**S2 为何不是原因码**：它是**预检自身的产出义务**，不是对提交物的判定。若报告漏了这句，问题在预检侧，不在供应商侧——因此不产生 `B`/`W` 码，而是判该份报告不合格、须重出（总纲 8.1 的「报告完整性」约束）。

**`S1` 改判据后，`B03` 的适用范围收窄了（v1.5）**：原来只要「提交物不是图片」就判 `B03`；现在是批次检索，**批次内无图片本身不构成 `B03`**——那是「没交」或「封装问题」，落 `W01`。`B03` 只剩两种情形：

1. **用户明确指定**某文件为本类目样品照片，而该文件不是图片（指定与实际不符，判定链断在这里）；
2. 文件头损坏到**无法判断类型**（既不像图片也不像已知文档）——此时记 `B03` 并写明「提交物形态不可归属」。

**`S1` 为什么这样改（v1.5 · 用户裁定）**：见 §1 末两段。一句话——**旧判据要求供应商把照片「命名成一张能被我识别的样品照片」，这是要求，不是检查**；新判据只问「有没有图」，把「这张图是不是样品照片」明确交给人工（`S2` 第 ② 句）。

**`S1` 未命中时的两种落点为什么不同（`W01` vs 「未执行」+`W01`）**：

| 情形 | 落点 | 理由 |
| --- | --- | --- |
| 批次内有 PDF / Word / Excel 等**可能含图的文档** | `W01` + 提示「若照片嵌于文档，请单独提取后重提」 | 照片**可能确实在**，只是封装方式无法按图片受理。判「没交」会误伤，判「已交」是无据推定——只能记缺件警告并让人处理 |
| 批次内**既无图片也无文档** | 该分则「未执行」+ `W01` | 确实没交。按总纲 3.2.4，声明含该类目、实到无 → 「未执行」+ 缺件（`src=SUB` → `W01`） |

> **本类目不记 `S04-S`**（v1.5 明确；v1.6 规范化）：`S04` 的构成要件是「该判定项须与本批**另一份文件比对**而对端不存在」，而本类目**无跨文件依赖**（§0 元信息「同批依赖：无」）——它不要求拿任何别的文件来对照。因此「本批没有图片」是**本类目整份没交**，不是「比对做不成」，结论是「未执行」+ `W01`（写明缺了哪一件），**到此为止**。
>
> **这不是本类目的例外，而是总纲限定的正常适用**（v1.6 订正）：v1.5 本段原文写「总纲 3.2.4 的『`W01` + `S04-S`』适用于一般情形，**本类目是例外，不得机械套用**」——**分则无权给总纲开例外**，那句话在规范层级上站不住（等于用分则去否定总纲条文）。总纲 **v0.20 §3.1** 已把限定写进总纲本身：「**本身无须跨文件比对的判定项，只记 `W01` 与『未执行』，不得记 `S04-S`**」。故本类目属**被限定覆盖的常规情形**，执行方按总纲 §3.1 新增的「判据落地顺序」走即可：① 先查本判定项有无跨文件依赖 → 本类目无 → 停在「未执行 + `W01`」；② **不必再查对端 `src`**（`S04-S` / `S04-C` 的分派前提根本不成立）。
>
> 硬记 `S04-S` 的代价（必须知道）：它**计入「未审条数」**，会让本类目未审计数虚增——而它一条判定都没开始做，是「未执行」不是「未审」；同时把「整份没交」写成「比对未完成」，会让人去找一份**本不存在的对端**。

## 5. 判定细则

**5.1 批次检索流程（v1.5 重写）**

按以下顺序执行，**第 5 步命中即停止**：

| 步 | 动作 | 结果 |
| --- | --- | --- |
| 1 | 取本批**可及证据集**内的全部提交件，剔除**已路由到其它类目**的独立文件（排除清单见 §5.1.1） | 候选集 |
| 2 | 压缩包（`zip` / `rar` / `7z`）**先解包**，解包所得文件加入候选集 | 候选集扩充 |
| 3 | 按**扩展名 + 文件头双校验**检索图片格式（`jpg` / `jpeg` / `png` / `bmp` / `tif` / `tiff` / `webp` / `heic`） | 命中集 |
| 4 | 对候选集中的 PDF 按 §5.2 判是否**单页纯图** | 命中集补充 |
| 5 | 命中集 ≥ 1 且至少 1 件可解码 → **`S1` 通过**，报告标「按文件类型推定」 | 结束 |
| 6 | 命中集为空，但候选集含 `pdf` / `doc` / `docx` / `xls` / `xlsx` / `ppt` / `pptx` | 见 §5.3（`W01` + 提示） |
| 7 | 候选集为空，或全为不可识读类型 | 「未执行」+ `W01` |

**扩展名与文件头不一致时以文件头为准**（改后缀不改格式是常见误操作），并在 10.2 说明。

**5.1.1 排除清单（不构成本类目提交物）**

| 已归属类目 | 其中不纳入本类目的图元 |
| --- | --- |
| 检验报告 / 测量报告 | 气泡图、测量示意图、报告内嵌照片 |
| 模具 / 检具验收报告 | 「实物照片」列 |
| PFMEA / 过程流程图 | 结构示意图、流程图 |
| 包装方案 | 包装示意图 |
| 全部文档类（PDF / Word / Excel / PPT） | **整份文档内的嵌入图**——只看它是不是「独立图片文件」，不解析内嵌图 |

> **为什么必须排除**：这些图元是**别的类目的内容**，不是供应商为「生产件样品照片」这一类目提交的东西。若不排除，任何一份带图的报告都会让本类目「自动通过」——那是把判定变成形式。

**5.2 纯图 PDF 的受理规则**

满足以下**全部**条件时，按图片受理：

1. 每页最多一张主图像，且该图像面积占页面 80% 以上。
2. 文字层为空，或提取结果仅为页眉页脚式的少量字符（< 20 字）。

受理后：

- 结论按图片判，10.2 注明「以 PDF 封装的图片，按图片格式受理」。
- **不得**因「扩展名不是图片」判 `B03`。

不满足全部条件（例如是带大量文字的排版文档内嵌照片）时，按 §5.3 处理。

**5.3 只有含文文档、没有独立图片 → `W01` + 提示（v1.5 由 `B03` 改为 `W01`）**

批次内无独立图片文件、但存在 PDF / Word / Excel 等可能含图的文档时：

- 记 **`W01`**（缺件：生产件样品照片），**不阻断**；
- 在 10.2 写提示：「**未检测到独立图片文件。若样品照片嵌于上述文档中，请单独提取为图片格式后重新提交；或在报告中注明所在文档与页码，供人工核对。**」；
- **不得**判 `B03`——旧版把「照片被封在 PDF 里」判成「提交物非图片」，等于因为封装方式给人开阻断单。

**为什么不是「已交」**：嵌入图无法按图片格式受理（无法确认它是一张完整照片，也无法保证分辨率），所以不能直接判通过；但也不能判「没交」——只能记缺件警告并交给人工。

**5.4 不判图像内容（本分则最容易被越界的一处）**

以下项目**一律 `S03`，不记问题、不影响结论**：

| 不得判的项 | 理由 |
| --- | --- |
| 照片张数是否足够 | 规则原文未规定张数 |
| 拍摄角度、光照、背景 | 属工程判断 |
| 分辨率、清晰度是否达标 | 规则原文未规定阈值 |
| 是否覆盖全部特征面、是否体现特殊特性 | 属工程判断 |
| 照片是否为本批次实物（非旧图复用） | 属真实性核查，超出预检能力 |

极低分辨率（如小于 200×200 像素）**只记入 10.2 提示**，**不记任何原因码**。

**5.5 客户差异层为空时的兜底**

本期 `E07` 只有 UAES 一条路由。若将来出现其它客户的样品照片规则（例如规定了张数与角度），**不得**套用本分则的 2 项——须先在 00-A §1 登记、§2 抽 `required_structure`，再在本分则 §7 增列差异层。

## 8. 级别与原因码

级别定义与原因码含义见总纲 5.2 / 8.1，本节只列本类目的典型情形。

| 原因码 | 本类目典型情形 | 责任侧 |
| --- | --- | --- |
| `B03` | **提交物形态不可归属**（v1.5 收窄）：用户明确指定某件为本类目而该件非图片；文件头既非图片也非已知文档 | 提交方 |

**`S04-S` / `S04-C` 本类目不产生**（v1.5 明确，**v1.6 归位**）：无跨文件依赖，缺件够不上 `S04` 的构成要件。**依据不是「本类目特殊」，而是总纲 v0.20 §3.1 的 `S04` 系适用限定**——须比对的判定项才配 `S04`，本类目一条都没有。详见 §4 末段。

## 9. 报告与输出

按总纲第 11 节「统一报告模板 v1.0」十章输出，本分则不再另行定义章序。

| 挂载位置 | 内容 |
| --- | --- |
| 第二章 | 文件级结论列填「路由 `U13` / L2」；本类目无同批组，该列填 `—`。**v1.5 起须写明命中件**：命中 N 件独立图片 / 未命中；未命中时写明分流（`W01` 或「未执行」） |
| 第四章 | 阻断项：`B03`（指定件非图片 / 形态不可归属）/ `B01`（全部命中件损坏）；警告项：`W01`（未检测到独立图片）/ `W05`（部分损坏） |
| 第九章 | 2 项结构判据结果（`RS-U13-S1`~`S2`），S2 须标明提示句是否已写入 |
| 10.1 | 提交物清单：文件名、识别格式、像素尺寸、可读性、是否解包所得 |
| 10.2 | 解析说明 + **S2 强制两句提示**：①「本类目按文件类型推定，未核验图像内容是否符合要求」；②「需人工确认样品照片是否符合要求」。**缺任一句即报告不合格** |

**结论口径**：任一 `B` 码 → 不通过；仅 `W` 码 → 通过；**「未执行」不进通过率统计**（总纲 5.1）；S2 未满足 → 该份报告不合格，须重出。

**识别置信度低不等于「未执行」**：低置信度按总纲 4.8 记 `B03`（识别失败 · 身份不可归属），出路为 4.9 人工指定。总纲 5.1 已把「未执行」收窄为**单一成因**（该条目既无分则也无 `required_structure`），识别置信度不在此列——把它记成「未执行」等于让一份认不出是谁的文件**免检放行**。

## 10. 不要做

1. 不要判照片拍得清不清楚、角度对不对、够不够张数——那是 `S03`。
2. 不要判照片是否体现了特殊特性或覆盖全部特征面——那是工程判断，属 `S03`。
3. 不要因为扩展名不是图片就判 `B03` 而不看一眼内容——纯图 PDF 必须按图片受理（§5.2），压缩包必须先解包（§5.1）。
4. 不要因为「是压缩包」直接判 `B03`——须先解包（§5.1）。
5. 不要在结论为通过时省略 S2 的人工复核提示——这是本类目唯一不可省的输出。
6. 不要用「识别失败」四个字代替具体措辞（§4 末段）。**`B03` 在 v1.5 只用于两种情形**：客户识别不出、用户指定件非图片——「批次内没图」不是 `B03`。
7. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。本类目本来就没有模板，更无从反推。
8. 不要因本批次缺其它文件记任何问题——本类目无同批依赖，**缺件只记 `W01` + 「未执行」，不得记 `S04-S` / `S04-C`**（§8 末段）。
9. 不要在报告里出现「疑似」「可能」类未定级表述。
10. 不要新增章、调整章序或自定义报告字段。
11. 不要修改 `00-A §2.1` 的判据文本；判据有误应先改 00-A，再同步本分则。**v1.5 的 `S1` 改写即由 00-A §2.1-U13 先行、本分则同步**。
12. **不要只判了前几张照片就给出整份结论**——多张一律逐张判定；没判完就记 `S06` 把缺口标出来，不得默认「其余应该也一样」。
13. **不要把 `S06` 当成 `B03`/`B01` 的替代或补充**——文件本体不可判仍按 `B03`/`B01` 落码，`S06` 只登记「没判完」这件事，不改变结论、不进整改单。
14. **不要把「批次内有图片」当成「本类目一定通过」**——必须先做 §5.1.1 排除，否则任何带图的报告都会让本类目自动通过，判定形同虚设。
15. **不要因为命中的图片不是「样品照片」就判 `B03`**——文件类型只能证明「这是一张图」，内容归属是人工的判断（`S2` 第 ② 句）。**这是本类目的能力边界，不是缺陷**。
16. **不要省略「按文件类型推定」六个字**——结论为通过时，报告必须让读者知道这个「通过」只代表「有一张图」，不代表「照片合格」。

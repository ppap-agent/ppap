## 1. 目的与边界

**目的**：判定这份《过程流程图》**是否具备可被对应客户审核的结构**——表头字段是否齐、工序行是否承载了活动信息、符号或连线是否表达了工序流转。

**为什么三个客户共用一份分则**：三家的判定对象是同一个文件类型（PFD），差异集中在**表头字段集**与**表达方式**，而非判定体系。按客户拆成三份会产生大量重复的通用细则与三处维护点；按字典号归并为一份、把差异放进 §7，与 `PPAP-01-1` 一份同时覆盖 UAES `E01` 与理想 `T01` 是同一做法。

**但三家差异是实质性的，不可互换判据**：

| 客户 | 表达方式 | 核心判定逻辑 | 判据数 |
| --- | --- | --- | --- |
| **UAES** | 图形化流程图（符号 + 连线） | 判**符号体系是否标准化**：关键工序有无标记、活动是否用图形符号、图例是否自洽 | 8 |
| **理想** | 表格化流程图（行 × 六类活动列） | 判**表头 8 字段 + 两个特性类别列 + 六类活动列是否填 + 是否有连线** | 8 |
| **蔚来** | 表格化流程图（行 × 六类活动列）+ 起止工序 | 判**表头 9 字段（多「修订日期」）+ 起止工序完整性 + 返工后须检验 + 跨文件对齐** | 11 |

**最容易被误用的一点**：把 UAES 的「符号必须标准化」套到理想 / 蔚来（它们是表格，没有符号）；或把理想的「六类活动列」套到 UAES（UAES 规则未要求六列）。**跨客户套用会整片误判。**

**边界三条**：

1. 本类目**不判实测值**，故不产生 `B06`；但判**连线与符号的内部一致性**，落 `W03` / `W06`。
2. 蔚来有跨文件依赖（特殊特性清单），缺对端一律 `W01`，**不阻断**。**此处不产生 `S04`**——本分则判定源为 L2（总纲 4.7），只判结构存在性与必填性、**不做跨文件一致性判定**，故无「受阻判定项」；`W01` 为缺件提示。升为 L1 后须按总纲 3.2.4 补 `S04-S` / `S04-C`。
3. UAES 与理想的客户差异层互不生效——报告须写明命中的是哪一条路由。

近义**只用于确认存在**。取值另按各条判定，不得因「列名近义通过」而放行取值。

**5.2 UAES 符号体系判定（S1 / S4 / S6 / S7）**

**关键工序标记的可接受形态（S1，任一命中即通过）**：

| 形态 | 识别方式 |
| --- | --- |
| 字符标记 `K` / `K1` / `K2`… | 工序框内或旁侧文字含 `K` + 数字 |
| 符号 `★` / `◆` / `▲` / `●` | 图形或文字符号 |
| 加粗 | 工序框文字字重加粗 |
| 底色填充 | 工序框有背景色（非白） |
| 虚框 / 双框 | 工序框线型为虚线或双线 |

**标准化图形符号的可接受形态（S4）**：

| 活动类型 | 标准符号 | 说明 |
| --- | --- | --- |
| 工序 / 制造 | 矩形 `□` | — |
| 检验 | 菱形 `◇` 或圆 `○` | — |
| 运输 | 箭头 `→` 或平行四边形 | — |
| 存储 | 倒三角 `▽` | — |
| 决策 / 分支 | 菱形 `◇` | 与检验菱形区分靠框内文字 |

**S4 的判定**：图中**至少 3 种**活动类型使用了上述标准形状，且**不存在**「全部工序都是纯文字矩形框」的情形。若整图均为同一矩形 + 文字，判 `B05`（纯文字列表）。若部分工序用图形符号、部分用文字，S4 通过，混用问题由 S6 判 `W03`。

**S6 的判定**：按活动类型聚类，同一类型出现 2 种以上不同形状 → `W03`。示例：检验既有菱形又有圆形 → `W03`。

**S7 的判定**：进货 / 过程 / 最终 / 巡检 / 自检五类检验活动，须能从符号（或符号 + 文字）识别为「检验」。全部检验活动都无法识别 → `W03`；部分可识别 → 通过，报告 10.1 列出未识别项。

**5.3 理想 / 蔚来「两个特性类别列」的判定（`L11-S2`）**

1. 「两个」指**产品**特性类别列与**过程**特性类别列各一，不是同一列出现两次。
2. 判定方式：分别匹配「产品…类别」与「过程…类别」；若只有一列名为「特性类别」（未区分产品 / 过程），记 `B05`（不足两列）。
3. 两列的**顺序**不作要求：产品列在前或过程列在前均可，按列名语义归属 `S3` / `S4`。

**5.4 `【G】` / `【Z】` 的符号含义（`L11-S3` / `L11-S4`）**

| 符号 | 含义 | 预检只做 |
| --- | --- | --- |
| `【G】` | 关键特殊特性（对应 CC） | 判「取值是否在集合内」 |
| `【Z】` | 重要特殊特性（对应 SC） | 同上 |

**预检只判取值是否 ∈ {`【G】`, `【Z】`}、以及有值后同行特性是否非空**，**不判**「这个特性该不该标为 G」。是否标对属 `S03`。

**5.5 六类活动列的「连线」判定（`L11-S8`）**

「连线」允许以下任一实现：

| 实现方式 | 识别方式 |
| --- | --- |
| 单元格边框线连通 | 相邻行有内容单元格之间存在连续的边框线 |
| 箭头图形 | 图形层存在箭头连接两个有内容单元格 |
| 专门的「连线 / 流程」列 | 该列有内容且内容表达流转 |

三种任一成立即视为「存在连线」。**不得**要求必须是矢量箭头——表格化流程图的连线常以边框实现。

**5.6 蔚来起止工序的判定（`N05-S8` / `N05-S9`）**

| 项 | 命中条件（任一） |
| --- | --- |
| 起始工序 | 「进料检验」/「来料检验」/「IQC」/「进货检验」 |
| 最终工序 | 「出货检验」/「出货」/「FQC」/「OQC」/「最终检验」 |

**只判存在，不判位置**——起始工序是否真的是第一行、最终工序是否真的是最后一行，属工序拆解合理性，记 `S03`。

**5.7 蔚来 S10 返工后须检验的判定**

1. 定位「返工」或「返修」有标记的行。
2. 检查**紧接的下一行**（行序 +1）的活动列是否为「检验」或「重检」。
3. 不符 → `W06`，报告写明行号与下一行的实际活动。
4. 返工行为**最后一行**（无下一行）时 → `W06`，写明「返工后无检验工序」。
5. **不得**跨多行搜索——规则原文是「下一行」。

**5.8 蔚来 S11 跨文件对齐（总纲 10.5）**

1. 建组键：**（客户 × 零件号）**。
2. 在本批次内查找同组的《特殊特性清单》（`T12`）。
3. **未找到对端 → `W01`**，写明「缺比对文件《特殊特性清单》」，**不阻断**。
4. 找到对端 → 按映射关系逐项比对：`特性分类` + `特殊特性种类` + `特性描述` + `特性值` → `【产品/过程】【类别】` + 特性。
5. 对不上的，按总纲 10.3 定归属（可能是 PFD 漏列，也可能是清单多列）；**不得**默认判 PFD 有责。
6. **不得**因缺对端而把 S1~S10 一并判缺失。

**5.9 客户差异层切换时的兜底**

若识别出的客户不在 UAES / 理想 / 蔚来三家之内，**不得**按任一家判定——须先在 00-A §1 登记、§2 抽 `required_structure`，再在本分则 §7 增列差异层。

## 6. 执行流程

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 识别：（客户, 文件类型）=（三家之一, 过程流程图），置信度 ≥ 中 | 路由 = `U16` / `L11` / `N05` |
| 2 | **按路由锁定判定项集**（§4.1 / §4.2 / §4.3），另两组不生效 | 生效判据清单 |

| 4 | 判「结构类」判据：UAES `S1`、`S2`、`S4`、`S8`；理想 `S2`、`S5`、`S6`；蔚来 `S3`~`S6` | `B05` |
| 5 | 判「内容类」判据：UAES `S3`、`S5`~`S7`；理想 `S3`、`S4`、`S7`、`S8`；蔚来 `S3`、`S4`、`S7`~`S10` | `W01` / `W02` / `W03` / `W06` |

## 7. 客户差异层

### 7.1 三家差异对照（判据不可互换）

| 维度 | UAES（`U16`） | 理想（`L11`） | 蔚来（`N05`） |
| --- | --- | --- | --- |
| 表达方式 | 图形化流程图 | 表格化（行 × 六类活动列） | 表格化（行 × 六类活动列） |
| 表头字段数 | 未规定（判符号体系） | **8 项**（无修订日期） | **9 项**（含修订日期） |
| 特性列组织 | 产品特性 / 过程特性列内标符号 | **两个**独立「特性类别」列，取值 `【G】`/`【Z】` | 产品 / 过程各一组「特性 + 类别」列 |
| 六类活动列 | **不要求** | 要求（制造 / 运输 / 存储 / 检验 / 返工 / 报废） | 要求（同左） |

| 图例 | 要求（`S3`、`S5`） | 不要求 | 不要求 |
| 起止工序 | 不要求 | 不要求 | **要求**（进料检验 / 出货检验） |
| 返工后须检验 | 不要求 | 不要求 | **要求**（`S10`） |
| 受控章 | **要求**（`S8`） | 不要求 | 不要求 |
| 跨文件依赖 | 无 | 无 | **特殊特性清单**（`W01`） |
| 判据数 | 8 | 8 | 11 |

### 7.2 三条硬约束

1. **跨客户套用判据即误判**：UAES 的符号标准化要求**不得**套到理想 / 蔚来（它们是表格，无符号）；理想的六类活动列要求**不得**套到 UAES（规则未要求）。
2. **表头清单不可合并**：蔚来 9 项含「修订日期」，理想 8 项不含。判蔚来时缺「修订日期」是 `B05`；判理想时**要求**有「修订日期」是加严。
3. **受控章只对 UAES 生效**：不得因 UAES 要求受控章而要求理想 / 蔚来也盖章。

### 7.3 预留位

新增客户时在本表加行，并同步在 00-A §1 / §2 登记。客户差异**只允许增删判定项、调整必填范围**，不得改本分则 §5 的通用细则。

## 10. 不要做

1. **不要跨客户套用判据**（§7.2 第 1 条）——这是本类目最严重的错误。
2. 不要要求理想 / 蔚来提供关键工序标记与图例（那是 UAES 的判据）。
3. 不要要求 UAES 提供六类活动列与两个特性类别列（那是理想 / 蔚来的判据）。
4. 不要要求理想 / 蔚来盖章（受控章只对 UAES 生效）。
5. 不要把蔚来的「修订日期」要求套到理想（§7.2 第 2 条）。
6. 不要判工序划分是否合理、关键工序选得对不对、特殊特性标得对不对——那是 `S03`。
7. 不要判 `【G】` / `【Z】` 标得是否正确——只判取值是否在集合内（§5.4）。
8. 不要要求连线必须是矢量箭头——边框线连通也算（§5.5）。
9. 不要跨多行搜索返工后的检验（蔚来 `S10`）——规则原文是「下一行」（§5.7）。
10. 不要判起始 / 最终工序是否在首末行（蔚来 `S8` / `S9`）——只判存在（§5.6）。
11. 不要因缺《特殊特性清单》而把其它判据一并判缺失（§5.8 第 6 项）。
12. 不要在未锁定路由时开始判据（§6 第 2 步）。
13. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。
14. 不要在报告里出现「疑似」「可能」类未定级表述。
15. 不要新增章、调整章序或自定义报告字段。
16. 不要修改 `00-A §2.1 / §2.2 / §2.3` 的判据文本；判据有误应先改 00-A，再同步本分则。

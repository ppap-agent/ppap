> 版本：v3.8

## 1. 目的与定位

本规则用于在正式审核之前，对待审的报告集做数据标准化预检，判断这批报告是否具备被后续规则审核的条件。

核心目的、非目标与三维度口径统一见总纲第 1、2、7 节；本分则只声明本类目的判定对象与业务边界。

**边界**：本规则只判断“能不能审”，不判断“审下来合不合格”。预检通过不等于报告合规，预检不通过不等于报告不合格。所有业务规则的符合性结论、防造假结论均由正式审核出具。

**判定维度只有三维**：数据正确性、数据完整性、数据一致性。原“规则可执行性”维度按总纲 2.3 不属本分则判定范围，本文件不接收规则文件实体、不比对规则与字典版本、不输出任何关于规则集的结论。

## 2. 范围与非目标

### 2.1 范围内

- 接收本次批次的报告集与范围声明。
- 识别批次内哪些文件属于本项报告型载体（顺序判定见 6.2）。
- 识别不可解析文件与结构不可还原的报告（6.3）。
- 以整个批次为对象，进行数据正确性、完整性、一致性检查。
- 自主推断跨文件、跨页、跨内嵌子报告的关联项。
- 输出 Markdown 报告，含批次级、文件级、报告级、要素级结论。

### 2.2 非目标

- 不重审规则文本、不评价规则合理性、不裁定规则口径。
- 不给出任何业务规则的符合性结论，不做防造假判定。
- 不负责 OCR、表格抽取、文档解析等技术实现，不规定工具路线。
- 不修复、不补全、不转换、不合并/拆分文件，不含整改后复检。
- 不输出评分、排名、通过率、健康度。
- 不输出程序可直接消费的 Schema。

### 2.3 批次边界

| 编号 | 要求 | 落点 |
| --- | --- | --- |
| BT-1 | 范围声明须含：项目标识 + PPAP 项清单 + 每项报告清单 + 全量/部分 | `COM-01` |
| BT-2 | 范围声明须与实际文件一致（名称、数量、版本） | `COM-01` |
| BT-3 | 同一报告多版本时须有版本说明 | `COM-02` |
| BT-4 | 依赖“计划—报告”配对的规则，仅报告一端提交时，计划端不判缺件 | `S04` 对端未到状态（配套 `W01`；**不是 `S01`**——该对象属本次范围、本批应收而未到） |
| BT-5 | 跨 PPAP 项一致性以同批提交为限；其他项未提交时不判不一致 | `CON-10` |

表单型文件（xlsx 计划+报告区）移交姊妹篇，不按本规则审。

### 2.4 规则侧事项一律排除

预检假定规则集已在前置入口定型、生效并完成口径裁定。规则是否录入、条数是否完整、引用字段是否在字典内、口径是否下发、规则是否自相矛盾，**一律不作为问题登记，不影响结论**（详见总纲 2.3）。

若规则集实际不可用，本规则**不产出任何结论**，直接返回「未执行」，由规则运营补齐后重跑；不得降级为「不通过」，也不得打回供应商。

### 2.5 证据封闭性

判定证据须落在**可及证据集**内（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源，总纲 3.2.1 / 4.4）；提交范围声明、项目上下文、应有件清单只能用于**排除**，不能用于**推定应有**。**不得因「应该有但没交」判缺件阻断**；缺项按两条通道分流，均不构成缺件阻断——跨文件对端缺按 `src` 记 `W01`+`S04-S` 或仅 `S04-C`，本文件区块缺按 7.2 分流（承载关键字段 → `B05`，不承载 → `W01`）。

| --- | --- |
| 报告型载体 | 独立成册的试验报告，具备封面、汇总、详情、照片、签署五段结构 |
| 表单型载体 | DVP&R 合一 xlsx，计划与报告并列在同一表内；不受本规则管辖 |

### 3.1 状态词：四个必须区分的概念

**「不适用」一词禁用**，必须按下表拆分为四种之一。四者为**状态**，不是级别，不参与通过判定。

| 状态 | 代码 | 定义 | 是否产生级别 |
| --- | --- | --- | --- |
| 范围外 | `S01` | 该对象**本就不属**本次提交范围（如 R1 部分提交下计划端本不在范围），或该文件不属本项类目。**判据与「交没交」无关** | 否 |
| 对端未到 | `S04` | 属本次范围、**在可及证据集内不存在**（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源，总纲 3.2.1；如已声明计划端却只交报告一端）。**分两子型**：`src=SUB` → `W01` + **`S04-S`**；`src=CUS`（如客户图纸、规范、模板本体）→ 仅 **`S04-C`**、**不配 `W01`**、不进缺件数，受阻的配对判定项记本态 | 否 |
| 规则不适配 | `S02` | 规则侧成因导致该项在本类目上无判定依据（预检不评，仅登记） | 否 |
| 移交 | `S03` | 该判断属正式审核（超差、合规、有效性、造假），预检只登记不判 | 否 |

**关键区分：**

- 「范围外」≠「文件不含该对象」。前者是该对象本就不属本次范围，后者是交了但文件里没有这个字段。
- **「本批没交」不再等于「范围外」**：属本次范围而应收未到记 `S04`（对端未到，配套 `W01`），`S01` 只留给「本就不属本次范围」（总纲 3.1、`BT-4`）。
- **`S04` 分两子型，判前必先核「可及证据集」（总纲 3.2，v0.7 新增）**：对端在 `SRC-1`（提交件）或 `SRC-2`（受控提供源：客户图纸、技术规范、客户表单模板、客户侧台账）内**已存在**的 → **正常比对，绝不记 `S04`**。集内确实没有时按 `src` 落码：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取）→ 仅 **`S04-C`**、**禁配 `W01`**、不进缺件数、进报告七章 7.2b。`src` 一律查《PPAP-00-A》**§4.3 对端来源登记表**，查不到记 `S02` 并报缺口，**不得现场推定**。**本分则全文凡记 `S04` 之处，一律按本子型标注。**
- **`S05`（受控模板缺结构）继承总纲**：本分则凡判 `B05` 之处，须先按总纲 **3.1 三分界**与 **5.2 两问**确认成因——查《PPAP-00-A》**§4.4 客户受控模板登记表**：该（客户 × 类型）登记**有**受控模板、且**模板本体也没有该列** → 记 **`S05`**（状态，**不阻断**、不配 `B`/`W` 码、不进缺件数、进报告七章 **7.2c**）；登记**无**（不限定表单格式）或**模板有而文件没有** → 仍记 `B05`。**本分则的 3.1 状态词表不列 `S05`**——它的定义、边界与取证要求只在总纲 3.1 / 3.3 / 5.2 维护，避免同一概念在多处分别表述。**`B`/`W` 原因码取值与判定严格程度逐字未改。**　**枚举优先级**：本分则凡用列举方式写状态码的地方——**判定结果取值、状态登记清单、六章装填白名单、「必须按 3.1 拆为…」之类的执行要求**——`S05` **都在其列**（分「已核对」/「待核」两种形态）。**若某处枚举文本仍只列到 `S04-C`，以本条为准**，不得因该处漏列而拒绝登记 `S05`。理由：v0.9 把 `S05` 加进总纲 3.1 之后，各分则的枚举没有同步扩，若按枚举字面执行，`S05` 会**有判据、无落点**——判出来了却装不进状态登记清单，等于这一档不存在。
- 「文件不含该对象」（如三方报告本身不设试验类型栏）**是材料侧问题，按缺项记 `W01` 警告**（见 7.2），不得记 `S01` 或 `S02`。
- 「规则不适配」只用于规则侧成因，不得用它兜住“文件里没有这个字段”。

## 4. 输入契约

### 4.1 必选输入

1. **批次报告集**：本次提交的全部文件。
2. **范围声明**：项目标识、本次覆盖的 PPAP 项与文件清单、全量或部分（BT-1）。

### 4.2 可选输入

- 申报阶段（DV / PV）说明；缺失时按 6.2 与 4.4 推断。
- 同源或配对的另一端文件（DVP 计划、其他 PPAP 项报告）。
- 客户专属报告模板或空白表格。

### 4.3 解析责任边界与能力前提

- OCR、表格抽取、图文理解、文档解析由外部系统或模型层负责，本规则不规定实现方式。
- 本规则基于可访问的文件内容、解析结果或模型多模态理解能力判断。
- 无法获得可判定证据时，记“文件无法解析”类问题（`COR-08` / `COM-10`），不得跳过检查。
- **执行方不具备视觉能力时**：印章、照片、签名类检查标注为「未执行」，在报告「未进行的检查」栏逐项声明（原 `EXE-09` 废止）。此类情形不产生任何级别、不判供应商——它不是文件缺陷，而是本次预检未覆盖的部分，须在下游正式审核中补齐。

### 4.4 缺失输入的降级策略

| 缺失项 | 降级方式 | 级别 |
| --- | --- | --- |
| 范围声明 | **按总纲 4.2 推定部分提交**（不做全量推断）；完全缺失记 `W01`，**不判 `B02`** | 警告 `W01` |
| 申报阶段 | 可按文件名 + 报告结构 + 编号阶段码推断，须写明路径与置信度；推断不足即阻断 | 阻断 `B03` |
| 判定用词归一表 | 可按语义相似度归并，须列出被归并的候选写法 | 警告 `W03` |
| 实验室名录 | 只按名称与章面文字推断性质，置信度记中 | 不记录 |
| 项目级应提交清单 | 不做范围外检查 | 不记录 |

> 原“规则集 / 字典版本”一行随规则侧退出而删除：预检不接收该输入，也不以其缺失为由判定任何问题（总纲 2.3）。

## 5. 输出契约

### 5.1 总体结论（仅两级）

| 总体结论 | 判定条件 | 后续处理 |
| --- | --- | --- |
| 通过 | 未发现阻断项 | 本批次可进入正式审核；警告项 100% 随报告移交 |
| 不通过 | 存在任一阻断项 | 按责任侧分派：材料侧打回整改、提交方补正、解析侧转技术支持 |

**另有唯一非结论返回值**：规则集不可用或本批无任何待审文件时，返回「未执行」并说明原因，不产出通过 / 不通过。

报告首段须同时给出：阻断 N 项 / 警告 M 项 / 状态 K 项（`S01` a / `S02` b / `S03` c / **`S04-S`** d / **`S04-C`** e），以及适用范围（项目标识、覆盖的 PPAP 项与文件数、是否部分提交）。部分提交时须声明对未提交部分不下任何结论。

### 5.2 原因码

结论为「不通过」时必须给出原因码。**一个阻断项一个码**，不得合并。

**阻断原因码**

码的含义见总纲 5.2，下表只列本类目典型情形。

| 码 | 本分则典型来源 |
| --- | --- |
| `B01` | `COM-10` 内嵌子报告不可解析且无替代 |
| `B02` | `COM-01`、`COM-02` |
| `B03` | `COM-03`、`COM-04`、`COM-06②` |
| `B04` | `COM-05` |
| `B05` | `COM-07`、`COM-08`、`COM-09`、`COM-13`、`COM-15` |
| `B06` | `COR-01`、`CON-01`、`CON-02`、`CON-03` |

**警告原因码**

码的含义见总纲 5.2，下表只列本类目典型情形。

| 码 | 本分则典型来源 |
| --- | --- |
| `W01` | `COM-06①`、`COM-07` 降级、`COM-11` |
| `W02` | `COM-14`、`COR-03`、`COR-04` |
| `W03` | `COR-02`、`COR-05`、`COR-06`、`COR-07` |
| `W04` | `CON-04`、`CON-06`…`CON-10` |
| `W05` | `COR-08`、`COR-09`、`COR-10`、`COM-10` |
| `W06` | `COR-11`、`CON-05`、`CON-11` |

> 原因码只做归因标签，不改变级别。同一条问题同时符合两个码时取更能说明成因的一个，并在证据链注明“同时构成 X 类”。

### 5.3 报告形式与问题记录字段

输出 Markdown 报告，证据落到最小颗粒度（文件 → 页码 → 页内区域；表格到行列，正文到段落或图注）。

| 字段 | 说明 |
| --- | --- |
| 编号 | `B-xx`（阻断）/ `W-xx`（警告）；状态项不编号，登记在状态表 |
| 类型 | 数据不规范 / 文件无法解析 |
| 细分类型 | 正确性 / 完整性 / 一致性 |
| 检查项编号 | `COR` / `COM` / `CON` 编号 |
| 原因码 | `B01`~`B06` / `W01`~`W06` |
| 位置 | 文件 → 页码 → 页内区域；跨页问题列全部位置 |
| 证据链 | 原值（不可见字符须显式标注）+ 位置 + 推断依据 + 关联项 |
| 影响 | 具体说明会让哪一条规则、以何种方式失真 |
| 严重级别 | 阻断 / 警告 |
| 责任侧 | 材料侧 / 提交方 / 解析侧 |
| 置信度 | 高 / 中 / 低，须说明依据 |
| 整改方向提示 | 给责任侧的可执行动作 |

### 5.4 结论颗粒度

| 颗粒度 | 输出要求 |
| --- | --- |
| 批次级 | 总体结论、原因码、适用范围、阻断清单、警告清单、状态登记、责任侧分布 |
| 文件级 | 每份文件是否存在阻断项、阻断数与警告数、最高级别 |
| 报告级 | 一份文件可能含多份报告或内嵌子报告，须逐份给结论 |
| 检查项级 | 每条检查项 满足 / 不满足 / `S01`~`S04` |
| 要素级 | 七类形式要素各自的可取性 |

### 5.5 不输出的内容

- 业务规则的符合性结论（该规则是否合规、不符合项数）。
- 防造假结论（过期、造假、敷衍、错配、未闭环）。
- 评分、排名、通过率、健康度。
- 任何关于规则集、数据字典、判定口径的问题或建议。

## 6. 执行流程

### 6.1 接收与范围确认

1. 接收报告集与范围声明。
2. 核对范围声明与实际文件（名称、数量、版本，BT-1、BT-2）。
3. 登记同一报告的多版本（BT-3）。
4. 剔除范围外文件（`COM-12`，记 `S01`）。
5. 确认全部或部分提交，并在报告中写明适用范围。

### 6.2 载体归属判定（顺序，不是并列条件）

1. **是否本项报告型载体**：有报告标题且具备五段结构中的可识别段落 → 本项。
2. **是否表单型载体**：具备“计划列 ≥2 项”（计划开始 / 计划结束 / 完成节点 / 样本状态）→ 移交姊妹篇，不按本规则审，记 `S01`。
3. **是否非本项**：无任何报告特征 → 剔除，记 `S01`（`COM-11`）。

有报告标题但结构要素严重缺失 → 记 `COM-05` 阻断 `B04`，本项不判“是否冒充”（防造假属正式审核）。

**申报阶段判定**：按「试验类型 / 项目阶段」标签 → 编号阶段码 → 标题与文件名顺序推断；三者皆无 → `COM-03` 阻断 `B03`。

### 6.3 可读性与结构核验

1. 逐份文件确认可访问、可解析；无法解析且无同源替代 → `B01`。
2. 确认五段结构可分段还原（封面 / 汇总 / 详情 / 照片 / 签署）→ 否则 `B04`（`COM-05`）。
3. 确认汇总表行与详情页可一一对应 → 否则 `B04`（`COM-05`）。
4. 识别内嵌子报告并单独登记；不可解析 → `COM-10`（有替代来源记 `W05`，否则 `B01`）。

**终止条件**：第 1、2 步任一失败，该文件后续内容检查不再执行，直接定级出结论；不得在结构不可判的情况下继续做内容比对（总纲 6）。

### 6.4 三维度检查

数据正确性（`COR`）、数据完整性（`COM`）、数据一致性（`CON`）并列执行。

判定前须先固定四件事：① 载体归属已确定；② 报告结构已分段；③ 汇总表行已与详情页一一对上；④ 内嵌子报告已识别并单独登记。四项未固定时不得开始判定——否则“某要素全篇不存在”只是取数失败，不是报告缺陷。

### 6.5 汇总判定与输出

1. 汇总全部问题并去重：同一根因跨文件重复时合并为 1 条 + 位置清单。
2. 计数口径并列给出、互不换算：问题清单按去重条目计数；文件级结论按该文件命中的检查项计数。
3. 同一事实落入多个检查项时取最高级别，注明“同时构成 X 类问题”，不重复计数。
4. 按 8.2 出总体结论并给出原因码，按 8.3 归集责任侧。
5. 按第 9 节模板输出。

## 7. 判定口径

### 7.0 编号与分级总则

- `COR` 正确性 / `COM` 完整性 / `CON` 一致性。
- **检查项共 37 项**：`COR` 11、`COM` 15、`CON` 11（v3.0 起；v2.0 及以前为 45 项，含 `EXE` 9 项）。
- 批次边界 `BT-1…BT-5` 是规则条文编号，不是检查项编号。
- 级别只有两种：阻断 / 警告。**观察项已取消**，原观察项按总纲 3.1 拆为 `S01` / `S02` / `S03` / `S04` 四种状态，登记于状态表，不参与通过判定。
- 升级与降级条件写在各表内，与表内默认级别同行生效。

### 7.1 数据正确性（COR）

关注报告内的数据本身是否科学、合理、自洽，不判业务规则符合性。

| COR-03 | 占位数据充当真实值 | 取值为占位集合：递增数字编号、`客户 A/B/C 公司`、`供应商代码 ABC`、`/`、`N/A`、`--`、`无`、`XX` | 警告 `W02` | 落在编号 / 件号 / 阶段且无替代来源 → 阻断 `B03` | 材料侧 |

| COR-08 | 局部不可解析导致证据不完整 | 文字层损坏、单元格被行高截断、内嵌图模糊或被遮挡、关键说明仅在批注 | 警告 `W05` | 承载判定所需值且无替代来源 → 阻断 `B01`；因执行方无视觉能力 → 该项标注「未执行」，不记级别（4.3） | 解析侧 / 材料侧（按成因） |
| COR-09 | 页码或分页体系矛盾 | 末页页脚与文件实际页数不符、出现 `1/888` 类写法、连续页码中断 | 警告 `W05` | — | 材料侧 |
| COR-10 | 印章形态不可识别 | 有印章痕迹但仅余残弧、章面文字不可辨、盖章压住正文 | 警告 `W05` | 印章完全不存在 → 不记本项，记 `COM-13` | 材料侧 |
| COR-11 | 页内自相矛盾 | 同页汇总与详情判定方向相反；同页出现两个件号；样品数量与后续分组描述不符 | 警告 `W06` | 涉及判定结论 → 阻断 `B06`（与 `CON-05` 同一事实，只计一次） | 材料侧 |

### 7.2 数据完整性（COM）

判断规则所需的数据前提是否存在、是否可定位、是否可归一。

| 编号 | 检查项 | 判据 | 默认级别 | 升级 / 降级 | 责任侧 |

| COM-02 | 同一报告多版本并存且无版本说明 | 见 BT-3 | 阻断 `B02` | 提交方书面指定唯一有效版本 → 不记录 | 提交方 |
| COM-03 | 验证阶段不可确定 | 未声明，且编号 / 标题 / 文件名均无 DV/PV 标识 | 阻断 `B03` | 声明后自行解除 | 提交方 |

| COM-07 | 三段照片不可得 | 全篇无试验前 / 试验中 / 试验后图注，或仅 1 张说明性 / 截面图 | 阻断 `B05` | 载体类型本身不含过程照片且规则未强制 → 警告 `W01` | 材料侧 |

| CON-08 | 印章 / 签署主体与出具方不匹配 | 印章文字 ↔ 封面出具单位 ↔ 实验室性质 | 警告 `W04` | 不判真伪 |

### 7.4 规则可执行性（EXE）：本分则不设

按总纲 2.3，规则侧问题不在预检判定范围内，原 `EXE-01`~`EXE-09` 九项，均不设。

| 旧编号 | 原检查项 | 去向 |
| --- | --- | --- |
| EXE-01 | 判定依据不可追溯 | 删除（纯规则侧） |
| EXE-02 | 规则引用字段不在字典内 | 删除（纯规则侧） |
| EXE-03 | 规则依赖字段在本批次 100% 不可得 | **重分类为 `COM-15`**（判定所需关键字段在结构上不存在），阻断 `B05` |
| EXE-04 | 判定阈值口径未定义 | 删除（纯规则侧） |
| EXE-05 | 规则在同一载体上存在两种执行方向 | 删除（纯规则侧） |
| EXE-06 | 依赖计划—报告配对的规则仅一端提交 | 改为 `S04` 对端未到状态，不设检查项 |
| EXE-07 | 已确认口径未随规则集下发 | 删除（纯规则侧） |
| EXE-08 | 未确认口径在本批次被触发 | 删除（纯规则侧） |
| EXE-09 | 执行方能力不足导致不可判 | 删除；改为 4.3 的能力前提，标注「未执行」，不记级别、不判供应商 |

**退出的边界**：

- `EXE-03` 之所以保留（改为 `COM-15`），是因为它的现象落在文件上——“这份报告里根本没有这一栏”，属文件结构缺陷，只是 v2.0 把整改责任派给了规则方。
- `EXE-06` 转为 `S04`（对端未到）：「计划端没交」使报告端的配对项无对象，但它**不是范围外**——该对象属本次范围、本批应收而未到（总纲 3.1）；且按 2.3 BT-4，计划端本身不判缺件。
- `EXE-09` 转为能力前提，因为“执行方看不了图”不是待审文件的属性，登记成问题会对供应商产生虚假指控。
- 其余六项的现象与责任都在规则侧，不符合“预检只判待审文件”的定位，不留任何出口。

原 6.3 规则可执行性预检整节、8.3 责任表的“规则所有者”行、报告模板的“需回退规则入口的事项”章节一并删除或改写。

### 7.5 客户差异层与结构基线

本分则是**单条目分则**：本期只承载 **理想 × DV / PV / 试验报告（`T03`）** 一条。单条目不等于「与客户无关」——它同样按总纲 4.7 路由，只是当前只登记了一条。

**（1）路由声明**

| 项 | 内容 |

| 载体边界 | 独立成册的试验报告；DVP&R 合一表单（xlsx）→ 02-1；实验室资质证书 → 02-3 |
| 其他客户同类型 | 规则未提供 → L3，记 `S02`，**不得**套用本分则判定 |

**（2）`required_structure` 结构基线**（源自客户审核规则 02 报告条款 1~6，与分则判定项取并集）

| --- | --- | --- | --- | --- |
| S1 | 「文件编号」或「报告编号」或「编号」字段存在且非空 | 不限模板，供应商自制或三方机构报告均可 | `COM-04`、`COR-01` | 缺字段 → `B05`；多值 / 残缺 → `B06` |
| S2 | 判定 / 结论取值 ∈ {符合, 通过, 合格, P, pass} | **严格一致，不接受意思相近的其他文字** | `COR-02`、`COM-08` | 无法归一 → `W03`；≥50% 不可归一 → `B05` |
| S3 | 「试验类型」字段存在，取值 ∈ {`DV`, `PV`}（大小写不敏感） | — | `COR-06`、`COM-06` | 缺字段 → `B05`；越界 → `W03` |
| S4 | 文件含**印章** | — | `COM-13`、`COR-10` | 缺 → `W01`；形态不可识别 → `W05` |
| S5 | 含「试验前」「实验中」「试验后」三段**图片** | — | `COM-07` | 缺任一段 → `W01` |

**（3）关键校准：客户原文「不通过」在预检中的降级**

客户规则 02 报告条款对以下情形均判「不通过」，但预检只判「能否被可靠审核」，故按下表重定级——**这是本分则与客户规则原文的刻意偏离，必须显式声明**：

| 客户原文情形 | 预检口径 | 理由 |
| --- | --- | --- |
| 无「编号」字段 / 编号为空 | `B05`（无字段）/ `W02`（空值） | 无字段＝主键不可承载（结构缺陷）；空值＝缺值 |
| 结论词为 `PASS`、`正确`、`实验合格，缺报告` 等非白名单写法 | `W03`，**不阻断** | 写法不规范，但结论方向仍可读出；`COR-02` 已有 ≥50% 阈值升级规则 |
| 无 DV / PV 标识 | `W03`，**不阻断** | 缺一项属性，不影响报告主体可审 |
| 无印章 / 缺三段照片 / 缺样品数量 | `W01`（缺项），**不阻断** | 总纲 7.2：三项均**不承载任何判定的关键字段**，故落 `W01` 而非 `B05`（承载关键字段的区块缺失才是 `B05`）；印章与照片「够不够」属正式审核（`S03`） |

**（4）本节不新增级别与原因码**，也不改 `COR`/`COM`/`CON` 任一条判据。六项结构基线的落点全部复用既有 37 项：S1~S3、S6 由 `COR-01`/`COR-02`/`COR-06`/`COM-04`/`COM-06`/`COM-08`/`COM-09` 覆盖，S4/S5 由 `COM-07`/`COM-13` 覆盖。

## 8. 严重级别与通过规则

### 8.1 级别定义

| 级别 | 定义 | 典型形态 | 影响结论 |
| --- | --- | --- | --- |
| 阻断 | 至少一条正式审核规则**无法得出唯一结论**，含“取不到数”与“结论方向不唯一” | 编号多值、判定不可得、三段照片全缺、样品数量不可得、范围未声明、印章不存在、关键栏位结构缺失 | **是 → 不通过** |
| 警告 | 判定仍可完成，但结果不完整或存在被误判风险 | 占位数据、假填充、写法混用、页码矛盾、印章残缺、签批栏空白、汇总详情冲突 | **否 → 仅记录并移交** |

**四种状态（不是级别，不参与通过判定）：**

| 状态 | 代码 | 本分则典型形态 |
| --- | --- | --- |
| 范围外 | `S01` | 表单型载体移交姊妹篇、非本项剔除、范围外文件；R1 档下计划端本不在范围 |
| 对端未到 | `S04` | 声明了计划端而本批未交、同批其他 PPAP 项应收未到。**按 `src` 分流**：`SUB` → 配套 `W01` + `S04-S`；`CUS` → 仅 `S04-C`、**不配 `W01`**（总纲 3.2.4） |
| 规则不适配 | `S02` | 规则侧成因导致某要素在本类载体上无判定依据（预检不评） |
| 移交 | `S03` | 例外放行结论值、印章有效性、照片场景真实性、校准超期等防造假判断 |

一条问题的级别只由“能否得出唯一结论”决定，“是否规范、是否合规、是否严重”一律留给正式审核。

> **警告不拦截的补偿**：警告项 100% 列入报告第五章并随报告移交正式审核；正式审核**不得因“预检已通过”而跳过警告指向的字段**（总纲 8.3）。

### 8.2 通过规则

无阻断即通过，存在任一阻断即不通过并给出原因码；警告不影响结论但须 100% 列报并移交；状态项不参与判定但不得略去不记（总纲 8.2 / 8.3）。

本分则补充：已确认口径（13.1）直接执行，不再作为缺口登记；原 13.3 口径缺口机制已随规则侧退出废止，13.3 仅保留已关闭缺口的历史记录与运行假设。

### 8.3 责任侧与处理去向

| 责任侧 | 涉及检查项 | 处理去向 | 是否打回供应商 |
| --- | --- | --- | --- |
| 材料侧 | `COR-01`…`COR-11`（除 `COR-08` 的损坏情形）、`COM-04`、`COM-05`、`COM-06②`、`COM-07`…`COM-09`、`COM-13`…`COM-15`、`CON-01`…`CON-11` | 阻断项打回整改；警告项记录并提示整改方向 | 阻断项：是；警告项：否 |
| 提交方 | `COM-01`、`COM-02`、`COM-03`、`COM-06①`、`COM-11`、`COM-12`、BT-4 的计划端缺失（`S01`） | 补充范围声明 / 指定唯一版本 / 说明提交范围与载体类型限制 | 否 |
| 解析侧 | `COR-08`（文件损坏 / 不可读）、`COM-10` | 转技术支持核查文件或补充解析能力 | 否 |

归口要求：

- 每个检查项只有一个主责任侧；`COR-08`、`COM-06` 是按成因二选一的唯二条目，须注明成因，不得两处同列。
- **不设规则侧责任方**（总纲 10）。原表中的“规则所有者”行随 `EXE` 组退出而删除。
- 报告中“打回供应商整改”与“提交方补正 / 解析侧核查”必须分表列示，混列会把范围问题当成供应商责任。

### 8.4 级别冲突处理

- 同一事实落入多个检查项时取最高级别，注明“同时构成 X 类问题”，不重复计数。
- **禁止降级原则**（总纲 8.4）：某类问题在全批次普遍存在，**不得因其普遍性而降低级别**；报告的相应条目须注明“该问题在本批次普遍存在，属系统性缺口，非个别疏漏”。
- **禁止的调整**：阻断 → 警告（除 7.x 表内明列降级条件外）；因置信度低而降级（应保持级别并标注置信度）；因整改成本高而降级。
- 允许的调整：阻断 → 警告，仅当存在**同源替代载体**（另一格式 / 另一份同源文件可读出同一事实），须注明替代载体位置。
- 置信度为低的推断不得单独构成阻断，须降为警告并注明需人工确认。
- 例外：`COM-03`（阶段不可确定）属“推不出可用阶段”，按 4.4 判阻断，不视为低置信度推断。

## 11. 执行约束

### 11.1 必须遵守

1. 按本文件流程执行，不跳过范围确认、载体归属判定、可读性与结构核验、三维度检查。
2. 以整个批次为对象，不局限于单文件，但不得外推到未提交部分。
3. 先定载体，再定“能不能取到数”，最后才讨论“能否判定”。
4. 报告结构必须分段还原（封面 / 汇总 / 详情 / 照片 / 签署），禁止当扁平文本处理。
5. 要素按名称与位置双重定位，禁止只按关键词命中就判“存在”。
6. 不可见字符须归一化后再判空，并显式标注编码。
7. 印章只判有无，不判有效性；签批栏只判有无内容，不判是否手签。
8. 完整性允许合理推断，须写明推断路径与置信度；置信度低时不得替代缺失记录。
9. 判定所需关键栏位在结构上不存在时，记 `COM-15` 阻断 `B05`；**不得表述为“规则不可执行”或“本批次不可执行”**。
10. 三维度并列，任一维度出现阻断即不通过；警告与状态项均不计入。
11. 只有阻断项停止流程；警告项随报告放行并全部移交正式审核。
12. 证据定位到最小颗粒度；差异统计须基于全量核对，不得估算或抽样外推。
13. 保持无状态，每次调用独立判定，输出 Markdown 报告。

### 11.2 禁止事项

1. 不要输出任何业务规则的符合性结论（只能写“该要素不可取 / 无法归一，导致某规则无法执行”）。
2. 不要输出任何关于规则集、数据字典、判定口径的问题、缺口或回退建议（总纲 2.3）。
3. 不要做防造假判定（校准超期、时长不足、照片场景不符、不合格未闭环、复制粘贴敷衍）。
4. 不要用“有红色像素”判印章存在（红手套、粉色水印、红色标题会误报），须叠加形状与章面文字。
5. 不要因关键词命中就判样品数量存在（注意事项句中普遍含同名字样）。
6. 不要把“三方报告无试验类型字段”判成供应商缺填（属载体缺陷，记 `W01`；责任侧为提交方）。
7. 不要把“合格 / OK / 满足要求”判成不通过（口径①：语义等价即通过，不记级别）。
8. 不要因印章残缺判不符合（骑缝章转扫描后单页必然残缺，只记警告并 `S03` 移交）。
9. 不要把警告项当成不通过理由；不要用签批栏空白替客户规则下结论。
10. 不要把“文件缺失”直接判为供应商漏交，须先看范围声明；不得因“应该有但没交”判缺件阻断。
11. 不要对未提交的 PPAP 项下任何结论；不要因缺少同源副本就判不通过。
12. 不要用页码页脚推断总页数；不要忽略内嵌子报告。
13. 不要修复、补全、转换、合并、拆分文件，也不要生成整改后的文件。
14. 不要给分、排名、通过率、健康度，不要在报告中出现技术实现方案。
15. 不要画版面还原图、印章/照片/签名截图、通过率饼图、健康度仪表盘、解析流水线图。
16. 不要因执行方无视觉能力而把该项判成供应商问题（应标注「未执行」，见 4.3）。

| ⑤ | 三方报告不设试验类型字段时如何取数 | 判为载体缺陷：`COM-06①` 警告 `W01`，责任侧为提交方，不打回供应商。判据：四类阶段标签皆无才算缺失 |
| ⑥ | `项目阶段：PV 阶段` 能否作为试验类型取数 | 认可。属等价写法别名表内，按 `PV` 取数，**不记录** |
| ⑦ | 签批栏空白如何处理 | 不拦截：记 `COM-14` 警告 `W02`、要求补签。客户 R1–R6 未就签名提出要求；不判是否本人手签 |

> **v3.0 对 ①⑤⑥ 的处置变化**：v2.0 因“警告也拦截”，只能把等价写法与载体缺陷放进“观察项”规避；v3.0 警告不拦截后，观察项整档取消——①⑥ 改为**不记录**（口径已认可，不构成问题），⑤ 改为**警告 `W01`**（缺项，责任侧提交方，不打回供应商）。

### 13.2 取数与归一细则

**① 判定用词**

| 原值 | 处理 |
| --- | --- |
| `符合`、`通过`、`P`、`pass`、`Pass` | 视为通过，不记录 |
| `合格`、`OK`、`满足要求`、`满足` | 视为通过，不记级别（附用词提示，见 13.1①） |
| `F`、`Fail`、`不合格`、`NG` | 不记录（属正式审核的结论值） |
| `带偏差放行`、`pass with deviation`、`偏差认可` | 例外放行类，以 `S03` 移交正式审核，不并入归一 |
| 空白、`/`、`--`、`N/A` | 在判定列记 `COM-08`；在其他字段记 `COR-03`，两者不并记 |

**② 试验类型**

| 判据 | 成因 | 处理 | 责任侧 |
| --- | --- | --- | --- |
| 存在「试验类型 / Test type / 试验阶段 / 项目阶段」任一标签（该位置可填 DV/PV），值为空或占位 | 填报缺陷 | `COM-06②` 阻断 `B03` | 材料侧 |
| 四类标签皆无（含仅「测试阶段：Others」） | 载体缺陷 | `COM-06①` 警告 `W01`，判“本批次未识别到阶段标识”，不打回供应商 | 提交方 |
| 有标签、值非 DV/PV 且语义不同（`空腔验证`、`型式试验`） | 取值越界 | `COR-06` 警告 `W03`，提示改标 | 材料侧 |
| 有标签、值为 `PV 测试`、`DV 试验`、`PV 阶段` 等等价写法 | 可归一 | 不记录（见 13.1⑥） | — |

报告同时设「试验类型」与「项目阶段」且取值不同 → 以「试验类型」为准，另记 `CON-11` 警告 `W04`。

**③ 印章与签批栏**

| 情形 | 结论 | 是否移交 |
| --- | --- | --- |
| 有完整印章 | 可取，不记录 | 否 |
| 有印章但被页边裁切 / 仅余残弧 | 可取，记 `COR-10` 警告 `W05`，注明疑骑缝章 | 是（`S03`） |
| 印章压在文字上、颜色很淡、章面不可辨 | 可取，记 `COR-10` 警告 `W05` | 是（`S03`） |
| 全篇无任何印章 | `COM-13` 阻断 `B05` | 否 |
| 电子签章（有可见电子签名标识） | 可取，不记录 | 否 |
| 签批四栏均有内容（手签 / 电子签 / 签章） | 可取，不记录 | 否 |
| 任一签批栏归一化后为空 | `COM-14` 警告 `W02`，要求补签 | 否 |
| 签署段整体不存在 | `COM-05` 阻断 `B04` | 否 |

**运行假设**（不作判定依据，不产生级别）

1. 数据字典为 DVR 端裁剪后的最小字段集，随字典版本更新；字典只用于判断字段是否存在与可归一，不用于判定合规。
2. 文件解析、抽取、图文理解由外部系统或模型层负责；执行方无视觉能力时按 4.3 标注「未执行」。
3. 同源判定以“编号相同 + 结构相同 + 内容高度相似”为依据，不做逐字节比对。
4. 整改为线下人工操作。
5. 本规则不覆盖防造假稽核，相关内容以 `S03` 移交正式审核。

# PPAP-01-1 检验报告 · 数据标准化预检规则

> 版本：v2.9
> 定位：PPAP 检验报告在正式业务规则审核前的输入质量门禁。
> 上位框架：《PPAP 数据标准化预检总纲 v0.14》，配套《PPAP-00-A 覆盖矩阵 · 路由表 v1.7》。
> 核心原则：**无阻断项即可通过；警告项仅记录、不拦截，但须 100% 列报并移交正式审核。**
> 输入前提：规则已在前置入口定型并生效；本规则只接收某项目内全部或部分 PPAP 待审文件，不接收规则文件实体，不评判规则本身。
> **路由前提**：必须先按总纲 4.5 判定（客户 × 文件类型），再加载本分则。本分则只承载 **UAES × `E01`** 与 **理想 × `T01`** 两条条目——两者的必备结构与必填字段不同（见 7.7），**不得混用同一套结构判据**。

## 1. 目的与定位

本规则用于在正式规则审核之前，对一个具体项目某次提交的检验报告文件做数据标准化预检，判断本次输入是否具备被后续规则审核的条件。

核心目的、非目标与三维度口径统一见总纲第 1、2、7 节；本分则只声明检验报告特有的判定主线与审核边界。

本规则**只做检查、判定和报告**，不做修复、补全、格式转换，不包含整改后复检流程。整改为线下人工操作，整改完成后重新无状态调用。

### 1.1 两条判定主线

| 判定主线 | 回答什么 | 判定对象 | 输出 | 章节 |
| --- | --- | --- | --- | --- |
| 门一 身份认定 | 这份文件**是不是**检验报告；是哪一类 | 文件本身 | A1 确认是·类型已定 / A2 确认是·类型未定 / B 确认否 / C 无法认定 | 6.2 |
| 门二 准入判定 | 这份（些）检验报告**能不能**进入深度审核 | 报告内的数据 | 通过 / 不通过 + 原因码 | 5、7、8.2 |

- 门一不通过，门二不启动。不是检验报告的文件不判、不计问题数。
- 门二只对门一确认「是」的文件生效；每条结论必须落到具体文件与具体类型。
- 两条线的结论都不表示「合格」：门一只说明该被审，门二只说明该判的动作都具备执行条件。
- 门一与门二都在**文件层面**判定，不涉及规则自身的可用性或口径。

### 1.2 预检与正式审核的边界

| 事项 | 正式规则审核 | 本规则 |
| --- | --- | --- |
| 报告类型归属判定 | 直接使用 | 负责 |
| 标准数据属性抽取与合法性 | 直接使用 | 负责 |
| 所需信息是否存在、可定位 | 由预检保证 | 负责 |
| 实测值是否在公差内、结果是否合规 | 负责 | **不做（`S03` 移交）** |
| 行内统计量与造假风险标签 | 负责 | **只抽取原值、不判定** |
| 签字 / 印章是否存在可判定证据 | 判是否合规 | 负责（不判真伪） |
| Cpk / 过程能力是否达标 | 负责 | 不做 |
| 输出通过 / 不通过 | 针对业务合规 | 针对输入质量 |

三条硬边界：

1. 预检不做任何涉及实测值的算术比对。IR-09（实测值落公差区间）、IR-11（同行数值重复）、IR-16（贴近上限提示）已移交正式审核，记 `S03`。
2. 预检只判「判定基准是否成立」。公差能否解析为合法闭区间（IR-31）属预检，实测值是否落入属正式审核。
3. 预检可做计数与结构判定。IR-30 处数守恒、IR-17 抽样样本量、IR-26 序号连续、IR-22 时间轴顺序属预检。

## 2. 范围与非目标

### 2.1 范围内

- 接收一个项目的单次提交：项目标识、提交范围声明、待审文件集、文件清单、可选版式形态画像。
- 门一身份认定，输出 A1 / A2 / B / C 四值；对认定为检验报告的文件按模板结构归入 R1 / R2 / R3 / R4。
- 识别报告拓扑结构（单页全包 / 表头后置 / 封面加子表），据此确定数据行范围与跨表核对范围。
- 按 24 项标准数据属性抽取属性值，判定完整性、格式与值域合法性、关系自洽性。
- 核对文件清单与实际文件，识别缺失件、多余件、重复提交件。
- 逐文件记录解析状态，区分「可解析」与「无法解析」。
- 在本次范围内自主推断跨文件、跨表、字段间关联项（不预设主键）。
- 输出 Markdown 报告，给出文件级、属性级、规则项级、批次级结论，并声明结论适用范围。

### 2.2 非目标

- 不接收、不解析、不改写规则描述文件实体；不评价规则是否可执行、口径是否定稿。
- 不负责 OCR、表格抽取、文档解析、印章识别、贴图式 GD&T 转译等底层实现，不规定技术路线。
- 不修复、不补全、不转换、不复检；不代填缺失的实测值、日期、供应商、零件号、签字人。
- 不做实测值与该行公差的算术比对（超差、正负看反、未注公差超差）。
- 不计算行内统计量（min / max / mean / 极差 / 标准差 / 行指纹）。
- 不输出造假风险标签（零方差克隆、跨行复制、贴名义值、尾数集中）。
- 不判定 Cpk、过程能力、样本量是否满足统计要求。
- 不判定项目齐套性，除非提交范围为 FULL 且提供项目应有文件清单。
- 不审核非检验报告类 PPAP 文件（控制计划、PFMEA、MSA、PSW 等）；门一判 B 类后只登记移交，不判不通过、不计问题数。
- 不追查本次未提交的文件，不推断其存在或不存在。
- 不进入正式业务规则合规审核，不包含整改后复检流程。
- 当前不输出程序接口级的数据结构定义。

### 2.3 明确排除：规则侧一切问题

规则侧一切问题**不登记、不定级、不影响结论**（清单见总纲 2.3）。由此：原 6.2「规则基线校验」整节废止、「规则可执行性」不属本分则判定范围、责任归属不设规则侧、「告知」级别取消（告知与警告的唯一差别是「是否影响放行」，而警告不拦截）。若规则集实际不可用，本文件返回「未执行」，不降级为「不通过」，也不打回供应商。

### 3.1 状态词：四个必须区分的概念

**「不适用」一词禁用**，必须按下表拆分为四种之一。四者为**状态**，不是级别，不参与通过判定。

| 状态 | 代码 | 定义 | 本类目典型情形 |
| --- | --- | --- | --- |
| 范围外 | `S01` | 该对象**本就不属**本次提交范围（本批不含该类目；规则项在本范围档下不适用）。**判据与「交没交」无关** | R1 部分提交下本不在范围的可靠性报告；门一判 B 类的非检验报告文件 |
| 对端未到 | `S04` | 属本次范围、**在可及证据集内不存在**（`SRC-1` 提交件与 `SRC-2` 受控提供源都没有，总纲 3.2.1；有明确「应有」依据，如项目应有清单或范围声明）。**按来源类别拆两子型**：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取，如客户图纸）→ 仅 **`S04-C`**、**不配 `W01`**、不进缺件数 | 声明应有气泡图 / 材料报告而本批未交；`IR-15` 等比对项因无对端而不判 |
| 规则不适配 | `S02` | 规则侧成因导致该项在本类目上无判定依据（预检不评） | A2（R4 其他检验报告）未覆盖的类型特有规则 |
| 移交 | `S03` | 该判断属正式审核，预检只登记不判 | IR-09 实测值落公差区间、IR-11 同行数值重复、IR-16 贴近上限提示 |

关键区分：

- 「范围外」≠「文件不含该对象」。前者是该对象本就不属本次范围，后者是交了但文件里没有这个字段。
- **「本批没交」不再等于「范围外」**：属本次范围而应收未到记 `S04`（对端未到，配套 `W01`），`S01` 只留给「本就不属本次范围」（总纲 3.1）。
- **`S04` 分两子型，判前必先核「可及证据集」（总纲 3.2，v0.7 新增）**：对端在 `SRC-1`（提交件）或 `SRC-2`（受控提供源：客户图纸、技术规范、客户表单模板、客户侧台账）内**已存在**的 → **正常比对，绝不记 `S04`**。集内确实没有时按 `src` 落码：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取）→ 仅 **`S04-C`**、**禁配 `W01`**、不进缺件数、进报告七章 7.2b。`src` 一律查《PPAP-00-A》**§4.3 对端来源登记表**，查不到记 `S02` 并报缺口，**不得现场推定**。**本分则全文凡记 `S04` 之处，一律按本子型标注。**
- **`S05`（受控模板缺结构）继承总纲**：本分则凡判 `B05` 之处，须先按总纲 **3.1 三分界**与 **5.2 两问**确认成因——查《PPAP-00-A》**§4.4 客户受控模板登记表**：该（客户 × 类型）登记**有**受控模板、且**模板本体也没有该列** → 记 **`S05`**（状态，**不阻断**、不配 `B`/`W` 码、不进缺件数、进报告七章 **7.2c**）；登记**无**（不限定表单格式）或**模板有而文件没有** → 仍记 `B05`。**本分则的 3.1 状态词表不列 `S05`**——它的定义、边界与取证要求只在总纲 3.1 / 3.3 / 5.2 维护，避免同一概念在多处分别表述。**`B`/`W` 原因码取值与判定严格程度逐字未改。**　**枚举优先级**：本分则凡用列举方式写状态码的地方——**判定结果取值、状态登记清单、六章装填白名单、「必须按 3.1 拆为…」之类的执行要求**——`S05` **都在其列**（分「已核对」/「待核」两种形态）。**若某处枚举文本仍只列到 `S04-C`，以本条为准**，不得因该处漏列而拒绝登记 `S05`。理由：v0.9 把 `S05` 加进总纲 3.1 之后，各分则的枚举没有同步扩，若按枚举字面执行，`S05` 会**有判据、无落点**——判出来了却装不进状态登记清单，等于这一档不存在。
- 「文件不含该对象」**是材料侧问题，按缺项处理记警告 `W01`**，不得记 `S01` 或 `S02`。
- 「规则不适配」只用于规则侧成因。不得用它兜住「文件里没有这个字段」。

## 4. 输入契约

### 4.1 必选输入

#### 4.1.1 判定依据清单（预置，非本次提交）

本规则引用的 35 条 IR（展开 36 行）是**判定依据清单**，不是本次需要校验的对象。只读引用，不评判其状态。

表中「预检处置」列是本规则的执行方式，取值只有三种：**检查**（正常判定） / **移交**（记 `S03`） / **退出**（不参与本规则判定）。

分层（便于定位执行层次）：

- L1 结构层：IR-01a / 01b、IR-02、IR-18
- L2 属性层：IR-04、IR-05、IR-10、IR-17、IR-19~21、IR-24~25、IR-27~29、IR-33~35
- L3 关系层：IR-06~08、IR-12~15、IR-22、IR-23、IR-26、IR-30~32
- L4 外部责任层：IR-03（已取代）、IR-09、IR-11、IR-16

| IR-01b | 项目报告齐套 | 全部 | 仅当 FULL **且**有项目应有清单时：应有类别均存在，缺任一类 → 不满足；条件不满足 → `S01` | 应有清单 + 实际文件 | 检查（缺类记 `W01`） |

#### 4.1.3 待审文件集

- 只提交文件实体，不提交规则。文件可能覆盖 PPAP 多个类别，不止检验报告。
- 文件类型不固定：`.xls / .xlsx`（表格型）与 `.pdf`（文本型 / 图像型）。
- 一个批次可能只含 1 个文件（部分提交），也可能含全部检验报告。
- 允许出现不代表同一零件的多个文件；不得假定存在跨文件统一主键。

#### 4.1.4 文件清单

- 用于确认本次提交范围，应能核对清单与实际文件是否一致。
- 清单格式当前不限定；缺省时以实际文件集合为范围，记 `W01`。
- 清单所列文件实际不可访问 → 阻断 `B02`（声明与实到不符）。

### 4.2 可选输入

- 项目应有文件清单：IR-01b 的唯一依据。缺省时项目齐套性不可判定，不阻断。
- 版式形态画像：影响 IR-29 符号集、IR-12 容忍策略、IR-17 样本量默认值。缺省取 CP-G。
- 项目主数据（车型 / 零件号 / 供应商）：用于「文件 vs 主数据」核对，是唯一允许跨出文件集的比对方向。
- 模板规范说明（工作簿内「填写说明」表）：版式与字段名的权威来源。
- 字典扩展项：尚未定稿、需按项目补充的取值，须标注为开放项。

可选输入为空时，报告中须声明「因缺少 XX 参考，本项判定为推断，置信度降低」。

### 4.3 解析责任边界与能力前提

- OCR、表格抽取、图文理解、文档解析、贴图式 GD&T 转译由外部系统或模型层负责，本规则不规定技术路线。
- 必须记录每个文件的解析状态；「无法解析」不等于「内容为空」。
- 判定「无法解析」须给出可复现依据（解析器报错原文 / 文字绘制指令数 / 图像对象数）。
- 纯图像扫描件（0 文字绘制指令）标注「需 OCR」，不得标注为「数据不规范」。
- 同源替代只在本次提交范围内查找，不得引用其他批次或历史版本。
- 属性抽取失败与文件解析失败分开记录：解析成功但属性无法抽取，属「数据不规范 ·完整性」。
- **贴图未转译**：该处属「局部不可解析」，记 `W05` 警告，责任侧解析侧。
- **文件本身不含图像对象**（如 xlsx 无扫描件、无签章图片）：不属解析失败，属「文件不含该对象」，记 `W01` 警告，责任侧材料侧。

### 4.4 证据封闭性

按总纲 4.4 / 3.2.1 执行：证据须落在**可及证据集**内（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源 = 客户图纸 / 规范 / 客户台账）；项目上下文、提交范围声明、应有件清单不得作为「推定应有」的依据。**不得因「应该有但没交」判缺件阻断**；缺项按两条通道分流——跨文件对端缺按 `src` 记 `W01`+`S04-S` 或仅 `S04-C`，本文件区块缺按 7.2 分流（承载关键字段 → `B05`，不承载 → `W01`）。

## 5. 输出契约

### 5.1 总体结论

门二的输出，只对 A1 / A2 类文件生效。结论两级与非结论返回值（「未执行」三情形）见总纲 5.1，本类目特例：

- **承载为 0**（全部文件判 B 类）记「未执行（本次无检验报告）」，不得记为通过。
- **B 类不参与总体结论**，数量单列；**C 类**不对文件内容判定，但其「归属不明」记批次级阻断 `B03`。
- **计数口径**：阻断 / 警告按问题条目计——同一规则在同一批次多份文件上的同类不满足合并 1 条，涉及文件数写入说明列；不同规则、不同细分类型不合并。规则项级另按「不满足规则数」单列，两套数字不得混用。
- **未执行时的输出**：只出报告前 3 节，说明原因，不产出通过 / 不通过。

总体结论必须附适用范围三元组：

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| 范围 | FULL / PART | 是否覆盖项目内全部检验报告 |
| 覆盖 | 已核对 / 未核对（无应有清单）/ **未覆盖（部分提交）** | 齐套性能否判定。**不得写「不适用」**——该词在 3.1 已整体禁用，此处原写法与禁令冲突 |
| 计数 | 本次 N 个文件（A1 n1、A2 n2、B n3、C n4，合计 = N） | 结论覆盖的实际对象 |

- 范围或覆盖不为「FULL + 已核对」时，结论只能表述为「本次提交的 N 个文件可审」，不得写成「该项目检验报告可审」或「项目齐套」。
- 结论不得表述为「数据无问题」「数值全部合格」「无造假风险」。

### 5.2 报告形式

- 输出 Markdown 报告，章节结构按第 9 节所引总纲第 11 节的十章固定。
- 报告头部须声明：审核批次、项目、提交范围、报告类别声明、版式形态画像、文件数与筛分计数、未进行的检查。
- 当前不要求对外提供程序接口。

### 5.3 问题记录字段

一条问题的十项必填字段按总纲 11.4 执行。本分则补充两项落点要求：**原因码**取 `B01`~`B06` / `W01`~`W06`（本类目典型情形见 5.4）；**文件位置**须给到工作表名 + 行号 + 列名，或页码 + 段落。

**责任侧与级别的关系**：级别只由「是否让某条规则无法得出唯一结论」决定（8.1），与责任侧**不构成映射**。同一级别可以落在任一责任侧之上：材料侧阻断（`B05`）、提交方阻断（`B02`）、解析侧阻断（`B01`）均成立。

### 5.4 原因码

结论为「不通过」时必须给出原因码。一个阻断项一个码，不得合并。

**阻断原因码（B 系列）**

码的含义见总纲 5.2，下表只列本类目典型情形。

| 码 | 本类目典型情形 |
| --- | --- |
| `B01` | 文件损坏 / 加密 / 纯图像无文本层且无同源可读件 |
| `B02` | 项目标识缺失；声明类别在范围内定位不到；清单所列文件实际不可访问 |
| `B03` | 门一 C 类：三元组部分命中但不足，无法认定是否属本项（原 R0 未归类阻断已取消，见 6.2.5） |
| `B04` | 拓扑结构无法识别（IR-18 不满足）；数据行范围不可靠 |
| `B05` | 要求列 / 实测列 / 判定列整列缺失；表尾区整块缺失 |
| `B06` | 封面与子表同名字段互斥；同源两版仅一处可读且值不同 |

**警告原因码（W 系列）**

码的含义见总纲 5.2，下表只列本类目典型情形。

### 5.5 结论颗粒度

| 颗粒度 | 输出要求 |
| --- | --- |
| 文件级 | 是否存在问题、问题数量、最高严重级别；并列筛分结果、类型归属、拓扑结构、解析状态 |
| 属性级 | 24 项属性的覆盖数、缺值项、无法抽取项（覆盖率与缺口清单） |
| 规则项级 | 满足 / 不满足 / 状态（`S01`~`S04`）+ 原因码 + 问题明细 |
| 批次级 | 总体结论 + 准入条件核对 + 门一认定分布 + 适用范围三元组 + 阻断 / 警告清单 + 属性覆盖率 |

规则项级必须能表达三种结果：满足 / 不满足 / 状态。把 `S01`~`S04` 填成「满足」是常见错误。

状态登记纪律：`S01`/`S02`/`S04` 不产生级别；`S03` 须写入「移交正式审核」清单，不得计入不通过，责任侧不得出现供应商；`S04` 须与 `W01` 成对出现、注明缺哪一件，进整改单并在补交后重跑。定义见 3.1。

### 6.2 门一：身份认定与类型定级

#### 6.2.1 认定内核：「要求 — 实测 — 判定」三元组

| 要素 | 含义 | 缺失时它是什么 |
| --- | --- | --- |
| 要求 | 合格判据：判定标准 / 质量标准 / 要求 / 公差（含「纯名义值 + 未注公差声明」） | 缺要求 → 测量记录 / 仪器输出 |
| 实测 | 实际测得的值，按样本展开或单值；允许 `/`、`NA` 占位，但列必须存在 | 缺实测 → 控制计划 / 检验规范 |
| 判定 | 依据要求对实测作出的逐项结论：区间比对结果，或通过型 / 描述型结论 | 缺判定 → 巡检流水 / 数据导出 |

- 三者同表共存才构成检验报告；`检查成绩书`、`首件检验报告`、`尺寸检查表` 能落到三元组即成立，`检验报告汇总表` 只有结论列而无实测列则不成立。
- 三元组按**列**判，不按「有没有这一行」判：要求列存在但整列为空属完整性问题（IR-04），实测列存在但整列占位属完整性问题（IR-08），均不是身份问题。

#### 6.2.2 认定判据与优先级

| 序 | 判据 | 作用 | 是否必要 |
| --- | --- | --- | --- |
| 1 | 结构三元组 | 不命中即不能认定 | **必要** |
| 2 | 表尾契约：零件号 / 零件名称 / 供应商 / 签批 / 日期中至少三项 | 加强证据 | 加强 |
| 3 | 列头特征与 R1 / R2 / R3 已知模板一致 | 加强证据，并给出类型 | 加强 |
| 4 | 文件名含「检验报告 / Inspection Report」 | 辅助证据，仅用于记录与定级 | 辅助 |
| 5 | 报告内标题含「检验报告」 | 辅助证据，仅用于记录与定级 | 辅助 |

认定纪律：

- 判据 1 是否决项：不命中时不论判据 2–5 命中多少，只能是 B 或 C。

- 判据 1 命中而判据 4 / 5 不命中时，仍认定为检验报告；标题缺失只影响 IR-02 的结论。
- 不得因文件出现在本次提交中、或紧跟检验报告之后，就默认它是检验报告。

置信度按命中组合记录（写入证据链，不改变结论）：1+3 或 1+2 记高；仅 1 记中；三元组某列仅部分可辨记低（结论仍为 A1 / A2，须注明人工复核）。

#### 6.2.5 类型定级

分流必须在三维度检查之前完成：R1 / R2 / R3 的规则集互斥，未分流导致漏审。优先级（逐级回退，须记录回退层级）：

1. 模板结构（列头特征）——主依据。

- 判据 1 与判据 4 / 5 不一致时按结构认定，记 `W04` 一致性警告并列出两个值，不因此判标题规则不满足。

- 一份文件内多个不连续明细区、各区三元组成立情况不一致时，按成立区段判定整体结论，不成立区段单列说明且其规则结果登记 `S02`；不得因某区段不成立把整份文件记 C 类。

### 6.3 拓扑结构识别

| 拓扑 | 形态特征 | 抽取策略 | 额外强制动作 |
| --- | --- | --- | --- |
| 单页全包型 | 单页内含表头、明细、表尾、签批 | 按行序扫描，表头区在前 | 无 |
| 表头后置型 | 表头区出现在数据行之后 | 先定位表头行，再反向界定数据行范围 | 记录表头行号，不得把表头行当数据行 |

识别不到三值之一 → IR-18 不满足，阻断 `B04`。拓扑判定失败意味着数据行范围不可靠，其后任何属性抽取与结论均不成立。

第二段 属性抽取：按 7.5 的 24 项逐项抽取，每项产出一个结果：

| 抽取结果 | 含义 | 后续处理 |
| --- | --- | --- |
| 已抽取 | 值取得且通过格式与值域校验 | 进入三维度检查 |
| 已抽取但非法 | 值取得但格式 / 枚举 / 值域不合规 | 记「数据不规范 ·正确性」+ `W03` |
| 无法抽取（承载位不存在） | 文件结构上无此列 / 此栏 | 记 `B05` 阻断（该文件不承载该判定） |
| 无法抽取（承载位存在但为空） | 有列无值 | 记 `W02` 警告 |
| 无法抽取（对端未到） | 承载位在未提交的子表 / 另一文件 | 缺件事实记 `W01`，该属性登记 **`S04`（对端未到）**，不记问题；补交后重跑 |

## 7. 三维度判定口径

### 7.1 数据正确性

关注单份文件内某个信息本身是否科学、合理、符合基本逻辑。判定依据优先级：

1. 字段类型、格式、值域（日期须合法、数值须可解析、单位须统一、枚举须在闭集内）。
2. 属性内部代数自洽（公差下限 ≤ 名义尺寸 ≤ 公差上限；处数 N ≥ 1；重量为正数）。
3. 基本常识与科学逻辑（非法字符、序号跳号需有解释）。
4. 业务常识（报告日期不得早于零件设计年代，不得为表格软件日期基线异常值）。
5. 领域规则或领域知识参考。

相关规则：IR-22 日期有效性与顺序、IR-31 公差代数自洽、IR-34 原始文本合法、IR-27 特征分类与单位匹配。

明确排除：实测值与该行公差的比较结论属 `S03` 移交项，不属本节。

常见正确性问题形态（判定模式示例，非结论）：

| 形态 | 示例（原样引用） | 原因码 |
| --- | --- | --- |
| 日期基线异常 / 年份不合理 | `1899.06.16`、`2001/1/3` | `W03` |
| 日期残缺并三列重复 | `0216 0216 0216` | `W03` |
| 数值带单位且多值同格 | `84.47Kg, 84.47Kg, 84.49Kg, ...` | `W03` |
| 表头顺序倒置 | 列头位于数据行之后（须由 IR-18 识别为表头后置型，不判为错误） | 不记问题 |
| 字段值列位偏移 | `零件名称` 标签右格为空，值落第二格 | `W03` |
| 公差表达式代数不自洽 | 公差下限 > 名义尺寸（未涉及实测值，属预检） | `W06` |
| 非法数值字符 | 应写 `34.19` 却写为 `34..19` | `W03` |

注意「表头倒置」与「表头缺失」的区别：前者是合法版式（IR-18 判满足），后者是缺陷（IR-02 判不满足）。

### 7.2 数据完整性

判断判定所需的数据是否存在、是否可定位、是否可归一。

**缺项统一规则：**

> 缺项是否阻断，取决于**该缺项是否由审核规则本身要求做跨文件比对**。

| 情形 | 处置 |
| --- | --- |
| 审核规则要求跨文件比对（如气泡图 ↔ 检验报告、封面附件勾选 ↔ 子表），而对照件未提交 | **按规则识别并写明具体缺哪一件**，记 `W01` 警告；**不阻断**，不阻碍进入下一步审核 |
| 文件内含的必备区块 / 子表缺失（同文件内可判） | 记 `W01` 警告 |
| 判定所需关键字段在**结构上不存在**（无此列 / 无此栏） | 阻断 `B05`——这已不是缺值，而是该文件不承载该判定 |

其他完整性要求：

- 核对范围是**可及证据集**（`SRC-1` ∪ `SRC-2`，总纲 3.2.1），**不是「本次提交文件」**——比对源内的图纸 / 规范 / 客户台账同样纳入比对，对端在集内已存在即**必须正常比对、不记 `S04`**。集内确无此件时按 `src` 分流：`SUB` → 缺件事实记 `W01` + 受阻项 **`S04-S`**；`CUS` → 仅 **`S04-C`**（不配 `W01`）。**均不得判缺件**，也不得记 `S01`（`S01` 只用于「本就不属本次范围」）。
- 按零件分组核对（键为表尾零件号 + 零件名称），不得跨零件汇总四类报告；分组失败记 `W01` 并按文件独立核对。
- 空值、占位符、假填充必须区分：空 ≠ `/` ≠ `NA`，分别记录。
- 「部分文件有、部分文件无」按文件列明，不得概括为「普遍存在」。

相关规则：IR-01a / 01b、IR-04、IR-05、IR-06、IR-08、IR-13、IR-14、IR-15、IR-17、IR-19、IR-20、IR-21、IR-24、IR-25。

| 完整性对象 | 对应属性 | 检查方式 |
| --- | --- | --- |
| 报告四要件（尺寸 / 材料 / 功能 / 可靠性） | — | 范围内清点；仅 FULL + 清单时核对项目应有（缺类记 `W01`） |
| 气泡图独立文件 | — | 按同物料编号 + 同物料名称检索（未检出且无「应有」声明 → `S01`；声明应有而缺 → `W01` + 该比对项 `S04`） |
| 表尾六字段 | 供应商主体 / 零件身份 / 签批时间轴 | 逐文件逐字段取值 |
| 供应商代码与联系方式 | 供应商主体信息 | 代码非空、格式非零件号 |
| 图纸版本号、重量 | 零件身份与版本 | 版本号非空、单件重量为正数 |
| 递交原因与附件勾选 | 递交契约与附件勾选 | 至少勾选一项、无残留 `____` |
| 三级签批姓名 | 签批链 | 逐级姓名非空且非占位符 |
| 全局设备池或行级量具 | 全局设备池 / 行级量具配置 | 二者至少一处非空 |
| 未注公差标准 | 未注公差标准声明 | 表头声明或已挂载兜底 |

### 7.3 数据一致性

关注不同数据之间的关联关系是否满足要求：不要求预先指定关联键，基于本次范围内整体内容自主推断关联项；跨文件、跨表格、字段间关联均须落在本次提交范围内；若提供项目主数据可做「文件 vs 主数据」核对（唯一允许跨出文件集的比对方向）；不得假定跨文件应当一致的零件号；关联推断依据写入证据链。

相关规则：IR-02 与模板结构、IR-07 方法列写法、IR-12 结果与量具模态、IR-22 时间轴、IR-23 职责分离、IR-30 处数守恒、IR-32 子要求完整。

| 维度 | 对应属性 | 说明 |
| --- | --- | --- |
| 标题 vs 模板结构 | — | 二者应指向同一类型 |
| 拓扑结构 vs 表头位置 | 报告拓扑结构 | 表头倒置为合法拓扑，不判缺陷 |
| 封面 vs 子表同名字段 | 供应商主体信息 / 零件身份与版本 | 封面加子表型必查 |
| 客户件号 vs 供方件号 | 零件身份与版本 | 不得互串 |
| 签批时间轴 | 签批时间轴 | 检验 ≤ 审核 ≤ 批准；跨度 ≤ 30 天 |
| 签批链职责分离 | 签批链 | 检验人 ≠ 审核人 |
| 判定标准 vs 结果取值形态 | 数据模态 × 供应商自填结论 | 定量行给数值，定性行给定性词 |
| 实测值 vs 量具模态 | 行级量具配置 × 数据模态 | 计数型不得产出连续小数；计量型不得只给通过 / 不通过 |
| 特征处数 vs 展开子行数 | 特征处数 | 处数 N = 展开子行数；斜杠数只决定该处样本数 |
| 复合特征子维度 vs 实测矩阵 | 复合特征子要求 | 长度与角度两个维度都应有承载 |
| 特殊特性标识 vs 附件勾选 | 特殊特性标识 × 递交契约 | 标识非空则须勾选 Cpk 附件 |

| 表尾区段数量 | — | 表尾六字段区不应重复出现 |
| 跨文件重复提交 | — | 内容相同仅文件名不同者，仅本次范围内识别 |
| 字段名一致性 | — | `责任人` vs `编制 / 审核`；`检查数据` vs `实测值` vs `Actual-Value` |
| 零件分组一致性 | 零件身份与版本 | 同一零件号下的报告应自洽 |
| 序号连续性 | 气泡序号与父子行 | 无断号、无孤立行 |
| 列数与样本量声明 | 抽样样本量 | 实测值列数应与样本量声明一致（不按 3 / 5 / 10 判合法列数） |

| --- | --- | --- |

## 8. 严重级别与深度审核准入

### 8.1 严重级别（仅两级）

级别定义与定级判据见总纲 8.1：阻断 = 该问题导致至少一条审核规则无法得出唯一结论；警告 = 判定仍可完成但结果不完整或存在被误判风险。本类目逐形态映射见 **8.5**。

### 8.2 通过规则

按总纲 8.2 / 8.3 执行：无阻断即通过，警告不影响结论但须 100% 列报并移交。本类目补充：存在阻断项时不支持继续后续流程；不通过必须按责任侧分派，整改为线下人工操作，整改后重新无状态执行。

### 8.3 准入条件

原 C1「判据可得」（规则基线可用、版本锁定、属性层清单随基线发布）**整条退出**（规则侧）。保留 C2–C5，编号不复用：

| 条件 | 内容 | 定级 |
| --- | --- | --- |
| C2 对象可读 | 文件可解析、拓扑可识别、类型定级完成（A1 或 A2） | 阻断 `B01` / `B04` |
| C3 对象齐备 | 深度审核所需每个属性都有值可定位且可解析（非法字符、截断、一格多值同属未满足）；声明的报告类别可在范围内定位 | 声明类别定位不到 → 阻断 `B02`；关键字段结构上不存在 → 阻断 `B05`；缺值 / 空值 / 值不可解析 → 警告 `W02` / `W03`；承载位在未提交子表 → `S04`（对端未到，配套 `W01`） |
| C4 基准成立 | 公差区间可构造、样本量可确定、量具模态可映射、符号可识别、日期与跨度可比 | 写法错误 → 警告 `W03` / `W06`；无显式公差已由兜底覆盖，不记问题 |
| C5 链路自洽 | 跨表 / 跨行 / 跨字段关系成立（处数守恒、序号连续、职责分离、附件与勾选自洽） | 警告 `W06` |

- **C2 是门槛条件**：不满足即不通过，不承认「部分可审」。
- **C3 / C4 / C5 是内容条件**：按上表定级，只有 `B` 系列原因码才构成不通过。

### 8.4 责任侧与处理去向

| 责任侧 | 涉及情形 | 处理去向 | 是否打回供应商 |
| --- | --- | --- | --- |
| 材料侧 | 文件内容的正确性、完整性、一致性问题（绝大多数 IR 与属性） | 打回整改 | 是 |
| 提交方 | 项目标识缺失、提交范围未声明、声明类别定位不到、清单与实到不符、多版本并存、门一 C 类归属不明 | 补充声明 / 指定唯一版本 / 说明提交范围 | 否 |
| 解析侧 | 文件损坏 / 加密 / 纯图像无文本层 / 贴图未转译 | 转技术支持核查 | 否 |

**归口规则**：

1. 每个问题**只能有一个主责任侧**，以 8.5 定级表的处置列为准。
2. 报告中「打回供应商整改」与「提交方补正 / 解析侧核查」**必须分表列示**，混列会导致范围问题被当成供应商责任。
3. IR-13 / IR-14 的「无签字 / 印章图像」归**材料侧**（文件不含该对象记 `W01`）；只有"文件有图像但解析不出"才归解析侧（`W05`）。

## 11. 执行要求与约束

模型或 Agent 执行本规则时应遵守：

1. 按本文件流程执行，不跳过门一身份认定、拓扑识别、类型定级和三维度检查；门一未完成前不得对任何文件出准入结论。
2. 不接收、不解析规则文件实体；不评价规则是否可执行、口径是否定稿（2.3）。
3. 判为 B 类的文件只列出、登记 `S01`、不判、不计数；判为 C 类的记批次级阻断 `B03` 并列入待确认。
4. 必须先完成拓扑识别（IR-18）与类型定级再抽取属性；拓扑失败直接阻断 `B04`，不得猜测后继续。
5. 提交范围为 PART 时不得判缺类别，一律登记 `S01`。
6. 不得做任何涉及实测值的算术比对；不得计算行内统计量，不得生成造假风险标签。
7. 不得跨出本次提交范围做替代与比对：同源替代、跨文件一致性、项目齐套性均只在范围内成立。
8. 以本次提交文件集为对象，不局限于单文件，也不得越出批次。
9. 正确性优先依据字段类型、基本常识、业务常识和领域知识；公差只做代数自洽校验。
10. 完整性允许合理推断，但须说明依据与置信度；抽取失败必须按 6.4 的四层分类显式列出。
11. 一致性不要求预设关联键，但不得假定跨文件统一零件号主键，且必须按零件分组。
12. 三维度并列，任一维度出现阻断即不通过；警告只记录。严格标准不用于范围外文件、`S03` 移交项。
13. 不修复、不补全、不转换、不复检；不代填任何缺失值。
14. 不通过必须按责任侧分派，不得进入后续正式审核；每次调用无状态。
15. 必须区分「数据不规范」与「文件无法解析」；必须按 5.4 给出原因码，不得自造原因码。
16. 证据定位到最小颗粒度（工作表 + 行 + 列，或页码 + 段落），并给出对应数据属性名称。
17. 总体结论须写明准入条件 C2–C5 核对结果、挡住准入的那一条与原因码，并附适用范围三元组；PART 或未核对时只能表述为「本次提交的 N 个文件可审」。
18. 同一事实若落入多个检查项，取最高级别并注明，只计一次。
19. 计数与结构判定（处数守恒、样本量、序号连续性、时间轴序关系）须由确定性逻辑执行，不得由模型估算；无法确定性执行时登记 `S02` 并在报告中声明「未执行」，不得改由估算，也不得报为阻断。
20. 版式形态画像须在报告头部声明；取 CP-G 时在局限性声明中注明「判定可能偏严」。
21. 警告项必须 100% 列报，不得合并、不得概括为「其余若干」；报告第八章局限性声明须逐字保留。

## 13. 待确认假设

与提交流程相关：

- 项目应有文件清单能否由上游提供——当前视为不可得，多数批次只能记「未核对」。
- 四份报告是否须同批次齐套——当前仅 FULL + 有清单时判，且缺类只记 `W01`。
- 逐零件提交时 PART 是否等价于「该零件已全交」——当前视为不等价。
- 「功能报告」是否等同于「全功能检验报告」——当前视为未定义，不推断等同。

与数据属性层相关：

- ISO 2768 兜底表的精度等级与适用范围——当前缺省 `m` 级，实际用 `f` / `c` / `v` 级时区间会偏差。
- 抽样应测样本量是否一律 5——当前 PPAP 默认 5，CP-C 试制期允许 3。
- 递交附件索引与子表的映射表——当前按名称相似匹配。
- 特殊特性符号集是否按画像差异化——当前取 CP-G 并集。
- 数据属性层是否作为对外接口交付——当前明确不交付。
- 行级量具列与表头全局设备池的优先级——当前以行级为准并记 `W06`。

与身份认定相关：

- 判定列不落文件、由系统另算的报告是否认定——当前判 C 类，放宽会连带影响 IR-08 与属性 20 / 23。
- 材料 / 可靠性 / 功能试验报告是否设专属模板——当前归 R4（A2），类型特有规则登记 `S02`。
- 首件 / 巡检 / 出厂检验报告是否纳入齐套口径——当前认定是检验报告但不计入报告四要件。
- 「报告四要件」与 17 类 PPAP 文件的映射关系——当前以项目配置为准。

与解析能力相关：

- xlsx 是否可用「责任人姓名非空」替代签字位——当前视为不可替代，无图像记 `W01`。
- 气泡图是否本批次必交、印章是否只对扫描件生效——当前气泡图未检出登记 `S01`，印章一律需图像证据。
- 贴图式 GD&T 的转译能力边界——当前贴图未转译记 `W05`，转译正确性不得由预检自证。
## 14. 补充口径
> 本节条款与正文冲突时以本节为准。

### A. 「判定栏已填、实测值全空」的定级（新增）

| 情形 | 判定 |
| --- | --- |
| 同一检验项的个别样本列为空，判定栏已填 | `W02`（空值占位） |
| 同一检验项的**全部样本列**均为空，判定栏已填 | `B05`（该行无法与判定栏对齐，结构不可用） |
| 判定栏为空且样本列全空 | `W01`（缺项） |
| 判定为 `NOT OK`，但实测值落在公差带内 | `S03`（算术比对与造假风险判断不属预检，移交正式审核） |

**不得因「判定栏已填 `OK`」而视为该项已完成。** 判定栏与实测值必须成对出现，缺一不成立。

### B. 封面勾选全空时的类别推定（新增）

| 情形 | 判定 | 责任侧 |
| --- | --- | --- |
| 勾选项全空，但文件内子表可唯一确定类别（如存在「尺寸报告」页） | 按子表推定类别，记 `W04` | 提交方 |
| 勾选项全空，且子表可支持多种类别解释 | `S02`（规则链无法选定），**不得**推定后硬判 | — |
| 勾选项与子表结论矛盾 | `B06` | 材料侧 |

**递交原因与附件索引属提交契约声明**，全空即声明缺失，归**提交方**补正（按总纲 10.2「补声明」判），**不打回供应商改文件本体**；若客户要求该栏由供应商填写，则转材料侧。

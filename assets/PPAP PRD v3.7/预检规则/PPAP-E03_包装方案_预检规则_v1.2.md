## 1. 目的与边界

**目的**：判定这份《包装方案》**是否具备可被 UAES 审核的结构**——即 7 个必备内容块是否都在、标题是否承载身份。

**不是**判定包装方案好不好。方案用几层瓦楞、用什么缓冲材料、能不能通过跌落测试，全部是正式审核的工程结论，预检不碰。

**边界三条**：

1. 本类目**不判实测值**、不判尺寸与公差，故不产生 `B06`（数值冲突类）。
2. 本类目**无跨文件依赖**，不得因「本批次没有图纸 / 没有 PFD」记任何问题。
3. 本类目**没有分则专属的客户差异**（本期仅 UAES 一家），客户差异层为预留位。

| S2 | 内容含「零件基础信息」块 | 块标题近义匹配 | `W01` | 1 |

## 5. 判定细则

**5.1 近义通过，但不放行取值**

块标题**意思相近即视为存在**（UAES 规则原文明确允许）。可接受的近义形态：

| 应有块 | 可接受的标题写法（示例，非穷举） |
| --- | --- |
| 零件基础信息 | 零件信息 / 产品基本信息 / 零件描述 |
| 供应商基础信息 | 供应商信息 / 供方资料 / 制造商信息 |
| 包装设计的基本要求 | 包装基本要求 / 通用包装要求 |
| 针对该零件包装的特殊要求 | 特殊包装要求 / 专用要求 / 客户特殊要求 |
| 包装方案信息 | 包装方案 / 包装形式说明 / 包装结构 |
| 包装材料清单 | 材料清单 / BOM / 包装物料明细 |

近义判定**只用于确认结构存在**。块内取值是否正确、材料是否填写完整，另按总纲 5.2 记 `W02`（空值）/ `W03`（越界），不得因为「标题近义通过」而连带放行取值。

**5.2 块存在但块内全空 → `W02`，不是 `B05`**

结构在、内容空，属「有结构无值」，按总纲 7.2 记 `W02`。**不得**升为 `B05`——`B05` 只给「结构根本不存在」。

**5.3 标题不含「包装方案」时的处置**

记 `B05`（S1）。同时报告须加一句提示：「文件标题未含『包装方案』，若确认属本类目，可人工指定文件类型后重跑本分则（总纲 4.9）」。

**不得**因为「内容看起来像包装方案」就把 S1 判通过——标题不承载身份，规则就没有稳定的判定对象；但也**不得**因此判整批不通过以外的额外问题（S1 已计一次，其余 6 项照常判，不重复计阻断）。

**5.4 客户差异层为空时的兜底**

本期 `E03` 只有 UAES 一条路由。若将来出现其它客户的包装方案规则，**不得**套用本分则的 7 项——须先在 00-A §1 登记、§2 抽 `required_structure`，再在本分则 §8 增列差异层。

## 6. 执行流程

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 识别：（客户, 文件类型）=（UAES, 包装方案），置信度 ≥ 中 | 路由 = `U09` / L2 |
| 2 | 取文档主标题，判 S1 | `B05` 或通过 |
| 3 | 按 §5.1 近义表逐个匹配 S2~S7 的块标题；命中的块再看块内是否非空 | 每块三态：存在有值 / 存在空 / 不存在 |
| 4 | 按 §4 表定级，汇总问题清单 | `B05` / `W01` / `W02` |
| 5 | 按总纲第 11 节十章模板出报告；本类目专属内容挂 10.x | 报告 |

**执行顺序不可调换**：先判 S1，再判 S2~S7。S1 未通过时仍要判完 S2~S7——缺标题不等于放弃其余结构判定，否则报告无法告诉供应商「到底缺哪些块」。

## 8. 级别与原因码

级别定义与原因码含义见总纲 5.2 / 8.1，本节只列本类目的典型情形。

| 原因码 | 本类目典型情形 | 责任侧 |
| --- | --- | --- |
| `B05` | 文档标题不含「包装方案」（S1 唯一情形） | 材料侧 |
| `W01` | 6 个内容块任一缺失 | 材料侧 |
| `W02` | 块存在但块内全空；块内必备取值未填 | 材料侧 |
| `W03` | 块内取值越界或写法不规范（如材料清单无任何材料名） | 材料侧 |

| `W05` | 解析成功但标题层级全丢失，块边界按段落近似 | 解析侧 |
| `S03` | 包装设计合理性、材料选型、成本——**移交正式审核，不记问题** | 正式审核 |

**本类目不产生 `B06`**：无数值比对、无跨文件比对。

## 9. 报告与输出

按总纲第 11 节「统一报告模板 v1.0」十章输出，本分则不再另行定义章序。

| 挂载位置 | 内容 |
| --- | --- |
| 第二章 | 文件级结论列填「路由 `U09` / L2」；本类目无同批组，该列填 `—` |
| 第四章 | 阻断项：仅 S1 可能入此章 |
| 第五章 | 警告项：6 个块的缺失与空值 |
| 第九章 | 7 项结构判据逐项结果（`RS-U09-S1`~`S7`），须标明每项「存在有值 / 存在空 / 不存在」 |
| 10.1 | 块识别结果表：块名、实际标题、命中方式（精确 / 近义）、块内是否非空 |
| 10.2 | 解析说明：标题层级是否可用、块边界如何确定 |

**结论口径**：任一 `B` 码 → 不通过；仅 `W` 码 → 通过。

**识别置信度低不等于「未执行」**：低置信度按总纲 4.8 记 `B03`（识别失败 · 身份不可归属），出路为 4.9 人工指定。总纲 5.1 已把「未执行」收窄为**单一成因**（该条目既无分则也无 `required_structure`），识别置信度不在此列——把它记成「未执行」等于让一份认不出是谁的文件**免检放行**。

## 10. 不要做

1. 不要判包装设计是否合理、材料是否选对、堆码层数是否足够——那是 `S03`。
2. 不要因为「标题不含包装方案」而拒绝判定其余 6 项。
3. 不要把「块存在但为空」记成 `B05`。
4. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。
5. 不要因本批次缺图纸 / PFD / PFMEA 等其它文件记任何问题——本类目无同批依赖。
6. 不要在报告里出现「疑似」「可能」类未定级表述。
7. 不要新增章、调整章序或自定义报告字段。
8. 不要修改 `00-A §2.1` 的判据文本；判据有误应先改 00-A，再同步本分则。

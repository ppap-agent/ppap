# PPAP-10 控制计划（CP）数据标准化预检规则

> 版本：v2.0
> 依据：《PPAP-00 数据标准化预检总纲 v0.14》（下称「总纲」）与《PPAP-00-A 覆盖矩阵 · 路由表 v1.7》。公共契约一律以总纲为准，本文件只写控制计划特有内容。
> 定位：控制计划正式审核前的输入质量门禁。
> **适用（客户 × 类型）**：**UAES / 理想 / 蔚来 × 控制计划（`T11`）** 三条条目。三者表头字段数与跨文件依赖差异极大（见 7.9），**不得互相套用**。
> **路由前提**：先按总纲 4.5 定（客户 × 文件类型），再加载本分则与对应客户差异层。
> 通过规则：**任一阻断项即不通过；警告项不影响结论，但必须 100% 列报并随报告移交正式审核。**

## 1. 目的与边界

在正式审核前，判断本次提交的 CP 文件子集是否**可判、可读、内部自洽，且足以支撑本次申请的审核范围**。

**只回答「能不能判、有没有自相矛盾」，不回答「够不够合规、够不够充分」。** 可判且不自相矛盾、仅不满足客户要求的，一律移交正式审核。

**不做**：OCR 与解析实现、合规审核、工程有效性审核、跨文件内容比对结论、特殊特性符号语义裁决、文件修复与复检、技术实现设计。

## 2. 术语

| 术语 | 说明 |
| --- | --- |
| 提交清单 | 本次提交的文件目录，含文件名、类型、零件号、版本、CP 阶段 |
| 审核范围声明 | 本次申请审核的文件族与规则域，三档：R1 单文件自检／R2 同族多份对齐／R3 跨文件穿透 |
| 提交子集 | 本次实际提交的文件集合，可能是项目全量批次包的一部分 |
| 项目文件清单 | 该项目下已存在的 PPAP 文件目录（可选），用于区分「本次未交」与「项目内也没有」 |
| 状态词 | `S01` 范围外／`S02` 规则不适配／`S03` 移交／**`S04-S` 对端未到·提交方应交件／`S04-C` 对端未到·甲方受控件**。五者均不产生问题记录、不计入问题数（总纲 3.1 / 3.2，详见 4.2） |
| 责任侧 | 材料侧／提交方／解析侧，含义见 7.7。**不设「规则侧」** |
| 附表／受控文件 | CP 正文以「机密」「见附表」「见受控 SOP」引用、内容不落在 CP 本体的文件 |
| 工序主行／参数子行 | 主行承载工序号与工序名称；子行两者皆空、仅承载特性参数，频次与容量继承主行 |
| 有效行 | 参与非空与取值判定的行集合，由工序主行及其参数子行构成 |
| 空指针引用 | 正文填代号或引用名，但全文未给出该代号定义 |
| 机密化空壳 | 以保密为由将公差列与后段管控列整体留空或合并，导致管控链断裂 |
| 掩码错误 | 显示为 `####`、`#REF!`、`#VALUE!`、`#N/A`、`#DIV/0!` 等，原始值不可见 |

## 3. 输入契约

### 3.1 必选输入

| 输入 | 要求 |
| --- | --- |
| 提交清单 | 文件名、文件类型、零件号、版本号、CP 阶段。缺任一项导致对应预检项取不到可判定值，记 `B02`（提交方） |
| 审核范围声明 | 三档之一。未声明时按 R1 推定并记 `W01`，**不阻断**（总纲 4.2） |
| 待检文件集 | 至少 1 份控制计划；正文引用到的附表与受控文件应随附 |

### 3.2 内置判定基准（不属于输入，不得向提交方索取）

| 基准 | 用途 | 载体 | 不可用时 |
| --- | --- | --- | --- |
| 产品特性／过程特性词根表 | C-08 错列判定 | 随分则内置 | 该批 C-08 标「未执行」，**不得**改为只记疑似 |
| 量具类型-物理量纲匹配表 | C-24、C-25 量具匹配判定 | 随分则内置 | 同上，标「未执行」 |
| 工艺时序常识基线 | C-19 反常识时序判定 | 随分则内置 | C-19 仅在明显反常识时判定，属正常路径，无需降级 |
| 特殊特性符号白名单 | 仅用于 M-05 判断「是否有取值」，**不裁决符号语义** | 随分则内置 | 符号语义不归预检裁决（11 附录第 4 条） |

内置基准不可用属执行方能力缺口：标「未执行」并单列能力缺口（总纲 4.4），**不记级别、不判供应商责任**。

### 3.3 可选输入

| 输入 | 用途 | 缺失时 |
| --- | --- | --- |
| 项目文件清单 | 区分「本次未交」与「项目内也没有」 | 「未提交」一律按「本次未交」处理，责任侧提交方；不因此升级为阻断 |

### 3.4 证据来源要求

- 解析产物须声明表头多行合并与跨页继承的处理方式；未声明者列级与表体级结论置信度记「中」（`W05`）。
- PDF 与 Excel 列级结论不可等同。
- 拿不到内容 → `B01`（解析侧）；结构上取不到可判定值 → `B05`（材料侧）；仅局部不可解析 → `W05`（解析侧）。**不得跳过检查，不得把解析失败写成「内容为空」。**

### 3.5 能力前提

执行方不具备某项读取能力时，对应预检项标「**未执行**」，不记级别、不判责任、不计入问题数，并在报告中单列能力缺口。

| 缺失能力 | 受影响预检项 | 处置 |
| --- | --- | --- |
| 无视觉通道（不能看扫描件版式） | P-03、C-07、M-06／M-07 | 未执行；不得判「行归属不可还原」 |
| 不能解包压缩文件 | M-11 | 未执行；不得判「附表缺失」 |
| 不能求值表格公式 | C-07 | 未执行；不得判「掩码错误」 |

## 4. 输出契约

### 4.1 总体结论

| 结论 | 条件 | 处理 |
| --- | --- | --- |
| 通过 | 无阻断项（**不论有无警告项**） | 按声明范围进入正式审核，警告项随报告移交 |
| 不通过 | 存在任一阻断项 | 打回整改 |
| 未执行 | 本批无 CP 文件，或执行方能力不足导致全部预检项无法执行 | 不计入结论统计，单列 |

**禁止的中间结论**：「基本通过」「有条件通过」「部分通过」。介于通过与不通过之间的一律判「不通过」。

警告项不改变结论但不免责：须 100% 列报、作为附件移交，正式审核不得因「预检已通过」跳过警告指向的字段。

### 4.2 预检项结论的状态取值

结果取值**仅限以下七种**，「无法判定」「不适用」已废止。

| 结果 | 含义 | 产生问题记录 | 计入问题数 |
| --- | --- | --- | --- |
| 满足 | 已检查且符合 | 否 | 否 |
| 不满足 | 已检查且不符合 | 是（阻断／警告 + 原因码） | 是 |
| `S01` 范围外 | 该对象**本就不属**本次范围（审核范围未覆盖；所依赖的非必填区块在本文件中本就不存在）。**判据与「交没交」无关** | 否，须列入状态登记 | 否 |
| `S04` 对端未到 | 该判定项须与本批另一份文件比对，而对端在**可及证据集**内不存在（`SRC-1` ∪ `SRC-2`，总纲 3.2.1）。**分两子型**：`S04-S`（`src=SUB`，缺件另记 `W01`）/ `S04-C`（`src=CUS`，如**图纸**、客户规范，**不配 `W01`**） | 否，须列入状态登记并注明缺哪一件 | 否 |
| `S02` 规则不适配 | 该预检项在本 CP 阶段或文件形态下无承载位置 | 否，须列入状态登记 | 否 |
| `S03` 移交 | 需语义判断，预检不判 | 否，须列入状态登记并写明移交理由 | 否 |
| 未执行 | 执行方能力缺口（3.5） | 否，单列能力缺口 | 否 |

**状态词不是级别**：级别只有阻断与警告；状态词表示「没判」，级别表示「判了且判成问题」。
- **`S04` 分两子型，判前必先核「可及证据集」（总纲 3.2，v0.7 新增）**：对端在 `SRC-1`（提交件）或 `SRC-2`（受控提供源：客户图纸、技术规范、客户表单模板、客户侧台账）内**已存在**的 → **正常比对，绝不记 `S04`**。集内确实没有时按 `src` 落码：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取）→ 仅 **`S04-C`**、**禁配 `W01`**、不进缺件数、进报告七章 7.2b。`src` 一律查《PPAP-00-A》**§4.3 对端来源登记表**，查不到记 `S02` 并报缺口，**不得现场推定**。**本分则全文凡记 `S04` 之处，一律按本子型标注。**
- **`S05`（受控模板缺结构）继承总纲**：本分则凡判 `B05` 之处，须先按总纲 **3.1 三分界**与 **5.2 两问**确认成因——查《PPAP-00-A》**§4.4 客户受控模板登记表**：该（客户 × 类型）登记**有**受控模板、且**模板本体也没有该列** → 记 **`S05`**（状态，**不阻断**、不配 `B`/`W` 码、不进缺件数、进报告七章 **7.2c**）；登记**无**（不限定表单格式）或**模板有而文件没有** → 仍记 `B05`。**本分则的 3.1 状态词表不列 `S05`**——它的定义、边界与取证要求只在总纲 3.1 / 3.3 / 5.2 维护，避免同一概念在多处分别表述。**`B`/`W` 原因码取值与判定严格程度逐字未改。**　**枚举优先级**：本分则凡用列举方式写状态码的地方——**判定结果取值、状态登记清单、六章装填白名单、「必须按 3.1 拆为…」之类的执行要求**——`S05` **都在其列**（分「已核对」/「待核」两种形态）。**若某处枚举文本仍只列到 `S04-C`，以本条为准**，不得因该处漏列而拒绝登记 `S05`。理由：v0.9 把 `S05` 加进总纲 3.1 之后，各分则的枚举没有同步扩，若按枚举字面执行，`S05` 会**有判据、无落点**——判出来了却装不进状态登记清单，等于这一档不存在。

「无法判定」的四类成因必须分开落：拿不到内容 → `B01`（解析侧）；结构上取不到可判定值 → `B05`（材料侧）；有列但值为空 → `W02`（材料侧）；需语义判断 → `S03`（移交）。

### 4.3 问题记录字段

类型（数据不规范／文件无法解析）· 细分类型（正确性／完整性／一致性，**不设「可判性」**）· 预检项编号 · 文件位置 · 证据链 · 影响（须点名具体审核规则）· 严重级别 · **原因码**（7.4）· **责任侧**（7.7）· 置信度（附依据）· 整改方向提示。

- `B` 类原因码只能配「阻断」，`W` 类只能配「警告」，不得出现「阻断 + `W01`」或「警告 + `B05`」。
- 问题编号统一为 `B-nn`（阻断）／`W-nn`（警告），与原因码 `B01`~`B06`／`W01`~`W06` 分开书写。

### 4.4 定位规范

| 形态 | 格式 |
| --- | --- |
| Excel | 文件名 > sheet > 单元格或行范围 |
| PDF（文本层） | 文件名 > 页码 > 表格序号 > 列名／行号 |
| PDF（扫描件） | 文件名 > 页码 > 视觉区域描述 |
| 跨页问题 | 文件名 > 起止页码 > 工序号 |
| 跨文件问题 | 检查范围：本次提交 N 个文件 + 已检索文件清单 |

### 4.5 输出颗粒度

- 文件级：每份是否存在问题、问题数、状态数、最高级别。
- 预检项级：七种结果之一 + 原因码 + 责任侧。
- 文件集级：总体结论、阻断清单、警告清单、**状态登记清单**、**未执行与解析侧待核清单**。

两份清单分工：状态登记清单装 `S01`／`S02`／`S03`／**`S04-S`／`S04-C`**／**`S05`（注明「已核对」／「待核」）**；未执行与解析侧待核清单只装能力缺口（未执行）与 `B01`／`W05`。**`S04` 系不得漏装**——控制计划的跨文件依赖（`P-05`）一旦对端未到，受阻项就在这里登记，漏装等于这条判定凭空消失。**`S05` 同样不得漏装**——UAES 控制计划（`U08`）在《00-A》§4.4.1 登记为「有（待补登记）」，其缺栏会落 `S05`；若清单不装 `S05`，这条判定既不在阻断清单、又不在状态清单，等于凭空消失。**材料侧问题一律进问题清单**，不得塞进这两份清单稀释。

## 5. 执行流程

1. 接收提交清单、审核范围声明、待检文件集。
2. 核对清单与实际文件；确认可解析性；识别同源与多版本文件。
3. 未声明范围时按 R1 推定并标注。
4. 对每个预检项执行**范围判定三问**，按 ①②③ 顺序取第一个「否」作为结论，其余记为佐证，不重复计数。

| 顺序 | 问题 | 回答为否 |
| --- | --- | --- |
| ① | 审核范围声明是否覆盖该项 | 结论＝`S01` 范围外 |
| ② | 依赖的提交侧材料是否在本次提交内 | 不满足，`B05`（提交方）；项目文件清单证明项目内已有且可调阅时降 `W01`。依赖内置基准时无此分支 |
| ③ | 数据是否可判 | 拿不到内容 → `B01`；结构上取不到可判定值 → `B05`；有列但值空 → `W02`；需语义判断 → `S03`；能力缺口 → 未执行 |

5. 并列执行 P／C／M／X 四组检查。
6. 汇总问题、给出三级颗粒度结论、编制状态登记清单。
7. 按通过规则判定并输出报告。

**判定基准是范围声明，不是批次包完整度**：申请审某项却没给材料＝不满足；没申请审某项＝`S01` 范围外。

## 7. 判定口径

### 7.1 纳入预检的三条判据（满足任一即可）

1. 违反基本常识、物理、算术或统计逻辑。
2. 导致后续审核无法定位或必然误判（缺列、行归属断裂、引用无定义、掩码乱码）。
3. 同一信息在不同位置或不同文件间矛盾。

M-03、M-12 按判据 2 纳入：只判「有没有、覆盖到没覆盖到」，不判「人员配置是否充分、工序划分是否合理」。

### 7.2 不属预检，移交正式审核（`S03`）

假 SPC 鉴伪、目视测量微观量、反应计划敷衍／缺追溯遏制／责任主体不明、返工无闭环、防错设备无点检、试生产频次未加严、过程参数未闭环、CP 与 PFMEA／PFD／PpK／MSA／SOP 的内容比对结论。

预检只判这些跨文件项的前置条件：是否提交、能否关联、工序号能否对齐。

以上各项一律记 `S03`，写明移交理由并列入状态登记，不产生问题记录、不计入问题数、不影响结论。不得因「问题看起来严重」而记成警告或阻断——那会让预检越界成审核，且整改方无从下手。

### 7.3 严重级别

| 级别 | 定义 | 对结论的作用 | 典型触发 |
| --- | --- | --- | --- |
| **阻断** | 该问题导致至少一项预检在**结构上取不到可判定值**（`B01`~`B06`），或导致行级判定整体失去依据 | 判「不通过」 | 文件无法解析、行归属不可还原、范围内材料未提交、关联键不可识别、必列缺失、空指针引用、机密化空壳、公差矛盾、时序倒流、量级失真、统计方法类型矛盾、跨页表头突变 |
| **警告** | 不影响「能不能判」，只影响「判得准不准」 | **不影响结论**，须 100% 列报并移交 | 清单不一致、同源未归并、表头字段空缺、核心小组单人、特性编号重号、日期链逆序、版本与履历脱节、掩码错误、设备工装列填充率三成至七成、页数不闭合、文件名标记异常、阶段标注异常 |

**定级唯一判据**：该项是否仍能得出确定结论。能得出 → 最多记警告；不能得出 → 阻断。不以「问题看起来严重不严重」或「整改成本高不高」定级。

### 7.5 严格标准与宽严边界

采用相对严格标准，允许记录潜在问题；一切推断须写明依据与置信度。**严格只作用于是否记警告，不作用于是否判阻断。**

| 情形 | 严格标准的适用 | 不得逾越的边界 |
| --- | --- | --- |
| 写法可能有歧义、也可能合规 | 记警告 | 不得据此判阻断 |
| 字段可读，但读出的值不足以支撑派生计算 | 记阻断（`B05`） | 这是判据不成立，不是「可疑」 |
| 材料未提交 | 写「缺项／未覆盖」：**已声明 R2／R3 而不足 → PFD/PFMEA/PGQP1 缺记 `W01` + `S04-S`；图纸缺仅记 `S04-C`（不配 `W01`），均不阻断**（P-05）；**未声明（推定 R1）→ 该项 `S01`**；**本文件正文引用的附表未随附 → `B05`**（M-11，须承载判定字段） | **不得写「不一致」**；**不得把跨文件缺件记成 `B05`** |
| 行业普遍存在的缺口 | 维持原级别 | 不得因整改成本高而降级，也不得因「别人都没有」而升级 |
| 拿不到内容（无文本层、无视觉能力） | 标「未执行」，不记级别 | 不得「从严推定」为阻断 |

### 7.7 责任侧与处理去向

责任侧错挂会把整改要求发给错误的一方，比不判更糟。

| 责任侧 | 含义 | 本分则典型问题 | 处理去向 |
| --- | --- | --- | --- |
| **材料侧** | 文件内容本身不合标准：缺列、空值、取值不合规、派生字段不自洽、跨文件取值冲突 | M-01~M-07、C-01~C-25、X-01~X-04、X-07（缺陷表现为本文件字段取值错或内部不自洽） | 打回供应商补正材料 |
| **提交方** | 文件组织方式或选择有误：提交范围、配对失败、清单不符、多版本未归并 | P-01、P-05、P-06、P-07、M-08、M-11、X-05、X-06、X-08、X-09，及 X-07 中仅表现为配对失败的情形 | 补正提交范围或文件组织，不要求供应商重做数据 |
| **解析侧** | 内容获取或结构识别存在不确定性，与文件质量无关 | P-02、P-03、C-07、`W05` 各项 | 换解析通道或标「未执行」，**不得发整改给供应商** |

**责任侧不是级别**：材料侧问题不一定阻断（如 M-02 空值），提交方问题也可能阻断（如提交清单缺 CP 阶段 → `B02`）。反之 P-05 虽归提交方，但只记 `W01` + `S04`、**不阻断**——责任侧与级别是两套维度，不得互相推导。

**X-07 责任侧按缺陷形态分**：缺陷是「本文件零件号栏填错／与自身编号栏矛盾」→ 材料侧；只是「两份文件对不上、无法判断谁错」→ 提交方。判定前须先按 7.8 做归属定位。

### 7.8 跨文件判定项的缺陷归属与去重

X-05~X-09 只判「是否一致」，不判「谁的错」。四情形（A 本文件错／B 配对件错／C 缺陷在配对件而本文件不可判／D 无法定位）按总纲 10.3 判，此处不重复。

**本文件特殊之处**：编号规则为 `QJ-CP-<零件号>-<项目号>`，编号栏内嵌零件号，构成天然**内部他证**。

- 零件号栏与编号栏内嵌号段**不一致** → 本文件内部不自洽，属 **A 情形**，记 `B06` 阻断，**不依赖配对件是否在场**。
- 两者一致但与配对件不一致 → 属 A / B / C / D，按总纲 10.3 判。

**阻断的独立性**：只要本文件零件号栏与编号栏自相矛盾，X-07 阻断即可独立成立。报告须把该内部矛盾作为首要证据，跨文件差异作为并列证据；不得只写「与 PFMEA 不一致」——那会使整改方向无法确定。

**跨文件匹配键**：CP ↔ CPK 的特性比对，键 = **工序段 + 图纸气泡号**，不得以 CP 的「序号」直接匹配 CPK 名称前缀。CP「序号」是工序内序号（每道工序从 1 重排），与图纸气泡号无对应关系；仅编号相同而规格不同、且分属不同工序段者，**不得**判 `B06`。

### 7.9 客户差异层（按客户 × 类型路由）

三条 L1 条目（UAES / 理想 / 蔚来 × `T11`）共用 `P`/`C`/`M`/`X` 四组判定，但**表头字段数、跨文件依赖、符号体系差异极大**——这是全套分则里跨客户分歧最大的一类。本节只写差异，**不改判定项的判据文本**——但**它是覆盖层**（v2.0 定，与总纲 7.6 规则 4 同一条通则），见下方效力声明。

> **覆盖效力（全库统一）**：客户差异层是对通用判定项在该客户上的**启用 / 关闭开关**。
>
> | 差异层写法 | 效力 | 落码 |
> | --- | --- | --- |
> | "**必备**" / 给出具体门槛 | 该项在**该客户上生效** | 按原项级别 |

## 11. 附录：「不要做」清单

1. 不要把本分则当正式审核用。
2. 不要把未提交的支撑文件写成「不一致」或「缺陷」，也**不要写成 `S01`**（`S01` 只用于「本就不属本次范围」）。按 `src` 落码：`src=SUB`（PFD / PFMEA / PGQP1 填报件）→ `W01` + `S04-S`；`src=CUS`（图纸）→ 仅 `S04-C`、不配 `W01`（总纲 3.2.4）。
3. 不要在未声明范围时擅自扩大检查范围。
4. 不要替客户裁决特殊特性符号语义（`CC/SC/KPC/ⓢ/★/◆/☆/G/Z/∇/D/TLD`）。
5. 不要在参考框架缺失时硬给结论。
6. 不要把 PDF 列级结论与 Excel 等同看待。
7. 不要用同源可读文件推断无法解析文件的内容。
8. 不要把状态词计入阻断或警告，也不要用「不通过」替代状态词；反之不得用状态词规避应判的问题。
9. 不要提出「由 AI 自动修复或补全」——整改是线下人工动作。
10. 不要为提升通过率放宽判定；通过规则无中间档。
11. 不要把同源重复文件当独立样本重复计数。
12. 不要在关联键缺失时臆造零件号映射。
13. 不要因解析能力未就绪或内置基准不可用而判供应商不通过（应标「未执行」）；但文件本身不可读仍应判 `B01`。**规则侧不存在**——不要为规则表述的歧义记问题。
14. 不要写入任何技术实现内容。
15. 不要把配对件缺失、多版本未归并这类提交范围问题记成材料侧；责任侧错挂比不判更糟。
16. 不要用「无法判定」四字代替定级；按成因落 `B01`／`B05`／`W02`／`W05`／`S03`。

## 1. 目的与边界

**目的**：判定这份《设备清单》**是否具备可被理想审核的设备开发与验收结构**——即主表是否存在、两级列（设备开发 7 子列 / 设备验收 3 子列）是否齐备、行内是否填全、验收「不通过 / 条件通过」时是否给了整改。

**不是**判定设备够不够用。设备型号选型、产能匹配、精度等级、整改措施是否有效，全部是正式审核的工程结论，预检只判**表格是否承载了这些内容**。

**边界三条**：

1. 本类目**不判实测值**、不做产能复算，故不产生 `B06`。
2. 本类目**无跨文件依赖**，不得因本批次缺其它文件记任何问题。
3. 本类目**没有分则专属的客户差异**（本期仅理想一家），客户差异层为预留位。

## 4. 判定项（10 项）

| # | 判定内容 | 判定方式 | 不满足时 | 来源条款 |
| --- | --- | --- | --- | --- |
| S1 | 含「设备开发/验收清单」表 | 表标题近义匹配 | **`B05`** | 1 |
| S2 | 含列「产线/工序」「设备开发」 | 一级列名匹配 | **`B05`** | 1 |
| S3 | 「设备开发」下含 7 子列：设备、供应商、设备型号、利旧设备数量、新采购设备数量、设备通用情况、计划到位时间 | 二级列名逐项匹配 | **`B05`** | 1 |

| S5 | 含「设备验收」列，其下含子列：验收结果、整改措施、整改计划 | 一级列 + 3 个二级列匹配 | **`B05`** | 2 |

| S7 | 验收结果为「不通过」或「条件通过」时，整改措施与整改计划均非空 | 逐行条件判定 | `W02` | 2 |
| S8 | 表头区含「车型」且非空 | 表头区字段匹配 + 非空 | 缺 → **`B05`**；空 → `W02` | 模板实测 r4 |
| S9 | 表头区含「零件名称」「零件号」且非空 | 同上 | 缺 → **`B05`**；空 → `W02` | 模板实测 r4 |
| S10 | 表头区含「供应商」且非空 | 同上 | 缺 → **`B05`**；空 → `W02` | 模板实测 r4 |

**S8~S10 是身份字段，判法与其他七项不同**：

1. **取证位置是表头区**（`JL-APQP-4-25/V1.0` 的第 4 行），**不是**列头行（第 5 行），也不是数据行。
2. **两个「供应商」不是同一个**：`S10` 取的是**表头 r4 的供应商**（提交方）；`S3` 子列里的「供应商」是**数据行 r5 的设备制造商供应商**。**不得互替**——把设备制造商当成提交方，会让每份设备清单都判 `B05`；反之把提交方当成设备供应商，会让 `S4` 的「7 子列同行非空」永远满足。
3. **判 `B05` 而不是 `B03`**：字段缺失是**结构**问题（`B05`，5.2 边界表）；只有当身份字段**存在但取不到唯一值**（如同一表头出现两个零件号）时，才按 `B03` 记（总纲 10.4 `K1` 同口径）。
4. **补这三项的直接目的**是让设备清单能被**总纲 10.5 按（客户 × 零件号）归组**：归不了组就做不了跨文件比对，此前这一类目在文件族模式下等于游离在外。

**为何「设备开发」与「设备验收」两级分开判**：这两组列来自理想规则的两个不同条款（第 1 条 / 第 2 条），对应两个不同的审核维度——设备**有没有配齐**与设备**验收过没过**。合并成一项会丢掉区分度：报告无法告诉供应商「是设备没报齐，还是验收没做完」。

## 5. 判定细则

**5.1 表标题与列名近义通过**

| 应有项 | 可接受的写法（示例，非穷举） |
| --- | --- |
| 设备开发/验收清单 | 设备清单 / 设备台账 / 设备开发与验收清单 / 产线设备清单 |
| 产线/工序 | 产线 / 工序 / 产线工序 / 生产线 / 工位 |
| 设备开发 | 设备开发计划 / 设备配置 |
| 设备 | 设备名称 / 设备名 / 设备类型 |
| 供应商 | 设备供应商 / 供方 / 制造商 |
| 设备型号 | 型号 / 规格型号 / 设备规格 |
| 利旧设备数量 | 利旧数量 / 沿用设备数 / 旧设备数量 |
| 新采购设备数量 | 新购数量 / 新增设备数 / 采购数量 |
| 设备通用情况 | 通用性 / 是否通用 / 通用程度 |
| 计划到位时间 | 到位时间 / 计划到货 / 预计到位 |
| 设备验收 | 验收 / 验收情况 |
| 验收结果 | 验收结论 / 验收判定 / 结果 |
| 整改措施 | 纠正措施 / 改善措施 / 措施 |
| 整改计划 | 整改计划时间 / 计划完成时间 / 整改排期 |

近义**只用于确认列存在**。列内取值另按 `W02` 判定，不得因「列名近义通过」而放行取值。

**5.2 多级表头还原（本类目的执行前提）**

1. 先识别一级列：「设备开发」「设备验收」。
2. 再识别其下二级列，归属到对应一级列。
3. **S2 只判一级列存在**，S3 / S5 判二级列存在。
4. 若合并单元格结构丢失（二级列被拆成独立一级列），按列名语义归属，**不判缺失**；记 `W05` 并在 10.2 说明「表头层级丢失，已按列名语义归属」。
5. **不得**因「二级列的位置不在预期列序」而判缺失——列序无关。

**5.3 S4 / S6 的行内判定范围**

1. 行键 = 「产线/工序」列。该列为空 → 该行跳过，**不判**（空行不是缺陷）。
2. S4 判定范围 = 「设备开发」一级列下的 **7 个二级列**（不含「产线/工序」本身）。
3. S6 判定范围 = 仅「验收结果」**一列**。
4. 任一列为空即记 `W02`，**一行只记一次**（不按列数累计）。
5. 剔除标题行、小计行、合计行：整行仅 1~2 个单元格有值且首列含「合计」「小计」「说明」等字样。

**5.4 S7 的条件判定**

| 验收结果取值 | 整改措施 | 整改计划 | 判定 |
| --- | --- | --- | --- |
| 通过 / 合格 | 任意 | 任意 | 通过（S7 不触发） |
| 不通过 / 未通过 | 非空 | 非空 | 通过 |
| 条件通过 / 有条件通过 | 非空 | 非空 | 通过 |
| 不通过 / 条件通过 | 任一为空 | — | `W02` |
| 空 | — | — | 记 S6 的 `W02`，**S7 不重复记** |

**S7 与 S6 不重复计**：验收结果为空时，问题已在 S6 记过 `W02`，S7 不得再记一次。

**5.5 不得越界判内容**

以下项目**一律 `S03`，不记问题、不影响结论**：

1. 设备型号是否满足工艺要求。
2. 计划到位时间是否延误（是否已过期）。
3. 利旧 / 新购数量是否合理。
4. 整改措施是否有效、整改计划是否可行。
5. 验收结果与整改内容是否匹配。

**5.6 客户差异层为空时的兜底**

本期 `T13` 只有理想一条路由。若将来出现其它客户的设备清单规则，**不得**套用本分则的 7 项——须先在 00-A §1 登记、§2 抽 `required_structure`，再在本分则 §7 增列差异层。

## 6. 执行流程

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 识别：（客户, 文件类型）=（理想, 设备清单），置信度 ≥ 中 | 路由 = `L13` / L2 |
| 2 | 定位主表（§5.1），还原多级表头（§5.2） | 一级列 + 二级列清单 |

## 10. 不要做

1. 不要判设备型号是否满足工艺、到位时间是否延误、整改措施是否有效——那是 `S03`。
2. 不要判利旧 / 新购数量是否合理。
3. 不要在表头层级未还原时判二级列缺失（§6 第 2 步）。
4. 不要因二级列「位置不在预期列序」判缺失——列序无关（§5.2 第 5 项）。
5. 不要把一行的多个空列记成多条 `W02`——一行只记一次（§5.3 第 4 项）。
6. 不要在验收结果为空时同时记 S6 与 S7（§5.4 末段）。
7. 不要对「产线/工序」为空的行判 S4 / S6——空行不是缺陷。
8. 不要把标题行 / 合计行当数据行判（§5.3 第 5 项）。
9. 不要用产能评估（`T14`）或模具验收（`T06`）的判定项套本类目（§2）。
10. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。
11. 不要因本批次缺其它文件记任何问题——本类目无同批依赖。
12. 不要在报告里出现「疑似」「可能」类未定级表述。
13. 不要新增章、调整章序或自定义报告字段。
14. 不要修改 `00-A §2.2` 的判据文本；判据有误应先改 00-A，再同步本分则。

| 深度档 | **不适用** | 深度档只对 L3 试探（总纲 7.7）；本条目为 L2 |

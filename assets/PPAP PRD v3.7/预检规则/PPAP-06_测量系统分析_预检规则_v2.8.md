> 版本：v2.8
> 定位：MSA 正式业务规则审核之前的输入质量门禁。
> 核心原则：**预检只判定「这批提交能否被可靠审核」，不判定「MSA 结论是否合格」。无阻断项即通过；警告不拦截，仅记录并随报告移交正式审核。** 每次调用独立判定，仅检查、判定和报告，不执行修复。

## 1. 目的与定位

本规则用于在 MSA 正式规则审核之前，对待审文件集做数据标准化预检，判断当前输入是否具备被完整、可信地审核的条件。

核心目的、非目标与三维度口径统一见总纲第 1、2、7 节；本分则只声明本类目的判定对象与业务边界。

本规则**只做检查、判定和报告**，不做修复、补全、格式转换，不包含整改后复检流程。

三条前提：

- **两段式运行**：规则已在规则入口定型并生效。本规则不接收规则文件实体，不承担规则解析、版本比对与口径裁定，**不输出任何关于规则集、口径、字典的问题**。
- 审核时只提交某项目中的**全部或部分**待审文件，文件集是批次子集，不等同于项目全量交付包。
- 判定证据必须落在**可及证据集**内（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源，总纲 3.2.1 / 4.4）；提交范围声明只能用于**排除**，不能用于**推定应有**。

## 2. 范围与非目标

### 2.1 范围内

- 接收待审文件集、提交范围声明、文件清单。
- 核对文件清单与实际提交是否一致。
- 以声明范围为边界，做数据正确性、完整性、一致性检查。
- 自主推断文件间、表单间、字段间的关联项并检查一致性。
- 区分「数据不规范」（→ 阻断 / 警告）与「范围外 / 应移交」（→ `S01` / `S03`）。
- 输出 Markdown 报告，给出文件级、规则项级、文件集级结论。
- 输出状态登记与待人工确认清单。

### 2.2 非目标

- 不判定 MSA 业务结论是否合格：`%R&R` 阈值、Kappa 阈值、ndc 阈值、计数型量具应做哪种分析，均属正式审核职责。
- 不执行附录 A 所列全量深审规则。
- 不负责 OCR、表格抽取、文档解析等底层实现，不规定解析工具与技术路线。
- 不评判规则本身（规则口径、规则集完整性、字典一致性均在规则入口处理）。
- 不修复、不补全、不转换、不复检。

### 3.1 状态词：四个必须区分的概念

**「不适用」一词禁用**，必须按总纲 3.1 拆分为四种之一。四者是**状态**，不是级别，不参与通过判定。

| 状态 | 代码 | 本域形态 |
| --- | --- | --- |
| 范围外 | `S01` | 规则所需关联对象**本就不在**本次提交范围（`P-15`）；不属本类目的文件剔除。**判据与「交没交」无关** |
| 对端未到 | `S04` | 关联对象属本次范围、**在可及证据集内不存在**（`SRC-1` ∪ `SRC-2`，总纲 3.2.1；如计划表列了某量具而报告未交、PGQP1 未随批）。**分两子型**：`src=SUB`（量具报告、kappa 分析、CP、PGQP1 填报件）→ `W01` + **`S04-S`**；`src=CUS`（客户图纸、规范、客户表单模板本体、客户台账）→ 仅 **`S04-C`**、**不配 `W01`** |
| 规则不适配 | `S02` | 规则侧成因导致某项在本域无判定依据（预检不评，本版已无此类来源） |
| 移交 | `S03` | 结论措辞归一化、分析类型选择是否正确、真实值与卷面值是否一致、造假嫌疑——均属正式审核或全量深审 |

**关键区分：**

- 「范围外」≠「文件不含该对象」。前者是该对象本就不属本次范围，后者是交了但表单里没有这个栏位（→ 按缺项记 `W01` 或按结构缺失记 `B05`）。
- **「本批没交」不再等于「范围外」**：属本次范围而应收未到记 `S04`（对端未到，配套 `W01`），`S01` 只留给「本就不属本次范围」（总纲 3.1）。
- **`S04` 分两子型，判前必先核「可及证据集」（总纲 3.2，v0.7 新增）**：对端在 `SRC-1`（提交件）或 `SRC-2`（受控提供源：客户图纸、技术规范、客户表单模板、客户侧台账）内**已存在**的 → **正常比对，绝不记 `S04`**。集内确实没有时按 `src` 落码：`src=SUB`（提交方能自行补出）→ `W01` + **`S04-S`**；`src=CUS`（只能向甲方索取）→ 仅 **`S04-C`**、**禁配 `W01`**、不进缺件数、进报告七章 7.2b。`src` 一律查《PPAP-00-A》**§4.3 对端来源登记表**，查不到记 `S02` 并报缺口，**不得现场推定**。**本分则全文凡记 `S04` 之处，一律按本子型标注。**
- **`S05`（受控模板缺结构）继承总纲**：本分则凡判 `B05` 之处，须先按总纲 **3.1 三分界**与 **5.2 两问**确认成因——查《PPAP-00-A》**§4.4 客户受控模板登记表**：该（客户 × 类型）登记**有**受控模板、且**模板本体也没有该列** → 记 **`S05`**（状态，**不阻断**、不配 `B`/`W` 码、不进缺件数、进报告七章 **7.2c**）；登记**无**（不限定表单格式）或**模板有而文件没有** → 仍记 `B05`。**本分则的 3.1 状态词表不列 `S05`**——它的定义、边界与取证要求只在总纲 3.1 / 3.3 / 5.2 维护，避免同一概念在多处分别表述。**`B`/`W` 原因码取值与判定严格程度逐字未改。**　**枚举优先级**：本分则凡用列举方式写状态码的地方——**判定结果取值、状态登记清单、六章装填白名单、「必须按 3.1 拆为…」之类的执行要求**——`S05` **都在其列**（分「已核对」/「待核」两种形态）。**若某处枚举文本仍只列到 `S04-C`，以本条为准**，不得因该处漏列而拒绝登记 `S05`。理由：v0.9 把 `S05` 加进总纲 3.1 之后，各分则的枚举没有同步扩，若按枚举字面执行，`S05` 会**有判据、无落点**——判出来了却装不进状态登记清单，等于这一档不存在。
- 「读不到」既不等于「范围外」也不等于「缺失」：按成因记 `B01`（无替代）或 `W05`（有替代 / 可另行确认）。

## 4. 输入契约

### 4.1 必选输入

**4.1.1 待审文件集**

- 文件类型不固定：表格、文档、PDF、压缩包内文件均可能出现。
- 允许同一表单同时以源表与导出件两种形态存在。
- 一致性检查的比对单位是整个提交文件集，不是单文件。

**4.1.2 提交范围声明**

- 说明本次覆盖哪些零件、量具、文件类型，或明确「本项目该类全部文件」。
- 格式不限定，但须能支撑「某对象是否在本次范围内」的判断。
- 允许缺省，缺省时按 `MSA-PRE-13` 判定，并**按部分提交推定**（总纲 4.2）。

**4.1.3 文件清单**

用于核对提交范围、数量、可访问性及压缩包内文件归属。清单有实无 → 阻断 `B02`。

### 4.2 可选输入

- 数据标准字典：本文件附录 B 已给出 MSA 初版。
- 量具物理字典：量具类型、标准分辨率、物理量纲（附录 C）。
- 项目内前序已提交的其他类别文件：仅在可获得时用于范围登记，不在本规则判定范围内。

### 4.3 判定责任边界与能力前提

- 内容获取方式由外部系统或模型能力负责，本规则不规定。
- 基于可获得的内容或模型理解能力判定；无法获得可判定内容时，**按成因定级**：无同源替代 → 阻断 `B01`；有替代来源或可另行确认 → 警告 `W05`。不得跳过检查，不得直接判「不满足」，也不得记「无法判定」后不作定级。
- 合并单元格按其覆盖范围理解；公式单元格以呈现值为准，公式存在而呈现为空时记「未生成」而非「未填写」，「未生成」的级别按其承载规则判定。
- **能力前提**：执行方不具备读取压缩包 / 图像 / 单元格公式的能力时，相关项在报告"未进行的检查"栏声明，标「未执行」，**不记级别、不判供应商责任**——能力不足不是文件缺陷。

### 4.4 证据封闭性

沿总纲 4.4 / 3.2.1：核对范围是**可及证据集**（`SRC-1` 提交件 ∪ `SRC-2` 受控提供源），**不是「提交件目录」**；对端在集内已存在即正常比对。集内确无此件时按 `src` 分流：`SUB` → `W01` + 受阻项 `S04-S`；`CUS`（客户图纸 / 规范 / 模板本体 / 台账）→ 仅 `S04-C`、**不配 `W01`**；**均不得判缺件阻断**，也不得记 `S01`；项目级清单与历史记录只能署名陈述。本域特例：允许同一文件内的**作用域覆盖式推断**（如表头跨行合并），须标注推断路径与置信度。

## 5. 输出契约

### 5.1 总体结论（仅两级）

| 总体结论 | 判定条件 | 后续处理 |
| --- | --- | --- |
| 通过 | 未发现阻断项 | 可进入正式审核；警告项 100% 随报告移交 |
| 不通过 | 存在任一阻断项 | 按责任侧分派：材料侧打回整改、提交方补正、解析侧转技术支持 |

**另有唯一非结论返回值**：本批未提交任何 MSA 类文件（本类目无待审对象）时，返回「未执行」并说明原因，不产出通过 / 不通过。**第六章状态登记须分两行写**：本类目整体标「**未执行**」；`S01` 只留给本批中**属其他类目**的文件。**不得用 `S01` 代替本类目的「未执行」**（总纲 5.1 禁令：混用会让覆盖率虚高）。

### 5.2 原因码

结论为「不通过」时必须给出原因码。**一个阻断项一个码**，不得合并。

**阻断原因码**

码的含义见总纲 5.2，下表只列本类目典型情形。

| 码 | 本分则典型来源 |
| --- | --- |
| `B01` | 文件打不开、加密、无文本层且渲染失败 |
| `B02` | `P-14`、清单核对、`P-21` 无正式版 |
| `B03` | `P-08③` 整列、`P-17` 整列 |
| `B04` | 表单结构整体损坏 |
| `B05` | `P-16` 结论表达、`P-17`、`P-18` |
| `B06` | `P-07` 表头元数据撕裂且无基准件 |

> **`B05` 的边界**：判据是该字段在本批**取不到可用于判定的值**，含「结构上无此栏」与「有栏但整栏不可归一」两种形态；**单纯空值不算**——空值按 `W02` 记警告。表单未提交不属 `B05`：本就不属本次范围记 `S01`；属本次范围而应收未到的，查《00-A》§4.3 得 `src`——`SUB` → `W01` + `S04-S`，`CUS` → 仅 `S04-C`（不配 `W01`）。

**警告原因码**

码的含义见总纲 5.2，下表只列本类目典型情形。

| 码 | 本分则典型来源 |
| --- | --- |
| `W01` | `P-15`、`P-19` 受控字段缺失、范围不可辨识时的降级记法 |
| `W02` | `P-03` 占位符、`P-19` 受控字段填占位值 |
| `W03` | `P-04` 个别单元格、`P-09` 量纲错配、`P-20` 量纲区间 |
| `W04` | `P-06` 属性冲突、`P-07` 元数据撕裂、`P-13` 声明与实物不符、`P-21` 多版本差异 |
| `W05` | `P-02a` 空白页、`P-17` 个别行 |
| `W06` | `P-10` 十分之一法则、`P-11` 样本量、`P-12②③`、`P-20` 区间异常 |

### 5.3 问题记录字段

| 影响 | 影响哪条正式审核规则，导致无法执行 / 结论不可信 / 结论可能反转 |

| 责任侧 | 材料侧 / 提交方 / 解析侧 |

| 判定状态 | 确定 / 待人工确认 |

### 5.4 结论颗粒度

| 颗粒度 | 输出要求 |
| --- | --- |
| 文件级 | 是否在声明范围内、是否存在问题、阻断数与警告数、最高级别 |

## 6. 执行流程

### 6.1 接收与提交范围确认

1. 接收待审文件集、提交范围声明、文件清单。
2. 核对文件清单与实际提交（数量、名称、压缩包内归属）。清单有实无 → 阻断 `B02`；实有清单无 → 警告 `W04`。
3. 判定提交范围为「已声明 / 未声明」「全量 / 部分」，写入报告首段。
4. 未声明时，按部分提交推定并记 `W01`；后续缺失类判定**不得据此判阻断**，改记 `W01` 并在影响栏注明"因范围不可辨识，不构成缺件阻断"（总纲 4.2）。
5. 清单所列但不可访问的，按 `MSA-PRE-13`、`14` 判定；文件存在但内容不可获得的，按 4.3 定级（`B01` / `W05`）。

### 6.2 判定口径（内置固化）

### 6.5 汇总判定

1. 汇总问题；同一根因在多处出现时合并为一条并列出全部坐标；同一缺陷被多条规则命中时只在责任最直接的规则下计一次（总纲 8.6）。
2. 标注细分类型、规则项、原因码、位置、证据链、影响、严重级别、责任侧、置信度、判定状态。
3. 分别给出文件级、规则项级、文件集级结论。

## 7. 三维度判定口径

### 7.1 数据正确性

关注某个信息本身是否科学、合理、符合基本逻辑。判定依据优先级：

1. 数据标准字典（附录 B）中的字段类型、格式、值域。
2. 基本常识与科学逻辑。
3. 业务常识（MSA 通行做法）。
4. 领域知识参考（AIAG MSA 手册、客户模板）。

**不判**：`%R&R` 是否达标、ndc 是否够、Kappa 是否合格、应做哪种分析——一律 `S03` 移交。

### 7.2 数据完整性

对照规则需要，判断相关数据是否存在、是否具备可追溯来源。

- 规则要求检查某项信息时，文件中应存在能反映该信息的原始数据。
- 数据可以是直接显示，也可以是同一文件内已明确的值的作用域覆盖。
- 允许合理推断，但必须说明推断依据、来源与置信度。
- 无法获得来源或推断依据不足时，按 4.3 定级（`B01` / `W05`），**不得记「无法判定」后不作定级**。
- 空值不等于结构缺失；公式返回空记「未生成」而非「未填写」；禁止从文件名、表单名、相邻数据行或其他文件推断编号、零件号并视为已填。

### 7.3 数据一致性

关注不同数据之间的关联是否成立。不要求预先指定关联键，应自主推断并把推断依据写入证据链。

| 编号 | 关联关系 | 检查要点 | 规则 |
| --- | --- | --- | --- |
| C1 | 计划表 ↔ 报告表 | 同零件号 + 同量具编号能否在提交范围内找到对应报告 | 05、06 |
| C2 | 计划表 ↔ 计数型报告 | 计数型量具能否找到同零件号 + 同编号的 Kappa 报告 | 05 |
| C3 | 完成状态 ↔ 报告实物 | 声明完成时，报告是否真有数据 | 02、03 |
| C4 | 结论勾选 ↔ 打印数值 | 勾选「可接受」时，同表 %GRR 是否确实达标 | 12 |
| C5 | 报告内部 | %GRR、ndc、结论三者是否自相矛盾（只判自洽，不判合格） | 12、20 |
| C6 | 同批次多版本 | 近似名文件之间业务字段是否一致，副本是否丢失状态 | 21 |
| C7 | 表单标题 ↔ 报告分析类型 | 自述的分析类型是否与表内数据形态相符 | 06 |

- 主键失败时可降级为「零件号 + 量具名称」或「零件号 + 被测参数」，须写明降级路径与置信度。
- 矛盾双方都记录，不替提交方选择以哪个为准。
- 文件名只作定位线索，不作判定证据。

### 7.4 严格标准及其边界

- 疑点一律记录，但不得无证据推断；所有推断性判断必须标注依据与置信度。
- **严格标准只影响"是否记警告"，不影响"是否判阻断"**：阻断的唯一判据是 9.1（是否让某条规则无法得出唯一结论）。严禁把"看起来很差"判成阻断。

### 7.6 客户差异层（按客户 × 类型路由）

本分则的两条 L1 条目（UAES / 理想 × `T07`）共用 21 条判定，但**计划表必填列、报告类型、跨文件依赖完全不同**。本节只写差异，不改任何判定口径。

| 项 | UAES × `T07` | 理想 × `T07` |
| --- | --- | --- |
| 计划表名称 | 「测量系统分析计划」或「**MSA 计划表**」 | 「测量系统分析计划」 |
| 计划表逐行必填 | 「序号 / NO」列有值时，同行**除备注外**其余列非空 | 同口径（序号 / NO 有值时除备注外非空） |
| 任务项字段 | 无 | 「**任务项一**」「**任务项二**」两字段，内容须**全部为 OK** |
| 报告类型分派 | **按量具类型分派**：人工 / 目视 / 通止规 / 塞规 / 塞尺 → **kappa**；其余（计量型）→ **重复性及再现性（GRR）** | 固定为「量具重复性和再现性」表；**无 kappa 路径** |

| 结论词要求 | GRR 结论须为「测量系统可以接受」；kappa 结论须为「**Acceptable**」 | R&R 结论须勾选「判定指标 R&R＜10%；该量具可接受」 |

| 量具编号要求 | 必须能取到量具编号（用于与 kappa / GRR 报告配对） | 无编号配对要求 |
| 共用母版风险 | 低（逐量具独立报告） | **高**：多台量具常共用同一张「目录」计划表（总纲 8.7 的典型场景） |

**关键校准：客户原文「不通过」在预检中的降级**

| 客户原文情形 | 预检口径 | 理由 |
| --- | --- | --- |
| 缺同零件号 PFD / 控制计划 / PGQP1 等对端文件 | `W01`，写明「缺比对文件《…》」，**不阻断** | 总纲 7.2：跨文件缺对照件一律警告 |
| GRR 结论非「测量系统可以接受」/ kappa 非「Acceptable」 | `S03` 移交，**不阻断**，仅登记事实 | 结论是否可接受属业务判断（7.1） |
| 任务项一 / 任务项二 非全 OK | `W06`（内部不自洽），**不阻断** | 任务项是汇总栏，其取值不合规属正式审核结论 |
| 计划表缺列 | `B05` | 结构上不承载该判定 |

**五条执行纪律**：

1. **先定条目，再判报告类型**。UAES 走「量具类型 → kappa / GRR」分派，理想只有 GRR 一条路——用理想的单路径去判 UAES 的计数型量具，会把合规的 kappa 报告判成「缺 GRR」。
2. **UAES 的 kappa 不是「可选补充」**，是计数型量具的**唯一正确载体**；反之理想文件中出现 kappa 不得据此加分或扣分。
3. **共用母版缺陷按总纲 8.7 列报**：理想的「目录」计划表被 N 份文件共用时，每份引用件均须标注继承关系，只计一次阻断。
4. **本节不新增级别与原因码**，落点全在 21 条既有规则内。
5. **客户非 UAES / 理想** → 落 L3 记 `S02`，不得按通用结构硬判。

## 9. 严重级别与通过规则

### 9.1 严重级别

| 级别 | 定义 | 是否影响结论 |
| --- | --- | --- |
| 阻断 | 该问题导致至少一条正式审核规则**无法得出唯一结论**——含"取不到数"与"结论方向不唯一"两种 | **是 → 不通过** |
| 警告 | 判定仍可完成，但结果不完整或存在被误判风险 | **否 → 仅记录并移交** |

**四种状态（不是级别，不参与通过判定）：**

| 状态 | 代码 | 本域典型形态 |
| --- | --- | --- |
| 范围外 | `S01` | 规则所需关联对象**本就不在**本次提交范围（`P-15`）；不属本类目的文件剔除 |
| 对端未到 | `S04` | 关联对象应收而未到、本批未提交该类型表单。**按 `src` 分流**：`SUB`（量具报告 / kappa / CP / PGQP1 填报件）→ 配套 `W01` + `S04-S`；`CUS`（客户图纸 / 规范 / 模板本体 / 台账）→ 仅 `S04-C`、**不配 `W01`**（总纲 3.2.4） |
| 规则不适配 | `S02` | 规则侧成因导致某项在本域无判定依据（本版已无此类来源） |
| 移交 | `S03` | 结论措辞归一化、分析类型选择是否正确、真实值与卷面值比对、造假嫌疑 |

> **警告不拦截的补偿**：警告项 100% 列入报告第五章并随报告移交正式审核；正式审核**不得因「预检已通过」而跳过警告指向的字段**（总纲 8.3）。

### 9.2 通过规则

无阻断即通过，存在任一阻断即不通过并给出原因码；警告不影响结论但须 100% 列报并移交；状态项不参与判定但不得略去不记（总纲 8.2 / 8.3）。

本分则补充：待人工确认项不单独影响结论，其级别随所在问题（阻断或警告），标记「待人工确认」只作说明，不另设计入规则。

## 12. 执行要求与约束

1. 按本文件流程执行，不跳过提交范围确认；**不执行任何规则侧核验或口径裁定**（总纲 2.3）。
2. 先定范围、再查缺失：任何「缺失」「不闭合」判定必须先确认对象在声明范围内；未声明时不得判缺件阻断。
3. 以整个提交文件集为对象，不局限于单文件；跨文件一致性必须显式执行。
4. 正确性优先依据类型、值域、基本常识、业务常识与领域知识。
5. 完整性允许合理推断，但必须说明依据与置信度；禁止代填。
6. 一致性应自主推断关联项；关联键缺失时不得判「不一致」，按成因记 `W05` 或 `W01`。
7. 维度一先判定，维度二至五并列；**存在任一阻断项即不通过**，警告不拦截。
8. 采用相对严格标准，疑点必录，但不得无证据推断；**不得把"看起来很差"判成阻断**。
9. 每次调用无状态，不继承历史整改记录。
10. 必须区分「数据不规范」（→ 问题清单）与「范围外 / 应移交」（→ 状态登记）。
11. 证据定位到最小颗粒度：文件 / 表单 / 单元格，或文件 / 页码。
12. 输出 Markdown 报告，警告项 100% 列报，状态项 100% 登记。
13. 不得判定 MSA 业务结论是否合格；不得执行附录 A 所列深审规则。
14. 同一缺陷被多条规则命中时只计一次，取最高级别并注明。
15. 「不适用」一词禁用，必须按 3.1 拆为 `S01` / `S02` / `S03` / `S04`。

## 15. 补充口径
> 本节条款与正文冲突时以本节为准。

### A. 计划表缺列的定级分岔（新增）

「精度 / 分辨率」「分析项目（计量型 / 计数型）」两类字段，**须先核模板代际，再定级**：

| 情形 | 判定 | 说明 |
| --- | --- | --- |
| 本代际计划表结构上**本应设该列**而缺失 | `B05` | 属文件缺陷 |
| 本代际计划表**不设该列**，但可由同文件分析表的 Gage information 区取得 | `W01` | 属**同源替代载体**（总纲 8.5），须注明替代载体位置，不得判阻断 |
| 本代际计划表不设该列，分析表亦取不到 | `B05` | 两侧均无，判定无依据 |
| 无法确定本代际是否应有该列 | `S02` | 规则不适配，预检不评 |

**报告须写明**：本次按哪一代际模板判定、该代际的应有列清单从何而来。缺此说明的 `B05` 不成立。

### B. 共用母版缺陷的列报（引用总纲 8.7）

多份 MSA 共用同一份「目录」计划表时，该表的结构缺陷在**每一份**引用文件中均须列报，但**只计一次阻断**，其余件标注「继承自共用件 `<文件名 › 工作表>`」，并在报告写明继承计数。

### C. 分析表内部一致性优先于跨文件一致性

当同一测量系统的「计划表」与「分析表」对同一属性给出不同写法时，**以分析表为准**（分析表是该系统的实际运算载体），计划表差异记 `W04`，不得据计划表反推分析表有误。

### 附录 D：常见误判

1. 把参考示例当正式数据：模板内「填表指南」类示例表恒为满填、结论为示例值，须与正式数据区分。
2. 把字典表当业务数据：仅含 OK/NOK 两行的辅助表不承载业务信息。
3. 在无勾选区的表单上查勾选：标准表单可能只有 %GRR、ndc 与结论句。
4. 用等值比较匹配文本：全半角、前后缀、分隔符、空格、换行均须归一化后包含匹配。
5. 把「编号为空」直接判「不一致」：应为 `P-17` 完整性问题，关联检查记 `W05`。
6. 把「范围外未提交」判「缺失」：本就不属范围由 `P-15` 记 `S01`；应收而未到的按 `src` 记 `W01` + `S04-S`（`SUB`）或仅 `S04-C`（`CUS`），同样不得判「缺失」。
7. 自行复算后覆盖卷面结论：预检只做卷面自洽比对，复算属深审（`S03`）。
8. 凭文件名或表单名判断内容：名称只作线索，不作证据。
9. 假设同文件内各报告表单结构一致：不同被测参数的表单版式可能完全不同。
10. 假设「已完成」等于「报告已提交」：完成状态与报告实物须分开核对。
11. 按文件名去重：同名不同容、同容不同名的情况都存在。
12. 引入规则中不存在的阈值：本域只用 10%、30%、ndc 5、Kappa 0.75。
13. 把同一缺陷在两条规则下各计一次：结论缺失只归 `P-16`，测量区为空只归 `P-02`，计划表编号整列为空只归 `P-18`，受控字段占位值只归 `P-19`。
14. **不要用「无法判定」代替定级**：读不到且有替代 → `W05`；读不到且无替代 → `B01`；范围不可知 → 记 `W01` 并注明不构成缺件阻断。也不要把 `S01` 写成「不适用」或当成「通过」。

## Q-01 ｜ B03（识别失败）是否卡死整批？

- **冲突依据**：G §4.8 / PRD G.4 将 B03 定为"阻断"；FR-02 规定"未移除阻断置灰"；但 IL-02.17/18 又写"不强制阻断，仅无法解析 B01 仍硬阻断"。
- **产品决议**：
  1. B03 = **文件级阻断**（该文件不送审），但**非整批硬卡死**——因 B03 提供解决路径（多项选择 / 手动指定）。
  2. **整批门禁【开始审核】置灰仅针对不可解决的硬阻断**：B01（格式门禁/无法解析）+ B04 / B05 / B06（内容/结构缺陷）中"未移除"者。"仅 B01 不能顺带豁免 B04/B05/B06" → 明确 B04/B05/B06 与 B01 同属硬阻断。
  3. **确认时仍未解决的 B03 文件 → 与 S02 同处理：自动移出审核队列、不计费**，不卡死整批；P3 明确提示"有 N 个文件待确定归属，将不送审并自动移除"。
  4. 报告 K 计数：B03 计入"阻断项披露"提醒，但**不计入卡死整批的硬阻断计数**。
- **落点（V3.6）**：§3.2 P3 提示行 B（识别失败段）、异常总表·识别失败行、「开始审核」可用性、IL-02.13 边界、验收要点；约束 #30 已为识别失败入口单独立约。
- **验收用例**：AC-16、AC-17、AC-19、AC-33。

## Q-02 ｜ 已确定客户/类型但无规则 → S02 还是保留 B03？

- **冲突依据**：IL-02.17 旧措辞"指定后未命中规则 → 仍为识别失败"；与提示行 B / G §4.9"已确定客户/类型无规则 = S02"矛盾。
- **产品决议**：严格二分——
  1. **仍无法确定归属**（未选 / 多候选未决）→ 维持 B03 / 候选视图。
  2. **已确定客户/类型但无生效规则**（经 IL-02.17/18 指定后）→ 转 **S02 无规则覆盖**，提示行仅"标准模板 / 反馈对应模板"两入口。
  3. 即纠正成功即脱离 B03；"指定后无规则"不再是 B03。修正 IL-02.17 旧措辞。
- **落点（V3.6）**：IL-02.17、IL-02.18 判定列；提示行 B（无规则覆盖段已为 S02）。
- **验收用例**：AC-18、AC-33。

## Q-03 ｜ 零送审任务如何收敛？自动移除 vs 跳过优先级？

- **冲突依据**：IL-02.03 允许取消全选继续；IL-02.16 全未匹配可 0 点完成；JP-10 却写"已匹配为 0 禁用"。
- **产品决议**：
  1. **【开始审核】启用条件**收敛为："存在未解决的硬阻断（B01/B04/B05/B06）才禁用"；全 S02 / 全取消勾选 / 混合 → 允许 0 点完成（修正 JP-10 旧"已匹配为 0 禁用"）。
  2. **自动移除 > 跳过**：未匹配（S02 / 未解决 B03）确认时**自动移除**（从未进送审集合）；已勾选的已匹配文件取消勾选 = **跳过**（不移除、不计费、不滞留于已移除区）。二者不重叠。
  3. 零送审任务完成 → **发送"本次任务无送审文件，未产生审核费用"飞书通知**、不产生审核报告、不进入 P5 审核队列。
- **落点（V3.6）**：JP-10、P3 复选框语义、「开始审核」可用性、IL-02.13（含空集合分支）、验收要点。
- **验收用例**：AC-19、AC-20、AC-23、AC-33。

## Q-04 ｜ 零送审任务的预检报告访问与纠正后版本

- **冲突依据**：JP-08 要求离开待确认去 P10；但零送审可能无审核历史；IL-02.17/18 会重预检，IL-02.08 说下载已留存 PDF 不重新生成。
- **产品决议**：
  1. 消息①深链：零送审任务仍定位 **P3 预检报告区域**（预检免费且先于审核，报告始终存在）；有 P10 审核历史版本时提供切换；确无留存显示"暂无可追溯预检报告"。
  2. **纠正归属/类型后（IL-02.17/18 触发重匹配+重预检）→ 重新生成最新版 PDF**，`precheck_report_generated_at` 更新；旧版本按 doc ID 历史版本机制**保留可追溯、不静默覆盖**。IL-02.08"不重新生成"仅适用于"未做纠正、仅查看"。
  3. 零送审任务**不产生 P11 正式审核报告**。
- **落点（V3.6）**：P3 预检报告区、IL-02.08、JP-08 / IL-11.09 / IL-19.05（既有多版本追溯描述）。
- **验收用例**：AC-29、AC-33。

## Q-05 ｜ 模板推断文件能否被覆盖？入口在哪？

- **冲突依据**：§2.5 / 匹配提示行允许覆盖"模板推断"客户，但 IL-02.17/18 入口只描述"识别失败/低置信"。
- **产品决议**：
  1. **允许覆盖** template_matched 归属；在 P3 匹配提示行"模板推断"标识旁加"更改"入口，**复用 IL-02.17/18 指定器 / 多项选择**。
  2. **亦允许覆盖 file_extracted（文件自身高置信识别）归属**，但覆盖时若与新归属不一致，弹"来源冲突"二次确认（仍允许覆盖，来源改 `manual`）。
  3. IL-02.17/18 适用范围由"识别失败/低置信"扩大为"识别失败 / 模板推断 / 用户质疑归属的文件"。覆盖后按新归属 × 类型重匹配规则 + 重内容级预检，来源改 `manual`，刷新字段/匹配/点数；不沿用旧结论。
- **落点（V3.6）**：P3 匹配提示行（已匹配）「更改」入口、IL-02.17、IL-02.18、术语表"模板匹配推断客户"。
- **验收用例**：AC-13、AC-16、AC-33。

## Q-06 ｜ 受控模板补登后的复核触发与留痕

- **冲突依据**：G 核心原则"不修复、不复检" vs M §4.4.9 要求补登后撤回 S05、改判 B05、重新预检。
- **产品决议**：
  1. 补登复核由**内部规则运营在后台发起**（A11/A19 后台能力），非系统自动、非用户侧触发。
  2. 已完成任务 / 已留存 PDF：更正作为**后台留痕动作**——记录"原 S05 待核 → 补登后 B05"变更日志，原 PDF 保留可查，新判定生成新版本 PDF（doc ID 历史版本）。**不静默覆盖、不主动推送用户重跑**。
  3. 当前判定中的登记状态（27 有 / 13 待补 / 1 无）、截止日 2027-01-01、逾期回落按 M 执行，**不新增通用整改闭环**。
- **落点（V3.6）**：新增约束 #37。
- **验收用例**：AC-08、AC-33。

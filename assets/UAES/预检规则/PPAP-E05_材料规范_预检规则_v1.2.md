## 1. 目的与边界

**目的**：判定这份《材料规范》**是否为受控状态的文件**——即是否带有受控标识。

**不是**判定材料规范写得好不好。牌号选型、力学性能、耐候要求、引用标准是否为最新版，全部是正式审核的工程结论，预检不碰。

**这是 41 个条目里唯一的「单判据类目」**：全部结论由「有无受控章」一项决定，没有第二项兜底。因此本分则的重点不在判据数量，而在**受控标识的识别口径必须写死**，否则同一份文件换个人跑会得出相反结论。

**边界三条**：

1. 本类目**不判实测值**、不判技术参数，故不产生 `B06`。
2. 本类目**无跨文件依赖**，不得因本批次缺图纸 / 缺其它文件记任何问题。
3. 本类目**不判受控章的真伪、签发人、有效期**——那是 `S03`。预检只判「有没有」，不判「算不算数」。

## 4. 判定项（1 项）

> 判据文本以 `00-A §2.1` 为准，本节只把它落成可执行判定。

| # | 判定内容 | 判定方式 | 不满足时 | 来源条款 |
| --- | --- | --- | --- | --- |
| S1 | 文件含**受控章**（受控标识） | 图像层印章检测 + 全文受控字样匹配，二者任一命中即通过 | **`B05`** | 1 |

**为何一项缺失就判 `B05`**：受控状态是本类目**唯一的判定对象**。规则原文对材料规范没有第二条结构要求，若受控标识缺失，这份文件在 UAES 的规则体系里就没有任何可判之处——不是「审出来不合格」，而是**规则无法定位判定对象**。这与 `E03` 的标题判 `B05` 是同一逻辑（总纲 7.2「是否承载关键字段」），不是对原文的加严。

## 5. 判定细则

**5.1 受控标识的三种可接受形态（任一命中即通过）**

| 形态 | 识别方式 | 判定 |
| --- | --- | --- |
| ① 印章图像 | 图像层检测到印章图形（红色 / 蓝色 / 黑色套印），且印章文字含「受控」或公司受控章字样 | 通过 |
| ② 受控水印 | 页面水印、页眉或页脚出现「受控文件」「CONTROLLED」「受控」字样 | 通过 |
| ③ 受控编号标注 | 出现「受控编号」「受控号」「文件受控编号」等字样并附编号值 | 通过 |

三种形态**地位平等**，不因「没盖章只有水印」而判缺失。规则原文只要求「受控标识」，并未限定实现方式。

**5.2 反向词优先于正向词**

同页出现以下字样时，**无论是否有印章，一律判 S1 不满足**（`B05`）：

| 反向字样 | 判定 | 理由 |
| --- | --- | --- |
| 「非受控」「 uncontrolled」「UNCONTROLLED」 | 不通过 | 文件自身声明不受控 |
| 「作废」「废除」「VOID」「OBSOLETE」 | 不通过 | 文件已被废止，不是本次提交的有效版本 |
| 「仅供参考」「参考件」「FOR REFERENCE ONLY」 | 不通过 | 明确排除在受控体系外 |

**反向词优先级高于正向词**——这是本分则唯一的例外规则：一份既盖了受控章又标「作废」的文件，判定为不受控。

**5.3 检测到多处标识时取「最强证据」并全部记录**

一份文件可能同时有印章、水印、编号。报告 10.2 须列出**全部命中位置**（页码 + 形态），不只记第一处。原因：后续若对受控状态有争议，需要能回指到具体页。

**5.4 不得越界判受控章本身**

以下项目**一律 `S03`，不记问题、不影响结论**：

1. 印章是否清晰、是否为原件、是否彩印。
2. 签发人是否具备授权、印章是否在有效期内（印章无有效期概念）。
3. 受控编号的编码规则是否符合公司规定。
4. 文件是否在文控系统内登记。

预检只回答「这份文件带不带受控标识」，不回答「这个受控标识能否被采信」。

**5.5 客户差异层为空时的兜底**

本期 `E05` 只有 UAES 一条路由。若将来出现其它客户的材料规范规则，**不得**套用本分则——须先在 00-A §1 登记、§2 抽 `required_structure`，再在本分则 §7 增列差异层。

## 6. 执行流程

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 识别：（客户, 文件类型）=（UAES, 材料规范），置信度 ≥ 中 | 路由 = `U10` / L2 |
| 2 | 全文文字层检索反向词（§5.2） | 命中即 `B05`，跳到第 5 步 |
| 3 | 全文检测受控标识三形态（§5.1），记录全部命中位置 | 命中 → 通过；未命中 → `B05` |
| 4 | 若图像层存在但印章不可辨，记 `W05` 并在 10.2 说明 | `W05` + `B05` |
| 5 | 按总纲第 11 节十章模板出报告；受控标识检测结果挂 10.2 | 报告 |

**执行顺序不可调换**：先查反向词，再查正向标识。反过来会让「盖章但已作废」的文件被判通过，这是本分则最容易出错的地方。

## 8. 级别与原因码

级别定义与原因码含义见总纲 5.2 / 8.1，本节只列本类目的典型情形。

| 原因码 | 本类目典型情形 | 责任侧 |
| --- | --- | --- |
| `B05` | 无任何受控标识；出现反向词（非受控 / 作废 / 仅供参考） | 材料侧 |
| `B01` | 文件损坏 / 加密 / 无文字层且无图像层 | 材料侧 |
| `B03` | 客户或文件类型识别不出 | 提交方 |
| `W05` | 印章区域图像模糊不可辨，受控状态无法确认 | 解析侧 |
| `S03` | 印章真伪、签发授权、受控编号规则——**移交正式审核，不记问题** | 正式审核 |

**本类目不产生 `B06`**：无数值比对、无跨文件比对。
**本类目不产生 `W01` / `W02` / `W03`**：除受控标识外无第二项结构，不存在「块缺失」或「字段为空」的判定对象。

## 9. 报告与输出

按总纲第 11 节「统一报告模板 v1.0」十章输出，本分则不再另行定义章序。

| 挂载位置 | 内容 |
| --- | --- |
| 第二章 | 文件级结论列填「路由 `U10` / L2」；本类目无同批组，该列填 `—` |
| 第四章 | 阻断项：S1 不满足时入此章 |
| 第五章 | 通常为空；仅印章不可辨时记 `W05` |
| 第九章 | 1 项结构判据结果（`RS-U10-S1`），须标明「命中形态 / 未命中」 |
| 10.1 | 受控标识检测表：页码、命中形态（印章 / 水印 / 编号 / 无）、原始文字 |
| 10.2 | 解析说明：文字层是否可用、图像层是否可用、检测了哪些页 |

**结论口径**：任一 `B` 码 → 不通过；仅 `W` 码 → 通过。

**识别置信度低不等于「未执行」**：低置信度按总纲 4.8 记 `B03`（识别失败 · 身份不可归属），出路为 4.9 人工指定。总纲 5.1 已把「未执行」收窄为**单一成因**（该条目既无分则也无 `required_structure`），识别置信度不在此列——把它记成「未执行」等于让一份认不出是谁的文件**免检放行**。

## 10. 不要做

1. 不要判材料牌号、性能指标、引用标准是否正确——那是 `S03`。
2. 不要判受控章是否清晰、是否原件、签发人是否有授权——那是 `S03`。
3. 不要在检测到印章后跳过反向词检索——「盖章但已作废」必须判不通过。
4. 不要只检测首页；受控章可能盖在末页或每页页脚。
5. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。
6. 不要把本类目的受控章要求套到 `E03` 包装方案上（`E03` 不要求受控章）。
7. 不要因本批次缺其它文件记任何问题——本类目无同批依赖。
8. 不要在报告里出现「疑似」「可能」类未定级表述。
9. 不要新增章、调整章序或自定义报告字段。
10. 不要修改 `00-A §2.1` 的判据文本；判据有误应先改 00-A，再同步本分则。

## 1. 目的与边界

**目的**：判定这份《顾客工程批准》**是否具备可被 UAES 审核的审批结构**——封面表格与否决列是否可判、备注栏是否可读、**按所选路径**签名与日期要件是否齐备、条件认可路径下的偏差清单是否同批在案。

**这是 41 个条目中唯一带「路径分支」的类目**：判定项不是全部同时生效，而是由文件上勾选的认可路径决定哪一组生效。写错路径就会报出整片假缺陷，因此 §5.1 的路径判定必须先于全部结构判定。

**边界三条**：

1. 本类目**不判实测值**，故不产生 `B06`；但**判日期时序自洽**（S4 / S7），落 `W06`。
2. 本类目**有跨文件依赖**（偏差认可汇总清单），但缺对端一律 `W01`，不阻断。**此处不产生 `S04`**——本分则判定源为 L2（总纲 4.7），只判 `required_structure` 的结构存在性与必填性，**不做跨文件一致性判定**，故不存在「受阻而没做成的判定项」；`W01` 在这里是缺件提示，不是受阻登记。若将来升级为 L1、开始判跨文件一致性，须按总纲 3.2.4 补 `S04-S` / `S04-C`。
3. 本类目**没有分则专属的客户差异**（本期仅 UAES 一家），客户差异层为预留位。

## 4. 判定项（8 项）

> 判据文本以 `00-A §2.1` 为准，本节只把它落成可执行判定。

| # | 判定内容 | 判定方式 | 不满足时 | 来源条款 |
| --- | --- | --- | --- | --- |
| S1 | 封面含表格，「否决 / Reject」列为可判定列 | 表头列名近义匹配 | **`B05`** | 1 |
| S2 | 封面含「UAES 批准的前提/备注」栏且文字可读 | 区域标题匹配 + 文字可读性判定 | 缺 → **`B05`**；不可读 → `W05` + `B05` | 1 |
| S3 | **完全认可路径**：组长（Team Leader）、审核（Checked by）、批准（Approved by）三处签名 + 日期齐全 | 三处逐一检查签名与日期 | `W01` | 1 |
| S4 | **完全认可路径**：S3 三处日期递增（组长 ≤ 审核 ≤ 批准） | 日期比较 | `W06` | 1 |
| S5 | **条件认可 / 偏差认可路径**：存在同零件编号 + 同零件名称的偏差认可汇总清单 | 同批建组查找对端（总纲 10.5） | `W01`，写明「缺比对文件《偏差认可汇总清单》」 | 1 |
| S6 | 该清单含字段：零件号、偏差项、UAES 评估确认、是否需要偏差 | 清单表头列名匹配 | **`B05`** | 1 |
| S7 | 封面整改承诺最晚期限与清单内备注日期**一致** | 取两处日期比对 | `W06`，并提示「封面条件认可时间与偏差汇总清单承诺时间不一致，请复核」 | 1 |
| S8 | 「否决」列标记（打×/勾）仅作**交叉校验**，以备注文字为首要依据 | 两处结论比对 | 二者冲突 → `W06` | 1 |

**S3 / S4 / S7 / S8 一律不判阻断——这是本分则最重要的一次口径校准。**

规则原文对「任一签名缺失或日期颠倒」判「不通过」。但预检的职责是「**能否被可靠审核**」：

| 情形 | 原文 | 预检 | 理由 |
| --- | --- | --- | --- |
| 签名缺失 | 不通过 | `W01` | 签名属形式要件，缺了可补；文件结构与结论仍可审 |
| 日期颠倒 / 两处不一致 | 不通过 | `W06` | 内部不自洽，但**不影响结论方向**，可读到具体日期 |
| 否决列与备注冲突 | 不通过 | `W06` | 规则明示「以备注文字为首要依据」，故冲突可解 |

「该不该批准」是 UAES 正式审核的结论（`S03`），不是预检的输出。依据：`00-A §4.2.1` 与 §4.2.3（四类不得放宽仅指结构不可判或代数不自洽，本类目不属于）。

## 5. 判定细则

**5.1 路径判定（必须先做，否则全部后续判定无效）**

封面上的认可路径由勾选 / 标记决定，分两组：

| 路径 | 识别依据 | 生效判定项 | 不生效判定项 |
| --- | --- | --- | --- |
| **完全认可** | 「完全认可」「Full Approval」被勾选 | S3、S4、S8 | S5、S6、S7 |
| **条件认可 / 偏差认可** | 「条件认可」「偏差认可」「Conditional / Deviation Approval」任一被勾选 | S5、S6、S7、S8 | S3、S4 |

处理规则：

1. S1、S2 两条与路径无关，**任何路径都必须判**。
2. 不生效的判定项，报告第九节记为「**本路径不适用**」，**不得**记为通过，也**不得**记为缺失。
3. 若**两条路径同时被勾选**：记 `W02`（勾选冲突），并按**两条路径都判**的方式出结果，报告须写明「路径冲突，已按两组全判，请复核勾选」。
4. 若**一条都未勾选、或标记不可辨**：记 `W05`（解析侧）+ 报告 10.2 说明；S3~S7 全部记「**路径无法判定**」，**不得**给任何 `B` 码——路径不明不是供应商的缺陷，是文件形态问题。

**5.2 S1「可判定列」的判定**

「否决 / Reject」列满足以下**任一**即视为「可判定列」存在：

| 情形 | 判定 | 说明 |
| --- | --- | --- |
| 表头含「否决」「Reject」「驳回」等字样 | 存在 | 标准情形 |
| 表头为「结论」「判定」且列内出现 ×/勾标记 | 存在 | 近义 + 有实际标记 |
| 表头存在但整列空白 | 存在 | 表头在，规则可定位；空白另按 §5.3 处理 |

表头**完全不存在**时判 S1 不满足（`B05`）——规则无法定位「否决」这一判定维度。

**5.3 列存在但整列空 → `W02`，不升 `B05`**

否决列有表头、无任何标记，属「有结构无值」，记 `W02`。**不得**升 `B05`。

**5.4 S2 备注栏「文字可读」的判定**

「可读」指：**存在文字层，或图像层中人眼可辨认的手写 / 印刷文字**。以下判为不可读（`W05` + `B05`）：

1. 栏位存在但完全空白——注意：**空白不属于「不可读」，属于「无内容」**，记 `W02`。
2. 栏位有文字但扫描模糊、笔画粘连、无法辨认任何完整词。
3. 栏位被图像遮盖、裁切。

**空白与不可读必须分开**：空白是材料侧问题（`W02`），不可读是解析侧问题（`W05`）。

**5.5 S5 同批依赖的处理（总纲 10.5）**

1. 建组键：**（客户 × 零件号）**。差异：本类目额外要求零件名称一致。
2. 先在本批次内找对端文件《偏差认可汇总清单》；找到 → 继续判 S6、S7。
3. **未找到 → `W01`，写明「缺比对文件《偏差认可汇总清单》」，不阻断**（总纲 10.5 硬约束、00-A §4.1）。
4. 对端存在但零件编号或名称不一致 → 视为**未找到对端**，记 `W01` 并写明不一致的具体值。
5. **不得**因缺对端而把 S6、S7 一并判缺失——它们是「无法判定」，不是「不存在」。

**5.6 S8 交叉校验的优先级**

规则原文明确「以备注文字为首要依据」，因此：

1. 备注文字与否决列标记**一致** → 通过。
2. 两者**冲突** → `W06`，并在报告中**以备注文字为准**记录结论方向。
3. 否决列无标记、备注有文字 → 按备注判，记 `S03` 说明「否决列未标记」，**不阻断**。

**5.7 客户差异层为空时的兜底**

本期 `E11` 只有 UAES 一条路由。若将来出现其它客户的顾客工程批准规则，**不得**套用本分则的 8 项——须先在 00-A §1 登记、§2 抽 `required_structure`，再在本分则 §7 增列差异层。

## 6. 执行流程

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 识别：（客户, 文件类型）=（UAES, 顾客工程批准），置信度 ≥ 中 | 路由 = `U19` / L2 |
| 2 | **先判路径**（§5.1）：完全认可 / 条件认可 / 冲突 / 无法判定 | 生效判定项清单 |
| 3 | 判 S1（否决列）、S2（备注栏）——与路径无关 | `B05` / `W02` / `W05` |
| 4 | 按路径判 S3、S4（完全认可）或 S5、S6、S7（条件/偏差） | `W01` / `W06` / `B05` |
| 5 | 判 S8 交叉校验 | `W06` 或通过 |
| 6 | 按 §4 表定级，汇总问题清单 | `B05` / `W01` / `W02` / `W06` / `W05` |
| 7 | 按总纲第 11 节十章模板出报告；路径与签署结果挂 10.1 | 报告 |

**第 2 步不可跳过**。跳过路径判定会把「条件认可」的文件按「完全认可」判，报出三条签名缺失——这是本类目最容易出现的整片假缺陷。

## 8. 级别与原因码

级别定义与原因码含义见总纲 5.2 / 8.1，本节只列本类目的典型情形。

| 原因码 | 本类目典型情形 | 责任侧 |
| --- | --- | --- |
| `B05` | 封面无表格；「否决 / Reject」列不存在；备注栏缺失；偏差清单缺必备字段 | 材料侧 |
| `W01` | 三处签名或日期任一缺失；缺对端《偏差认可汇总清单》 | 材料侧 |
| `W02` | 否决列整列为空；备注栏空白；两条路径同时勾选 | 材料侧 |
| `W06` | 三处日期非递增；封面期限与清单日期不一致；否决列与备注冲突 | 材料侧 |
| `B01` | 文件损坏 / 加密 / 无文字层且无图像层 | 材料侧 |
| `B03` | 客户或文件类型识别不出 | 提交方 |
| `W05` | 备注栏模糊不可读；路径标记不可辨 | 解析侧 |
| `S03` | 是否应当批准、批准条件是否充分、偏差是否可接受；否决列未标记但备注有文字——**移交正式审核，不记问题** | 正式审核 |

**本类目 `S03` 不影响结论**：`S03` 不是结论码。

## 9. 报告与输出

按总纲第 11 节「统一报告模板 v1.0」十章输出，本分则不再另行定义章序。

| 挂载位置 | 内容 |
| --- | --- |

| 第五章 | 警告项：签名缺失、日期不自洽、缺对端、列整列空 |
| 第九章 | 8 项结构判据逐项结果（`RS-U19-S1`~`S8`），**不生效项须明确记「本路径不适用」** |
| 10.1 | 路径与签署表：路径判定结果、三处签名与日期、偏差清单匹配情况（零件编号 / 名称） |
| 10.2 | 解析说明：手写区域可读性、路径标记识别方式、是否有冲突 |

**识别置信度低不等于「未执行」**：低置信度按总纲 4.8 记 `B03`（识别失败 · 身份不可归属），出路为 4.9 人工指定。总纲 5.1 已把「未执行」收窄为**单一成因**（该条目既无分则也无 `required_structure`），识别置信度不在此列——把它记成「未执行」等于让一份认不出是谁的文件**免检放行**。

## 10. 不要做

1. **不要跳过路径判定**直接判签名与偏差清单（§6 第 2 步）。
2. 不要因签名缺失或日期颠倒就判整份文件不通过——落 `W01` / `W06`（§4 末段）。
3. 不要把「本路径不适用」记成通过或缺失。
4. 不要在路径无法判定时给任何 `B` 码（§5.1 第 4 项）。
5. 不要因缺《偏差认可汇总清单》而把 S6/S7 一并判缺失——记「无法判定」（§5.5 第 5 项）。
6. 不要把备注栏「空白」与「不可读」混为一谈（§5.4 末段）。
7. 不要用否决列标记推翻备注文字——规则明示以备注为首要依据（§5.6）。
8. 不要判 UAES 是否应当批准、偏差是否可接受——那是 `S03`。
9. 不要在手写区域做文字识别并据此判结论方向。
10. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。
11. 不要在报告里出现「疑似」「可能」类未定级表述。
12. 不要新增章、调整章序或自定义报告字段。
13. 不要修改 `00-A §2.1` 的判据文本；判据有误应先改 00-A，再同步本分则。

## 11. 可配置项

| 项 | 是否可配置 | 说明 |
| --- | --- | --- |
| 8 项结构判据 | **不可配置** | 来自客户规则，配置化即等于改规则 |
| 「否决 / Reject」列近义词典 | 可配置 | 只允许**扩充**，不得删减 |
| 路径名称近义词典（完全认可 / 条件认可 / 偏差认可） | 可配置 | 只允许**扩充**，不得删减 |
| 签名缺失的定级（`W01`） | **不可配置** | `00-A §4.2.1` 已定；改为 `B` 码即等于替客户做否决决策 |
| 日期不自洽的定级（`W06`） | **不可配置** | 同上 |
| 同批建组键是否包含零件名称 | **不可配置为「否」** | 本类目判据明确要求同零件编号 + 同零件名称 |
| 置信度门槛 | 可配置（不低于「中」） | **低于中 → `B03` 识别失败（总纲 4.8）**；**不得返回「未执行」**——其成因已由总纲 5.1 收窄为唯一一种 |
| 深度档 | **不适用** | 深度档只对 L3 试探（总纲 7.7）；本条目为 L2 |

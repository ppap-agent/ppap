## 1. 目的与边界

**目的**：判定这份《APQP 项目问题清单》**是否具备可被理想审核的问题台账结构**——即主表与 4 个身份字段是否齐备、「未完全关闭」时是否有对应的问题登记行、登记行是否填了措施 / 时间 / 负责人、四个风险列取值是否规范。

**不是**判定项目有没有问题、问题解没解决。这是本类目最容易越界的地方：问题清单的「内容」天然是业务信息，预检只判**台账结构是否成立**。

**边界三条**：

1. 本类目**不判实测值**，故不产生 `B06`。
2. 本类目**无跨文件依赖**，不得因本批次缺其它文件记任何问题。
3. 本类目**没有分则专属的客户差异**（本期仅理想一家），客户差异层为预留位。

## 4. 判定项（5 项）

> 判据文本以 `00-A §2.2` 为准，本节只把它落成可执行判定。

| # | 判定内容 | 判定方式 | 不满足时 | 来源条款 |
| --- | --- | --- | --- | --- |
| S1 | 含「项目问题清单」表，含字段：车型、供应商名称、零件编号、零件名称，且均非空 | 表标题 + 4 字段匹配 + 非空 | 缺 → **`B05`**；空 → `W02` | 1 |
| S2 | 四个「是否完全关闭」字段任一为「No」时，「问题描述」列须存在内容非空行 | 条件触发 + 行存在性 | `W01`（缺问题登记，非结构缺失） | 2 |
| S3 | 问题描述有值时，同行「对应措施」「时间节点」「负责人」均非空 | 逐行判定 | `W02` | 3 |
| S4 | 问题描述有值时，同行四个风险列（整车/总成功/性能性、SOP+3 产能风险、安全性、法律法规风险）取值为「Yes」或「No」 | 逐行取值集合校验 | `W03` | 4 |
| S5 | 「时间节点」晚于当前时间 | 日期比较（当前日期为预检执行日） | 早于 → **`S03`**（逾期属整改有效性，移交正式审核） | 3 |

**S2 为何判 `W01` 而非 `B05`**：四个「是否完全关闭」字段有 `No`、但问题描述列没有对应登记行——这是**该登记的没登记**，属缺项，不是结构不存在。表在、列在，规则可定位；缺的是内容。按总纲 7.2 落 `W01`。

**S5 为何判 `S03` 而非阻断**：时间节点已过期是**整改有效性问题**，不是结构缺陷。预检只判「有没有写时间节点」（S3 已覆盖），是否逾期、逾期是否可接受交给正式审核。**预检若在此处阻断，等于替理想判定项目失败**（`00-A §4.2.1`）。

## 5. 判定细则

**5.1 表标题与字段名近义通过**

| 应有项 | 可接受的写法（示例，非穷举） |
| --- | --- |
| 项目问题清单 | APQP 问题清单 / 问题跟踪清单 / 项目问题台账 / 开口项清单 |
| 车型 | 项目车型 / 车型代号 / 适用车型 |
| 供应商名称 | 供方名称 / 供应商 / 制造商 |
| 零件编号 | 零件号 / 产品编号 / 物料编号 |
| 零件名称 | 产品名称 / 件名 / 零件名 |
| 是否完全关闭（四项） | 过程审核是否关闭 / 检验体系审核是否完全关闭 / 供应商追溯体系评审 / 其他专项关闭情况 |
| 问题描述 | 问题 / 问题点 / 开口项描述 / 不符合描述 |
| 对应措施 | 措施 / 纠正措施 / 改善措施 / 对策 |
| 时间节点 | 计划完成时间 / 节点 / 完成时间 / 目标日期 |
| 负责人 | 责任人 / 担当 / 责任者 |
| 四个风险列 | 整车/总成功/性能性风险、SOP+3产能风险、安全性风险、法律法规风险 |

近义**只用于确认存在**。取值另按 S3~S5 判定。

**5.2 S2 的触发与判定**

1. 逐个读取四个「是否完全关闭」字段的值，取值集合按 `{Yes, No}` 判（含 `Y/N`、`是/否` 的等价写法）。
2. **任一为 `No`** → 触发 S2，要求「问题描述」列至少存在 **1 行内容非空**。
3. 无任何内容行 → `W01`，报告写明「有未关闭项但问题描述列无登记内容」。
4. **四个全为 `Yes` 或全部为空** → S2 **不适用**，记「本项不适用」，不记问题。
   - 全为空的情形须在 10.1 注明「四项关闭状态均未填，S2 未触发」，并按需提示补充——**不记原因码**（本分则未从规则原文抽到「关闭状态必填」的要求，不得自行加严）。

**5.3 S3 / S4 的行范围**

1. 行范围 = 「问题描述」列有非空值的**全部行**。
2. S3 判定范围 = 「对应措施」「时间节点」「负责人」三列，任一为空即 `W02`，**一行只记一次**。
3. S4 判定范围 = 四个风险列的**取值位**，任一取值不在 `{Yes, No}`（含等价的 `Y/N`、`是/否`）即 `W03`，**一行只记一次**。
   - **四类风险合并为一列时，S4 照常判**：真实模板存在「一个表头承载四类风险」的情形（实测 `JL-APQP-4-07 B/V1.0` 的 `I7` 一个表头下即四类风险）。此时按**单元格内文本切分**取证：识别四个子项（整车/总成功/性能性、SOP+3 产能风险、安全性、法律法规风险）及紧随其后的取值，逐个按 `{Yes, No}` 校验；**不得因「只有一列」判 S4 不成立或记 `B05`**——结构合并是模板设计，不是缺栏。切分不出四个子项的（如整格一段自由文本），记 `W03`（取值不可归一），**不判 `B05`**。
   - 合并列与四列拆分**不得互相换算要求**：不得因某模板拆成四列就更严、合并成一列就更松，判定式完全相同。
4. 四个风险列**允许整列为空**——此时 S4 记「本项不适用」，不记 `W03`。理由：规则原文只要求「有值时取值规范」，未要求必填。
5. 剔除标题行、小计行：整行仅 1~2 个单元格有值且首列含「合计」「小计」「说明」等字样。

**5.4 S5 的时间比较口径**

1. 当前日期 = **预检执行日**，须在报告 10.2 写明具体日期。
2. 「时间节点」为空 → 已在 S3 记 `W02`，**S5 不再记**。
3. 「时间节点」无法解析为日期（如「见备注」「持续推进」）→ 记 `W03`（写法不规范），**不记 `S03`**。
4. 时间节点 **≤ 当前日期** → `S03`，报告写明「时间节点已到期或逾期」，并列出该行。
5. `S03` **不影响结论**，只写进报告供正式审核参考。

**5.5 不得越界判内容**

以下项目**一律 `S03`，不记问题、不影响结论**：

1. 问题是否真的已关闭（`Yes` 是否属实）。
2. 措施是否有效、是否针对根因。
3. 风险评级是否正确（把高风险评成低风险）。
4. 逾期是否可接受、是否需要升级。
5. 「是否完全关闭」四项是否覆盖了全部审核维度。

**5.6 客户差异层为空时的兜底**

本期 `T15` 只有理想一条路由。若将来出现其它客户的问题清单规则，**不得**套用本分则的 5 项——须先在 00-A §1 登记、§2 抽 `required_structure`，再在本分则 §7 增列差异层。

## 6. 执行流程

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 识别：（客户, 文件类型）=（理想, APQP 项目问题清单），置信度 ≥ 中 | 路由 = `L15` / L2 |
| 2 | 定位主表与 4 个身份字段（§5.1） | `B05` / `W02` |
| 3 | 读取四个「是否完全关闭」字段，判 S2 是否触发（§5.2） | `W01` 或「不适用」 |
| 4 | 圈定问题登记行，判 S3、S4（§5.3） | `W02` / `W03` |
| 5 | 判 S5 时间节点（§5.4） | `S03` |
| 6 | 按 §4 表定级，汇总问题清单 | `B05` / `W01` / `W02` / `W03` / `S03` |
| 7 | 按总纲第 11 节十章模板出报告；触发与行判定结果挂 10.1 | 报告 |

**第 3 步必须在第 4 步之前**：S2 决定「问题登记行是否存在」，S3/S4 决定「登记行填得如何」。顺序颠倒会在无登记行的文件上报出 0 条 S3，掩盖真正问题。

## 9. 报告与输出

按总纲第 11 节「统一报告模板 v1.0」十章输出，本分则不再另行定义章序。

| 挂载位置 | 内容 |
| --- | --- |
| 第二章 | 文件级结论列填「路由 `L15` / L2」；本类目无同批组，该列填 `—` |
| 第四章 | 阻断项：主表缺失、4 个身份字段缺失 |
| 第五章 | 警告项：字段为空、无问题登记、登记行缺值、取值越界 |
| 第九章 | 5 项结构判据逐项结果（`RS-L15-S1`~`S5`），S2/S4/S5 须标明「本项不适用」或具体行号 |
| 10.1 | 字段与触发表：4 个身份字段值、4 个关闭状态值、S2 触发结果、登记行数与行号 |
| 10.2 | 解析说明：当前日期（`S5` 基准）、表格线是否完整、无法解析为日期的取值 |
| 10.3 | **口径说明**：若 S5 出 `S03`，须写「时间节点已逾期，预检仅记录事实，是否可接受由正式审核判定」 |

**结论口径**：任一 `B` 码 → 不通过；仅 `W` 码 → 通过；仅 `S03` → 通过。

**识别置信度低不等于「未执行」**：低置信度按总纲 4.8 记 `B03`（识别失败 · 身份不可归属），出路为 4.9 人工指定。总纲 5.1 已把「未执行」收窄为**单一成因**（该条目既无分则也无 `required_structure`），识别置信度不在此列——把它记成「未执行」等于让一份认不出是谁的文件**免检放行**。

## 10. 不要做

1. 不要判问题是否真已关闭、措施是否有效、风险评级是否正确——那是 `S03`。
2. 不要因为时间节点逾期就判整份文件不通过——记 `S03`（§4 末段）。
3. 不要在没有未关闭项时判 S2 缺失——记「不适用」（§5.2 第 4 项）。
4. 不要要求四个风险列必填——规则原文只要求「有值时取值规范」（§5.3 第 4 项）。
5. 不要把时间节点无法解析记为逾期（`S03`）——应记 `W03`（§5.4 第 3 项）。
6. 不要在时间节点为空时同时记 S3 与 S5（§5.4 第 2 项）。
7. 不要把一行的多个空列记成多条 `W02`——一行只记一次。
8. 不要跳过 S2 直接判 S3/S4（§6 末段）。
9. 不要用模板版式反推客户或文件类型（总纲 4.5 识别禁令）。
10. 不要因本批次缺其它文件记任何问题——本类目无同批依赖。
11. 不要在报告里出现「疑似」「可能」类未定级表述。
12. 不要新增章、调整章序或自定义报告字段。
13. 不要修改 `00-A §2.2` 的判据文本；判据有误应先改 00-A，再同步本分则。

| 逾期的定级（`S03`） | **不可配置** | `00-A §4.2.1` 已定；改为 `B` 码即等于替客户判定项目失败 |
| 当前日期来源 | 可配置（须可由报告追溯） | 不得使用文件内日期代替执行日 |
| 置信度门槛 | 可配置（不低于「中」） | **低于中 → `B03` 识别失败（总纲 4.8）**；**不得返回「未执行」**——其成因已由总纲 5.1 收窄为唯一一种 |
| 深度档 | **不适用** | 深度档只对 L3 试探（总纲 7.7）；本条目为 L2 |
